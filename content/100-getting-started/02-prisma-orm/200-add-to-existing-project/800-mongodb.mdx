[MongoDB](https://www.mongodb.com/) 是一個流行的基於文件的 NoSQL 資料庫，以其靈活性、可擴展性和開發者友善的特性而聞名。在本指南中，您將學習如何將 Prisma ORM 加入現有的 TypeScript 專案、將其連接到 MongoDB、自省現有的資料庫架構，並開始使用型別安全的 Prisma Client 進行查詢。

:::warning[Prisma ORM v7 的 MongoDB 支援]

**Prisma ORM v7 的 MongoDB 支援將在近期推出。** 在此期間，使用 MongoDB 時請使用 **Prisma ORM v6.19**（最新的 v6 版本）。

本指南使用 Prisma ORM v6.19 以確保與 MongoDB 的完全相容性。

:::

:::tip

如果您正在從 Mongoose 遷移到 Prisma ORM，請參閱我們的 [Migrate from Mongoose guide](/guides/migrate-from-mongoose)。

:::

## 前置需求

為了成功完成本指南，您需要：

- 在您的機器上安裝 [Node.js](https://nodejs.org/en/)（請參閱[系統需求](/orm/more/upgrade-guides/upgrading-versions/upgrading-to-prisma-6#minimum-supported-nodejs-versions)以了解官方支援的版本）
- 具有 `package.json` 檔案的現有 TypeScript 專案
- 存取具有副本集部署的 MongoDB 4.2+ 伺服器。我們建議使用 [MongoDB Atlas](https://www.mongodb.com/cloud/atlas)。

:::warning

MongoDB 資料庫連接器使用交易來支援巢狀寫入。交易**需要**[副本集](https://www.mongodb.com/docs/manual/tutorial/deploy-replica-set/)部署。最簡單的部署副本集方式是使用 [Atlas](https://www.mongodb.com/docs/atlas/getting-started/)。它可以免費開始使用。

:::

確保您手邊有資料庫[連線 URL](/orm/reference/connection-urls)（包含您的身份驗證憑證）！

:::note

如果您的專案包含多個具有 `package.json` 檔案的目錄（例如，`frontend`、`backend` 等），請注意 Prisma ORM 是專門設計用於 API/後端層。要設定 Prisma，請導航至包含相關 `package.json` 檔案的適當後端目錄，並在那裡設定 Prisma。

:::

## 1. 設定 Prisma ORM

導航至您現有的專案目錄並安裝所需的相依套件：

```terminal
npm install prisma@6.19 @types/node --save-dev
npm install @prisma/client@6.19 dotenv
```

以下是各套件的功能說明：

- **`prisma`** - Prisma CLI，用於執行 `prisma init`、`prisma db pull` 和 `prisma generate` 等指令
- **`@prisma/client`** - Prisma Client 函式庫，用於查詢您的資料庫
- **`dotenv`** - 從您的 `.env` 檔案載入環境變數

:::info[為什麼使用 Prisma v6.19？]

這是完全支援 MongoDB 的 Prisma ORM v6 最新穩定版本。Prisma ORM v7 的 MongoDB 支援即將推出。

您也可以安裝 `prisma@6` 和 `@prisma/client@6` 以自動取得最新的 v6 版本。

:::

## 2. 初始化 Prisma ORM

使用以下指令建立 [Prisma Schema](/orm/prisma-schema) 檔案，設定您的 Prisma ORM 專案：

```terminal
npx prisma init --datasource-provider mongodb --output ../generated/prisma
```

此指令會執行以下幾項操作：

- 建立包含 `schema.prisma` 檔案的 `prisma/` 目錄，其中包含您的資料庫連線設定
- 在根目錄中建立用於環境變數的 `.env` 檔案
- 建立用於 Prisma 設定的 `prisma.config.ts` 檔案

產生的 `prisma.config.ts` 檔案如下所示：

```typescript file=prisma.config.ts
import { defineConfig, env } from 'prisma/config'

export default defineConfig({
  schema: 'prisma/schema.prisma',
  migrations: {
    path: 'prisma/migrations',
  },
  engine: "classic",
  datasource: {
    url: env('DATABASE_URL'),
  },
})
```

將 `dotenv` 加入 `prisma.config.ts`，以便 Prisma 可以從您的 `.env` 檔案載入環境變數：

```typescript file=prisma.config.ts
// add-start
import 'dotenv/config'
// add-end
import { defineConfig, env } from 'prisma/config'

export default defineConfig({
  schema: 'prisma/schema.prisma',
  migrations: {
    path: 'prisma/migrations',
  },
  engine: "classic",
  datasource: {
    url: env('DATABASE_URL'),
  },
})
```

產生的 schema 使用 [ESM-first `prisma-client` generator](/orm/prisma-schema/overview/generators#prisma-client) 並具有自訂輸出路徑：

```prisma file=prisma/schema.prisma
generator client {
  provider = "prisma-client"
  output   = "../generated/prisma"
}

datasource db {
  provider = "mongodb"
  url = env("DATABASE_URL")
}
```

## 3. 連接您的資料庫

使用您的 MongoDB 連線 URL 更新 `.env` 檔案：

```bash file=.env
DATABASE_URL="mongodb+srv://username:password@cluster.mongodb.net/mydb"
```

對於 MongoDB Atlas，連線 URL 格式為：

```
mongodb+srv://USERNAME:PASSWORD@CLUSTER.mongodb.net/DATABASE
```

自行託管的 MongoDB 連線 URL 格式：

```
mongodb://USERNAME:PASSWORD@HOST:PORT/DATABASE
```

連線 URL 組成部分：

- **`USERNAME`**：您的資料庫使用者名稱
- **`PASSWORD`**：您的資料庫使用者密碼
- **`HOST`**：執行 [`mongod`](https://www.mongodb.com/docs/manual/reference/program/mongod/#mongodb-binary-bin.mongod) 或 [`mongos`](https://www.mongodb.com/docs/manual/reference/program/mongos/#mongodb-binary-bin.mongos) 的主機
- **`PORT`**：資料庫伺服器執行的連接埠（通常為 `27017`）
- **`DATABASE`**：您的資料庫名稱

:::tip

對於 MongoDB Atlas，您可以手動將資料庫名稱附加到連線 URL，因為 Atlas 預設不包含它。

:::

### 連線問題疑難排解

#### `Error in connector: SCRAM failure: Authentication failed.`

如果您看到 `Error in connector: SCRAM failure: Authentication failed.` 錯誤訊息，您可以透過在連線字串末尾[加入](https://github.com/prisma/prisma/discussions/9994#discussioncomment-1562283) `?authSource=admin` 來指定身份驗證的來源資料庫。

#### `Raw query failed. Error code 8000 (AtlasError): empty database name not allowed.`

如果您看到 `Raw query failed. Code: unknown. Message: Kind: Command failed: Error code 8000 (AtlasError): empty database name not allowed.` 錯誤訊息，請務必將資料庫名稱附加到資料庫 URL。您可以在這個 [GitHub issue](https://github.com/prisma/docs/issues/5562) 中找到更多資訊。

## 4. 自省您的資料庫

執行以下指令以自省您現有的資料庫：

```terminal
npx prisma db pull
```

此指令會：
- 從您的 `.env` 檔案讀取 `DATABASE_URL`
- 連接到您的 MongoDB 資料庫
- 取樣您集合中的文件以推斷架構
- 在您的 `schema.prisma` 檔案中產生 Prisma 模型

![Introspect your database with Prisma ORM](/img/getting-started/prisma-db-pull-generate-schema.png)

:::info

**MongoDB 自省限制：** Prisma 透過取樣文件來自省 MongoDB。您可能需要手動：
- 使用 `@relation` 屬性加入關聯欄位
- 如果取樣未捕捉到所有變化，調整欄位型別
- 加入自省期間未偵測到的索引和約束

:::

## 5. 產生 Prisma ORM 型別

基於自省的 schema 產生 Prisma Client：

```terminal
npx prisma generate
```

這會在 `generated/prisma` 目錄中建立針對您資料庫架構的型別安全 Prisma Client。

## 6. 實例化 Prisma Client

建立一個工具檔案來實例化 Prisma Client：

```typescript file=lib/prisma.ts
import "dotenv/config";
import { PrismaClient } from '../generated/prisma/client'

const prisma = new PrismaClient()

export { prisma }
```

## 7. 查詢您的資料庫

現在您可以使用 Prisma Client 來查詢資料庫。建立一個 `script.ts` 檔案：

```typescript file=script.ts
import { prisma } from './lib/prisma'

async function main() {
  // Example: Fetch all records from a collection
  // Replace 'user' with your actual model name
  const allUsers = await prisma.user.findMany()
  console.log('All users:', JSON.stringify(allUsers, null, 2))
}

main()
  .then(async () => {
    await prisma.$disconnect()
  })
  .catch(async (e) => {
    console.error(e)
    await prisma.$disconnect()
    process.exit(1)
  })
```

執行腳本：

```terminal
npx tsx script.ts
```

## 8. 演進您的 schema

MongoDB 不像關聯式資料庫那樣支援遷移。相反地，使用 `db push` 來同步 schema 變更：

### 8.1. 更新您的 Prisma schema 檔案

使用您想要的變更修改 Prisma schema 檔案。例如，新增一個新模型：

```prisma file=prisma/schema.prisma
// add-start
model Post {
  id        String   @id @default(auto()) @map("_id") @db.ObjectId
  title     String
  content   String?
  published Boolean  @default(false)
  authorId  String   @db.ObjectId
  author    User     @relation(fields: [authorId], references: [id])
}

model User {
  id    String @id @default(auto()) @map("_id") @db.ObjectId
  email String @unique
  name  String?
  posts Post[]
}
// add-end
```

:::info

在 MongoDB 中，`id` 欄位映射到 `_id` 並使用 `@db.ObjectId` 型別。關聯使用帶有 `@db.ObjectId` 註解的 `String` 型別。

:::

### 8.2. 將變更推送到您的資料庫

```terminal
npx prisma db push
```

此指令會：
- 將 schema 變更套用到您的 MongoDB 資料庫
- 自動重新產生 Prisma Client

:::info[為什麼使用 `db push` 而不是遷移？]

MongoDB 使用靈活的 schema 模型。Prisma Migrate（建立遷移檔案）不支援 MongoDB。請始終使用 `prisma db push` 來同步您的 schema 變更。

:::

## 9. 探索您的資料

您可以使用 [MongoDB Atlas](https://www.mongodb.com/cloud/atlas)、MongoDB shell 或 MongoDB Compass 來檢視和管理您的資料。

[Prisma Studio](/orm/tools/prisma-studio) 目前不支援 MongoDB。未來版本可能會加入支援。更多資訊請參閱 [Databases supported by Prisma Studio](/orm/tools/prisma-studio#databases-supported-by-prisma-studio)。
