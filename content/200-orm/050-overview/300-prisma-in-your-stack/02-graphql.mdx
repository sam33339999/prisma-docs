<TopBlock>

[GraphQL](https://graphql.org/) 是一種用於 API 的查詢語言。它通常被用作 RESTful API 的替代方案,但也可以作為現有 RESTful 服務之上的額外「閘道」層。

使用 Prisma ORM,你可以建立連接到資料庫的 GraphQL 伺服器。Prisma ORM 完全不限制你使用的 GraphQL 工具。在建立 GraphQL 伺服器時,你可以將 Prisma ORM 與 Apollo Server、GraphQL Yoga、TypeGraphQL、GraphQL.js 或你在 GraphQL 伺服器設定中使用的幾乎任何工具或函式庫結合使用。

</TopBlock>

## GraphQL 伺服器的內部運作

GraphQL 伺服器由兩個主要元件組成:

- GraphQL schema(型別定義 + resolvers)
- HTTP 伺服器

請注意,GraphQL schema 可以採用 code-first 或 SDL-first 的方式撰寫。查看這篇[文章](https://www.prisma.io/blog/the-problems-of-schema-first-graphql-development-x1mn4cb0tyl3)以了解更多關於這兩種方法的資訊。如果你喜歡 SDL-first 方法但仍希望讓程式碼具有類型安全性,請查看 [GraphQL Code Generator](https://the-guild.dev/graphql/codegen) 以根據 SDL 生成各種型別定義。

GraphQL schema 和 HTTP 伺服器通常由不同的函式庫處理。以下是目前 GraphQL 伺服器工具及其用途的概述:

| 函式庫 (npm 套件) | 用途                     | 與 Prisma ORM 相容 | Prisma 整合                                                             |
| :-------------------- | :-------------------------- | :------------------------- | :----------------------------------------------------------------------------- |
| `graphql`             | GraphQL schema (code-first) | 是                        | 否                                                                             |
| `graphql-tools`       | GraphQL schema (SDL-first)  | 是                        | 否                                                                             |
| `type-graphql`        | GraphQL schema (code-first) | 是                        | [`typegraphql-prisma`](https://www.npmjs.com/package/typegraphql-prisma)       |
| `nexus`               | GraphQL schema (code-first) | 是                        | [`nexus-prisma`](https://graphql-nexus.github.io/nexus-prisma/) _早期預覽版_ |
| `apollo-server`       | HTTP 伺服器                 | 是                        | n/a                                                                            |
| `express-graphql`     | HTTP 伺服器                 | 是                        | n/a                                                                            |
| `fastify-gql`         | HTTP 伺服器                 | 是                        | n/a                                                                            |
| `graphql-yoga`        | HTTP 伺服器                 | 是                        | n/a                                                                            |

除了這些獨立且單一用途的函式庫外,還有幾個專案正在建立整合的_應用程式框架_:

| 框架                           | 技術堆疊     | 建立者                                          | Prisma ORM                 | 說明                            |
| :---------------------------------- | :-------- | :------------------------------------------------ | :------------------------- | :------------------------------------- |
| [Redwood.js](https://rwsdk.com/) | 全端 | [Tom Preston-Werner](https://github.com/mojombo/) | 建立於 Prisma ORM 之上 | _將全端帶入 JAMstack。_ |

> **注意**:如果你發現清單中缺少任何 GraphQL 函式庫/框架,請告知我們。

## 常見問題

### Prisma ORM 在 GraphQL 伺服器中扮演什麼角色?

無論你使用上述哪種 GraphQL 工具/函式庫,Prisma ORM 都會在你的 GraphQL resolvers 內部使用來連接到你的資料庫。它在你的 resolvers 中扮演的角色與任何其他 ORM 或 SQL 查詢建構器相同。

在 GraphQL 查詢的 resolver 中,Prisma ORM 通常從資料庫讀取資料以在 GraphQL 回應中返回它。在 GraphQL mutation 的 resolver 中,Prisma ORM 通常也會將資料寫入資料庫(例如建立新記錄或更新現有記錄)。
