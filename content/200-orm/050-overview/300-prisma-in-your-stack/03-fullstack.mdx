<TopBlock>

全端框架,例如 Next.js、Remix 或 SvelteKit,模糊了伺服器和客戶端之間的界線。這些框架還提供了不同的模式來在伺服器上獲取和變更資料。

你可以使用你選擇的框架,從應用程式的伺服器端部分使用 Prisma Client 查詢你的資料庫。

</TopBlock>

## 支援的框架

以下是可與 Prisma ORM 一起使用的框架和函式庫的非詳盡清單:

- [Next.js](https://nextjs.org/)
- [Remix](https://remix.run)
- [SvelteKit](https://svelte.dev/)
- [Nuxt](https://nuxt.com/)
- [Redwood](https://rwsdk.com/)
- [t3 stack — using tRPC](https://create.t3.gg/)
- [Wasp](https://wasp-lang.dev/)

## 全端應用程式範例(例如 Next.js)

:::tip

如果你想學習如何使用 Next.js 和 Prisma ORM 建立應用程式,請查看這個全面的[影片教學](https://www.youtube.com/watch?v=QXxy8Uv1LnQ&ab_channel=ByteGrad)。

:::

假設你有一個類似於以下的 Prisma schema:

```prisma
datasource db {
  provider = "sqlite"
  url      = "file:./dev.db"
}

generator client {
  provider = "prisma-client"
  output   = "./generated"
}

model Post {
  id        Int     @id @default(autoincrement())
  title     String
  content   String?
  published Boolean @default(false)
  author    User?   @relation(fields: [authorId], references: [id])
  authorId  Int?
}

model User {
  id    Int     @id @default(autoincrement())
  email String  @unique
  name  String?
  posts Post[]
}
```

你現在可以在 `getServerSideProps`、`getStaticProps`、API 路由中,或使用 API 函式庫(例如 [tRPC](https://trpc.io/) 和 [GraphQL](https://graphql.org/))來實作使用 [Prisma Client API](/orm/prisma-client) 查詢資料庫的邏輯。

### `getServerSideProps`

```ts
// (in /pages/index.tsx)

// Alternatively, you can use `getStaticProps`
// in place of `getServerSideProps`.
export const getServerSideProps = async () => {
  const feed = await prisma.post.findMany({
    where: {
      published: true,
    },
  })
  return { props: { feed } }
}
```

Next.js 會將 props 傳遞給你的 React 元件,你可以在其中顯示來自資料庫的資料。

### API 路由

```ts
// Fetch all posts (in /pages/api/posts.ts)
const prisma = new PrismaClient()

export default async function handle(req, res) {
  const posts = await prisma.post.findMany({
    where: {
      published: true,
    },
  })
  res.json(posts)
}
```

請注意,你可以在 Next.js API 路由內使用 Prisma ORM 向資料庫發送查詢 - 支援 REST、GraphQL 和 tRPC。

然後你可以獲取資料並在前端中顯示它。
