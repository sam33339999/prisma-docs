本頁探討使用 Prisma ORM 和 Cloudflare D1 的相關概念,說明 Cloudflare D1 與其他資料庫提供者之間的共通性和差異,並引導您完成配置應用程式以整合 Cloudflare D1 的過程。

Prisma ORM 對 Cloudflare D1 的支援目前處於[預覽](/orm/more/releases#preview)階段。我們非常感謝您[在 GitHub 上](https://github.com/prisma/prisma/discussions/23646)的反饋。

如果您想使用 D1 和 Prisma ORM 部署 Cloudflare Worker,請遵循此[教學](/guides/cloudflare-d1)。

## 什麼是 Cloudflare D1?

D1 是 Cloudflare 的原生無伺服器資料庫,最初於 [2022 年推出](https://blog.cloudflare.com/introducing-d1/)。它基於 SQLite,可以在使用 Cloudflare Workers 部署應用程式時使用。

遵循 Cloudflare 的地理分佈原則並將運算和資料靠近應用程式使用者,D1 支援自動讀取複製。它根據資料庫獲得的查詢數量以及來自何處,動態管理資料庫實例的數量和唯讀副本的位置。

對於寫入操作,查詢會傳送到單個主實例,以將變更傳播到所有讀取副本並確保資料一致性。

## 與其他資料庫提供者的共通性

D1 基於 SQLite。

使用 Prisma ORM 與 D1 的許多方面就像使用 Prisma ORM 與任何其他關聯式資料庫一樣。您仍然可以:

- 使用 [Prisma Schema Language](/orm/prisma-schema) 建模您的資料庫
- 在 schema 中使用 Prisma ORM 現有的 [`sqlite` 資料庫連接器](/orm/overview/databases/sqlite)
- 在應用程式中使用 [Prisma Client](/orm/prisma-client) 與 D1 的資料庫伺服器通訊

## 需要考慮的差異

在決定使用 D1 和 Prisma ORM 時,D1 與 SQLite 之間有一些差異需要考慮。您應該注意以下幾點:

- **進行架構變更**。使用 Prisma ORM 7,您需要透過 Wrangler CLI 使用 D1 的[遷移系統](https://developers.cloudflare.com/d1/reference/migrations/)結合 [`prisma migrate diff`](/orm/reference/prisma-cli-reference#migrate-diff) 命令進行遷移工作流程。有關更多資訊,請參閱下面的 [在 D1 上使用 Prisma ORM 進行架構遷移](#schema-migrations-with-prisma-orm-on-d1)部分。
- **本地和遠端 D1 (SQLite) 資料庫**。Cloudflare 提供本地和遠端版本的 D1。[本地](https://developers.cloudflare.com/d1/build-with-d1/local-development/)版本使用 `wrangler d1` CLI 的 `--local` 選項管理,位於 `.wrangler/state`。[遠端](https://developers.cloudflare.com/d1/build-with-d1/remote-development/)版本由 Cloudflare 管理,透過 HTTP 存取。

## 如何在 Cloudflare Workers 或 Cloudflare Pages 中連接到 D1

在 Prisma ORM 中使用 D1 時,您需要使用 `sqlite` 資料庫提供者和 `@prisma/adapter-d1` [驅動程式適配器](/orm/overview/databases/database-drivers#driver-adapters)。

如果您想使用 D1 和 Prisma ORM 部署 Cloudflare Worker,請遵循這些[逐步說明](/guides/cloudflare-d1)。

## 在 D1 上使用 Prisma ORM 進行架構遷移

使用 Prisma ORM 7,在 Cloudflare D1 中管理資料庫架構遷移的建議方法是使用 Wrangler CLI 結合 `prisma migrate diff`。

### 使用 Wrangler CLI 與 `Prisma Migrate diff`

Cloudflare D1 自帶的[遷移系統](https://developers.cloudflare.com/d1/reference/migrations/)透過 `wrangler d1` CLI 命令運作。

Wrangler CLI 提供遷移的結構,但您需要從 Prisma schema 生成 SQL 語句。這就是 [`prisma migrate diff`](/orm/reference/prisma-cli-reference#migrate-diff) 的用武之地 - 它根據您的 Prisma schema 生成 SQL 語句,然後您可以使用 Wrangler 套用這些語句。

#### 建立初始遷移

建立初始遷移的工作流程如下。假設您有一個沒有任何表的全新 D1 實例。

##### 1. 更新您的 Prisma 資料模型

這是您想要對應到 D1 實例的 Prisma schema 的初始版本:

```prisma
model User {
  id    Int     @id @default(autoincrement())
  email String  @unique
  name  String?
}
```

##### 2. 使用 `wrangler` CLI 建立遷移檔案

接下來,您需要使用 [`wrangler d1 migrations create`](https://developers.cloudflare.com/workers/wrangler/commands/#migrations-create) 命令建立遷移檔案:

```terminal
npx wrangler d1 migrations create __YOUR_DATABASE_NAME__ create_user_table
```

由於這是第一次遷移,此命令將提示您建立 `migrations` 資料夾。請注意,如果您想將遷移檔案儲存在不同的位置,可以[使用 Wrangler 自訂它](https://developers.cloudflare.com/d1/reference/migrations/#wrangler-customizations)。

命令執行後,假設您為遷移檔案的位置選擇了預設的 `migrations` 名稱,該命令已為您建立了以下資料夾和檔案:

```no-copy
migrations/
└── 0001_create_user_table.sql
```

但是,在您可以將遷移套用到 D1 實例之前,您實際上需要將 SQL 語句放入目前為空的 `0001_create_user_table.sql` 檔案中。

##### 3. 使用 `Prisma Migrate diff` 生成 SQL 語句

要生成初始 SQL 語句,您可以使用 `prisma migrate diff` 命令,它比較兩個_架構_(透過其 `--to-X` 和 `--from-X` 選項)並生成從一個「演化」到另一個所需的步驟。這些架構可以是 Prisma 或 SQL 架構。

對於初始遷移,您可以使用特殊的 `--from-empty` 選項:

```terminal
npx prisma migrate diff \
  --from-empty \
  --to-schema ./prisma/schema.prisma \
  --script \
  --output migrations/0001_create_user_table.sql
```

上述命令使用以下選項:

- `--from-empty`: SQL 語句的來源是空架構。
- `--to-schema ./prisma/schema.prisma`: SQL 語句的目標是 `./prisma/schema.prisma` 中的架構。
- `--script`: 將結果輸出為 SQL。如果省略此選項,「遷移步驟」將以純英文生成。
- `--output migrations/0001_create_user_table.sql`: 將結果儲存在 `migrations/0001_create_user_table.sql` 中。

執行此命令後,`migrations/0001_create_user_table.sql` 將具有以下內容:

```sql file=migrations/0001_create_user_table.sql no-copy
-- CreateTable
CREATE TABLE "User" (
    "id" INTEGER NOT NULL PRIMARY KEY AUTOINCREMENT,
    "email" TEXT NOT NULL,
    "name" TEXT
);

-- CreateIndex
CREATE UNIQUE INDEX "User_email_key" ON "User"("email");
```

##### 4. 使用 `wrangler d1 migrations apply` 執行遷移

最後,您可以對 D1 實例套用遷移。

對於**本地**實例,執行:

```terminal
npx wrangler d1 migrations apply __YOUR_DATABASE_NAME__ --local
```

對於**遠端**實例,執行:

```terminal
npx wrangler d1 migrations apply __YOUR_DATABASE_NAME__ --remote
```

#### 使用進一步的遷移演化您的架構

對於任何進一步的遷移,您可以使用相同的工作流程,但不是使用 `--from-empty`,您需要使用 `--from-local-d1`,因為 `prisma migrate diff` 命令的來源架構現在是該本地 D1 實例的當前架構,而目標仍然是您的(然後更新的)Prisma schema。

##### 1. 更新您的 Prisma 資料模型

假設您已使用另一個模型更新了 Prisma schema:

```prisma
model User {
  id    Int     @id @default(autoincrement())
  email String  @unique
  name  String?
  posts Post[]
}

model Post {
  id       Int    @id @default(autoincrement())
  title    String
  author   User   @relation(fields: [authorId], references: [id])
  authorId Int
}
```

##### 2. 使用 `wrangler` CLI 建立遷移檔案

像以前一樣,您首先需要建立遷移檔案:

```terminal
npx wrangler d1 migrations create __YOUR_DATABASE_NAME__ create_post_table
```

命令執行後(再次假設您為遷移檔案的位置選擇了預設的 `migrations` 名稱),該命令已在 `migrations` 資料夾中建立了一個新檔案:

```no-copy
migrations/
├── 0001_create_user_table.sql
└── 0002_create_post_table.sql
```

如之前所述,您現在需要將 SQL 語句放入目前為空的 `0002_create_post_table.sql` 檔案中。

##### 3. 使用 `Prisma Migrate diff` 生成 SQL 語句

如上所述,您現在需要使用 `--from-local-d1` 而不是 `--from-empty` 來指定來源架構:

```terminal
npx prisma migrate diff \
  --from-local-d1 \
  --to-schema ./prisma/schema.prisma \
  --script \
  --output migrations/0002_create_post_table.sql
```

上述命令使用以下選項:

- `--from-local-d1`: SQL 語句的來源是本地 D1 資料庫檔案。
- `--to-schema ./prisma/schema.prisma`: SQL 語句的目標是 `./prisma/schema.prisma` 中的架構。
- `--script`: 將結果輸出為 SQL。如果省略此選項,「遷移步驟」將以純英文生成。
- `--output migrations/0002_create_post_table.sql`: 將結果儲存在 `migrations/0002_create_post_table.sql` 中。

執行此命令後,`migrations/0002_create_post_table.sql` 將具有以下內容:

```sql file=migrations/0002_create_post_table.sql no-copy
-- CreateTable
CREATE TABLE "Post" (
    "id" INTEGER NOT NULL PRIMARY KEY AUTOINCREMENT,
    "title" TEXT NOT NULL,
    "authorId" INTEGER NOT NULL,
    CONSTRAINT "Post_authorId_fkey" FOREIGN KEY ("authorId") REFERENCES "User" ("id") ON DELETE RESTRICT ON UPDATE CASCADE
);
```

##### 4. 使用 `wrangler d1 migrations apply` 執行遷移

最後,您可以對 D1 實例套用遷移。

對於**本地**實例,執行:

```terminal
npx wrangler d1 migrations apply __YOUR_DATABASE_NAME__ --local
```

對於**遠端**實例,執行:

```terminal
npx wrangler d1 migrations apply __YOUR_DATABASE_NAME__ --remote
```

## 限制

### 不支援交易

Cloudflare D1 目前不支援交易(請參閱[開放功能請求](https://github.com/cloudflare/workers-sdk/issues/2733))。因此,Prisma ORM 不支援 Cloudflare D1 的交易。使用 Prisma 的 D1 適配器時,隱式和顯式交易將被忽略並作為單獨的查詢執行,這破壞了交易 ACID 屬性的保證。
