## 什麼是 Turso?

[Turso](https://turso.tech/) 是一個基於 [libSQL](https://turso.tech/libsql) 的邊緣託管分散式資料庫,libSQL 是 [SQLite](https://sqlite.org/) 的開源和開放貢獻的分支,使您能夠將資料靠近您的應用程式並最小化查詢延遲。Turso 也可以託管在遠端伺服器上。

## 與其他資料庫提供者的共通性

libSQL 與 SQLite 100% 相容。libSQL 擴展了 SQLite 並添加了以下功能和能力:

- 支援複製
- 支援自動備份
- 能夠將 Turso 嵌入為其他程式(如 Linux 核心)的一部分
- 支援使用者定義函式
- 支援非同步 I/O

> 要了解更多關於 libSQL 的差異以及它與 SQLite 的不同之處,請參閱 [libSQL Manifesto](https://turso.tech/libsql-manifesto)。

使用 Prisma ORM 與 Turso 的許多方面就像使用 Prisma ORM 與任何其他關聯式資料庫一樣。您仍然可以:

- 使用 [Prisma Schema Language](/orm/prisma-schema) 建模您的資料庫
- 在 schema 中使用 Prisma ORM 現有的 [`sqlite` 資料庫連接器](/orm/overview/databases/sqlite)
- 在應用程式中使用 [Prisma Client](/orm/prisma-client) 與 Turso 的資料庫伺服器通訊

## 需要考慮的差異

在決定使用 Turso 和 Prisma ORM 時,Turso 與 SQLite 之間有一些差異需要考慮。您應該注意以下幾點:

- **遠端和嵌入式 SQLite 資料庫**。libSQL 使用 HTTP 連接到遠端 SQLite 資料庫。libSQL 也支援遠端資料庫副本和嵌入式副本。嵌入式副本使您能夠在應用程式內部複製主資料庫。
- **進行架構變更**。由於 libSQL 使用 HTTP 連接到遠端資料庫,這使得它與 Prisma Migrate 不相容。然而,您可以使用 [`prisma migrate diff`](/orm/reference/prisma-cli-reference#migrate-diff) 建立架構遷移,然後使用 [Turso 的 CLI](https://docs.turso.tech/reference/turso-cli) 將變更套用到資料庫。

## 如何連接和查詢 Turso 資料庫

後續章節介紹如何建立 Turso 資料庫、取得資料庫憑證並連接到您的資料庫。

### 如何佈建資料庫並取得資料庫憑證

:::info

確保您已安裝 [Turso CLI](https://docs.turso.tech/reference/turso-cli) 以管理您的資料庫。

:::

如果您沒有現有的資料庫,可以執行以下命令來佈建資料庫:

```terminal
turso db create turso-prisma-db
```

上述命令將在離您位置最近的區域建立資料庫。

執行以下命令以取得資料庫的連接字串:

```terminal
turso db show turso-prisma-db
```

接下來,建立一個身份驗證令牌,允許您連接到資料庫:

```terminal
turso db tokens create turso-prisma-db
```

使用身份驗證令牌和連接字串更新您的 `.env` 檔案:

```bash file=.env
TURSO_AUTH_TOKEN="eyJhbGciOiJFZERTQSIsInR5cCI6IkpXVCJ9..."
TURSO_DATABASE_URL="libsql://turso-prisma-db-user.turso.io"
```

### 如何連接到 Turso 資料庫

要開始使用,請安裝 Prisma ORM 的 libSQL 驅動程式適配器套件:

```terminal
npm install @prisma/adapter-libsql
```

更新您的 Prisma Client 實例:

```ts
import { PrismaClient } from '../prisma/generated/client'
import { PrismaLibSQL } from '@prisma/adapter-libsql'

const adapter = new PrismaLibSQL({
  url: `${process.env.TURSO_DATABASE_URL}`,
  authToken: `${process.env.TURSO_AUTH_TOKEN}`,
})
const prisma = new PrismaClient({ adapter })
```

您可以在專案中像平常一樣使用具有完整類型安全的 Prisma Client。

## 使用 Turso 管理架構變更

Prisma CLI 命令(如 `prisma migrate dev` 或 `prisma db push`)需要本地 SQLite 連接。要將架構變更推送到 Turso,請使用此工作流程:

1. **配置 Prisma CLI 以目標本地 SQLite 檔案。**
   更新 `.env` 和 `prisma.config.ts`,使 Prisma CLI 命令寫入本地檔案而不是遠端 Turso 資料庫:

```bash file=.env showLineNumbers
LOCAL_DATABASE_URL="file:./dev.db"
```

```ts file=prisma.config.ts showLineNumbers
import 'dotenv/config'
import { defineConfig, env } from 'prisma/config'

export default defineConfig({
  schema: 'prisma/schema.prisma',
  migrations: {
    path: 'prisma/migrations',
  },
  datasource: {
    url: env('LOCAL_DATABASE_URL'),
  },
})
```

2. **在本地生成遷移。**
   執行 `prisma migrate dev --name <migration-name>` 以更新本地 SQLite 資料庫並在 `prisma/migrations` 中生成 SQL 檔案。

3. **使用 Turso CLI 套用生成的 SQL。**
   使用 [`turso db shell` 命令](https://docs.turso.tech/cli/introduction)對您的遠端資料庫執行 SQL(將 `test` 替換為您的資料庫名稱):

```bash showLineNumbers
turso db shell test < ./prisma/migrations/20251118131940_init/migration.sql
```

將資料庫名稱 (`test`) 和遷移資料夾 (`20251118131940_init`) 替換為 `prisma migrate dev` 生成的值。

## 嵌入式 Turso 資料庫副本

Turso 支援[嵌入式副本](https://turso.tech/blog/introducing-embedded-replicas-deploy-turso-anywhere-2085aa0dc242)。Turso 的嵌入式副本使您能夠在應用程式_內部_擁有主要遠端資料庫的副本。嵌入式副本的行為類似於本地 SQLite 資料庫。資料庫查詢更快,因為您的資料庫在應用程式內部。

### 嵌入式資料庫副本的運作方式

當您的應用程式最初建立與資料庫的連接時,主資料庫將完成查詢:

![Embedded Replica: First remote read](./images/embedded-replica-remote-read.png)

Turso 將 (1) 在您的應用程式內部建立嵌入式副本,並 (2) 將資料從主資料庫複製到副本,以便在本地可用:

![Embedded Replica: Remote DB Copy](./images/embedded-replica-create-replica.png)

嵌入式副本將完成後續的讀取查詢。libSQL 客戶端提供 [`sync()`](https://docs.turso.tech/sdk/ts/reference#manual-sync) 方法,您可以呼叫它以確保嵌入式副本的資料保持新鮮。

![Embedded Replica: Local DB reads](./images/embedded-replica-read.png)

使用嵌入式副本,此設定保證了響應式應用程式,因為資料將在本地可用且更快存取。

就像您可能熟悉的讀取副本設定一樣,寫入操作會轉發到主要遠端資料庫並執行,然後才傳播到所有嵌入式副本。

![Embedded Replica: Write operation propagation](./images/embedded-replica-write-propagation.png)

1. 寫入操作傳播被轉發到資料庫。
1. 資料庫使用來自 1 的更新回應伺服器。
1. 寫入操作傳播到資料庫副本。

您的應用程式的資料需求將決定您應該多久在遠端資料庫和嵌入式資料庫副本之間同步資料。例如,您可以使用中介軟體函式(例如 Express 和 Fastify)或 cron 作業來同步資料。

### 如何在遠端資料庫和嵌入式副本之間同步資料

要開始在 Prisma ORM 中使用嵌入式副本,請在應用程式中添加 libSQL 的 `sync()` 方法。下面的範例顯示如何使用 Express 中介軟體同步資料。

```ts highlight=5-8;add;
import express from 'express'
const app = express()

// ... 您的應用程式程式碼的其餘部分
//add-start
app.use(async (req, res, next) => {
  await libsql.sync()
  next()
})
//add-end

app.listen(3000, () => console.log(`Server ready at http://localhost:3000`))
```
也可以作為 [Prisma Client 擴充功能](/orm/prisma-client/client-extensions)實作。下面的範例顯示在執行建立、更新或刪除操作後自動同步。

```ts highlight=5-8
const prisma = new PrismaClient().$extends({
  query: {
    $allModels: {
      async $allOperations({ operation, model, args, query }) {
        const result = await query(args)

        // 在任何寫入操作後同步嵌入式副本
        if (['create', 'update', 'delete'].includes(operation)) {
          await libsql.sync()
        }

        return result
      }
    }
  }
})
```
