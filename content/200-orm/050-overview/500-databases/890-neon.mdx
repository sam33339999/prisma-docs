## 什麼是 Neon?

[Neon](https://neon.tech/) 是一個完全託管的無伺服器 PostgreSQL,提供豐富的免費方案。Neon 分離儲存和運算,並提供現代開發者功能,例如無伺服器、分支、無底儲存等。Neon 是開源的,使用 Rust 編寫。

在[此處](https://neon.tech/docs/introduction)了解更多關於 Neon 的資訊。

## 與其他資料庫提供者的共通性

使用 Prisma ORM 與 Neon 的許多方面就像使用 Prisma ORM 與任何其他 PostgreSQL 資料庫一樣。您可以:

- 使用 [Prisma Schema Language](/orm/prisma-schema) 建模您的資料庫
- 在 schema 中使用 Prisma ORM 的 [`postgresql` 資料庫連接器](/orm/overview/databases/postgresql),以及 [Neon 提供給您的連接字串](https://neon.tech/docs/connect/connect-from-any-app)
- 如果您在 Neon 上已有資料庫架構,可在現有專案中使用 [Introspection](/orm/prisma-schema/introspection)
- 使用 [`prisma migrate dev`](/orm/prisma-migrate/workflows/development-and-production) 在 Neon 資料庫中追蹤架構遷移
- 使用 [`prisma db push`](/orm/prisma-migrate/workflows/prototyping-your-schema) 將 schema 的變更推送到 Neon
- 在應用程式中使用 [Prisma Client](/orm/prisma-client) 與 Neon 託管的資料庫通訊

## 需要考慮的差異

在決定使用 Neon 與 Prisma ORM 時,您應該注意 Neon 與 PostgreSQL 之間的一些差異:

- **Neon 的無伺服器模型** — 預設情況下,Neon 在 5 分鐘不活動後將[運算](https://neon.tech/docs/introduction/compute-lifecycle)縮放至零。在此狀態下,運算實例處於_閒置_狀態。此功能的特點是「冷啟動」的概念。從閒置狀態啟動運算需要 500 毫秒到幾秒鐘的時間。根據連接資料庫所需的時間,您的應用程式可能會逾時。要了解更多,請參閱:[連接延遲和逾時](https://neon.tech/docs/guides/prisma#connection-timeouts)。
- **Neon 的連接池** — Neon 使用 PgBouncer 提供連接池,支援多達 10,000 個並發連接。要了解更多,請參閱:[連接池](https://neon.tech/docs/connect/connection-pooling)。

## 如何使用 Neon 的連接池

如果您想使用 Neon 中提供的[連接池](https://neon.tech/docs/guides/prisma#use-connection-pooling-with-prisma),您需要在 Prisma Client 透過驅動程式適配器使用的連接字串的主機名稱中添加 `-pooler`:

```bash file=.env
# 使用池化連接到 Neon。
DATABASE_URL=postgres://daniel:<password>@ep-mute-rain-952417-pooler.us-east-2.aws.neon.tech:5432/neondb?sslmode=require
```

Prisma CLI 命令(例如 `prisma migrate` 或 `prisma db pull`)現在從 `prisma.config.ts` 讀取直接連接字串。配置池化和非池化環境變數:

```env file=.env highlight=5-6;add showLineNumbers
# 使用池化連接到 Neon(透過適配器供 Prisma Client 使用)。
DATABASE_URL=postgres://daniel:<password>@ep-mute-rain-952417-pooler.us-east-2.aws.neon.tech/neondb?sslmode=require

# Prisma CLI 使用的直接資料庫連接。
DIRECT_URL="postgres://daniel:<password>@ep-mute-rain-952417.us-east-2.aws.neon.tech/neondb"
```

將 `prisma.config.ts` 指向直接連接字串:

```ts file=prisma.config.ts showLineNumbers
import 'dotenv/config'
import { defineConfig, env } from 'prisma/config'

export default defineConfig({
  schema: 'prisma/schema.prisma',
  datasource: {
    url: env('DIRECT_URL'),
  },
})
```

在執行時,使用 `@prisma/adapter-neon` 透過池化連接字串實例化 Prisma Client:

```ts file=src/db/client.ts showLineNumbers
import { PrismaClient } from '../prisma/generated/client'
import { PrismaNeon } from '@prisma/adapter-neon'

const adapter = new PrismaNeon({ connectionString: process.env.DATABASE_URL })
export const prisma = new PrismaClient({ adapter })
```

:::info

我們強烈建議在您的 `DATABASE_URL` 環境變數中使用池化連接字串。您將獲得 Prisma CLI 的出色開發者體驗,同時無論部署策略如何都允許連接被池化。雖然這對於每個應用程式並非絕對必要,但無伺服器解決方案最終將需要連接池。

:::

## 解決連接逾時

從 Prisma ORM 連接到 Neon 時發生的連接逾時會導致類似以下錯誤:

```text no-copy
Error: P1001: Can't reach database server at `ep-white-thunder-826300.us-east-2.aws.neon.tech`:`5432`
Please make sure your database server is running at `ep-white-thunder-826300.us-east-2.aws.neon.tech`:`5432`.
```

此錯誤很可能意味著 Prisma Client 建立的連接在 Neon 運算啟動之前就逾時了。

Neon 運算有兩個主要狀態:_活動_和_閒置_。活動表示運算目前正在執行。如果 5 分鐘沒有查詢活動,Neon 預設將運算置於閒置狀態。請參閱 Neon 的文件以[了解更多](https://neon.tech/docs/introduction/compute-lifecycle)。

當您從 Prisma ORM 連接到閒置運算時,Neon 會自動啟動它。啟動通常在幾秒鐘內發生,但增加的延遲可能導致連接逾時。要解決此問題,您可以透過添加 `connect_timeout` 參數來調整 Neon 連接字串。此參數定義等待開啟新連接的最大秒數。預設值為 5 秒。更高的設定應該提供避免連接逾時問題所需的時間。例如:

```text wrap
DATABASE_URL=postgres://daniel:<password>@ep-mute-rain-952417.us-east-2.aws.neon.tech/neondb?connect_timeout=10
```

:::info

`connect_timeout` 設定為 0 表示沒有逾時。

:::

連接逾時的另一個可能原因是 Prisma ORM 的[連接池](/orm/prisma-client/setup-and-configuration/databases-connections/connection-pool),其預設逾時為 10 秒。這對於 Neon 來說通常足夠,但如果您仍然遇到連接逾時,可以嘗試將此限制提高(除了上面描述的 `connect_timeout` 設定之外),方法是將 `pool_timeout` 參數設定為更高的值。例如:

```text wrap
DATABASE_URL=postgres://daniel:<password>@ep-mute-rain-952417.us-east-2.aws.neon.tech/neondb?connect_timeout=15&pool_timeout=15
```

## 如何在 Prisma ORM 中使用 Neon 的無伺服器驅動程式

[Neon 無伺服器驅動程式](https://github.com/neondatabase/serverless)是一個適用於 JavaScript 和 TypeScript 的低延遲 Postgres 驅動程式,允許您透過 HTTP 或 WebSockets 而不是 TCP 從無伺服器和邊緣環境查詢資料。

您可以使用[驅動程式適配器](/orm/overview/databases/database-drivers#driver-adapters)將 Prisma ORM 與 Neon 無伺服器驅動程式一起使用。驅動程式適配器允許您使用不同的資料庫驅動程式(而不是 Prisma ORM 提供的預設驅動程式)與資料庫通訊。

:::info

此功能自 Prisma ORM [v6.16.0](https://pris.ly/release/6.16.0) 起正式可用。

:::

要開始使用,請安裝 Prisma ORM 的 Neon 適配器:

```terminal
npm install @prisma/adapter-neon
```

更新您的 Prisma Client 實例:

```ts
import { PrismaClient } from '../prisma/generated/client'
import { PrismaNeon } from '@prisma/adapter-neon'
import dotenv from 'dotenv'

dotenv.config()
const connectionString = `${process.env.DATABASE_URL}`

const adapter = new PrismaNeon({ connectionString })
const prisma = new PrismaClient({ adapter })
```

然後,您可以像平常一樣使用具有完整類型安全的 Prisma Client。Prisma Migrate、內省和 Prisma Studio 將繼續像以前一樣使用 Prisma schema 中定義的連接字串工作。

### 注意事項

#### 指定 PostgreSQL schema

您可以在實例化 `PrismaNeon` 時透過傳入 `schema` 選項來指定 [PostgreSQL schema](https://www.postgresql.org/docs/current/ddl-schemas.html):

```ts
const adapter = new PrismaNeon(
  { connectionString },
  { schema: 'myPostgresSchema' })
```
