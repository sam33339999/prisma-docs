## 什麼是 MongoDB？

[MongoDB](https://www.mongodb.com/) 是一個 NoSQL 資料庫，以 [BSON](https://bsonspec.org/) 格式儲存資料，這是一種類似 JSON 的文件格式，專為以鍵值對儲存資料而設計。它通常用於 JavaScript 應用程式開發，因為文件模型很容易映射到應用程式程式碼中的物件，並且內建支援高可用性和水平擴展。

MongoDB 將資料儲存在不需要預先定義架構的集合中，就像您在關聯式資料庫中處理表格時需要做的那樣。每個集合的結構也可以隨時間變化。這種靈活性可以讓您的資料模型快速迭代，但這確實意味著在使用 Prisma ORM 處理 MongoDB 資料庫時存在許多差異。

## 與其他資料庫提供商的共同點

使用 Prisma ORM 與 MongoDB 的某些方面與使用 Prisma ORM 與關聯式資料庫相同。您仍然可以：

- 使用 [Prisma Schema Language](/orm/prisma-schema) 建模您的資料庫
- 使用 [`mongodb` 資料庫連接器](/orm/overview/databases)連接到您的資料庫
- 如果您已經有 MongoDB 資料庫，可以為現有專案使用[自省](/orm/prisma-schema/introspection)
- 使用 [`db push`](/orm/prisma-migrate/workflows/prototyping-your-schema) 將架構中的變更推送到資料庫
- 在您的應用程式中使用 [Prisma Client](/orm/prisma-client)，根據您的 Prisma Schema 以型別安全的方式查詢您的資料庫

## 需要考慮的差異

MongoDB 的基於文件的結構和靈活的架構意味著，使用 Prisma ORM 與 MongoDB 在許多方面與使用它與關聯式資料庫不同。以下是一些您需要注意的差異領域：

- **定義 ID**：MongoDB 文件有一個 `_id` 欄位(通常包含 [ObjectID](https://www.mongodb.com/docs/manual/reference/bson-types/#std-label-objectid))。Prisma ORM 不支援以 `_` 開頭的欄位，因此需要使用 `@map` 屬性將其映射到 Prisma ORM 欄位。有關更多資訊，請參閱[在 MongoDB 中定義 ID](/orm/prisma-schema/data-model/models#defining-ids-in-mongodb)。

- **遷移現有資料以符合您的 Prisma schema**：在關聯式資料庫中，所有資料都必須符合您的架構。如果您在遷移時變更架構中特定欄位的型別，所有資料也必須更新以符合。相反，MongoDB 不強制執行任何特定架構，因此您在遷移時需要小心。有關更多資訊，請參閱[如何遷移舊資料以符合您的 Prisma schema](#how-to-migrate-existing-data-to-match-your-prisma-schema)。

- **自省和 Prisma ORM 關聯**：當您自省現有的 MongoDB 資料庫時，您將獲得一個沒有關聯的架構，並且需要手動新增缺少的關聯。有關更多資訊，請參閱[如何在自省後新增缺少的關聯](#how-to-add-in-missing-relations-after-introspection)。

- **過濾 `null` 和缺少的欄位**：MongoDB 區分將欄位設為 `null` 和根本不設定它，這在關聯式資料庫中是不存在的。Prisma ORM 目前沒有表達 MongoDB 中這種區別，這意味著您在過濾 `null` 和缺少的欄位時需要小心。有關更多資訊，請參閱[如何過濾 `null` 和缺少的欄位](#how-to-filter-for-null-and-missing-fields)

- **啟用複製**：Prisma ORM 在內部使用 [MongoDB 交易](https://www.mongodb.com/docs/manual/core/transactions/)來避免巢狀查詢的部分寫入。使用交易時，MongoDB 要求啟用資料集的複製。要做到這一點，您需要配置[副本集](https://www.mongodb.com/docs/manual/replication/) — 這是一組維護相同資料集的 MongoDB 進程。請注意，仍然可以使用單一資料庫，只需在其中建立一個只有一個節點的副本集。如果您使用 MongoDB 的 [Atlas](https://www.mongodb.com/atlas/database) 託管服務，副本集已為您配置好，但如果您在本地執行 MongoDB，則需要自己設定副本集。有關更多資訊，請參閱 MongoDB 的[部署副本集指南](https://www.mongodb.com/docs/manual/tutorial/deploy-replica-set/)。

### 大型集合的效能考慮
#### 問題
透過 Prisma 處理大型 MongoDB 集合時，某些操作可能會變得緩慢且消耗大量資源。特別是，需要掃描整個集合的操作(例如 `count()`)可能會達到查詢執行時間限制，並且隨著資料集的增長而顯著影響效能。

#### 解決方案
要解決大型 MongoDB 集合的效能問題，請考慮以下方法：

1. 對於大型集合，請考慮使用 MongoDB 的 `estimatedDocumentCount()` 而不是 `count()`。此方法速度更快，因為它使用有關集合的元資料。您可以使用 Prisma 的 `runCommandRaw` 方法來執行此命令。

2. 對於經常存取的計數，請考慮實作計數器快取。這涉及維護一個包含預先計算的計數的單獨文件，您可以在新增或移除文件時更新該文件。


## 如何使用 Prisma ORM 與 MongoDB

本節提供有關如何執行需要 MongoDB 特定步驟的任務的說明。

### 如何遷移現有資料以符合您的 Prisma schema

隨著時間的推移遷移您的資料庫是開發週期的重要組成部分。在開發期間，您需要更新您的 Prisma schema(例如，新增新欄位)，然後更新開發環境資料庫中的資料，並最終將更新的架構和新資料推送到生產資料庫。

:::info

使用 MongoDB 時，請注意，您的架構和資料庫之間的「耦合」被刻意設計為不如 SQL 資料庫那麼嚴格；MongoDB 不會強制執行架構，因此您必須驗證資料完整性。

:::

這些更新架構和資料庫的迭代任務可能會導致您的架構和資料庫中的實際資料之間出現不一致。讓我們看一個可能發生這種情況的場景，然後檢查您和您的團隊可以考慮用於處理這些不一致的幾種策略。

**場景**：您需要為使用者包含電話號碼以及電子郵件。您目前在 `schema.prisma` 檔案中有以下 `User` 模型：

```prisma file=prisma/schema.prisma showLineNumbers
model User {
  id    String @id @default(auto()) @map("_id") @db.ObjectId
  email String
}
```

您可以使用多種策略來遷移此架構：

- **「按需」更新**：使用這種策略，您和您的團隊同意可以根據需要對架構進行更新。但是，為了避免由於資料和架構之間的不一致而導致遷移失敗，團隊達成一致，新增的任何新欄位都明確定義為可選的。

  在上面的場景中，您可以將可選的 `phoneNumber` 欄位新增到 Prisma schema 中的 `User` 模型：

  ```prisma file=prisma/schema.prisma highlight=4;add showLineNumbers
  model User {
    id          String  @id @default(auto()) @map("_id") @db.ObjectId
    email       String
    //add-next-line
    phoneNumber String?
  }
  ```

  然後使用 `npx prisma generate` 命令重新產生您的 Prisma Client。

  接下來，更新您的應用程式以反映新欄位，並重新部署您的應用程式。

  由於 `phoneNumber` 欄位是可選的，您仍然可以查詢尚未定義電話號碼的舊使用者。資料庫中的記錄將在應用程式的使用者開始在新欄位中輸入他們的電話號碼時「按需」更新。

  另一個選項是在必需欄位上新增預設值，例如：

  ```prisma file=prisma/schema.prisma highlight=4;add showLineNumbers
  model User {
    id          String @id @default(auto()) @map("_id") @db.ObjectId
    email       String
    //add-next-line
    phoneNumber String @default("000-000-0000")
  }
  ```

  然後當您遇到缺少的 `phoneNumber` 時，該值將被強制轉換為 `000-000-0000`。

- **「無破壞性變更」更新**：此策略建立在第一個策略的基礎上，您的團隊進一步達成共識，您不重新命名或刪除欄位，只新增新欄位，並始終將新欄位定義為可選的。可以透過在 CI/CD 流程中新增檢查來驗證架構沒有向後不相容的變更，從而強制執行此策略。

- **「一次性」更新**：此策略類似於關聯式資料庫中的傳統遷移，其中所有資料都更新以反映新架構。在上述場景中，您將建立一個腳本，為資料庫中的所有現有使用者新增電話號碼欄位的值。然後，您可以在應用程式中將該欄位設為必需欄位，因為架構和資料是一致的。

### 如何在自省後新增缺少的關聯

自省現有的 MongoDB 資料庫後，您需要手動新增模型之間的關聯。MongoDB 沒有透過外鍵定義關聯的概念，就像您在關聯式資料庫中那樣。但是，如果您在 MongoDB 中有一個集合，其中有一個「類似外鍵」的欄位與另一個集合的 ID 欄位相符，Prisma ORM 將允許您在集合之間模擬關聯。

例如，採用具有兩個集合 `User` 和 `Post` 的 MongoDB 資料庫。這些集合中的資料具有以下格式，其中 `userId` 欄位將使用者連結到貼文：

`User` 集合：

- `_id` 欄位，型別為 `objectId`
- `email` 欄位，型別為 `string`

`Post` 集合：

- `_id` 欄位，型別為 `objectId`
- `title` 欄位，型別為 `string`
- `userId` 欄位，型別為 `objectID`

使用 `db pull` 自省時，這會被拉入 Prisma Schema，如下所示：

```prisma file=prisma/schema.prisma showLineNumbers
model Post {
  id     String @id @default(auto()) @map("_id") @db.ObjectId
  title  String
  userId String @db.ObjectId
}

model User {
  id    String @id @default(auto()) @map("_id") @db.ObjectId
  email String
}
```

這缺少 `User` 和 `Post` 模型之間的關聯。要解決此問題，請手動將 `user` 欄位新增到 `Post` 模型，並使用 `userId` 作為 `fields` 值的 `@relation` 屬性，將其連結到 `User` 模型，並將 `posts` 欄位新增到 `User` 模型作為反向關聯：

```prisma file=prisma/schema.prisma highlight=5;add|11;add showLineNumbers
model Post {
  id     String @id @default(auto()) @map("_id") @db.ObjectId
  title  String
  userId String @db.ObjectId
  //add-next-line
  user   User   @relation(fields: [userId], references: [id])
}

model User {
  id    String @id @default(auto()) @map("_id") @db.ObjectId
  email String
  //add-next-line
  posts Post[]
}
```

有關如何在 Prisma ORM 中使用關聯的更多資訊，請參閱[我們的文件](/orm/prisma-schema/data-model/relations)。

### 如何過濾 `null` 和缺少的欄位

要了解 MongoDB 如何區分 `null` 和缺少的欄位，請考慮具有可選 `name` 欄位的 `User` 模型範例：

```ts
model User {
  id    String  @id @default(auto()) @map("_id") @db.ObjectId
  email String
  name  String?
}
```

首先，嘗試建立一個將 `name` 欄位明確設為 `null` 的記錄。Prisma ORM 將按預期返回 `name: null`：

<CodeWithResult expanded={true}>

<cmd>

```ts
const createNull = await prisma.user.create({
  data: {
    email: 'user1@prisma.io',
    name: null,
  },
})
console.log(createNull)
```

</cmd>

<cmdResult>

```code no-copy
{
  id: '6242c4ae032bc76da250b207',
  email: 'user1@prisma.io',
  name: null
}
```

</cmdResult>

</CodeWithResult>

如果您直接檢查 MongoDB 資料庫，您還將看到一條新記錄，其中 `name` 設為 `null`：

```json
{
  "_id": "6242c4af032bc76da250b207",
  "email": "user1@prisma.io",
  "name": null
}
```

接下來，嘗試建立一個記錄而不明確設定 `name` 欄位：

<CodeWithResult expanded={true}>

<cmd>

```ts
const createMissing = await prisma.user.create({
  data: {
    email: 'user2@prisma.io',
  },
})
console.log(createMissing)
```

</cmd>

<cmdResult>

```code no-copy
{
  id: '6242c4ae032bc76da250b208',
  email: 'user2@prisma.io',
  name: null
}
```

</cmdResult>

</CodeWithResult>

Prisma ORM 仍然返回 `name: null`，但如果您直接在資料庫中查看，您會發現該記錄根本沒有定義 `name` 欄位：

```json
{
  "_id": "6242c4af032bc76da250b208",
  "email": "user2@prisma.io"
}
```

Prisma ORM 在兩種情況下都返回相同的結果，因為我們目前沒有辦法在 MongoDB 中指定欄位在底層資料庫中為 `null` 和根本未定義的欄位之間的這種差異 — 有關更多資訊，請參閱[此 Github 問題](https://github.com/prisma/prisma/issues/12555)。

這意味著您目前在過濾 `null` 和缺少的欄位時必須小心。過濾具有 `name: null` 的記錄將只返回第一條記錄，其中 `name` 明確設為 `null`：

<CodeWithResult expanded={true}>

<cmd>

```ts
const findNulls = await prisma.user.findMany({
  where: {
    name: null,
  },
})
console.log(findNulls)
```

</cmd>

<cmdResult>

```terminal no-copy
[
  {
    id: '6242c4ae032bc76da250b207',
    email: 'user1@prisma.io',
    name: null
  }
]
```

</cmdResult>

</CodeWithResult>

這是因為 `name: null` 正在檢查相等性，而不存在的欄位不等於 `null`。

要同時包含缺少的欄位，請使用 [`isSet` 篩選器](/orm/reference/prisma-client-reference#isset)明確搜尋為 `null` 或未設定的欄位。這將返回兩條記錄：

<CodeWithResult expanded={true}>

<cmd>

```ts
const findNullOrMissing = await prisma.user.findMany({
  where: {
    OR: [
      {
        name: null,
      },
      {
        name: {
          isSet: false,
        },
      },
    ],
  },
})
console.log(findNullOrMissing)
```

</cmd>

<cmdResult>

```terminal no-copy
[
  {
    id: '6242c4ae032bc76da250b207',
    email: 'user1@prisma.io',
    name: null
  },
  {
    id: '6242c4ae032bc76da250b208',
    email: 'user2@prisma.io',
    name: null
  }
]
```

</cmdResult>

</CodeWithResult>

## 範例

要連接到 MongoDB 伺服器，請在 [Prisma Schema](/orm/prisma-schema) 中配置 [`datasource`](/orm/prisma-schema/overview/data-sources) 區塊：

```prisma file=schema.prisma showLineNumbers
datasource db {
  provider = "mongodb"
  url      = env("DATABASE_URL")
}
```

傳遞給 `datasource` 區塊的欄位為：

- `provider`：指定 `mongodb` 資料來源連接器。
- `url`：指定 MongoDB 伺服器的[連接 URL](#connection-url)。在這種情況下，使用[環境變數](/orm/more/development-environment/environment-variables)來提供連接 URL。

:::warning

MongoDB 資料庫連接器使用交易來支援巢狀寫入。交易**需要**[副本集](https://www.mongodb.com/docs/manual/tutorial/deploy-replica-set/)部署。部署副本集最簡單的方法是使用 [Atlas](https://www.mongodb.com/docs/atlas/getting-started/)。免費開始使用。

:::

## 連接詳情

### 連接 URL

MongoDB 連接 URL 可以根據您如何託管資料庫以不同方式配置。標準配置由以下元件組成：

![MongoDB 連接 URL 的結構](./mongodb.png)

#### 基礎 URL 和路徑

連接 URL 的基礎 URL 和路徑部分由您的驗證憑證、主機(以及可選的埠號)和資料庫組成。

```
mongodb://USERNAME:PASSWORD@HOST/DATABASE
```

以下元件構成資料庫的 _基礎 URL_：

| 名稱     | 佔位符 | 描述                                                                                                                                                                                                                                                                                                                                                |
| :------- | :---------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 使用者     | `USERNAME`  | 資料庫使用者名稱，例如 `janedoe`                                                                                                                                                                                                                                                                                                                                 |
| 密碼 | `PASSWORD`  | 資料庫使用者密碼                                                                                                                                                                                                                                                                            |
| 主機     | `HOST`      | [`mongod`](https://www.mongodb.com/docs/manual/reference/program/mongod/#mongodb-binary-bin.mongod) 實例正在執行的主機。如果您正在執行分片叢集，這將是 [`mongos`](https://www.mongodb.com/docs/manual/reference/program/mongos/#mongodb-binary-bin.mongos) 實例。這可以是主機名稱、IP 位址或 UNIX 域套接字。 |
| 埠     | `PORT`      | 資料庫伺服器正在執行的埠，例如 `1234`。如果沒有提供，則使用預設的 `27017`。                                                                                                                                                                                                                                                               |
| 資料庫 | `DATABASE`  | 要使用的資料庫名稱。如果未指定但設定了 `authSource` 選項，則使用 `authSource` 資料庫名稱。如果連接字串中的資料庫和 `authSource` 選項都未指定，則預設為 `admin`                                                                                                    |

:::info

您必須對特殊字元進行[百分比編碼](/orm/reference/connection-urls#special-characters)。

:::

#### 參數

連接 URL 還可以接受參數。以下範例設定了三個參數：

- 一個 `ssl` 連接
- 一個 `connectTimeoutMS`
- 和 `maxPoolSize`

```
mongodb://USERNAME:PASSWORD@HOST/DATABASE?ssl=true&connectTimeoutMS=5000&maxPoolSize=50
```

請參閱 [MongoDB 連接字串文件](https://www.mongodb.com/docs/manual/reference/connection-string/)以獲取完整的連接字串參數列表。沒有 Prisma ORM 特定的參數。

## 使用 `ObjectId`

MongoDB 文件的 `_id` 欄位通常包含 [ObjectId](https://www.mongodb.com/docs/manual/reference/bson-types/#std-label-objectid)：

```json
{
  "_id": { "$oid": "60d599cb001ef98000f2cad2" },
  "createdAt": { "$date": { "$numberLong": "1624611275577" } },
  "email": "ella@prisma.io",
  "name": "Ella",
  "role": "ADMIN"
}
```

任何映射到底層資料庫中的 `ObjectId` 的欄位(最常見的是 ID 和關聯純量欄位)：

- 必須是 `String` 或 `Bytes` 型別
- 必須包含 `@db.ObjectId` 屬性
- 可以選擇性地使用 `@default(auto())` 在文件建立時自動產生有效的 `ObjectId`

以下是使用 `String` 的範例：

```prisma
model User {
  id String @id @default(auto()) @map("_id") @db.ObjectId
  // 其他欄位
}
```

以下是使用 `Bytes` 的另一個範例：

```prisma
model User {
  id Bytes @id @default(auto()) @map("_id") @db.ObjectId
  // 其他欄位
}
```

另請參閱：[在 MongoDB 中定義 ID 欄位](/orm/prisma-schema/data-model/models#defining-ids-in-mongodb)

### 產生 `ObjectId`

要在您的應用程式中產生有效的 `ObjectId`(用於測試目的或手動設定 ID 欄位值)，請使用 [`bson`](https://www.npmjs.com/package/bson) 套件。

```
npm install --save bson
```

```ts
import { ObjectId } from 'bson'

const id = new ObjectId()
```

## 與關聯式資料庫連接器的差異

本節涵蓋 MongoDB 連接器與 Prisma ORM 的關聯式資料庫連接器不同的方式。

### 不支援 Prisma Migrate

目前，沒有計劃新增對 [Prisma Migrate](/orm/prisma-migrate) 的支援，因為 MongoDB 專案不依賴內部架構，其中需要使用額外的工具來管理變更。`@unique` 索引的管理透過 `db push` 實現。

### 不支援 `@@id` 和 `autoincrement()`

[`@@id`](/orm/reference/prisma-schema-reference#id-1) 屬性(多個欄位的 ID)不受支援，因為 MongoDB 中的主鍵始終位於模型的 `_id` 欄位上。

[`autoincrement()`](/orm/reference/prisma-schema-reference#generate-autoincrementing-integers-as-ids-relational-databases-only) 函式(建立遞增的 `@id` 值)不受支援，因為 `autoincrement()` 不適用於 MongoDB 中 `_id` 欄位具有的 `ObjectID` 型別。

### 循環引用和引用動作

如果您的模型中有循環引用，無論是來自自我關聯還是模型之間的關聯循環，並且您使用[引用動作](/orm/prisma-schema/data-model/relations/referential-actions)，您必須將引用動作設為 `NoAction` 以防止無限循環的動作。

有關更多詳細資訊，請參閱[引用動作的特殊規則](/orm/prisma-schema/data-model/relations/referential-actions/special-rules-for-referential-actions)。

### 副本集配置

MongoDB 只允許您在副本集上啟動交易。Prisma ORM 在內部使用交易來避免巢狀查詢的部分寫入。這意味著我們繼承了需要配置副本集的要求。

當您嘗試在沒有配置副本集的部署上使用 Prisma ORM 的 MongoDB 連接器時，Prisma ORM 會顯示訊息 `Error: Transactions are not 支援 this deployment`。錯誤訊息的完整文字如下：

```

Invalid `prisma.post.create()` invocation in
/index.ts:9:21

   6 await prisma.$connect()
   7
   8 // Create the first post
→  9 await prisma.post.create(
  Error in connector: Database error. error code: unknown, error message: Transactions are not supported by this deployment
    at cb (/node_modules/@prisma/client/runtime/index.js:34804:17)

  clientVersion: '3.xx.0'

```

要解決此問題，我們建議您將部署變更為已配置副本集的部署。

一個簡單的方法是使用 [MongoDB Atlas](https://www.mongodb.com/cloud/atlas) 啟動一個免費實例，該實例開箱即支援副本集。

也可以選擇使用此指南在本地執行副本集：https://www.mongodb.com/docs/manual/tutorial/convert-standalone-to-replica-set

## MongoDB 與 Prisma schema 之間的型別映射

MongoDB 連接器將 Prisma ORM [資料模型](/orm/prisma-schema/data-model/models)中的[純量型別](/orm/prisma-schema/data-model/models#scalar-fields)映射到 MongoDB 的原生欄位型別，如下所示：

> 或者，請參閱 [Prisma schema 參考](/orm/reference/prisma-schema-reference#model-field-scalar-types)以獲取按 Prisma 型別組織的型別映射。

### 從 Prisma ORM 到 MongoDB 的原生型別映射

| Prisma ORM | MongoDB                                                                |
| ---------- | ---------------------------------------------------------------------- |
| `String`   | `string`                                                               |
| `Boolean`  | `bool`                                                                 |
| `Int`      | `int`                                                                  |
| `BigInt`   | `long`                                                                 |
| `Float`    | `double`                                                               |
| `Decimal`  | [目前不支援](https://github.com/prisma/prisma/issues/12637) |
| `DateTime` | `timestamp`                                                            |
| `Bytes`    | `binData`                                                              |
| `Json`     |                                                                        |

MongoDB 目前不支援的型別：

- `Decimal128`
- `Undefined`
- `DBPointer`
- `Null`
- `Symbol`
- `MinKey`
- `MaxKey`
- `Object`
- `Javascript`
- `JavascriptWithScope`
- `Regex`

### 在自省時從 MongoDB 映射到 Prisma ORM 型別

在自省 MongoDB 資料庫時，Prisma ORM 使用相關的[純量型別](/orm/prisma-schema/data-model/models#scalar-fields)。某些特殊型別還會獲得額外的原生型別註釋：

| MongoDB (型別 \| 別名) | Prisma ORM | 支援 | 原生資料庫型別屬性 | 備註 |
| ------------------------- | ---------- | :-------: | :----------------------------- | :---- |
| `objectId`                | `String`   |    ✔️     | `@db.ObjectId`                 |       |

[自省](/orm/prisma-schema/introspection)將**尚未支援**的原生資料庫型別新增為 [`Unsupported`](/orm/reference/prisma-schema-reference#unsupported) 欄位：

```prisma file=schema.prisma showLineNumbers
model Example {
  id    String                           @id @default(auto()) @map("_id") @db.ObjectId
  name  String
  regex Unsupported("RegularExpression")
}
```
