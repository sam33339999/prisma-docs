本指南探討使用 Prisma ORM 和 Supabase 的相關概念,說明 Supabase 與其他資料庫提供者之間的共通性和差異,並引導您完成配置應用程式以整合 Supabase 的過程。

## 什麼是 Supabase?

[Supabase](https://supabase.com/) 是一個 PostgreSQL 託管服務和開源 Firebase 替代方案,提供構建產品所需的所有後端功能。與 Firebase 不同,Supabase 由 PostgreSQL 支援,可以使用 Prisma ORM 直接存取。

要了解更多關於 Supabase 的資訊,您可以在[此處](https://supabase.com/docs/guides/getting-started/architecture)查看其架構,在[此處](https://supabase.com/docs/guides/getting-started/features)查看功能

## 與其他資料庫提供者的共通性

使用 Prisma ORM 與 Supabase 的許多方面就像使用 Prisma ORM 與任何其他關聯式資料庫一樣。您仍然可以:

- 使用 [Prisma Schema Language](/orm/prisma-schema) 建模您的資料庫
- 在 schema 中使用 Prisma ORM 現有的 [`postgresql` 資料庫連接器](/orm/overview/databases/postgresql),以及 [Supabase 提供給您的連接字串](https://supabase.com/docs/guides/database/connecting-to-postgres#connecting-to-external-libraries-and-tools)
- 如果您在 Supabase 中已有資料庫架構,可在現有專案中使用 [Introspection](/orm/prisma-schema/introspection)
- 使用 [`db push`](/orm/prisma-migrate/workflows/prototyping-your-schema) 將 schema 的變更推送到 Supabase
- 在應用程式中使用 [Prisma Client](/orm/prisma-client) 與 Supabase 的資料庫伺服器通訊

## 特定考量事項

如果您想使用 Supabase 提供的[連接池功能](https://supabase.com/docs/guides/database/connecting-to-postgres#connection-pooling-in-depth),您需要使用透過 [Supabase 資料庫設定](https://supabase.com/dashboard/project/_/settings/database)提供的連接池連接字串,並在環境變數末尾附加 `?pgbouncer=true`,該環境變數是當您使用驅動程式適配器實例化 Prisma Client 時讀取的:

```env file=.env
# 透過 Supavisor 使用連接池連接到 Supabase。
DATABASE_URL="postgres://postgres.[your-supabase-project]:[password]@aws-0-[aws-region].pooler.supabase.com:6543/postgres?pgbouncer=true"
```

Supabase 為每個資料庫提供三種類型的連接字串:

1. **直接資料庫連接字串** – `postgresql://postgres:password@db.[your-project-ref].supabase.co:5432/postgres`

2. **交易池連接字串** – `postgresql://postgres.[your-project-ref]:password@aws-0-[region].pooler.supabase.com:6543/postgres`

3. **會話池連接字串** – `postgresql://postgres.[your-project-ref]:password@aws-0-[region].pooler.supabase.com:5432/postgres`

Prisma CLI 命令(例如遷移和內省)現在從 `prisma.config.ts` 讀取直接的非池化連接字串。配置兩個環境變數 — 用於 Prisma Client 的池化連接字串 (`DATABASE_URL`) 和用於 Prisma CLI 的直接連接字串 (`DIRECT_URL`):

```env file=.env highlight=5-7;add showLineNumbers
# 透過 Supavisor 使用連接池連接到 Supabase。
DATABASE_URL="postgres://postgres.[your-supabase-project]:[password]@aws-0-[aws-region].pooler.supabase.com:6543/postgres?pgbouncer=true"

# Prisma CLI 使用的直接資料庫連接。
DIRECT_URL="postgres://postgres.[your-supabase-project]:[password]@aws-0-[aws-region].pooler.supabase.com:5432/postgres"
# 或
DIRECT_URL="postgresql://postgres:password@db.[your-project-ref].supabase.co:5432/postgres"
```

將 `prisma.config.ts` 指向直接連接字串:

```ts file=prisma.config.ts showLineNumbers
import 'dotenv/config'
import { defineConfig, env } from 'prisma/config'

export default defineConfig({
  schema: 'prisma/schema.prisma',
  datasource: {
    url: env('DIRECT_URL'),
  },
})
```

在執行時,使用池化的 `DATABASE_URL` 透過驅動程式適配器實例化 Prisma Client。這將直接連接字串限定在 Prisma CLI 工作流程中,同時您的應用程式連接繼續透過 Supavisor 流動。

```ts file=src/db/client.ts showLineNumbers
import { PrismaClient } from '../prisma/generated/client'
import { PrismaPg } from '@prisma/adapter-pg'

const adapter = new PrismaPg({ connectionString: process.env.DATABASE_URL })
export const prisma = new PrismaClient({ adapter })
```

:::info

我們強烈建議除了 `DIRECT_URL` 外還使用 Supavisor 的連接池。您將獲得 Prisma CLI 的出色開發者體驗,同時無論您的部署策略如何都允許連接被池化。雖然這對於每個應用程式並非絕對必要,但無伺服器解決方案最終將需要連接池。

:::
