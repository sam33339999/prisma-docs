Prisma 和 [PlanetScale](https://planetscale.com/) 結合,提供一個開發環境,利用 Prisma 的 ORM 和 PlanetScale 的高度可擴展 MySQL 平台,優化資料存取應用程式的快速、類型安全開發。

本文件探討使用 Prisma ORM 和 PlanetScale 的相關概念,說明 PlanetScale 與其他資料庫提供者之間的共通性和差異,並引導您完成配置應用程式以整合 PlanetScale 的過程。

## 什麼是 PlanetScale?

PlanetScale 使用 [Vitess](https://vitess.io/) 資料庫叢集系統來提供與 MySQL 相容的資料庫平台。功能包括:

- **企業級可擴展性。** PlanetScale 提供高可用的生產資料庫叢集,支援跨多個資料庫伺服器的擴展。這在無伺服器環境中特別有用,因為它避免了必須[管理連接限制](/orm/prisma-client/setup-and-configuration/databases-connections#serverless-environments-faas)的問題。
- **資料庫分支。** PlanetScale 允許您建立[資料庫架構的分支](https://planetscale.com/docs/concepts/branching),以便您可以在開發分支上測試變更,然後再套用到生產資料庫。
- **支援[非阻塞架構變更](https://planetscale.com/docs/concepts/nonblocking-schema-changes)。** PlanetScale 提供一個工作流程,允許使用者更新資料庫架構而不鎖定資料庫或造成停機。

## 與其他資料庫提供者的共通性

使用 Prisma ORM 與 PlanetScale 的許多方面就像使用 Prisma ORM 與任何其他關聯式資料庫一樣。您仍然可以:

- 使用 [Prisma Schema Language](/orm/prisma-schema) 建模您的資料庫
- 在 schema 中使用 Prisma ORM 現有的 [`mysql` 資料庫連接器](/orm/overview/databases/mysql),以及 [PlanetScale 提供給您的連接字串](https://planetscale.com/docs/concepts/connection-strings)
- 如果您在 PlanetScale 中已有資料庫架構,可在現有專案中使用 [Introspection](/orm/prisma-schema/introspection)
- 使用 [`db push`](/orm/prisma-migrate/workflows/prototyping-your-schema) 將 schema 的變更推送到資料庫
- 在應用程式中使用 [Prisma Client](/orm/prisma-client) 與 PlanetScale 的資料庫伺服器通訊

## 需要考慮的差異

PlanetScale 的分支模型和可擴展性設計意味著也有一些差異需要考慮。決定使用 PlanetScale 與 Prisma ORM 時,您應該注意以下幾點:

- **分支和部署請求。** PlanetScale 提供兩種類型的資料庫分支:_開發分支_,允許您測試架構變更,以及_生產分支_,受保護不受直接架構變更影響。相反,變更必須首先在開發分支上建立,然後使用部署請求部署到生產環境。生產分支具有高可用性並包含自動每日備份。要了解更多,請參閱 [如何使用分支和部署請求](#how-to-use-branches-and-deploy-requests)。
- **參照動作和完整性。** 為了支援跨多個資料庫伺服器的擴展,PlanetScale [預設不使用外鍵約束](https://planetscale.com/docs/learn/operating-without-foreign-key-constraints),外鍵約束通常用於關聯式資料庫中強制執行不同表之間資料的關係,並要求使用者在應用程式中手動處理。然而,您可以在 [PlanetScale 資料庫設定中明確啟用它們](https://planetscale.com/docs/concepts/foreign-key-constraints)。如果您不明確啟用這些,您仍然可以維護資料中的這些關係,並透過使用 Prisma ORM 的 `prisma` 關聯模式在 [Prisma Client 中模擬關聯](/orm/prisma-schema/data-model/relations/relation-mode#emulate-relations-in-prisma-orm-with-the-prisma-relation-mode)的能力,允許使用[參照動作](/orm/prisma-schema/data-model/relations/referential-actions)。更多資訊請參閱 [如何在 Prisma Client 中模擬關聯](#option-1-emulate-relations-in-prisma-client)。
- **在外鍵上建立索引。** 當[在 Prisma ORM 中模擬關聯](#option-1-emulate-relations-in-prisma-client)時(即當_不_在資料庫層級使用外鍵約束時),您需要在外鍵上建立專用索引。在標準 MySQL 資料庫中,如果表有帶外鍵約束的欄位,該欄位會自動建立索引。當 PlanetScale 配置為不使用外鍵約束時,當 Prisma Client 模擬關聯時,[目前](https://github.com/prisma/prisma/issues/10611)不會建立這些索引,這可能導致查詢未能很好地優化。為避免這種情況,您可以在 Prisma ORM 中建立索引。更多資訊請參閱 [如何在外鍵上建立索引](#2-create-indexes-on-foreign-keys)。
- **使用 `db push` 進行架構變更。** 當您將開發分支合併到生產分支時,PlanetScale 會自動比較兩個架構並生成自己的架構差異。這意味著 Prisma ORM 的 [`prisma migrate`](/orm/prisma-migrate) 工作流程(生成自己的遷移檔案歷史)在使用 PlanetScale 時並不自然契合。這些遷移檔案可能無法反映 PlanetScale 在分支合併時執行的實際架構變更。

  :::warning

  我們建議在使用 PlanetScale 進行架構變更時不要使用 `prisma migrate`。相反,我們建議您使用 `prisma db push` 命令。

  :::

  有關其運作方式的範例,請參閱 [如何使用 `db push` 進行架構變更](#how-to-make-schema-changes-with-db-push)

- **Introspection**。當您對現有資料庫進行內省且_未_在 [PlanetScale 資料庫中啟用外鍵約束](#option-2-enable-foreign-key-constraints-in-the-planetscale-database-settings)時,您將獲得一個沒有關聯的架構,因為它們通常基於連接表的外鍵來定義。在這種情況下,您需要手動添加缺少的關聯。更多資訊請參閱 [如何在 Introspection 後添加缺少的關聯](#how-to-add-in-missing-relations-after-introspection)。

## 如何使用分支和部署請求

使用 Prisma ORM 連接到 PlanetScale 時,您需要為分支使用正確的連接字串。可以從您的 PlanetScale 帳戶找到給定資料庫分支的連接 URL,方法是前往分支的概覽頁面並選擇「Connect」下拉式選單。在「Passwords」部分,生成新密碼並從下拉式選單中選擇「Prisma」以獲取 Prisma 格式的連接 URL。有關如何連接到 PlanetScale 資料庫的更多詳細資訊,請參閱 Prisma ORM 的[入門指南](/getting-started/prisma-orm/quickstart/planetscale)。

每個 PlanetScale 資料庫都會建立一個名為 `main` 的分支,它最初是一個開發分支,您可以用來測試架構變更。一旦您對所做的變更感到滿意,就可以[將其升級](https://planetscale.com/docs/concepts/branching#promote-a-branch-to-production)為生產分支。請注意,您只能將新變更推送到開發分支,因此後續變更需要在單獨的開發分支上建立,然後使用[部署請求](https://planetscale.com/docs/concepts/branching#promote-a-branch-to-production)部署到生產環境。

如果您嘗試推送到生產分支,您將收到[錯誤訊息](/orm/reference/error-reference#p3022) `Direct execution of DDL (Data Definition Language) SQL statements is disabled on this database.`

## 如何在 PlanetScale 中使用關聯(並啟用參照完整性)

### 選項 1: 在 Prisma Client 中模擬關聯

#### 1. 設定 `relationMode = "prisma"`

PlanetScale 預設不在其資料庫架構中使用外鍵約束。然而,Prisma ORM 依賴底層資料庫中的外鍵約束來強制執行 Prisma schema 中模型之間的參照完整性。

在 Prisma ORM 3.1.1 及更高版本中,您可以[使用 `prisma` 關聯模式在 Prisma Client 中模擬關聯](/orm/prisma-schema/data-model/relations/relation-mode#emulate-relations-in-prisma-orm-with-the-prisma-relation-mode),這避免了在資料庫中需要外鍵約束。

要在 Prisma Client 中啟用關聯模擬,請在 `datasource` 區塊中將 `relationMode` 欄位設定為 `"prisma"`:

```prisma file=schema.prisma
datasource db {
  provider     = "mysql"
  relationMode = "prisma"
}
```

:::info

設定關聯模式的能力是作為 Prisma ORM 3.1.1 版本中 `referentialIntegrity` 預覽功能的一部分引入的,並在 Prisma ORM 4.8.0 及更高版本中正式可用。<br /><br />`relationMode` 欄位在 Prisma ORM 4.5.0 版本中被重新命名,之前名為 `referentialIntegrity`。

:::

如果您在 Prisma schema 中使用關聯且 `relationMode` 欄位使用預設的 `"foreignKeys"` 選項,當 Prisma ORM 嘗試建立外鍵時,PlanetScale 會產生錯誤,Prisma ORM 會輸出 [P3021 錯誤訊息](/orm/reference/error-reference#p3021)。(在 2.27.0 之前的版本中,它會輸出原始資料庫錯誤。)

#### 2. 在外鍵上建立索引

當您[在 Prisma Client 中模擬關聯](#option-1-emulate-relations-in-prisma-client)時,需要建立自己的索引。作為需要添加索引的情況範例,考慮這個有文章和評論的部落格架構:

```prisma file=schema.prisma
model Post {
  id       Int       @id @default(autoincrement())
  title    String
  content  String
  likes    Int       @default(0)
  comments Comment[]
}

model Comment {
  id      Int    @id @default(autoincrement())
  comment String
  postId  Int
  post    Post   @relation(fields: [postId], references: [id], onDelete: Cascade)
}
```

`Comment` 模型中的 `postId` 欄位引用 `Post` 模型中對應的 `id` 欄位。然而,這在 PlanetScale 中並未實作為外鍵,因此該欄位沒有自動索引。這意味著某些查詢可能未能很好地優化。例如,如果您查詢具有特定文章 `id` 的所有評論,PlanetScale 可能必須進行完整的表查找。這可能會很慢,而且成本很高,因為 PlanetScale 的計費模式是根據讀取的行數收費。

為避免這種情況,您可以使用 [Prisma ORM 的 `@@index` 參數](/orm/reference/prisma-schema-reference#index)在 `postId` 欄位上定義索引:

```prisma file=schema.prisma highlight=15;add
model Post {
  id       Int       @id @default(autoincrement())
  title    String
  content  String
  likes    Int       @default(0)
  comments Comment[]
}

model Comment {
  id      Int    @id @default(autoincrement())
  comment String
  postId  Int
  post    Post   @relation(fields: [postId], references: [id], onDelete: Cascade)

  //add-next-line
  @@index([postId])
}
```

然後您可以[使用 `db push`](#how-to-make-schema-changes-with-db-push) 將此變更添加到您的架構。

在 4.7.0 及更高版本中,如果您有關聯但關聯純量欄位上沒有索引,Prisma ORM 會警告您。更多資訊請參閱[索引驗證](/orm/prisma-schema/data-model/relations/relation-mode#index-validation)。

:::warning

需要注意的一個問題是,[隱式多對多關聯](/orm/prisma-schema/data-model/relations/many-to-many-relations#implicit-many-to-many-relations)無法以這種方式添加索引。如果查詢速度或成本是問題,在這種情況下您可能需要使用[顯式多對多關聯](/orm/prisma-schema/data-model/relations/many-to-many-relations#explicit-many-to-many-relations)。

:::

### 選項 2: 在 PlanetScale 資料庫設定中啟用外鍵約束

自 2024 年 2 月起,PlanetScale 資料庫中的外鍵約束支援已正式可用。請按照 [PlanetScale 文件](https://planetscale.com/docs/concepts/foreign-key-constraints)中的說明在您的資料庫中啟用它們。

然後,您可以使用 Prisma ORM 並在 Prisma schema 中定義關聯,無需額外配置。

在這種情況下,您可以像其他支援外鍵約束的資料庫一樣定義關聯,例如:

```prisma file=schema.prisma
model Post {
  id       Int       @id @default(autoincrement())
  title    String
  content  String
  likes    Int       @default(0)
  comments Comment[]
}

model Comment {
  id      Int    @id @default(autoincrement())
  comment String
  postId  Int
  post    Post   @relation(fields: [postId], references: [id], onDelete: Cascade)
}
```

使用此方法,_不_需要:

- 在 Prisma schema 中設定 `relationMode = "prisma"`
- 在外鍵上定義額外的索引

此外,introspection 會自動在您的 Prisma schema 中建立關聯欄位,因為它可以檢測資料庫中的外鍵約束。

## 如何使用 `db push` 進行架構變更

要在 PlanetScale 中使用 `db push`,您首先需要[在 Prisma Client 中啟用關聯模擬](#option-1-emulate-relations-in-prisma-client)。在未啟用參照模擬的情況下推送到分支將會產生[錯誤訊息](/orm/reference/error-reference#p3021) `Foreign keys cannot be created on this database.`

作為範例,假設您決定向上面的部落格文章架構添加新的 `excerpt` 欄位。您首先需要[建立新的開發分支並連接到它](#how-to-use-branches-and-deploy-requests)。

接下來,將以下內容添加到您的 `schema.prisma` 檔案中:

```prisma file=schema.prisma highlight=5;edit
model Post {
  id       Int       @id @default(autoincrement())
  title    String
  content  String
  //edit-next-line
  excerpt  String?
  likes    Int       @default(0)
  comments Comment[]
}

model Comment {
  id      Int    @id @default(autoincrement())
  comment String
  postId  Int
  post    Post   @relation(fields: [postId], references: [id], onDelete: Cascade)

  @@index([postId])
}
```

要推送這些變更,請在終端中導航到您的專案目錄並執行

```terminal
npx prisma db push
```

一旦您對開發分支上的變更感到滿意,就可以開啟部署請求將這些變更部署到生產分支。

有關更多範例,請參閱 PlanetScale 關於使用 `db push` 進行 [Prisma ORM 自動遷移](https://planetscale.com/docs/prisma/automatic-prisma-migrations)的教學。

## 如何在內省後添加缺少的關聯

> **注意**: 本節僅在您使用 `relationMode = "prisma"` 在 Prisma ORM 中模擬外鍵約束時相關。如果您在 PlanetScale 資料庫中啟用了外鍵約束,可以忽略本節。

使用 `npx prisma db pull` 進行內省後,您獲得的架構可能缺少一些關聯。例如,以下架構缺少 `User` 和 `Post` 模型之間的關聯:

```prisma file=schema.prisma
model Post {
  id        Int      @id @default(autoincrement())
  createdAt DateTime @default(now())
  title     String   @db.VarChar(255)
  content   String?
  authorId  Int

  @@index([authorId])
}

model User {
  id    Int     @id @default(autoincrement())
  email String  @unique
  name  String?
}
```

在這種情況下,您需要手動添加關聯:

```prisma file=schema.prisma highlight=6,16;add
model Post {
  id        Int      @id @default(autoincrement())
  createdAt DateTime @default(now())
  title     String   @db.VarChar(255)
  content   String?
  //add-next-line
  author    User     @relation(fields: [authorId], references: [id])
  authorId  Int

  @@index([authorId])
}

model User {
  id    Int     @id @default(autoincrement())
  email String  @unique
  name  String?
  //add-next-line
  posts Post[]
}
```

有關更詳細的範例,請參閱 [PlanetScale 入門指南](/getting-started/prisma-orm/add-to-existing-project/planetscale)。

## 如何在 Prisma schema 中定義分片鍵 (預覽)

[分片](https://planetscale.com/docs/vitess/sharding)是當資料庫負載增長時進行擴展的流行技術。

從 [v6.10.0](https://github.com/prisma/prisma/releases/tag/6.10.0) 開始,Prisma ORM 原生支援 PlanetScale 上的分片(作為[預覽](/orm/more/releases#preview)功能),透過 Prisma schema 中的 [`@shardKey`](/orm/reference/prisma-schema-reference#shardkey) 和 [`@@shardKey`](/orm/reference/prisma-schema-reference#shardkey-1) 屬性,您可以將其應用於模型中應作為資料庫設定中分片鍵的欄位。

要使用分片鍵屬性,您需要在 `generator` 上指定 `shardKeys` 預覽功能:

```prisma
generator client {
  provider = "prisma-client"
  output = "./generated/prisma"
  previewFeatures = ["shardKeys"]
}
```

現在您可以使用 `@shardKey` 和 `@@shardKey` 屬性:

**單欄位分片鍵**

```prisma
model User {
  id     String @default(uuid())
  region String @shardKey
}
```

**多欄位分片鍵**

```prisma
model User {
  id         String @default(uuid())
  country    String
  customerId String
  @@shardKey([country, customerId])
}
```

## 如何在 Prisma ORM 中使用 PlanetScale 無伺服器驅動程式 (預覽)

[PlanetScale 無伺服器驅動程式](https://planetscale.com/docs/tutorials/planetscale-serverless-driver)提供了一種透過 HTTP 與資料庫通訊和執行查詢的方式。

您可以使用 [`@prisma/adapter-planetscale`](https://www.npmjs.com/package/@prisma/adapter-planetscale) 驅動程式適配器將 Prisma ORM 與 PlanetScale 無伺服器驅動程式一起使用。驅動程式適配器允許您透過 HTTP 與資料庫通訊。

:::info

此功能自 Prisma ORM [v6.16.0](https://pris.ly/release/6.16.0) 起正式可用。

:::


:::info

確保將連接字串中的主機值更新為 `aws.connect.psdb.cloud`。您可以在[此處](https://planetscale.com/docs/tutorials/planetscale-serverless-driver#add-and-use-the-planetscale-serverless-driver-for-javascript-to-your-project)了解更多相關資訊。

```bash
DATABASE_URL='mysql://johndoe:strongpassword@aws.connect.psdb.cloud/clear_nightsky?sslaccept=strict'
```

:::

安裝 Prisma ORM 的 PlanetScale 適配器、PlanetScale 無伺服器驅動程式和 `undici` 套件:

```terminal
npm install @prisma/adapter-planetscale undici
```

:::info

使用 Node.js 18 以下版本時,必須提供自訂 fetch 函式實作。我們建議使用 `undici` 套件,Node 的內建 fetch 就是基於此套件。Node.js 18 及更高版本包含內建的全域 `fetch` 函式,因此您無需安裝額外的套件。

:::

更新您的 Prisma Client 實例以使用 PlanetScale 無伺服器驅動程式:

```ts
import { PrismaPlanetScale } from '@prisma/adapter-planetscale'
import { PrismaClient } from './generated/prisma/client'
import dotenv from 'dotenv'
import { fetch as undiciFetch } from 'undici'

dotenv.config()
const connectionString = `${process.env.DATABASE_URL}`

const adapter = new PrismaPlanetScale({ url: connectionString, fetch: undiciFetch })
const prisma = new PrismaClient({ adapter })
```

然後,您可以像平常一樣使用具有完整類型安全的 Prisma Client。Prisma Migrate、內省和 Prisma Studio 將繼續像以前一樣使用 Prisma schema 中定義的連接字串工作。
