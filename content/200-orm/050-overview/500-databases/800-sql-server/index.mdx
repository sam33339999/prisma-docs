Microsoft SQL Server 資料來源連接器將 Prisma ORM 連接到 [Microsoft SQL Server](https://learn.microsoft.com/en-us/sql/sql-server/?view=sql-server-ver15) 資料庫伺服器。

## 範例

要連接到 Microsoft SQL Server 資料庫,您需要在 [Prisma schema](/orm/prisma-schema) 中配置一個 [`datasource`](/orm/prisma-schema/overview/data-sources) 區塊:

```prisma file=schema.prisma showLineNumbers
datasource db {
  provider = "sqlserver"
}
```

資料庫連接 URL 在 `prisma.config.ts` 中配置:

```ts file=prisma.config.ts
import 'dotenv/config'
import { defineConfig, env } from 'prisma/config'

export default defineConfig({
  schema: 'prisma/schema.prisma',
  datasource: {
    url: env('DATABASE_URL'),
  },
})
```

:::info

使用 Prisma CLI 命令時,環境變數不會自動載入。您需要使用像 `dotenv` 這樣的套件從 `.env` 檔案載入環境變數,或確保在您的 shell 中設置了環境變數。

:::

傳遞給 `datasource` 區塊的欄位有:

- `provider`: 指定 `sqlserver` 資料來源連接器。
- `url` 欄位在 `prisma.config.ts` 中配置,並指定 Microsoft SQL Server 資料庫的[連接 URL](#connection-details)。


## 使用 `node-mssql` 驅動程式

從 [`v5.4.0`](https://github.com/prisma/prisma/releases/tag/5.4.0) 開始,您可以使用 Prisma ORM 搭配 JavaScript 生態系統中的資料庫驅動程式(而不是使用 Prisma ORM 的內建驅動程式)。您可以透過使用[驅動程式適配器](/orm/overview/databases/database-drivers)來實現。

對於 SQLite,[`node-mssql`](https://github.com/tediousjs/node-mssql) 是 JavaScript 生態系統中最受歡迎的驅動程式之一。

本節說明如何將它與 Prisma ORM 和 `@prisma/adapter-mssql` 驅動程式適配器一起使用。

### 1. 安裝依賴項

首先,安裝 Prisma ORM 的 `node-mssql` 驅動程式適配器:

```terminal
npm install @prisma/adapter-mssql
```

### 2. 使用驅動程式適配器實例化 Prisma Client

現在,當您實例化 Prisma Client 時,需要將 Prisma ORM 的驅動程式適配器實例傳遞給 `PrismaClient` 建構函式:

```ts
import 'dotenv/config'
import { PrismaMssql } from '@prisma/adapter-mssql'
import { PrismaClient } from '../prisma/generated/client'

const config = {
  server: 'localhost',
  port: 1433,
  database: 'mydb',
  user: 'sa',
  password: 'mypassword',
  options: {
    encrypt: true, // Use this if you're on Windows Azure
    trustServerCertificate: true, // Use this if you're using self-signed certificates
  },
}

const adapter = new PrismaMssql(config)
const prisma = new PrismaClient({ adapter })
```

## 連接詳細資訊

用於連接到 Microsoft SQL Server 資料庫的連接 URL 遵循 [JDBC 標準](https://learn.microsoft.com/en-us/sql/connect/jdbc/building-the-connection-url?view=sql-server-ver15)。

以下範例使用 SQL 身份驗證(使用者名稱和密碼)並啟用 TLS 加密連接:

```
sqlserver://HOST[:PORT];database=DATABASE;user=USER;password=PASSWORD;encrypt=true
```

:::warning

注意: 如果您在連接字串中使用以下任何字元,[您將需要轉義它們](https://learn.microsoft.com/en-us/sql/connect/jdbc/building-the-connection-url?view=sql-server-ver16#escaping-values-in-the-connection-url)。

```terminal
:\=;/[]{}  # these are characters that will need to be escaped
```

要轉義這些字元,請在包含特殊字元的值周圍使用大括號 `{}`。例如:

```terminal
sqlserver://HOST[:PORT];database=DATABASE;user={MyServer/MyUser};password={ThisIsA:SecurePassword;};encrypt=true
```

:::

### 使用[整合安全性](https://learn.microsoft.com/en-us/previous-versions/dotnet/framework/data/adonet/sql/authentication-in-sql-server)(僅限 Windows)

以下範例使用目前登入的 Windows 使用者登入到 Microsoft SQL Server:

```
sqlserver://localhost:1433;database=sample;integratedSecurity=true;trustServerCertificate=true;
```

以下範例使用特定的 Active Directory 使用者登入到 Microsoft SQL Server:

```
sqlserver://localhost:1433;database=sample;integratedSecurity=true;username=prisma;password=aBcD1234;trustServerCertificate=true;
```

#### 連接到命名實例

以下範例使用整合安全性連接到 Microsoft SQL Server 的命名實例 (`mycomputer\sql2019`):

```
sqlserver://mycomputer\sql2019;database=sample;integratedSecurity=true;trustServerCertificate=true;
```

## 限制和已知問題

### Prisma Migrate 注意事項

Prisma Migrate 在 [2.13.0](https://github.com/prisma/prisma/releases/tag/2.13.0) 及更高版本中支援,但有以下注意事項:

#### 資料庫 綱要 名稱

SQL Server 沒有類似 PostgreSQL 的 `SET search_path` 命令。這意味著當您建立遷移時,必須在連接 URL 中定義與生產資料庫所使用的相同 schema 名稱。對於大多數使用者來說,這是 `dbo`(預設值)。但是,如果生產資料庫使用另一個 schema 名稱,則必須手動編輯所有遷移 SQL 以反映生產環境_或_在建立遷移之前更改連接 URL(例如: `schema=name`)。

#### 循環引用

當每個模型互相引用時,模型之間可能會發生循環引用,形成一個閉環。使用 Microsoft SQL Server 資料庫時,如果關係上的[參照動作](/orm/prisma-schema/data-model/relations/referential-actions)設定為除 [`NoAction`](/orm/prisma-schema/data-model/relations/referential-actions#noaction) 以外的其他值,Prisma ORM 將顯示驗證錯誤。

有關更多資訊,請參閱 [SQL Server 中參照動作的特殊規則](/orm/prisma-schema/data-model/relations/referential-actions/special-rules-for-referential-actions)。

#### 破壞性變更

某些遷移將導致比您預期更多的變更。例如:

- 新增或移除 `autoincrement()`。這無法透過修改欄位來實現,而是需要重新建立表格(包括所有約束、索引和外鍵)並在表格之間移動所有資料。
- 此外,無法從表格中刪除所有欄位(PostgreSQL 或 MySQL 可以)。如果遷移需要重新建立所有表格欄位,它也將重新建立表格。

#### 不支援共享預設值

在某些情況下,使用者可能希望將預設值定義為共享物件:

```sql file=default_objects.sql
CREATE DEFAULT catcat AS 'musti';

CREATE TABLE cats (
    id INT IDENTITY PRIMARY KEY,
    name NVARCHAR(1000)
);

sp_bindefault 'catcat', 'dbo.cats.name';
```

使用儲存程序 `sp_bindefault`,預設值 `catcat` 可以在多個表格中使用。Prisma ORM 管理預設值的方式是按表格:

```sql file=default_per_table.sql showLineNumbers
CREATE TABLE cats (
    id INT IDENTITY PRIMARY KEY,
    name NVARCHAR(1000) CONSTRAINT DF_cat_name DEFAULT 'musti'
);
```

最後一個範例在進行內省時,會產生以下模型:

```prisma file=schema.prisma showLineNumbers
model cats {
  id   Int     @id @default(autoincrement())
  name String? @default("musti")
}
```

而第一個範例不會內省出預設值:

```prisma file=schema.prisma showLineNumbers
model cats {
  id   Int     @id @default(autoincrement())
  name String?
}
```

如果將 Prisma Migrate 與共享預設物件一起使用,則必須手動對 SQL 進行變更。

### 資料模型限制

#### 無法使用具有 `UNIQUE` 約束和篩選索引的欄位作為外鍵

Microsoft SQL Server [只允許在具有 `UNIQUE` 約束的欄位中有一個 `NULL` 值](https://learn.microsoft.com/en-us/sql/relational-databases/tables/unique-constraints-and-check-constraints?view=sql-server-ver15)。例如:

- 使用者表格有一個名為 `license_number` 的欄位
- `license_number` 欄位具有 `UNIQUE` 約束
- `license_number` 欄位只允許**一個** `NULL` 值

解決此問題的標準方法是建立一個排除 `NULL` 值的篩選唯一索引。這允許您插入多個 `NULL` 值。如果您沒有在資料庫中建立索引,嘗試使用 Prisma Client 將多個 `null` 值插入欄位時將會出錯。

_然而_,建立索引使得無法在資料庫中將 `license_number` 用作外鍵(或在對應的 Prisma Schema 中用作關係純量欄位)

### 原始查詢注意事項

#### 使用 `String @db.VarChar(n)` 欄位 / `VARCHAR(N)` 欄位的原始查詢

[原始查詢](/orm/prisma-client/using-raw-sql/raw-queries)中的 `String` 查詢參數始終編碼為 SQL Server 的 `NVARCHAR(4000)`(如果您的 `String` 長度 \<= 4000)或 `NVARCHAR(MAX)`。如果您將 `String` 查詢參數與類型為 `String @db.VarChar(N)`/`VARCHAR(N)` 的欄位進行比較,這可能會導致 SQL Server 上的隱式轉換,影響索引效能並可能導致高 CPU 使用率。

以下是一個範例:
```prisma
model user {
  id Int @id
  name String @db.VarChar(40)
}
```
此查詢會受到影響:
```ts
await prisma.$queryRaw`SELECT * FROM user WHERE name = ${"John"}`
```

為了避免此問題,我們建議您始終在原始查詢中手動將 `String` 查詢參數轉換為 `VARCHAR(N)`:
```ts
await prisma.$queryRaw`SELECT * FROM user WHERE name = CAST(${"John"} AS VARCHAR(40))`
```
這使 SQL Server 能夠執行叢集索引搜尋而不是叢集索引掃描。
