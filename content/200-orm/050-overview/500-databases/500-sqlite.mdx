SQLite 資料來源連接器將 Prisma ORM 連接到 [SQLite](https://www.sqlite.org/) 資料庫檔案。這些檔案總是具有 `.db` 副檔名(例如：`dev.db`)。

預設情況下，SQLite 連接器包含一個負責連接到您的資料庫的資料庫驅動程式。您可以使用[驅動程式適配器](/orm/overview/databases/database-drivers#driver-adapters) (預覽版) 從 Prisma Client 使用 JavaScript 資料庫驅動程式連接到您的資料庫。

## 範例

要連接到 SQLite 資料庫檔案，您需要在 [Prisma schema](/orm/prisma-schema) 中配置 [`datasource`](/orm/prisma-schema/overview/data-sources) 區塊：

```prisma file=schema.prisma
datasource db {
  provider = "sqlite"
}
```

`datasource` 區塊指定了 `sqlite` 資料來源連接器。

在 Prisma ORM 7 中，資料庫連接 URL 是在 [`prisma.config.ts`](/orm/reference/prisma-config-reference) 中配置的：

```typescript file=prisma.config.ts
import { defineConfig } from 'prisma/config'

export default defineConfig({
  schema: 'prisma/schema.prisma',
  datasource: {
    url: 'file:./dev.db',
  },
})
```

連接 URL 總是以前綴 `file:` 開頭，然後包含指向 SQLite 資料庫檔案的檔案路徑。在此範例中，檔案位於同一目錄中，名稱為 `dev.db`。

## 使用 `better-sqlite3` 驅動程式

從 [`v5.4.0`](https://github.com/prisma/prisma/releases/tag/5.4.0) 開始，您可以將 Prisma ORM 與 JavaScript 生態系統中的資料庫驅動程式一起使用(而不是使用 Prisma ORM 的內建驅動程式)。您可以透過使用[驅動程式適配器](/orm/overview/databases/database-drivers)來實現這一點。

對於 SQLite，[`better-sqlite3`](https://github.com/WiseLibs/better-sqlite3) 是 JavaScript 生態系統中最受歡迎的驅動程式之一。

本節說明如何將它與 Prisma ORM 和 `@prisma/adapter-better-sqlite3` 驅動程式適配器一起使用。

### 1. 安裝依賴項

首先，安裝 Prisma ORM 的 `better-sqlite3` 驅動程式適配器：

```terminal
npm install @prisma/adapter-better-sqlite3
```

### 2. 使用驅動程式適配器實例化 Prisma Client

現在，當您實例化 Prisma Client 時，您需要將 Prisma ORM 的驅動程式適配器實例傳遞給 `PrismaClient` 建構函式：

```ts
import { PrismaBetterSqlite3 } from '@prisma/adapter-better-sqlite3';
import { PrismaClient } from './generated/prisma';

const adapter = new PrismaBetterSqlite3({
  url: "file:./prisma/dev.db"
})
const prisma = new PrismaClient({ adapter })
```

:::tip 在 Bun 中使用 SQLite
在 Bun 上執行 Prisma Client 時，請使用 `@prisma/adapter-libsql` 驅動程式適配器。Bun 不支援 `better-sqlite3` 所依賴的原生 SQLite 驅動程式(請參閱 [`node:sqlite` 參考](https://bun.com/reference/node/sqlite))。實例化適配器並將其傳遞給 `PrismaClient`：

```ts
import { PrismaClient } from '../prisma/generated/client';
import { PrismaLibSql } from '@prisma/adapter-libsql';

const adapter = new PrismaLibSql({
  url: process.env.DATABASE_URL ?? '',
});

const prisma = new PrismaClient({ adapter });

export default prisma;
```
:::

### 3. 配置時間戳格式以實現向後相容性

在使用 SQLite 的驅動程式適配器時，您可以使用 `timestampFormat` 選項來配置如何在資料庫中儲存 `DateTime` 值。

預設情況下，驅動程式適配器將 `DateTime` 值儲存為 **ISO 8601 字串**，這是 SQLite 最方便的格式，因為 SQLite 的日期/時間函式預設期望 ISO 8601 格式。

但是，如果您需要與 Prisma ORM 的原生 SQLite 驅動程式 **100% 向後相容**(例如，在遷移現有資料庫時)，您應該使用 `unixepoch-ms` 格式，它將時間戳儲存為自 Unix 紀元以來的毫秒數：

```ts
import { PrismaBetterSqlite3 } from '@prisma/adapter-better-sqlite3';
import { PrismaClient } from './generated/prisma';

const adapter = new PrismaBetterSqlite3({
  url: "file:./prisma/dev.db"
}, {
  timestampFormat: 'unixepoch-ms'
})
const prisma = new PrismaClient({ adapter })
```

:::info

`timestampFormat` 選項適用於 `@prisma/adapter-better-sqlite3` 和 `@prisma/adapter-libsql` 驅動程式適配器。

:::

**何時使用每種格式：**

- **ISO 8601 (預設)**：最適合新專案，並且與 SQLite 的內建日期/時間函式整合良好。
- **`unixepoch-ms`**：從 Prisma ORM 的原生 SQLite 驅動程式遷移時需要，以保持與現有時間戳資料的相容性。

## SQLite 到 Prisma schema 之間的型別映射

SQLite 連接器將[資料模型](/orm/prisma-schema/data-model/models)中的[純量型別](/orm/prisma-schema/data-model/models#scalar-fields)映射到原生欄位型別，如下所示：

> 或者，請參閱 [Prisma schema 參考](/orm/reference/prisma-schema-reference#model-field-scalar-types)以獲取按 Prisma ORM 型別組織的型別映射。

### 從 Prisma ORM 到 SQLite 的原生型別映射

| Prisma ORM | SQLite        |
| ---------- | ------------- |
| `String`   | `TEXT`        |
| `Boolean`  | `BOOLEAN`     |
| `Int`      | `INTEGER`     |
| `BigInt`   | `INTEGER`     |
| `Float`    | `REAL`        |
| `Decimal`  | `DECIMAL`     |
| `DateTime` | `NUMERIC`     |
| `Json`     | `JSONB`       |
| `Bytes`    | `BLOB`        |
| `Enum`     | `TEXT`        |

:::note

SQLite 沒有專門的布林型別。雖然此表格顯示 `BOOLEAN`，但欄位被分配了 **NUMERIC 親和性**(儲存 `0` 表示 false，`1` 表示 true)。[了解更多](https://www.sqlite.org/datatype3.html#boolean)。

:::

:::warning

在 SQLite 中使用 `enum` 欄位時，請注意以下幾點：

- **沒有資料庫級別的正確性強制執行**：如果您繞過 Prisma ORM 並在資料庫中儲存無效的列舉條目，Prisma Client 查詢在讀取該條目時將在執行時失敗。
- **沒有遷移級別的正確性強制執行**：在架構變更後，可能會以類似 MongoDB 的方式最終出現不正確的資料(因為資料庫不檢查列舉)。

:::

## 大數字的四捨五入錯誤

SQLite 是一個寬鬆型別的資料庫。如果您的 Schema 有一個 `Int` 型別的欄位，那麼 Prisma ORM 會阻止您插入大於整數的值。但是，沒有任何東西阻止資料庫直接接受更大的數字。這些手動插入的大數字在查詢時會導致四捨五入錯誤。

為了避免此問題，Prisma ORM 4.0.0 及更高版本會在從資料庫讀取數字時檢查它們是否在整數的邊界內。如果數字不符合，那麼 Prisma ORM 會拋出 P2023 錯誤，例如：

```
Inconsistent column data: Conversion failed:
Value 9223372036854775807 does not fit in an INT column,
try migrating the 'int' column type to BIGINT
```

## 連接詳情

### 連接 URL

SQLite 連接器的連接 URL 指向您檔案系統上的一個檔案，並在 `prisma.config.ts` 中配置。例如，以下兩個路徑是等效的，因為 `.db` 在同一目錄中：

```typescript file=prisma.config.ts
datasource: {
  url: 'file:./dev.db',
}
```

與以下相同：

```typescript file=prisma.config.ts
datasource: {
  url: 'file:dev.db',
}
```

您也可以從根目錄或檔案系統中的任何其他位置指定檔案：

```typescript file=prisma.config.ts
datasource: {
  url: 'file:/Users/janedoe/dev.db',
}
```
