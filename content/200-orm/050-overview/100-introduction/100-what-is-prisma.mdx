Prisma ORM 是一個[開源](https://github.com/prisma/prisma)的下一代 ORM。它由以下部分組成：

- **Prisma Client**：為 Node.js 和 TypeScript 自動生成的型別安全查詢建構器
- **Prisma Migrate**：遷移系統
- **Prisma Studio**：用於檢視和編輯資料庫資料的圖形介面。

  :::info

  **Prisma Studio** 是 Prisma ORM 中唯一不開源的部分。您只能在本地執行 Prisma Studio。

  :::

Prisma Client 可以在 _任何_ Node.js（支援的版本）或 TypeScript 後端應用程式中使用（包括無伺服器應用程式和微服務）。這可以是 [REST API](/orm/overview/prisma-in-your-stack/rest)、[GraphQL API](/orm/overview/prisma-in-your-stack/graphql)、gRPC API，或任何其他需要資料庫的應用程式。

## Prisma ORM 如何運作？

### Prisma schema

每個使用 Prisma ORM 工具包中工具的專案都從 [Prisma schema](/orm/prisma-schema) 開始。Prisma schema 允許開發者以直觀的資料建模語言定義他們的 _應用程式模型_。它還包含資料庫連接並定義一個 _產生器_：

<TabbedContent code>
<TabItem value="Relational databases">
```prisma
datasource db {
  provider = "postgresql"
}

generator client {
  provider = "prisma-client"
  output   = "./generated"
}

model Post {
  id        Int     @id @default(autoincrement())
  title     String
  content   String?
  published Boolean @default(false)
  author    User?   @relation(fields: [authorId], references: [id])
  authorId  Int?
}

model User {
  id    Int     @id @default(autoincrement())
  email String  @unique
  name  String?
  posts Post[]
}
```

</TabItem>
<TabItem value="MongoDB">
```prisma
datasource db {
  provider = "mongodb"
  url      = env("DATABASE_URL")
}

generator client {
  provider = "prisma-client-js"
}

model Post {
  id        String  @id @default(auto()) @map("_id") @db.ObjectId
  title     String
  content   String?
  published Boolean @default(false)
  author    User?   @relation(fields: [authorId], references: [id])
  authorId  String  @db.ObjectId
}

model User {
  id    String  @id @default(auto()) @map("_id") @db.ObjectId
  email String  @unique
  name  String?
  posts Post[]
}
```

</TabItem>
</TabbedContent>

> **注意**：Prisma schema 擁有強大的資料建模功能。例如，它允許您定義「Prisma 層級」的[關聯欄位](/orm/prisma-schema/data-model/relations)，這將使得在 [Prisma Client API 中處理關聯](/orm/prisma-client/queries/relation-queries)變得更容易。在上面的案例中，`User` 上的 `posts` 欄位僅定義在「Prisma 層級」，意味著它不會在底層資料庫中表現為外鍵。

在此 schema 中，您需要配置三件事：

- **資料來源**：指定您的資料庫連接。資料庫連接 URL 在 `prisma.config.ts` 中配置。
- **產生器**：表示您想要生成 Prisma Client
- **資料模型**：定義您的應用程式模型

### 配置資料庫連接

資料庫連接 URL 在 `prisma.config.ts` 檔案中配置。在您的專案根目錄建立一個 `prisma.config.ts` 檔案：

```ts file=prisma.config.ts
import 'dotenv/config'
import { defineConfig, env } from 'prisma/config'

export default defineConfig({
  schema: 'prisma/schema.prisma',
  migrations: {
    path: 'prisma/migrations',
    seed: 'tsx ./prisma/seed.ts',
  },
  datasource: {
    url: env('DATABASE_URL'),
  },
})
```

:::info

當使用 Prisma CLI 指令時，環境變數不會自動載入。您需要使用像 `dotenv` 這樣的套件來從 `.env` 檔案載入環境變數，或確保您的環境變數已在 shell 中設定。

:::

### Prisma schema 資料模型

在本頁面中，重點在於資料模型。您可以在相應的文件頁面上了解更多關於[資料來源](/orm/prisma-schema/overview/data-sources)和[產生器](/orm/prisma-schema/overview/generators)的資訊。

#### Prisma schema 資料模型的功能

資料模型是[模型](/orm/prisma-schema/data-model/models#defining-models)的集合。一個模型有兩個主要功能：

- 代表關聯式資料庫中的表格或 MongoDB 中的集合
- 為 Prisma Client API 中的查詢提供基礎

#### 取得資料模型

將資料模型「放入」Prisma schema 有兩種主要工作流程：

- 手動編寫資料模型並使用 [Prisma Migrate](/orm/prisma-migrate) 將其對應到資料庫
- 透過[內省](/orm/prisma-schema/introspection)資料庫來生成資料模型

一旦定義了資料模型，您可以[生成 Prisma Client](/orm/prisma-client/setup-and-configuration/generating-prisma-client)，它將為定義的模型公開 CRUD 和更多查詢。如果您使用 TypeScript，您將獲得所有查詢的完整型別安全（即使只檢索模型欄位的子集）。

### 使用 Prisma Client 存取您的資料庫

#### 生成 Prisma Client

使用 Prisma Client 的第一步是安裝 `@prisma/client` 和 `prisma` npm 套件：

```terminal
npm install prisma --save-dev
npm install @prisma/client
```

然後，您可以執行 `prisma generate`：

```terminal
npx prisma generate
```

`prisma generate` 指令會讀取您的 Prisma schema 並 _生成_ Prisma Client 程式碼。程式碼會生成到您的產生器區塊中 `output` 欄位指定的路徑（例如，如上面 schema 範例所示的 `./generated`）。

在您變更資料模型後，您需要透過執行 `prisma generate` 來手動重新生成 Prisma Client，以確保生成的程式碼得到更新。

#### 使用 Prisma Client 向您的資料庫傳送查詢

一旦生成了 Prisma Client，您就可以在程式碼中匯入它並向資料庫傳送查詢。以下是設定程式碼的範例。

##### 匯入並實例化 Prisma Client

<TabbedContent code>
<TabItem value="import">

```ts
import { PrismaClient } from './generated/client'

const prisma = new PrismaClient()
```

</TabItem>
<TabItem value="require">

```js
const { PrismaClient } = require('./generated/client')

const prisma = new PrismaClient()
```

</TabItem>
</TabbedContent>

現在您可以開始透過生成的 Prisma Client API 傳送查詢，以下是一些查詢範例。請注意，所有 Prisma Client 查詢都會回傳 _純 JavaScript 物件_。

在 [Prisma Client API 參考](/orm/prisma-client)中了解更多可用的操作。

##### 從資料庫檢索所有 `User` 記錄

```ts
// 在 `async` 函式內執行
const allUsers = await prisma.user.findMany()
```

##### 在每個回傳的 `User` 物件上包含 `posts` 關聯

```ts
// 在 `async` 函式內執行
const allUsers = await prisma.user.findMany({
  include: { posts: true },
})
```

##### 篩選包含 `"prisma"` 的所有 `Post` 記錄

```ts
// 在 `async` 函式內執行
const filteredPosts = await prisma.post.findMany({
  where: {
    OR: [
      { title: { contains: 'prisma' } },
      { content: { contains: 'prisma' } },
    ],
  },
})
```

##### 在同一個查詢中建立新的 `User` 和新的 `Post` 記錄

```ts
// 在 `async` 函式內執行
const user = await prisma.user.create({
  data: {
    name: 'Alice',
    email: 'alice@prisma.io',
    posts: {
      create: { title: 'Join us for Prisma Day 2020' },
    },
  },
})
```

##### 更新現有的 `Post` 記錄

```ts
// 在 `async` 函式內執行
const post = await prisma.post.update({
  where: { id: 42 },
  data: { published: true },
})
```

#### 與 TypeScript 一起使用

請注意，當使用 TypeScript 時，此查詢的結果將是 _靜態型別_，因此您不會意外存取不存在的屬性（並且任何拼寫錯誤都會在編譯時被捕獲）。在文件的[生成型別的進階用法](/orm/prisma-client/type-safety/operating-against-partial-structures-of-model-types)頁面上了解更多關於利用 Prisma Client 生成型別的資訊。

## 典型的 Prisma ORM 工作流程

如上所述，將資料模型「放入」Prisma schema 有兩種方式。根據您選擇的方法，您的主要 Prisma ORM 工作流程可能會有所不同。

### Prisma Migrate

使用 **Prisma Migrate**（Prisma ORM 的整合資料庫遷移工具），工作流程如下：

1. 手動調整您的 [Prisma schema 資料模型](/orm/prisma-schema/data-model/models)
1. 使用 `prisma migrate dev` CLI 指令遷移您的開發資料庫
1. 在應用程式程式碼中使用 Prisma Client 來存取您的資料庫

![使用 Prisma Migrate 的典型工作流程](/img/orm/prisma-migrate-development-workflow.png)

要了解更多關於 Prisma Migrate 工作流程的資訊，請參閱：

- [使用 Prisma Migrate 部署資料庫變更](/orm/prisma-client/deployment/deploy-database-changes-with-prisma-migrate)

* [使用 Prisma Migrate 進行開發](/orm/prisma-migrate)

### SQL 遷移和內省

如果由於某種原因，您不能或不想使用 Prisma Migrate，您仍然可以使用內省來從資料庫 schema 更新您的 Prisma schema。
使用 **SQL 遷移和內省**時的典型工作流程略有不同：

1. 使用 SQL 或第三方遷移工具手動調整您的資料庫 schema
1. （重新）內省您的資料庫
1. 可選擇[（重新）配置您的 Prisma Client API](/orm/prisma-client/setup-and-configuration/custom-model-and-field-names)
1. （重新）生成 Prisma Client
1. 在應用程式程式碼中使用 Prisma Client 來存取您的資料庫

![內省工作流程](/img/orm/prisma-evolve-app-workflow.png)

要了解更多關於內省工作流程的資訊，請參閱[內省章節](/orm/prisma-schema/introspection)。
