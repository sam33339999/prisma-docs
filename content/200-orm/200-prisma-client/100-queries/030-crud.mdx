## 建立

### 建立單一記錄

以下查詢建立 ([`create()`](/orm/reference/prisma-client-reference#create)) 一個具有兩個欄位的單一使用者:

<CodeWithResult outputResultText="query">
<cmd>

```ts
const user = await prisma.user.create({
  data: {
    email: 'elsa@prisma.io',
    name: 'Elsa Prisma',
  },
})
```

</cmd>
<cmdResult>

```js no-copy
{
  id: 22,
  name: 'Elsa Prisma',
  email: 'elsa@prisma.io',
  profileViews: 0,
  role: 'USER',
  coinflips: []
}
```

</cmdResult>
</CodeWithResult>

使用者的 `id` 是自動生成的,而您的 schema 決定[哪些欄位是必填的](/orm/prisma-schema/data-model/models#optional-and-mandatory-fields)。

#### 使用生成的類型建立單一記錄

以下範例產生相同的結果,但在 `create()` 查詢的上下文_之外_建立一個名為 `user` 的 `UserCreateInput` 變數。在完成簡單檢查("是否應在此 `create()` 查詢中包含貼文?")後,將 `user` 變數傳入查詢:

```ts
import { PrismaClient, Prisma } from '../prisma/generated/client'

const prisma = new PrismaClient()

async function main() {
  let includePosts: boolean = false
  let user: Prisma.UserCreateInput

  // Check if posts should be included in the query
  if (includePosts) {
    user = {
      email: 'elsa@prisma.io',
      name: 'Elsa Prisma',
      posts: {
        create: {
          title: 'Include this post!',
        },
      },
    }
  } else {
    user = {
      email: 'elsa@prisma.io',
      name: 'Elsa Prisma',
    }
  }

  // Pass 'user' object into query
  const createUser = await prisma.user.create({ data: user })
}

main()
```

有關使用生成類型的更多資訊,請參閱:[生成的類型](/orm/prisma-client/type-safety)。

### 建立多個記錄

Prisma Client 在 [2.20.0](https://github.com/prisma/prisma/releases/2.20.0) 及更高版本中支援批量插入作為 GA 功能。

以下 [`createMany()`](/orm/reference/prisma-client-reference#createmany) 查詢建立多個使用者並跳過任何重複項(`email` 必須是唯一的):

<CodeWithResult expanded="{true}" outputResultText="query">
<cmd>

```ts
const createMany = await prisma.user.createMany({
  data: [
    { name: 'Bob', email: 'bob@prisma.io' },
    { name: 'Bobo', email: 'bob@prisma.io' }, // Duplicate unique key!
    { name: 'Yewande', email: 'yewande@prisma.io' },
    { name: 'Angelique', email: 'angelique@prisma.io' },
  ],
  skipDuplicates: true, // Skip 'Bobo'
})
```

</cmd>
<cmdResult>

```js no-copy
{
  count: 3
}
```

</cmdResult>

</CodeWithResult>

:::warning

注意:使用 MongoDB、SQLServer 或 SQLite 時不支援 `skipDuplicates`。

:::

`createMany()` 使用單一 `INSERT INTO` 語句配合多個值,這通常比每行使用單獨的 `INSERT` 更有效率:

```sql
BEGIN
INSERT INTO "public"."User" ("id","name","email","profileViews","role","coinflips","testing","city","country") VALUES (DEFAULT,$1,$2,$3,$4,DEFAULT,DEFAULT,DEFAULT,$5), (DEFAULT,$6,$7,$8,$9,DEFAULT,DEFAULT,DEFAULT,$10), (DEFAULT,$11,$12,$13,$14,DEFAULT,DEFAULT,DEFAULT,$15), (DEFAULT,$16,$17,$18,$19,DEFAULT,DEFAULT,DEFAULT,$20) ON CONFLICT DO NOTHING
COMMIT
SELECT "public"."User"."country", "public"."User"."city", "public"."User"."email", SUM("public"."User"."profileViews"), COUNT(*) FROM "public"."User" WHERE 1=1 GROUP BY "public"."User"."country", "public"."User"."city", "public"."User"."email" HAVING AVG("public"."User"."profileViews") >= $1 ORDER BY "public"."User"."country" ASC OFFSET $2
```

> **注意**: `$transaction` 內的多個 `create()` 語句會產生多個 `INSERT` 語句。

### 建立並返回多個記錄

:::info

此功能在 Prisma ORM 5.14.0 及更高版本中適用於 PostgreSQL、CockroachDB 和 SQLite。

:::

您可以使用 `createManyAndReturn()` 來建立多個記錄並返回結果物件。

<CodeWithResult outputResultText="query">
<cmd>

```ts
const users = await prisma.user.createManyAndReturn({
  data: [
    { name: 'Alice', email: 'alice@prisma.io' },
    { name: 'Bob', email: 'bob@prisma.io' },
  ],
})
```

</cmd>
<cmdResult>

```js no-copy

  name: 'Alice',
  email: 'alice@prisma.io',
  profileViews: 0,
  role: 'USER',
  coinflips: []
}, {
  id: 23,
  name: 'Bob',
  email: 'bob@prisma.io',
  profileViews: 0,
  role: 'USER',
  coinflips: []
}]
```

</cmdResult>
</CodeWithResult>

:::warning

使用 `createManyAndReturn()` 時無法使用 `relationLoadStrategy: join`。

:::

## 讀取

### 透過 ID 或唯一識別符號取得記錄

以下查詢透過唯一識別符號或 ID 返回單一記錄 ([`findUnique()`](/orm/reference/prisma-client-reference#findunique)):

```ts
// By unique identifier
const user = await prisma.user.findUnique({
  where: {
    email: 'elsa@prisma.io',
  },
})

// By ID
const user = await prisma.user.findUnique({
  where: {
    id: 99,
  },
})
```

如果您使用 MongoDB 連接器且底層 ID 類型為 `ObjectId`,您可以使用該 `ObjectId` 的字串表示:

```ts
// By ID
const user = await prisma.user.findUnique({
  where: {
    id: '60d5922d00581b8f0062e3a8',
  },
})
```

### 取得所有記錄

以下 [`findMany()`](/orm/reference/prisma-client-reference#findmany) 查詢返回_所有_ `User` 記錄:

```ts
const users = await prisma.user.findMany()
```

您也可以[分頁您的結果](/orm/prisma-client/queries/pagination)。

### 取得符合特定條件的第一個記錄

以下 [`findFirst()`](/orm/reference/prisma-client-reference#findfirst) 查詢返回_最近建立的使用者_,該使用者至少有一篇貼文擁有超過 100 個讚:

1. 按降序 ID 排序使用者(最大的在前) - 最大的 ID 是最近的
2. 返回降序排列中第一個至少有一篇貼文擁有超過 100 個讚的使用者

```ts
const findUser = await prisma.user.findFirst({
  where: {
    posts: {
      some: {
        likes: {
          gt: 100,
        },
      },
    },
  },
  orderBy: {
    id: 'desc',
  },
})
```

### 取得篩選後的記錄清單

Prisma Client 支援對記錄欄位和相關記錄欄位進行[篩選](/orm/prisma-client/queries/filtering-and-sorting)。

#### 按單一欄位值篩選

以下查詢返回所有 `email` 以 `"prisma.io"` 結尾的 `User` 記錄:

```ts
const users = await prisma.user.findMany({
  where: {
    email: {
      endsWith: 'prisma.io',
    },
  },
})
```

#### 按多個欄位值篩選

以下查詢使用[運算子](/orm/reference/prisma-client-reference#filter-conditions-and-operators)的組合來返回名字以 `E` 開頭_或_至少有 1 次個人資料檢視的管理員:

```ts
const users = await prisma.user.findMany({
  where: {
    OR: [
      {
        name: {
          startsWith: 'E',
        },
      },
      {
        AND: {
          profileViews: {
            gt: 0,
          },
          role: {
            equals: 'ADMIN',
          },
        },
      },
    ],
  },
})
```

#### 按相關記錄欄位值篩選

以下查詢返回 email 以 `prisma.io` 結尾_且_至少有_一篇_貼文 (`some`) 尚未發布的使用者:

```ts
const users = await prisma.user.findMany({
  where: {
    email: {
      endsWith: 'prisma.io',
    },
    posts: {
      some: {
        published: false,
      },
    },
  },
})
```

有關按相關欄位值篩選的更多範例,請參閱 [使用關聯](/orm/prisma-client/queries/relation-queries)。

### 選擇欄位子集

以下 `findUnique()` 查詢使用 `select` 返回特定 `User` 記錄的 `email` 和 `name` 欄位:

<CodeWithResult outputResultText="query">
<cmd>

```ts

  where: {
    email: 'emma@prisma.io',
  },
  select: {
    email: true,
    name: true,
  },
})
```

</cmd>
<cmdResult>

```js no-copy

```

</cmdResult>
</CodeWithResult>

有關包含關聯的更多資訊,請參閱:

- [選擇欄位](/orm/prisma-client/queries/select-fields)
- [關聯查詢](/orm/prisma-client/queries/relation-queries)

#### 選擇相關記錄欄位的子集

以下查詢使用巢狀 `select` 返回:

- 使用者的 `email`
- 每篇貼文的 `likes` 欄位

<CodeWithResult outputResultText="query">
<cmd>

```ts
const user = await prisma.user.findUnique({
  where: {
    email: 'emma@prisma.io',
  },
  select: {
    email: true,
    posts: {
      select: {
        likes: true,
      },
    },
  },
})
```

</cmd>
<cmdResult>

```js no-copy

```

</cmdResult>
</CodeWithResult>

有關包含關聯的更多資訊,請參閱 [選擇欄位並包含關聯](/orm/prisma-client/queries/select-fields)。

### 選擇不重複的欄位值

### 更新_或_建立記錄

以下查詢使用 [`upsert()`](/orm/reference/prisma-client-reference#upsert) 更新具有特定電子郵件地址的 `User` 記錄,或者如果該記錄不存在則建立它:

<CodeWithResult outputResultText="query">
<cmd>

```ts
const upsertUser = await prisma.user.upsert({
  where: {
    email: 'viola@prisma.io',
  },
  update: {
    name: 'Viola the Magnificent',
  },
  create: {
    email: 'viola@prisma.io',
    name: 'Viola the Magnificent',
  },
})
```

</cmd>
<cmdResult>

```js no-copy
{
   "id": 43,
   "name": "Viola the Magnificent",
   "email": "viola@prisma.io",
   "profileViews": 0,
   "role": "ADMIN",
   "coinflips": [],
}
```

</cmdResult>
</CodeWithResult>

:::info

從 4.6.0 版本開始,Prisma Client 盡可能使用資料庫原生 SQL 命令執行 upsert。[了解更多](/orm/reference/prisma-client-reference#database-upserts)。

:::

Prisma Client 沒有 `findOrCreate()` 查詢。您可以使用 `upsert()` 作為替代方案。要使 `upsert()` 的行為像 `findOrCreate()` 方法,請為 `upsert()` 提供一個空的 `update` 參數。

:::warning

使用 `upsert()` 作為 `findOrCreate()` 替代方案的限制是,`upsert()` 只會在 `where` 條件中接受唯一的模型欄位。因此,如果 `where` 條件包含非唯一欄位,則無法使用 `upsert()` 來模擬 `findOrCreate()`。

:::

### 更新數字欄位

使用[原子數字運算](/orm/reference/prisma-client-reference#atomic-number-operations)來**根據目前值**更新數字欄位 - 例如,遞增或相乘。以下查詢將 `views` 和 `likes` 欄位遞增 `1`:

```ts
const updatePosts = await prisma.post.updateMany({
  data: {
    views: {
      increment: 1,
    },
    likes: {
      increment: 1,
    },
  },
})
```

### 連接和斷開相關記錄

有關斷開 ([`disconnect`](/orm/reference/prisma-client-reference#disconnect)) 和連接 ([`connect`](/orm/reference/prisma-client-reference#connect)) 相關記錄的資訊,請參閱 [使用關聯](/orm/prisma-client/queries/relation-queries)。

## 刪除

### 刪除單一記錄

以下查詢使用 [`delete()`](/orm/reference/prisma-client-reference#delete) 刪除單一 `User` 記錄:

```ts
const deleteUser = await prisma.user.delete({
  where: {
    email: 'bert@prisma.io',
  },
})
```

嘗試刪除擁有一篇或多篇貼文的使用者會導致錯誤,因為每篇 `Post` 都需要一個作者 - 請參閱[級聯刪除](#cascading-deletes-deleting-related-records)。

### 刪除多個記錄

以下查詢使用 [`deleteMany()`](/orm/reference/prisma-client-reference#deletemany) 刪除所有 `email` 包含 `prisma.io` 的 `User` 記錄:

```ts
const deleteUsers = await prisma.user.deleteMany({
  where: {
    email: {
      contains: 'prisma.io',
    },
  },
})
```

嘗試刪除擁有一篇或多篇貼文的使用者會導致錯誤,因為每篇 `Post` 都需要一個作者 - 請參閱[級聯刪除](#cascading-deletes-deleting-related-records)。

### 刪除所有記錄

以下查詢使用 [`deleteMany()`](/orm/reference/prisma-client-reference#deletemany) 刪除所有 `User` 記錄:

```ts
const deleteUsers = await prisma.user.deleteMany({})
```

請注意,如果使用者有任何相關記錄(例如貼文),此查詢將會失敗。在這種情況下,您需要[先刪除相關記錄](#cascading-deletes-deleting-related-records)。

### 級聯刪除(刪除相關記錄)

:::warning

在 [2.26.0](https://github.com/prisma/prisma/releases/tag/2.26.0) 及更高版本中,可以使用**預覽功能** [參照動作](/orm/prisma-schema/data-model/relations/referential-actions) 進行級聯刪除。

:::

以下查詢使用 [`delete()`](/orm/reference/prisma-client-reference#delete) 刪除單一 `User` 記錄:

```ts
const deleteUser = await prisma.user.delete({
  where: {
    email: 'bert@prisma.io',
  },
})
```

然而,範例 schema 包含 `Post` 和 `User` 之間的**必要關聯**,這意味著您無法刪除擁有貼文的使用者:

```
The change you are trying to make would violate the required relation 'PostToUser' between the `Post` and `User` models.
```

要解決此錯誤,您可以:

- 將關聯設為可選:

  ```prisma highlight=3,4;add|5,6;delete
  model Post {
    id       Int   @id @default(autoincrement())
    //add-start
    author   User? @relation(fields: [authorId], references: [id])
    authorId Int?
    //add-end
    //delete-start
    author   User  @relation(fields: [authorId], references: [id])
    authorId Int
    //delete-end
  }
  ```

- 在刪除使用者之前將貼文的作者更改為另一個使用者。

- 在交易中使用兩個單獨的查詢刪除使用者及其所有貼文(所有查詢都必須成功):

  ```ts
  const deletePosts = prisma.post.deleteMany({
    where: {
      authorId: 7,
    },
  })

  const deleteUser = prisma.user.delete({
    where: {
      id: 7,
    },
  })

  const transaction = await prisma.$transaction([deletePosts, deleteUser])
  ```

### 刪除所有資料表的所有記錄

有時您想要從所有資料表中移除所有資料,但保留實際的資料表。這在開發環境和測試時特別有用。

以下顯示如何使用 Prisma Client 和 Prisma Migrate 從所有資料表中刪除所有記錄。

#### 使用 `deleteMany()` 刪除所有資料

當您知道應該刪除資料表的順序時,可以使用 [`deleteMany`](/orm/reference/prisma-client-reference#deletemany) 函式。這會在 [`$transaction`](/orm/prisma-client/queries/transactions) 中同步執行,並且可以與所有類型的資料庫一起使用。

```ts
const deletePosts = prisma.post.deleteMany()
const deleteProfile = prisma.profile.deleteMany()
const deleteUsers = prisma.user.deleteMany()

// The transaction runs synchronously so deleteUsers must run last.
await prisma.$transaction([deleteProfile, deletePosts, deleteUsers])
```

✅ **優點**:

- 當您事先知道 schema 的結構時效果很好
- 同步刪除每個資料表的資料

❌ **缺點**:

- 在使用關聯式資料庫時,此函式的擴展性不如使用更通用的解決方案,該解決方案會查找並 `TRUNCATE` 您的資料表,而不管它們的關聯約束如何。請注意,使用 MongoDB 連接器時不會出現此擴展問題。

> **注意**: `$transaction` 對每個模型的資料表執行級聯刪除,因此必須按順序呼叫它們。

#### 使用原始 SQL / `TRUNCATE` 刪除所有資料

如果您熟悉原始 SQL,可以使用 [`$executeRawUnsafe`](/orm/prisma-client/using-raw-sql/raw-queries#executerawunsafe) 對資料表執行 `TRUNCATE` 查詢。

在以下範例中,第一個標籤顯示如何透過使用 `$queryRaw` 查找來對 Postgres 資料庫執行 `TRUNCATE`,該查找會映射資料表並在單一查詢中 `TRUNCATE` 所有資料表。

第二個標籤顯示對 MySQL 資料庫執行相同的功能。在這種情況下,必須在執行 `TRUNCATE` 之前移除約束,然後在完成後重新建立約束。整個過程作為 `$transaction` 執行

<TabbedContent code>

<TabItem value="PostgreSQL">

```ts
const tablenames = await prisma.$queryRaw<
  Array<{ tablename: string }>
>`SELECT tablename FROM pg_tables WHERE schemaname='public'`

const tables = tablenames
  .map(({ tablename }) => tablename)
  .filter((name) => name !== '_prisma_migrations')
  .map((name) => `"public"."${name}"`)
  .join(', ')

try {
  await prisma.$executeRawUnsafe(`TRUNCATE TABLE ${tables} CASCADE;`)
} catch (error) {
  console.log({ error })
}
```

</TabItem>

<TabItem value="MySQL">

```ts
const transactions: PrismaPromise<any>[] = []
transactions.push(prisma.$executeRaw`SET FOREIGN_KEY_CHECKS = 0;`)

const tablenames = await prisma.$queryRaw<
  Array<{ TABLE_NAME: string }>
>`SELECT TABLE_NAME from information_schema.TABLES WHERE TABLE_SCHEMA = 'tests';`

for (const { TABLE_NAME } of tablenames) {
  if (TABLE_NAME !== '_prisma_migrations') {
    try {
      transactions.push(prisma.$executeRawUnsafe(`TRUNCATE ${TABLE_NAME};`))
    } catch (error) {
      console.log({ error })
    }
  }
}

transactions.push(prisma.$executeRaw`SET FOREIGN_KEY_CHECKS = 1;`)

try {
  await prisma.$transaction(transactions)
} catch (error) {
  console.log({ error })
}
```

</TabItem>

</TabbedContent>

✅ **優點**:

- 可擴展
- 非常快速

❌ **缺點**:

- 無法撤銷操作
- 使用保留的 SQL 關鍵字作為資料表名稱可能會在嘗試執行原始查詢時造成問題

#### 使用 Prisma Migrate 刪除所有記錄

如果您使用 Prisma Migrate,可以使用 `migrate reset`,這將會:

1. 刪除資料庫
2. 建立新資料庫
3. 套用遷移
4. 用資料填充資料庫
