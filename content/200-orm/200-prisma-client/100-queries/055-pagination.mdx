<TopBlock>

Prisma Client 支援位移分頁和基於游標的分頁。

</TopBlock>

## 位移分頁

位移分頁使用 `skip` 和 `take` 來跳過一定數量的結果並選擇有限的範圍。以下查詢跳過前 3 筆 `Post` 記錄並返回第 4 - 7 筆記錄：

```ts line-number
const results = await prisma.post.findMany({
  skip: 3,
  take: 4,
})
```

![](/img/orm/offset-skip-take.png)

要實作分頁結果，你只需要 `skip` 頁數乘以每頁顯示的結果數量。

### ✔ 位移分頁的優點

- 你可以立即跳到任何頁面。例如，你可以 `skip` 200 筆記錄並 `take` 10 筆，這模擬了直接跳到結果集的第 21 頁（底層 SQL 使用 `OFFSET`）。這在基於游標的分頁中是不可能的。
- 你可以以任何排序順序對相同的結果集進行分頁。例如，你可以跳到按名字排序的 `User` 記錄列表的第 21 頁。這在基於游標的分頁中是不可能的，因為它需要按唯一的、連續的欄位排序。

### ✘ 位移分頁的缺點

- 位移分頁**無法擴展**在資料庫層級。例如，如果你跳過 200,000 筆記錄並取得前 10 筆，資料庫仍然必須遍歷前 200,000 筆記錄才能返回你要求的 10 筆 - 這會負面影響效能。

### 位移分頁的使用情境

- 小結果集的淺層分頁。例如，一個部落格介面允許你按作者篩選 `Post` 記錄並對結果進行分頁。

### 範例：篩選和位移分頁

以下查詢返回所有 `email` 欄位包含 `prisma.io` 的記錄。查詢跳過前 40 筆記錄並返回第 41 - 50 筆記錄。

```ts line-number
const results = await prisma.post.findMany({
  skip: 40,
  take: 10,
  where: {
    email: {
      contains: 'prisma.io',
    },
  },
})
```

### 範例：排序和位移分頁

以下查詢返回所有 `email` 欄位包含 `Prisma` 的記錄，並按 `title` 欄位排序結果。查詢跳過前 200 筆記錄並返回第 201 - 220 筆記錄。

```ts line-number
const results = await prisma.post.findMany({
  skip: 200,
  take: 20,
  where: {
    email: {
      contains: 'Prisma',
    },
  },
  orderBy: {
    title: 'desc',
  },
})
```

## 基於游標的分頁

基於游標的分頁使用 `cursor` 和 `take` 在給定的**游標**之前或之後返回有限的結果集。游標會為你在結果集中的位置做書籤，並且必須是唯一的、連續的欄位 - 例如 ID 或時間戳記。

以下範例返回包含 `"Prisma"` 一詞的前 4 筆 `Post` 記錄，並將最後一筆記錄的 ID 儲存為 `myCursor`：

> **注意**：由於這是第一個查詢，沒有游標需要傳入。

```ts showLineNumbers
const firstQueryResults = await prisma.post.findMany({
  take: 4,
  where: {
    title: {
      contains: 'Prisma' /* Optional filter */,
    },
  },
  orderBy: {
    id: 'asc',
  },
})

// Bookmark your location in the result set - in this
// case, the ID of the last post in the list of 4.

//highlight-start
const lastPostInResults = firstQueryResults[3] // Remember: zero-based index! :)
const myCursor = lastPostInResults.id // Example: 29
//highlight-end
```

以下圖表顯示了前 4 個結果的 ID - 或第 1 頁。下一個查詢的游標是 **29**：

![](/img/orm/cursor-1.png)

第二個查詢返回包含 `"Prisma"` 一詞且**在提供的游標之後**的前 4 筆 `Post` 記錄（換句話說 - ID 大於 **29** 的記錄）：

```ts line-number
const secondQueryResults = await prisma.post.findMany({
  take: 4,
  skip: 1, // Skip the cursor
  //highlight-start
  cursor: {
    id: myCursor,
  },
  //highlight-end
  where: {
    title: {
      contains: 'Prisma' /* Optional filter */,
    },
  },
  orderBy: {
    id: 'asc',
  },
})

const lastPostInResults = secondQueryResults[3] // Remember: zero-based index! :)
const myCursor = lastPostInResults.id // Example: 52
```

以下圖表顯示了 ID 為 **29** 的記錄**之後**的前 4 筆 `Post` 記錄。在這個範例中，新的游標是 **52**：

![](/img/orm/cursor-2.png)

### FAQ

#### 我是否總是需要 skip: 1？

如果你不使用 `skip: 1`，你的結果集將包含你的前一個游標。第一個查詢返回四個結果，游標是 **29**：

![](/img/orm/cursor-1.png)

沒有 `skip: 1`，第二個查詢返回游標之後（和_包含_）的 4 個結果：

![](/img/orm/cursor-3.png)

如果你使用 `skip: 1`，游標不會被包含：

![](/img/orm/cursor-2.png)

你可以選擇是否使用 `skip: 1`，這取決於你想要的分頁行為。

#### 我可以猜測游標的值嗎？

如果你猜測下一個游標的值，你將分頁到結果集中的未知位置。雖然 ID 是連續的，但你無法預測增量的速率（`2`、`20`、`32` 比 `1`、`2`、`3` 更有可能，特別是在已篩選的結果集中）。

#### 基於游標的分頁使用底層資料庫中的游標概念嗎？

不，游標分頁不使用底層資料庫中的游標（[例如 PostgreSQL](https://www.postgresql.org/docs/9.2/plpgsql-cursors.html)）。

#### 如果游標值不存在會發生什麼？

使用不存在的游標會返回 `null`。Prisma Client 不會嘗試定位相鄰的值。

### ✔ 基於游標的分頁的優點

- 基於游標的分頁**可以擴展**。底層 SQL 不使用 `OFFSET`，而是查詢所有 ID 大於 `cursor` 值的 `Post` 記錄。

### ✘ 基於游標的分頁的缺點

- 你必須按你的游標排序，這必須是唯一的、連續的欄位。
- 你不能僅使用游標跳到特定頁面。例如，你無法準確預測哪個游標代表第 400 頁（頁面大小 20）的開始，而不先請求第 1 - 399 頁。

### 基於游標的分頁的使用情境

- 無限滾動 - 例如，按日期/時間降序排序部落格文章，每次請求 10 篇部落格文章。
- 批次分頁瀏覽整個結果集 - 例如，作為長時間運行的資料匯出的一部分。

### 範例：篩選和基於游標的分頁

```ts line-number
const secondQuery = await prisma.post.findMany({
  take: 4,
  skip: 1,
  cursor: {
    id: myCursor,
  },
  //highlight-start
  where: {
    title: {
      contains: 'Prisma' /* Optional filter */,
    },
  },
  //highlight-end
  orderBy: {
    id: 'asc',
  },
})
```

### 排序和基於游標的分頁

基於游標的分頁需要你按連續的、唯一的欄位（如 ID 或時間戳記）排序。這個值 - 稱為游標 - 會為你在結果集中的位置做書籤，並允許你請求下一組資料。

### 範例：使用基於游標的分頁向後翻頁

要向後翻頁，將 `take` 設定為負值。以下查詢返回 `id` 小於 200 的 4 筆 `Post` 記錄，不包括游標：

```ts line-number
const myOldCursor = 200

const firstQueryResults = await prisma.post.findMany({
  take: -4,
  skip: 1,
  cursor: {
    id: myOldCursor,
  },
  where: {
    title: {
      contains: 'Prisma' /* Optional filter */,
    },
  },
  orderBy: {
    id: 'asc',
  },
})
```
