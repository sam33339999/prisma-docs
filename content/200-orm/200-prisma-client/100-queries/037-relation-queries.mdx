Prisma Client 的一個關鍵功能是能夠查詢兩個或更多模型之間的[關聯](/orm/prisma-schema/data-model/relations)。關聯查詢包括:

- 透過 [`select`](/orm/reference/prisma-client-reference#select) 和 [`include`](/orm/reference/prisma-client-reference#include) 進行[巢狀讀取](#nested-reads)(有時稱為_預先載入_)
- 具有[交易](/orm/prisma-client/queries/transactions)保證的[巢狀寫入](#nested-writes)
- [對相關記錄進行篩選](#relation-filters)

Prisma Client 還有一個[用於遍歷關聯的流暢 API](#fluent-api)。

## 巢狀讀取

巢狀讀取允許您從資料庫中的多個資料表讀取相關資料 - 例如使用者和該使用者的貼文。您可以:

- 使用 [`include`](/orm/reference/prisma-client-reference#include) 在查詢回應中包含相關記錄,例如使用者的貼文或個人資料。
- 使用巢狀 [`select`](/orm/reference/prisma-client-reference#select) 包含相關記錄的特定欄位。您也可以在 `include` 內巢狀 `select`。

### 關聯載入策略(預覽)

從版本 [5.8.0](https://github.com/prisma/prisma/releases/tag/5.8.0) 開始,您可以在每個查詢層級決定_如何_讓 Prisma Client 執行關聯查詢(即應套用什麼_載入策略_),透過 `relationLoadStrategy` 選項適用於 PostgreSQL 資料庫。

從版本 [5.10.0](https://github.com/prisma/prisma/releases/tag/5.10.0) 開始,此功能也適用於 MySQL。

因為 `relationLoadStrategy` 選項目前處於預覽狀態,您需要透過 Prisma schema 檔案中的 `relationJoins` 預覽功能標誌來啟用它:

```prisma file=schema.prisma showLineNumbers
generator client {
  provider        = "prisma-client"
  output          = "./generated"
  previewFeatures = ["relationJoins"]
}
```

新增此標誌後,您需要再次執行 `prisma generate` 來重新生成 Prisma Client。`relationJoins` 功能目前在 PostgreSQL、CockroachDB 和 MySQL 上可用。

Prisma Client 支援兩種關聯載入策略:

- `join`(預設):使用資料庫層級的 `LATERAL JOIN`(PostgreSQL)或相關子查詢(MySQL),並透過單一查詢從資料庫獲取所有資料。
- `query`:向資料庫發送多個查詢(每個資料表一個)並在應用程式層級連接它們。

這兩個選項之間另一個重要的區別是,`join` 策略在資料庫層級使用 JSON 聚合。這意味著它在資料庫中建立 Prisma Client 返回的 JSON 結構,從而節省應用程式層級的運算資源。

> **注意**: 一旦 `relationLoadStrategy` 從[預覽](/orm/more/releases#preview)進入[正式版本](/orm/more/releases/#generally-available-ga),`join` 將普遍成為所有關聯查詢的預設值。

#### 範例

您可以在支援 `include` 或 `select` 的任何查詢的頂層使用 `relationLoadStrategy` 選項。

以下是使用 `include` 的範例:

```ts
const users = await prisma.user.findMany({
  relationLoadStrategy: 'join', // or 'query'
  include: {
    posts: true,
  },
})
```

以下是使用 `select` 的另一個範例:

```ts
const users = await prisma.user.findMany({
  relationLoadStrategy: 'join', // or 'query'
  select: {
    posts: true,
  },
})
```

#### 何時使用哪種載入策略?

- `join` 策略(預設)在大多數情況下會更有效。在 PostgreSQL 上,它使用 `LATERAL JOINs` 和 JSON 聚合的組合來減少結果集中的冗餘,並將轉換查詢結果為預期 JSON 結構的工作委派給資料庫伺服器。在 MySQL 上,它使用相關子查詢透過單一查詢獲取結果。
- 根據資料集和查詢的特性,在某些邊緣情況下 `query` 可能更高效。我們建議您分析資料庫查詢以識別這些情況。
- 如果您想節省資料庫伺服器上的資源並在應用程式伺服器中執行合併和轉換資料的繁重工作(這可能更容易擴展),請使用 `query`。

## 篩選關聯清單

當您使用 `select` 或 `include` 返回相關資料的子集時,您可以在 `select` 或 `include` 內**篩選和排序關聯清單**。

例如,以下查詢返回與使用者關聯的未發布貼文的標題清單:

```ts
const result = await prisma.user.findFirst({
  select: {
    posts: {
      where: {
        published: false,
      },
      orderBy: {
        title: 'asc',
      },
      select: {
        title: true,
      },
    },
  },
})
```

您也可以使用 `include` 撰寫相同的查詢,如下所示:

```ts
const result = await prisma.user.findFirst({
  include: {
    posts: {
      where: {
        published: false,
      },
      orderBy: {
        title: 'asc',
      },
    },
  },
})
```

## 巢狀寫入

巢狀寫入允許您在**單一交易**中將**關聯資料**寫入資料庫。

巢狀寫入:

- 為在單一 Prisma Client 查詢中跨多個資料表建立、更新或刪除資料提供**交易保證**。如果查詢的任何部分失敗(例如,建立使用者成功但建立貼文失敗),Prisma Client 會回滾所有變更。
- 支援資料模型支援的任何巢狀層級。
- 在使用模型的建立或更新查詢時可用於[關聯欄位](/orm/prisma-schema/data-model/relations#relation-fields)。以下部分顯示每個查詢可用的巢狀寫入選項。

### 建立單一記錄和多個相關記錄

有兩種方式可以建立或更新單一記錄和多個相關記錄 - 例如,一個使用者與多篇貼文:

- 使用巢狀 [`create`](/orm/reference/prisma-client-reference#create) 查詢
- 使用巢狀 [`createMany`](/orm/reference/prisma-client-reference#createmany-1) 查詢

在大多數情況下,巢狀 `create` 更可取,除非需要 [`skipDuplicates` 查詢選項](/orm/reference/prisma-client-reference#nested-createmany-options)。以下是描述這兩個選項之間差異的快速表格:

| 功能                          | `create` | `createMany` | 注意事項                                                                                                                                                                                        |
| :--------------------------- | :------- | :----------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 支援巢狀額外關聯               | ✔        | ✘ \*         | 例如,您可以在一個查詢中建立使用者、多篇貼文和每篇貼文的多個評論。<br />\* 您可以在一對一關聯中手動設定外鍵 - 例如: `{ authorId: 9}` |
| 支援一對多關聯                 | ✔        | ✔            | 例如,您可以建立使用者和多篇貼文(一個使用者有多篇貼文)                                                                                                                 |
| 支援多對多關聯                 | ✔        | ✘            | 例如,您可以建立貼文和多個分類(一篇貼文可以有多個分類,一個分類可以有多篇貼文)                                                             |
| 支援跳過重複記錄               | ✘        | ✔            | 使用 `skipDuplicates` 查詢選項。                                                                                                                                                              |

作為替代方案,您可以先發送查詢來建立將要連接的記錄,然後再建立實際的記錄。例如:

```ts
const categories = await prisma.category.createManyAndReturn({
  data: [
    { name: 'Fun', },
    { name: 'Technology', },
    { name: 'Sports', }
  ],
  select: {
    id: true
  }
});

const posts = await prisma.post.createManyAndReturn({
  data: [{
    title: "Funniest moments in 2024",
    categoryId: categories.find(category => category.name === 'Fun')!.id
  }, {
    title: "Linux or macOS — what's better?",
    categoryId: categories.find(category => category.name === 'Technology')!.id
  },
  {
    title: "Who will win the next soccer championship?",
    categoryId: categories.find(category => category.name === 'Sports')!.id
  }]
});
```

如果您想在單一資料庫查詢中建立_所有_記錄,請考慮使用 [`$transaction`](/orm/prisma-client/queries/transactions#the-transaction-api) 或[類型安全的原始 SQL](/orm/prisma-client/using-raw-sql/typedsql)。


### 建立多個記錄和多個相關記錄

您無法在 `createMany()` 或 `createManyAndReturn()` 查詢中存取關聯,這意味著您無法在單一巢狀寫入中建立多個使用者和多篇貼文。以下**不可能**:

```ts highlight=6-8,13-15;delete
const createMany = await prisma.user.createMany({
  data: [
    {
      name: 'Yewande',
      email: 'yewande@prisma.io',
      //delete-start
      posts: {
        // Not possible to create posts!
      },
      //delete-end
    },
    {
      name: 'Noor',
      email: 'noor@prisma.io',
      //delete-start
      posts: {
        // Not possible to create posts!
      },
      //delete-end
    },
  ],
})
```

### 連接多個記錄

以下查詢建立 ([`create`](/orm/reference/prisma-client-reference#create)) 一個新的 `User` 記錄,並將該記錄連接 ([`connect`](/orm/reference/prisma-client-reference#connect)) 到三篇現有貼文:

<CodeWithResult outputResultText="query">
<cmd>

```ts highlight=4-6;normal
const result = await prisma.user.create({
  data: {
    email: 'vlad@prisma.io',
    //highlight-start
    posts: {
      connect: [{ id: 8 }, { id: 9 }, { id: 10 }],
    },
    //highlight-end
  },
  include: {
    posts: true, // Include all posts in the returned object
  },
})
```

## 關聯篩選

### 對"一對多"關聯進行篩選

Prisma Client 提供 [`some`](/orm/reference/prisma-client-reference#some)、[`every`](/orm/reference/prisma-client-reference#every) 和 [`none`](/orm/reference/prisma-client-reference#none) 選項,可透過關聯的"一對多"側相關記錄的屬性來篩選記錄。例如,根據貼文的屬性篩選使用者。

例如:

| 需求                                                                       | 要使用的查詢選項                 |
| --------------------------------------------------------------------------------- | ----------------------------------- |
| "我想要一個清單,列出至少有一篇未發布 `Post` 記錄的每個 `User`" | `some` 貼文未發布        |
| "我想要一個清單,列出沒有未發布 `Post` 記錄的每個 `User`"          | `none` 的貼文未發布 |
| "我想要一個清單,列出只有未發布 `Post` 記錄的每個 `User`"        | `every` 貼文未發布         |

例如,以下查詢返回符合以下條件的 `User`:

- 沒有瀏覽次數超過 100 的貼文
- 所有貼文的讚數少於或等於 50

```ts
const users = await prisma.user.findMany({
  where: {
    //highlight-start
    posts: {
      none: {
        views: {
          gt: 100,
        },
      },
      every: {
        likes: {
          lte: 50,
        },
      },
    },
    //highlight-end
  },
  include: {
    posts: true,
  },
})
```

### 對"一對一"關聯進行篩選

Prisma Client 提供 [`is`](/orm/reference/prisma-client-reference#is) 和 [`isNot`](/orm/reference/prisma-client-reference#isnot) 選項,可透過關聯的"一對一"側相關記錄的屬性來篩選記錄。例如,根據作者的屬性篩選貼文。

例如,以下查詢返回符合以下條件的 `Post` 記錄:

- 作者的名字不是 Bob
- 作者年齡超過 40

```ts highlight=3-13;normal
const users = await prisma.post.findMany({
  where: {
    //highlight-start
    author: {
      isNot: {
        name: 'Bob',
      },
      is: {
        age: {
          gt: 40,
        },
      },
    },
  },
  //highlight-end
  include: {
    author: true,
  },
})
```

### 對缺少"一對多"記錄進行篩選

例如,以下查詢使用 `none` 返回所有沒有貼文的使用者:

```ts highlight=3-5;normal
const usersWithZeroPosts = await prisma.user.findMany({
  where: {
    //highlight-start

      none: {},
    },
    //highlight-end
  },

  },
})
```

以下查詢返回所有沒有作者關聯的貼文:

```js highlight=3;normal
const postsWithNoAuthor = await prisma.post.findMany({
  where: {
    //highlight-next-line

  },

    author: true,
  },
```


## 流暢 API

流暢 API 讓您透過函式呼叫_流暢地_遍歷模型的[關聯](/orm/prisma-schema/data-model/relations)。請注意,_最後_的函式呼叫決定整個查詢的返回類型(下面的程式碼片段中新增了相應的類型註釋以使其明確)。

此查詢返回特定 `User` 的所有 `Post` 記錄:

```ts
const postsByUser: Post[] = await prisma.user
  .findUnique({ where: { email: 'alice@prisma.io' } })
  .posts()
```

這等同於以下 `findMany` 查詢:

```ts
const postsByUser = await prisma.post.findMany({
  where: {
    author: {
      email: 'alice@prisma.io',
    },
  },
})
```

查詢之間的主要區別在於,流暢 API 呼叫被轉換為兩個單獨的資料庫查詢,而另一個只產生單一查詢(請參閱此 [GitHub 問題](https://github.com/prisma/prisma/issues/1984))

> **注意**: 您可以利用 `.findUnique({ where: { email: 'alice@prisma.io' } }).posts()` 查詢會由 Prisma Client 中的 Prisma 資料載入器自動批次處理這一事實,來[避免 GraphQL 解析器中的 n+1 問題](/orm/prisma-client/queries/query-optimization-performance#solving-n1-in-graphql-with-findunique-and-prisma-clients-dataloader)。

此請求返回特定貼文的所有分類:

```ts
const categoriesOfPost: Category[] = await prisma.post
  .findUnique({ where: { id: 1 } })
  .categories()
```

請注意,您可以鏈接任意多個查詢。在此範例中,鏈接從 `Profile` 開始,經過 `User` 到達 `Post`:

```ts
const posts: Post[] = await prisma.profile
  .findUnique({ where: { id: 1 } })
  .user()
  .posts()
```

鏈接的唯一要求是前一個函式呼叫必須僅返回_單一物件_(例如,由 `findUnique` 查詢或"一對一關聯"如 `profile.user()` 返回)。

以下查詢**不可能**,因為 `findMany` 不返回單一物件而是_清單_:

```ts
// This query is illegal
const posts = await prisma.user.findMany().posts()
```
