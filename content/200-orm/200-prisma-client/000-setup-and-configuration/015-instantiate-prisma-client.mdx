<TabItem value="TypeScript">


```js
const { PrismaClient } = require('../prisma/generated/client')
```

## `PrismaClient` 實例的數量很重要

您的應用程式通常應該只建立 `PrismaClient` 的**一個實例**。如何實現這一點取決於您是在[長時間執行的應用程式](/orm/prisma-client/setup-and-configuration/databases-connections#prismaclient-in-long-running-applications)中還是在 [serverless 環境](/orm/prisma-client/setup-and-configuration/databases-connections#prismaclient-in-serverless-environments)中使用 Prisma ORM。

這樣做的原因是每個 `PrismaClient` 實例都會管理一個連線池,這意味著大量的客戶端可能會**耗盡資料庫連線限制**。這適用於所有資料庫連接器。

如果您使用 **MongoDB 連接器**,連線由 MongoDB 驅動程式連線池管理。如果您使用**關聯式資料庫連接器**,連線由 Prisma ORM 的[連線池](/orm/prisma-client/setup-and-configuration/databases-connections/connection-pool)管理。每個 `PrismaClient` 實例都會建立自己的池。

1. 每個客戶端都會建立自己的[查詢引擎](/orm/more/under-the-hood/engines)實例。
1. 每個查詢引擎都會建立一個[連線池](/orm/prisma-client/setup-and-configuration/databases-connections/connection-pool),預設池大小為:

   - 關聯式資料庫為 `num_physical_cpus * 2 + 1`
   - [MongoDB 為 `100`](https://www.mongodb.com/docs/manual/reference/connection-string-options/#mongodb-urioption-urioption.maxPoolSize)

1. 太多連線可能會開始**拖慢您的資料庫**,並最終導致錯誤,例如:

   ```
   Error in connector: Error querying the database: db error: FATAL: sorry, too many clients already
       at PrismaClientFetcher.request
   ```
