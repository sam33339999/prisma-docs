<TopBlock>

資料庫可以處理有限數量的並行連線。每個連線都需要 RAM，這意味著僅僅增加資料庫連線限制而不擴展可用資源：

- ✔ 可能允許更多進程連線，_但是_
- ✘ 會顯著影響**資料庫效能**，並可能導致資料庫因記憶體不足錯誤而**關閉**

應用程式**管理連線**的方式也會影響效能。本指南描述如何在 [serverless 環境](#serverless-environments-faas)和[長時間執行的進程](#long-running-processes)中處理連線管理。

:::warning

本指南著重於**關聯式資料庫**以及如何配置和調整 Prisma ORM 連線池（MongoDB 使用 MongoDB 驅動程式連線池）。

:::

</TopBlock>

## 長時間執行的進程

長時間執行的進程範例包括託管在 Heroku 或虛擬機等服務上的 Node.js 應用程式。使用以下檢查清單作為長時間執行環境中連線管理的指南：

- 從[建議的連線池大小（`connection_limit`）](#recommended-connection-pool-size)開始，並[調整它](#optimizing-the-connection-pool)
- 確保你有[**一個**全域的 `PrismaClient` 實例](#prismaclient-in-long-running-applications)

### 建議的連線池大小

長時間執行進程的建議連線池大小（`connection_limit`）[起始值](#optimizing-the-connection-pool)為**預設連線池大小**（`num_physical_cpus * 2 + 1`）÷ **應用程式實例數量**。

:::info

`num_physical_cpus` 指的是應用程式執行所在機器的 CPU 數量。

:::

如果你有**一個**應用程式實例：

- 預設連線池大小預設為（`num_physical_cpus * 2 + 1`）- 你不需要設定 `connection_limit` 參數。
- 你可以選擇性地[調整連線池大小](#optimizing-the-connection-pool)。

如果你有**多個**應用程式實例：

- 你必須**手動**[設定 `connection_limit` 參數](/orm/prisma-client/setup-and-configuration/databases-connections/connection-pool#setting-the-connection-pool-size)。例如，如果你計算的連線池大小為 _10_，並且你有 _2_ 個應用程式實例，則 `connection_limit` 參數應**不超過 _5_**。
- 你可以選擇性地[調整連線池大小](#optimizing-the-connection-pool)。

### 長時間執行應用程式中的 `PrismaClient`

在**長時間執行**的應用程式中，我們建議你：

- ✔ 建立**一個** `PrismaClient` 實例並在整個應用程式中重複使用
- ✔ _僅在開發環境中_將 `PrismaClient` 指派給全域變數，以[防止熱重載建立新實例](#prevent-hot-reloading-from-creating-new-instances-of-prismaclient)

#### 重複使用單一 `PrismaClient` 實例

要重複使用單一實例，請建立一個匯出 `PrismaClient` 物件的模組：

```ts file=client.ts
import { PrismaClient } from '../prisma/generated/client'

let prisma = new PrismaClient()

export default prisma
```

該物件在第一次匯入模組時會被[快取](https://nodejs.org/api/modules.html#modules_caching)。後續請求會返回快取的物件，而不是建立新的 `PrismaClient`：

```ts file=app.ts
import prisma from './client'

async function main() {
  const allUsers = await prisma.user.findMany()
}

main()
```

你不必完全複製上面的範例 - 目標是確保 `PrismaClient` 被快取。例如，你可以[在 `context` 物件中實例化 `PrismaClient`](https://github.com/prisma/prisma-examples/blob/9f1a6b9e7c25b9e1851bd59b273046158d748995/typescript/graphql-express/src/context.ts#L9)，然後[傳遞給 Express 應用程式](https://github.com/prisma/prisma-examples/blob/9f1a6b9e7c25b9e1851bd59b273046158d748995/typescript/graphql-express/src/server.ts#L12)。

#### 不要明確呼叫 `$disconnect()`

在持續提供請求的長時間執行應用程式的情境中，你[不需要明確呼叫 `$disconnect()`](/orm/prisma-client/setup-and-configuration/databases-connections/connection-management#calling-disconnect-explicitly)。建立新連線需要時間，如果你在每次查詢後斷開連線，可能會減慢應用程式速度。

#### 防止熱重載建立新的 `PrismaClient` 實例

像 [Next.js](https://nextjs.org/) 這樣的框架支援變更檔案的熱重載，這使你能夠在不重新啟動的情況下看到應用程式的變更。然而，如果框架刷新負責匯出 `PrismaClient` 的模組，這可能會導致**在開發環境中建立額外、不需要的 `PrismaClient` 實例**。

作為解決方法，你可以僅在開發環境中將 `PrismaClient` 儲存為全域變數，因為全域變數不會被重新載入：

```ts file=client.ts
import { PrismaClient } from '../prisma/generated/client'

const globalForPrisma = globalThis as unknown as { prisma: PrismaClient }

export const prisma =
  globalForPrisma.prisma || new PrismaClient()

if (process.env.NODE_ENV !== 'production') globalForPrisma.prisma = prisma
```

匯入和使用 Prisma Client 的方式不變：

```ts file=app.ts
import { prisma } from './client'

async function main() {
  const allUsers = await prisma.user.findMany()
}

main()
```

## Serverless 環境（FaaS）

Serverless 環境範例包括託管在 AWS Lambda、Vercel 或 Netlify Functions 上的 Node.js 函式。使用以下檢查清單作為 serverless 環境中連線管理的指南：

- 熟悉 [serverless 連線管理挑戰](#the-serverless-challenge)
- 根據你是否有外部連線池器[設定連線池大小（`connection_limit`）](#recommended-connection-pool-size-1)，並可選擇性地[調整連線池大小](#optimizing-the-connection-pool)
- [在處理程序外實例化 `PrismaClient`](#instantiate-prismaclient-outside-the-handler)，並且不要明確呼叫 `$disconnect()`
- 配置[函式並行性](#concurrency-limits)並處理[閒置連線](#zombie-connections)

### Serverless 挑戰

在 serverless 環境中，每個函式建立**自己的實例** `PrismaClient`，每個客戶端實例都有自己的連線池。

考慮以下範例，其中單一 AWS Lambda 函式使用 `PrismaClient` 連線到資料庫。`connection_limit` 為 **3**：

![An AWS Lambda function connecting to a database.](./serverless-connections.png)

流量激增導致 AWS Lambda 產生兩個額外的 lambda 來處理增加的負載。每個 lambda 建立一個 `PrismaClient` 實例，每個的 `connection_limit` 為 **3**，這導致資料庫最多有 **9** 個連線：

![Three AWS Lambda function connecting to a database.](./serverless-connections-2.png)

200 個_並行函式_（因此有 600 個可能的連線）回應流量激增 📈 可能會很快耗盡資料庫連線限制。此外，任何**暫停**的函式預設會保持其連線開啟，並阻止其他函式使用它們。

1. 從[將 `connection_limit` 設定為 `1`](#recommended-connection-pool-size-1) 開始
2. 如果較小的連線池大小不夠，請考慮使用[外部連線池器，如 PgBouncer](#external-connection-poolers)

### 建議的連線池大小

serverless 環境中建議的連線池大小（`connection_limit`）取決於：

- 你是否使用[外部連線池器](#external-connection-poolers)
- 你的函式是否[設計為並行發送查詢](#optimizing-for-parallel-requests)

#### 不使用外部連線池器

如果你**沒有**使用外部連線池器，請_先_將連線池大小（`connection_limit`）設定為 **1**，然後[優化](#optimizing-for-parallel-requests)。每個傳入請求啟動一個短暫的 Node.js 進程，在流量激增期間，許多具有高 `connection_limit` 的並行函式可以快速**耗盡_資料庫_連線限制**。

以下範例示範如何在連線 URL 中將 `connection_limit` 設定為 1：

<TabbedContent code>
<TabItem value="PostgreSQL">

```
postgresql://USER:PASSWORD@HOST:PORT/DATABASE?schema=public&connection_limit=1
```

</TabItem>
<TabItem value="MySQL">

```
mysql://USER:PASSWORD@HOST:PORT/DATABASE?connection_limit=1
```

</TabItem>
</TabbedContent>

:::tip

如果你使用 AWS Lambda 並且_沒有_配置 `connection_limit`，請參閱以下 GitHub issue 以獲取有關預期預設連線池大小的資訊：https://github.com/prisma/docs/issues/667

:::

#### 使用外部連線池器

如果你使用外部連線池器，請使用預設連線池大小（`num_physical_cpus * 2 + 1`）作為起點，然後[調整連線池大小](#optimizing-the-connection-pool)。外部連線池器應該防止流量激增壓垮資料庫。

#### 為並行請求優化

如果你很少或從不在連線池大小設定為 1 的情況下超過資料庫連線限制，你可以進一步優化連線池大小。考慮一個並行發送查詢的函式：

```ts
Promise.all() {
  query1,
  query2,
  query3
  query4,
  ...
}
```

如果 `connection_limit` 為 1，此函式被迫**串行**發送查詢（一個接一個），而不是**並行**。這會減慢函式處理請求的能力，並可能導致連線池逾時錯誤。調整 `connection_limit` 參數，直到流量激增：

- 不會耗盡資料庫連線限制
- 不會導致連線池逾時錯誤

### Serverless 環境中的 `PrismaClient`

#### 在處理程序外實例化 `PrismaClient`

在[函式處理程序範圍之外](https://github.com/prisma/e2e-tests/blob/5d1041d3f19245d3d237d959eca94d1d796e3a52/platforms/serverless-lambda/index.ts#L3)實例化 `PrismaClient` 以增加重複使用的機會。只要處理程序保持「溫暖」（使用中），連線就可能被重複使用：

```ts highlight=3;normal
import { PrismaClient } from '../prisma/generated/client'

const client = new PrismaClient()

export async function handler() {
  /* ... */
}
```

#### 不要明確呼叫 `$disconnect()`

你[不需要在函式結尾明確呼叫 `$disconnect()`](/orm/prisma-client/setup-and-configuration/databases-connections/connection-management#calling-disconnect-explicitly)，因為容器可能被重複使用。建立新連線需要時間，會減慢函式處理請求的能力。

### 其他 serverless 注意事項

#### 容器重複使用

不能保證後續附近的函式呼叫會命中相同的容器 - 例如，AWS 可以隨時選擇建立新容器。

程式碼應該假設容器是無狀態的，並且僅在連線不存在時才建立連線 - Prisma Client JS 已經實作了這個邏輯。

#### 殭屍連線

標記為「待移除」且未被重複使用的容器仍然**保持連線開啟**，並可能在該狀態下保持一段時間（AWS 未知且未記錄）。這可能導致資料庫連線的次優利用。

一個潛在的解決方案是**清理閒置連線**（[`serverless-mysql`](https://github.com/jeremydaly/serverless-mysql) 實作了這個想法，但不能與 Prisma ORM 一起使用）。

#### 並行限制

根據你的 serverless 並行限制（並行執行的 serverless 函式數量），你仍然可能耗盡資料庫的連線限制。當太多函式被同時呼叫時，每個都有自己的連線池，最終會耗盡資料庫連線限制。要防止這種情況，你可以[設定 serverless 並行限制](https://docs.aws.amazon.com/lambda/latest/dg/configuration-concurrency.html)為低於資料庫最大連線限制除以每個函式呼叫使用的連線數（因為你可能希望能夠從另一個客戶端連線以用於其他目的）。

## 優化連線池

如果查詢引擎無法[在時間限制內處理佇列中的查詢](/orm/prisma-client/setup-and-configuration/databases-connections/connection-pool#how-the-connection-pool-works)，你將在日誌中看到連線池逾時例外。連線池逾時可能發生在：

- 許多使用者同時存取你的應用程式
- 你並行發送大量查詢（例如，使用 `await Promise.all()`）

如果在配置建議的連線池大小後仍然持續遇到連線池逾時，你可以進一步調整 `connection_limit` 和 `pool_timeout` 參數。

### 增加連線池大小

:::note

自 Prisma ORM v7 起，[驅動程式適配器](/orm/overview/databases/database-drivers)成為關聯式資料庫的預設選項，提供更好的效能和開發者體驗。在[這裡](/orm/prisma-client/setup-and-configuration/no-rust-engine)瞭解更多。

**在 Prisma ORM v7 中，預設生成器配置使用驅動程式適配器**：

```prisma
generator client {
  provider = "prisma-client"
  output   = "../generated/prisma"
}
```

使用驅動程式適配器時，連線池配置由你提供的 Node.js 驅動程式（如 `pg`、`mariadb` 或 `mssql`）處理。請參閱[連線池指南](/orm/prisma-client/setup-and-configuration/databases-connections/connection-pool)以獲取 v7 預設值和配置詳細資訊。

Prisma ORM 還有自己可配置的逾時，與資料庫驅動程式逾時分開。如果你遇到逾時錯誤並不確定它來自特定驅動程式還是 Prisma Client，請參閱 [Prisma Client 逾時和交易選項文件](/orm/prisma-client/queries/transactions#transaction-options)。

你可以在我們的部落格上[閱讀有關此變更的效能和 DX 改進](https://www.prisma.io/blog/prisma-orm-without-rust-latest-performance-benchmarks)。

:::


增加連線池大小允許查詢引擎並行處理更多查詢。請注意，你的資料庫必須能夠支援增加的並行連線數，否則你將**耗盡資料庫連線限制**。

要增加連線池大小，請手動將 `connection_limit` 設定為更高的數字：

```prisma
datasource db {
  provider = "postgresql"
  url      = "postgresql://johndoe:mypassword@localhost:5432/mydb?schema=public&connection_limit=40"
}
```

> **Note**: Setting the `connection_limit` to 1 in serverless environments is a recommended starting point, but [this value can also be tuned](#optimizing-for-parallel-requests).

### Increasing the pool timeout

Increasing the pool timeout gives the query engine more time to process queries in the queue. You might consider this approach in the following scenario:

- You have already increased the `connection_limit`.
- You are confident that the queue will not grow beyond a certain size, otherwise **you will eventually run out of RAM**.

To increase the pool timeout, set the `pool_timeout` parameter to a value larger than the default (10 seconds):

```prisma
datasource db {
  provider = "postgresql"
  url      = "postgresql://johndoe:mypassword@localhost:5432/mydb?connection_limit=5&pool_timeout=20"
}
```

### 停用連線池逾時

停用連線池逾時可防止查詢引擎在等待連線 x 秒後拋出例外，並允許佇列累積。在以下情況下，你可能會考慮這種方法：

- 你在有限時間內提交大量查詢 - 例如，作為匯入或更新資料庫中每個客戶的作業的一部分。
- 你已經增加了 `connection_limit`。
- 你確信佇列不會增長到超過某個大小，否則**你最終會用完 RAM**。

要停用連線池逾時，請將 `pool_timeout` 參數設定為 `0`：

```prisma
datasource db {
  provider = "postgresql"
  url      = "postgresql://johndoe:mypassword@localhost:5432/mydb?connection_limit=5&pool_timeout=0"
}
```

## 外部連線池器

像 [Prisma Accelerate](/accelerate) 和 PgBouncer 這樣的連線池器可防止你的應用程式耗盡資料庫的連線限制。

要讓 Prisma Client 保持在池化連線上，同時允許 Prisma CLI 命令（例如，遷移或內省）直接連線，請定義兩個環境變數：

```env file=.env highlight=4-6;add showLineNumbers
# 使用 PgBouncer 連線到資料庫的連線 URL。
DATABASE_URL="postgres://root:password@127.0.0.1:54321/postgres?pgbouncer=true"

# 用於 Prisma CLI 命令的直接連線到資料庫的 URL。
DIRECT_URL="postgres://root:password@127.0.0.1:5432/postgres"
```

配置 `prisma.config.ts` 指向直接連線字串。Prisma CLI 命令始終從此配置讀取。

```ts file=prisma.config.ts showLineNumbers
import 'dotenv/config'
import { defineConfig, env } from 'prisma/config'

export default defineConfig({
  schema: 'prisma/schema.prisma',
  datasource: {
    url: env('DIRECT_URL'),
  },
})
```

在執行時，使用驅動程式適配器（例如 `@prisma/adapter-pg`）實例化 Prisma Client，該適配器使用池化連線字串：

```ts file=src/db/client.ts showLineNumbers
import { PrismaClient } from '../prisma/generated/client'
import { PrismaPg } from '@prisma/adapter-pg'

const adapter = new PrismaPg({ connectionString: process.env.DATABASE_URL })
export const prisma = new PrismaClient({ adapter })
```

### Prisma Accelerate

[Prisma Accelerate](/accelerate) 是由 Prisma 建構的託管外部連線池器，整合在 [Prisma Data Platform](/platform) 中，並為你處理連線池。

### PgBouncer

PostgreSQL 僅支援一定數量的並行連線，當服務使用量增加時，特別是在 [serverless 環境](#serverless-environments-faas)中，這個限制可能會很快達到。

[PgBouncer](https://www.pgbouncer.org/) 持有資料庫的連線池，並透過位於 Prisma Client 和資料庫之間來代理傳入的客戶端連線。這減少了資料庫在任何給定時間必須處理的進程數。PgBouncer 將有限數量的連線傳遞給資料庫，並在連線可用時將額外的連線排入佇列以供傳遞。要使用 PgBouncer，請參閱[使用 PgBouncer 配置 Prisma Client](/orm/prisma-client/setup-and-configuration/databases-connections/pgbouncer)。

### AWS RDS Proxy

由於 AWS RDS Proxy 固定連線的方式，當與 Prisma Client 一起使用時，[它不提供任何連線池優勢](/orm/prisma-client/deployment/caveats-when-deploying-to-aws-platforms#aws-rds-proxy)。
