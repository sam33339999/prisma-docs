Prisma Schema 的預設名稱是 `prisma` 資料夾中的單一檔案 `schema.prisma`。當您的 schema 如此命名時,Prisma CLI 將自動偵測它。

## Prisma Schema 位置

Prisma CLI 按以下順序在以下位置尋找 Prisma Schema:

1.  由 [`--schema` 旗標](/orm/reference/prisma-cli-reference)指定的位置,在執行 `introspect`、`generate`、`migrate` 和 `studio` 時可用:

    ```terminal
    prisma generate --schema=./alternative/schema.prisma
    ```

2.  在 `package.json` 檔案中指定的位置 (2.7.0 及更高版本):

    ```json
    "prisma": {
      "schema": "db/schema.prisma"
    }
    ```

3.  預設位置:

    - `./prisma/schema.prisma`
    - `./schema.prisma`

Prisma CLI 會輸出將使用的 schema 路徑。以下範例顯示 `prisma db pull` 的終端機輸出:

```no-lines
Environment variables loaded from .env
//highlight-next-line
Prisma Schema loaded from prisma/schema.prisma

Introspecting based on datasource defined in prisma/schema.prisma …

✔ Introspected 4 models and wrote them into prisma/schema.prisma in 239ms

Run prisma generate to generate Prisma Client.
```

## 多檔案 Prisma schema

如果您偏好將 Prisma schema 拆分為多個檔案,可以建立如下設定:

```
prisma/
├── migrations
├── models
│   ├── posts.prisma
│   ├── users.prisma
│   └── ... other `.prisma` files
└── schema.prisma
```

:::note

多檔案 Prisma schema 自 [v6.7.0](https://pris.ly/release/6.7.0) 起正式發布。在此之前,可以透過 `prismaSchemaFolder` 預覽功能旗標使用。

:::

### 使用方式

使用多檔案 Prisma schema 時,您必須明確指定包含 schema 檔案的目錄位置 (包括含有 `generator` 區塊的主要 `schema.prisma` 檔案)。

您可以透過以下三種方式之一執行此操作:

- 將 `--schema` 選項傳遞給 Prisma CLI 命令 (例如 `prisma migrate dev --schema ./prisma`)
- 在 `package.json` 中設定 `prisma.schema` 欄位:
  ```jsonc
  // package.json
  {
    "prisma": {
      "schema": "./prisma"
    }
  }
  ```
- 在 [`prisma.config.ts`](/orm/reference/prisma-config-reference#schema) 中設定 `schema` 屬性 (適用於 Prisma ORM v7):
  ```ts
  import { defineConfig, env } from 'prisma/config'
  import 'dotenv/config'

  export default defineConfig({
    schema: 'prisma/schema.prisma',
    migrations: {
      path: 'prisma/migrations',
      seed: 'tsx prisma/seed.ts',
    },
    datasource: {
      url: env('DATABASE_URL'),
    },
  })
  ```

  :::note

  我們建議使用 [Prisma Config 檔案](/orm/reference/prisma-config-reference#schema)來指定 Prisma schema 的位置。這是指定 Prisma schema 位置以及其他配置選項的最靈活方式。

  :::

:::warning

包含 `generator` 區塊的 `schema.prisma` 檔案必須位於您在 schema 配置中指定的相同目錄中。例如,如果您配置 `schema: 'prisma'`,您的 `schema.prisma` 檔案必須位於 `prisma/schema.prisma`,而不是像 `prisma/models/schema.prisma` 這樣的子目錄中。

:::

您還必須將 `migrations` 目錄放置在與 `schema.prisma` 檔案相同的層級。

例如,假設 `schema.prisma` 定義了 `generator` 區塊,以下是正確的目錄結構:

```
# All files must be inside the `prisma/` directory
# `migrations` and `schema.prisma` must be at the same level
prisma/
├── migrations
├── models
│   ├── posts.prisma
│   └── users.prisma
└── schema.prisma  # Contains generator block
```

:::info

如果您的 schema 檔案位於 `prisma/` 目錄中 (如上所示),`prisma generate` 和 `prisma migrate dev` 等 Prisma CLI 命令將無需額外配置即可運作,因為 `./prisma/schema.prisma` 是預設位置。

:::

### 多檔案 Prisma Schema 的提示

我們發現有幾種模式與此功能搭配使用效果良好,將有助於您充分利用它:

- 按領域組織您的檔案:將相關模型分組到同一個檔案中。例如,將所有與使用者相關的模型保留在 `user.prisma` 中,而與貼文相關的模型則放在 `post.prisma` 中。
- 使用清晰的命名慣例:schema 檔案應該清晰簡潔地命名。使用像 `user.prisma` 和 `post.prisma` 這樣的名稱,而不是 `myModels.prisma` 或 `CommentFeaturesSchema.prisma`。
- 擁有明顯的「主要」schema 檔案:雖然您現在可以擁有任意多個 schema 檔案,但仍然需要一個地方來定義 `generator` 區塊。我們建議擁有一個明顯是「主要」檔案的單一 schema 檔案,以便輕鬆找到此區塊。`main.prisma`、`schema.prisma` 和 `base.prisma` 是我們看到效果不錯的幾個名稱。

我們 fork 的 [`dub` by dub.co](https://github.com/prisma/dub) 是一個很好的範例,展示了如何將真實世界的專案調整為使用多檔案 Prisma Schema。
