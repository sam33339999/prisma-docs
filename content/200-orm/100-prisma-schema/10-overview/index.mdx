Prisma Schema（或簡稱 _schema_）是您 Prisma ORM 設定的主要配置方法。它由以下部分組成：

- [**資料來源（Data sources）**](/orm/prisma-schema/overview/data-sources)：指定 Prisma ORM 應該連接的資料來源詳細資訊（例如 PostgreSQL 資料庫）
- [**產生器（Generators）**](/orm/prisma-schema/overview/generators)：指定應根據資料模型產生哪些客戶端（例如 Prisma Client）
- [**資料模型定義（Data model definition）**](/orm/prisma-schema/data-model)：指定您的應用程式[模型](/orm/prisma-schema/data-model/models#defining-models)（每個資料來源的資料形狀）及其[關聯](/orm/prisma-schema/data-model/relations)

它通常是一個名為 `schema.prisma` 的單一檔案（或多個具有 `.prisma` 副檔名的檔案），儲存在一個已定義但可自訂的[位置](/orm/prisma-schema/overview/location)。如果您偏好的話，也可以[將您的 Prisma schema 組織在多個檔案中](/orm/prisma-schema/overview/location#multi-file-prisma-schema)。

有關 schema 每個部分的詳細資訊，請參閱 [Prisma schema API 參考](/orm/reference/prisma-schema-reference) <span class="api"></span>。

每當呼叫 `prisma` 命令時，CLI 通常會從 schema 讀取一些資訊，例如：

- `prisma generate`：從 Prisma schema 讀取_所有_上述資訊，以產生正確的資料來源客戶端程式碼（例如 Prisma Client）。
- `prisma migrate dev`：讀取資料來源和資料模型定義以建立新的遷移。

您也可以在 schema 中[使用環境變數](#accessing-environment-variables-from-the-schema)，以便在呼叫 CLI 命令時提供配置選項。

## 範例

以下是一個 Prisma Schema 的範例，它指定了：

- 一個資料來源（PostgreSQL 或 MongoDB）
- 一個產生器（Prisma Client）
- 一個包含兩個模型（具有一個關聯）和一個 `enum` 的資料模型定義
- 幾個[原生資料型別屬性](/orm/prisma-schema/data-model/models#native-types-mapping)（`@db.VarChar(255)`、`@db.ObjectId`）

<TabbedContent code>
<TabItem value="Relational databases">

```prisma
datasource db {
  provider = "postgresql"
}

generator client {
  provider = "prisma-client"
  output   = "./generated"
}

model User {
  id        Int      @id @default(autoincrement())
  createdAt DateTime @default(now())
  email     String   @unique
  name      String?
  role      Role     @default(USER)
  posts     Post[]
}

model Post {
  id        Int      @id @default(autoincrement())
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  published Boolean  @default(false)
  title     String   @db.VarChar(255)
  author    User?    @relation(fields: [authorId], references: [id])
  authorId  Int?
}

enum Role {
  USER
  ADMIN
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma
datasource db {
  provider = "mongodb"
  url      = env("DATABASE_URL")
}

generator client {
  provider = "prisma-client-js"
}

model User {
  id        String   @id @default(auto()) @map("_id") @db.ObjectId
  createdAt DateTime @default(now())
  email     String   @unique
  name      String?
  role      Role     @default(USER)
  posts     Post[]
}

model Post {
  id        String   @id @default(auto()) @map("_id") @db.ObjectId
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  published Boolean  @default(false)
  title     String
  author    User?    @relation(fields: [authorId], references: [id])
  authorId  String   @db.ObjectId
}

enum Role {
  USER
  ADMIN
}
```

## 語法

Prisma Schema 檔案使用 Prisma Schema Language（PSL）編寫。有關詳細資訊和範例，請參閱[資料來源](/orm/prisma-schema/overview/data-sources)、[產生器](/orm/prisma-schema/overview/generators)、[資料模型定義](/orm/prisma-schema/data-model)，當然還有 [Prisma Schema API 參考](/orm/reference/prisma-schema-reference)頁面。

### VS Code

PSL 的語法高亮可通過 [VS Code 擴充套件](https://marketplace.visualstudio.com/items?itemName=Prisma.prisma)獲得（它還可以讓您自動格式化 Prisma schema 的內容，並用紅色波浪線指示語法錯誤）。了解更多關於[在編輯器中設定 Prisma ORM](/orm/more/development-environment/editor-setup) 的資訊。

### GitHub

GitHub 上的 PSL 程式碼片段也可以透過使用 `.prisma` 副檔名或在 Markdown 中使用 `prisma` 標註程式碼區塊來進行語法高亮渲染：

````
```prisma
model User {
  id        Int      @id @default(autoincrement())
  createdAt DateTime @default(now())
  email     String   @unique
  name      String?
}
```
````

## 從 schema 存取環境變數

您可以使用環境變數在呼叫 CLI 命令或執行 Prisma Client 查詢時提供配置選項。

直接在您的 schema 中硬編碼 URL 是可能的，但不建議這樣做，因為它會帶來安全風險。在 schema 中使用環境變數可以讓您**將機密資訊保留在 schema 之外**，進而**提高 schema 的可移植性**，讓您能在不同的環境中使用它。

可以使用 `env()` 函數來存取環境變數：

```prisma
datasource db {
  provider = "postgresql"
}
```

您可以在以下位置使用 `env()` 函數：

- datasource url
- Generator binary targets

有關如何在開發期間使用 `.env` 檔案的更多資訊，請參閱[環境變數](/orm/more/development-environment/environment-variables)。

## 註解

Prisma Schema Language 支援三種類型的註解：

- `// comment`：此註解是為了讀者的清晰度而設，不會出現在 schema 的抽象語法樹（AST）中。
- `/// comment`：這些註解將作為 AST 節點的描述出現在 schema 的抽象語法樹（AST）中。工具可以使用這些註解來提供額外的資訊。所有註解都附加到下一個可用的節點上 - 不支援[自由浮動註解](https://github.com/prisma/prisma/issues/3544)，並且不會包含在 AST 中。
- `/* block comment */`：這些註解將出現在抽象語法樹中，與 `///` 註解類似。

以下是一些不同的範例：

```prisma
/// This comment will get attached to the `User` node in the AST
model User {
  /// This comment will get attached to the `id` node in the AST
  id     Int   @default(autoincrement())
  // This comment is just for you
  weight Float /// This comment gets attached to the `weight` node
}

// This comment is just for you. It will not
// show up in the AST.

/// This comment will get attached to the
/// Customer node.
model Customer {
  /**
   * ...and so will this comment
   */
}
```

## 自動格式化

Prisma ORM 支援自動格式化 `.prisma` 檔案。有兩種格式化 `.prisma` 檔案的方法：

- 執行 [`prisma format`](/orm/reference/prisma-cli-reference#format) <span class="api"></span> 命令。
- 安裝 [Prisma VS Code 擴充套件](https://marketplace.visualstudio.com/items?itemName=Prisma.prisma)並呼叫 [VS Code 格式化操作](https://code.visualstudio.com/docs/editor/codebasics#_formatting) - 手動或在儲存時。

沒有配置選項 - [格式化規則](#formatting-rules)是固定的（類似於 Golang 的 `gofmt`，但不像 Javascript 的 `prettier`）：

### 格式化規則

#### Configuration blocks are aligned by their `=` sign

```
block _ {
  key      = "value"
  key2     = 1
  long_key = true
}
```

#### 欄位定義對齊成由 2 個或更多空格分隔的欄

```
block _ {
  id          String       @id
  first_name  LongNumeric  @default
}
```

#### 空白行重設區塊對齊和格式化規則

```
block _ {
  key   = "value"
  key2  = 1
  key10 = true

  long_key   = true
  long_key_2 = true
}
```

```
block _ {
  id  String  @id
              @default

  first_name  LongNumeric  @default
}
```

#### 多行欄位屬性與其餘欄位屬性正確對齊

```
block _ {
  id          String       @id
                           @default
  first_name  LongNumeric  @default
}
```

#### 區塊屬性排序到區塊的末尾

```
block _ {
  key   = "value"

  @@attribute
}
```
