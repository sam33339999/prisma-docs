您可以使用 Prisma CLI 自我檢視資料庫，以便在您的 [Prisma schema](/orm/prisma-schema) 中產生[資料模型](/orm/prisma-schema/data-model)。資料模型是[產生 Prisma Client](/orm/prisma-client/setup-and-configuration/custom-model-and-field-names) 所需的。

自我檢視通常用於在[將 Prisma ORM 加入現有專案](/getting-started/prisma-orm/add-to-existing-project/postgresql)時產生資料模型的_初始_版本。

然而，它也可以在應用程式中[_重複_使用](#introspection-with-an-existing-schema)。這種情況最常見於當您_未_使用 [Prisma Migrate](/orm/prisma-migrate)，而是使用純 SQL 或其他遷移工具來執行結構描述遷移時。在這種情況下，您還需要重新自我檢視資料庫，然後重新產生 Prisma Client，以在您的 [Prisma Client API](/orm/prisma-client) 中反映結構描述的變更。

## 自我檢視做了什麼？

自我檢視有一個主要功能：使用反映當前資料庫結構描述的資料模型來填充您的 Prisma schema。

![Introspect your database with Prisma](/img/orm/prisma-db-pull-generate-schema.png)

以下是它在 SQL 資料庫上的主要功能概述：

- 將資料庫中的_資料表_對應到 [Prisma 模型](/orm/prisma-schema/data-model/models#defining-models)
- 將資料庫中的_欄位_對應到 Prisma 模型的[欄位](/orm/prisma-schema/data-model/models#defining-fields)
- 將資料庫中的_索引_對應到 Prisma schema 中的[索引](/orm/prisma-schema/data-model/models#defining-an-index)
- 將_資料庫約束_對應到 Prisma schema 中的[屬性](/orm/prisma-schema/data-model/models#defining-attributes)或[類型修飾符](/orm/prisma-schema/data-model/models#type-modifiers)

在 MongoDB 上，主要功能如下：

- 將資料庫中的_集合_對應到 [Prisma 模型](/orm/prisma-schema/data-model/models#defining-models)。由於 MongoDB 中的_集合_沒有預定義的結構，Prisma ORM 會_取樣_集合中的_文件_，並相應地衍生模型結構（即它將_文件_的欄位對應到 Prisma 模型的[欄位](/orm/prisma-schema/data-model/models#defining-fields)）。如果在集合中檢測到_嵌入類型_，這些將被對應到 Prisma schema 中的[複合類型](/orm/prisma-schema/data-model/models#defining-composite-types)。
- 如果集合包含至少一個包含索引中的欄位的文件，則將資料庫中的_索引_對應到 Prisma schema 中的[索引](/orm/prisma-schema/data-model/models#defining-an-index)

您可以在資料來源連接器的相關文件頁面上了解更多關於 Prisma ORM 如何將資料庫中的類型對應到 Prisma schema 中可用的類型：

- [PostgreSQL](/orm/overview/databases/postgresql#type-mapping-between-postgresql-and-prisma-schema)
- [MySQL](/orm/overview/databases/mysql#type-mapping-between-mysql-to-prisma-schema)
- [SQLite](/orm/overview/databases/sqlite#type-mapping-between-sqlite-to-prisma-schema)
- [Microsoft SQL Server](/orm/overview/databases/sql-server#type-mapping-between-microsoft-sql-server-to-prisma-schema)

## `prisma db pull` 指令

您可以使用 [Prisma CLI](/orm/tools/prisma-cli#installation) 的 `prisma db pull` 指令自我檢視資料庫。請注意，使用此指令需要在您的 Prisma schema [`datasource`](/orm/prisma-schema/overview/data-sources) 中設定[連線 URL](/orm/reference/connection-urls)。

以下是 `prisma db pull` 內部執行步驟的高階概述：

1. 從 Prisma schema 中的 `datasource` 配置讀取[連線 URL](/orm/reference/connection-urls)
1. 開啟與資料庫的連線
1. 自我檢視資料庫結構描述（即讀取資料表、欄位和其他結構...）
1. 將資料庫結構描述轉換為 Prisma schema 資料模型
1. 將資料模型寫入 Prisma schema 或[更新現有結構描述](#introspection-with-an-existing-schema)

## 自我檢視工作流程

對於不使用 Prisma Migrate，而是使用純 SQL 或其他遷移工具的專案，典型的工作流程如下：

1. 變更資料庫結構描述（例如使用純 SQL）
1. 執行 `prisma db pull` 以更新 Prisma schema
1. 執行 `prisma generate` 以更新 Prisma Client
1. 在您的應用程式中使用更新後的 Prisma Client

請注意，隨著應用程式的發展，[此過程可以重複無數次](#introspection-with-an-existing-schema)。

![Introspect workflow](/img/orm/prisma-evolve-app-workflow.png)

## 規則和慣例

Prisma ORM 採用了許多慣例來將資料庫結構描述轉換為 Prisma schema 中的資料模型：

### 模型、欄位和列舉名稱

欄位、模型和列舉名稱（識別符號）必須以字母開頭，通常只能包含底線、字母和數字。您可以在相關文件頁面上找到每個識別符號的命名規則和慣例：

- [命名模型](/orm/reference/prisma-schema-reference#naming-conventions)
- [命名欄位](/orm/reference/prisma-schema-reference#naming-conventions-1)
- [命名列舉](/orm/reference/prisma-schema-reference#naming-conventions-2)

識別符號的一般規則是它們需要遵守此正規表示式：

```
[A-Za-z][A-Za-z0-9_]*
```

#### 無效字元的淨化

在自我檢視期間，**無效字元**會被淨化：

- 如果它們出現在識別符號中字母的_之前_，它們會被刪除。
- 如果它們出現在第一個字母_之後_，它們會被底線取代。

此外，轉換後的名稱會使用 `@map` 或 `@@map` 對應到資料庫，以保留原始名稱。

將以下資料表視為範例：

```sql
CREATE TABLE "42User" (
  _id SERIAL PRIMARY KEY,
  _name VARCHAR(255),
  two$two INTEGER
);
```

由於資料表名稱中的前導 `42` 以及欄位上的前導底線和 `$` 在 Prisma ORM 中是被禁止的，自我檢視會加入 `@map` 和 `@@map` 屬性，以便這些名稱遵守 Prisma ORM 的命名慣例：

```prisma
model User {
  id      Int     @id @default(autoincrement()) @map("_id")
  name    String? @map("_name")
  two_two Int?    @map("two$two")

  @@map("42User")
}
```

#### 淨化後的重複識別符號

如果淨化導致重複的識別符號，不會立即執行錯誤處理。您稍後會收到錯誤，並可以手動修正它。

考慮以下兩個資料表的情況：

```sql
CREATE TABLE "42User" (
  _id SERIAL PRIMARY KEY
);

CREATE TABLE "24User" (
  _id SERIAL PRIMARY KEY
);
```

這將導致以下自我檢視結果：

```prisma
model User {
  id Int @id @default(autoincrement()) @map("_id")

  @@map("42User")
}

model User {
  id Int @id @default(autoincrement()) @map("_id")

  @@map("24User")
}
```

### 欄位順序

自我檢視會以與資料庫中對應資料表欄位相同的順序列出模型欄位。

### 屬性順序

自我檢視會按以下順序加入屬性（此順序由 `prisma format` 反映）：

- 區塊層級：`@@id`、`@@unique`、`@@index`、`@@map`
- 欄位層級：`@id`、`@unique`、`@default`、`@updatedAt`、`@map`、`@relation`

### 關聯

Prisma ORM 將在資料庫資料表上定義的外鍵轉換為[關聯](/orm/prisma-schema/data-model/relations)。

#### 一對一關聯

當資料表上的外鍵具有 `UNIQUE` 約束時，Prisma ORM 會將[一對一](/orm/prisma-schema/data-model/relations/one-to-one-relations)關聯加入您的資料模型，例如：

```sql
CREATE TABLE "User" (
    id SERIAL PRIMARY KEY
);
CREATE TABLE "Profile" (
    id SERIAL PRIMARY KEY,
    "user" integer NOT NULL UNIQUE,
    FOREIGN KEY ("user") REFERENCES "User"(id)
);
```

Prisma ORM 將此轉換為以下資料模型：

```prisma
model User {
  id      Int      @id @default(autoincrement())
  Profile Profile?
}

model Profile {
  id   Int  @id @default(autoincrement())
  user Int  @unique
  User User @relation(fields: [user], references: [id])
}
```

#### 一對多關聯

預設情況下，對於在資料庫結構描述中找到的外鍵，Prisma ORM 會將[一對多](/orm/prisma-schema/data-model/relations/one-to-many-relations)關聯加入您的資料模型：

```sql
CREATE TABLE "User" (
    id SERIAL PRIMARY KEY
);
CREATE TABLE "Post" (
    id SERIAL PRIMARY KEY,
    "author" integer NOT NULL,
    FOREIGN KEY ("author") REFERENCES "User"(id)
);
```

這些資料表被轉換為以下模型：

```prisma
model User {
  id   Int    @id @default(autoincrement())
  Post Post[]
}

model Post {
  id     Int  @id @default(autoincrement())
  author Int
  User   User @relation(fields: [author], references: [id])
}
```

#### 多對多關聯

[多對多](/orm/prisma-schema/data-model/relations/many-to-many-relations)關聯在關聯式資料庫中通常表示為[關聯表](/orm/prisma-schema/data-model/relations/many-to-many-relations#relation-tables)。

Prisma ORM 支援兩種在 Prisma schema 中定義多對多關聯的方式：

- [隱式多對多關聯](/orm/prisma-schema/data-model/relations/many-to-many-relations#implicit-many-to-many-relations)（Prisma ORM 在背後管理關聯表）
- [顯式多對多關聯](/orm/prisma-schema/data-model/relations/many-to-many-relations#explicit-many-to-many-relations)（關聯表作為[模型](/orm/prisma-schema/data-model/models#defining-models)存在）

如果_隱式_多對多關聯遵守 Prisma ORM 的[關聯表慣例](/orm/prisma-schema/data-model/relations/many-to-many-relations#conventions-for-relation-tables-in-implicit-m-n-relations)，則會被識別。否則，關聯表會在 Prisma schema 中呈現為模型（因此使其成為_顯式_多對多關聯）。

此主題在關於[關聯](/orm/prisma-schema/data-model/relations)的文件頁面上有詳細介紹。

#### 消除關聯的歧義

如果不需要，Prisma ORM 通常會省略 [`@relation`](/orm/prisma-schema/data-model/relations#the-relation-attribute) 屬性上的 `name` 引數。考慮前一節中的 `User` ↔ `Post` 範例。`@relation` 屬性只有 `references` 引數，`name` 被省略了，因為在這種情況下不需要：

```prisma
model Post {
  id     Int  @id @default(autoincrement())
  author Int
  User   User @relation(fields: [author], references: [id])
}
```

如果在 `Post` 資料表上定義了_兩個_外鍵，則需要它：

```sql
CREATE TABLE "User" (
    id SERIAL PRIMARY KEY
);
CREATE TABLE "Post" (
    id SERIAL PRIMARY KEY,
    "author" integer NOT NULL,
    "favoritedBy" INTEGER,
    FOREIGN KEY ("author") REFERENCES "User"(id),
    FOREIGN KEY ("favoritedBy") REFERENCES "User"(id)
);
```

在這種情況下，Prisma ORM 需要使用專用的關聯名稱來[消除關聯的歧義](/orm/prisma-schema/data-model/relations#disambiguating-relations)：

```prisma
model Post {
  id                          Int   @id @default(autoincrement())
  author                      Int
  favoritedBy                 Int?
  User_Post_authorToUser      User  @relation("Post_authorToUser", fields: [author], references: [id])
  User_Post_favoritedByToUser User? @relation("Post_favoritedByToUser", fields: [favoritedBy], references: [id])
}

model User {
  id                          Int    @id @default(autoincrement())
  Post_Post_authorToUser      Post[] @relation("Post_authorToUser")
  Post_Post_favoritedByToUser Post[] @relation("Post_favoritedByToUser")
}
```

請注意，您可以將 [Prisma ORM 層級](/orm/prisma-schema/data-model/relations#relation-fields)的關聯欄位重新命名為您喜歡的任何名稱，以便在產生的 Prisma Client API 中看起來更友善。

## 使用現有結構描述的自我檢視

在關聯式資料庫中使用現有 Prisma Schema 執行 `prisma db pull` 會將對結構描述的手動變更與在資料庫中的變更合併。（此功能首次加入於版本 2.6.0。）對於 MongoDB，目前自我檢視僅用於初始資料模型的一次性作業。重複執行將導致自訂變更的遺失，如下面列出的那些。

關聯式資料庫的自我檢視會維護以下手動變更：

- `model` 區塊的順序
- `enum` 區塊的順序
- 註解
- `@map` 和 `@@map` 屬性
- `@updatedAt`
- `@default(cuid())`（`cuid()` 是 Prisma ORM 層級函式）
- `@default(uuid())`（`uuid()` 是 Prisma ORM 層級函式）
- 自訂 `@relation` 名稱

> **注意**：只有資料庫層級上模型之間的關聯才會被拾取。這意味著**必須設定外鍵**。

結構描述的以下屬性由資料庫決定：

- `model` 區塊內欄位的順序
- `enum` 區塊內值的順序

> **注意**：所有 `enum` 區塊都列在 `model` 區塊下方。

### 強制覆寫

若要覆寫手動變更，並僅基於自我檢視的資料庫產生結構描述並忽略任何現有的 Prisma Schema，請在 `db pull` 指令中加入 `--force` 旗標：

```terminal
npx prisma db pull --force
```

使用案例包括：

- 您想要從基於底層資料庫產生的結構描述重新開始
- 您有一個無效的結構描述，必須使用 `--force` 才能讓自我檢視成功

## 僅自我檢視資料庫結構描述的子集

Prisma ORM [尚未正式支援](https://github.com/prisma/prisma/issues/807)僅自我檢視資料庫結構描述的子集。

然而，您可以透過建立一個只能存取您想要在 Prisma schema 中表示的資料表的新資料庫使用者來實現此目的，然後使用該使用者執行自我檢視。自我檢視將只包含新使用者可以存取的資料表。

如果您的目標是從 [Prisma Client 產生](/orm/prisma-client/setup-and-configuration/generating-prisma-client)中排除某些模型，您可以在 Prisma schema 中的模型定義中加入 [`@@ignore` 屬性](/orm/reference/prisma-schema-reference#ignore-1)。被忽略的模型會從產生的 Prisma Client 中排除。

## 不支援功能的自我檢視警告

Prisma Schema Language (PSL) 可以表達 Prisma ORM 支援的[目標資料庫](/orm/reference/supported-databases)的大多數資料庫功能。然而，仍有一些功能和函式是 Prisma Schema Language 尚需表達的。

對於這些功能，Prisma CLI 會檢測您資料庫中功能的使用情況並返回警告。Prisma CLI 還會在 Prisma schema 中使用這些功能的模型和欄位中加入註解。警告還會包含因應措施建議。

`prisma db pull` 指令會顯示以下不支援的功能：

- 從版本 [4.13.0](https://github.com/prisma/prisma/releases/tag/4.13.0) 開始：
  - [分區資料表](https://github.com/prisma/prisma/issues/1708)
  - [PostgreSQL 列層級安全性](https://github.com/prisma/prisma/issues/12735)
  - [索引排序順序、`NULLS FIRST` / `NULLS LAST`](https://github.com/prisma/prisma/issues/15466)
  - [CockroachDB 列層級 TTL](https://github.com/prisma/prisma/issues/13982)
  - [註解](https://github.com/prisma/prisma/issues/8703)
  - [PostgreSQL 延遲約束](https://github.com/prisma/prisma/issues/8807)
- 從版本 [4.14.0](https://github.com/prisma/prisma/releases/tag/4.14.0) 開始：
  - [檢查約束](https://github.com/prisma/prisma/issues/3388)（MySQL + PostgreSQL）
  - [排除約束](https://github.com/prisma/prisma/issues/17514)
  - [MongoDB $jsonSchema](https://github.com/prisma/prisma/issues/8135)
- 從版本 [4.16.0](https://github.com/prisma/prisma/releases/tag/4.16.0) 開始：
  - [運算式索引](https://github.com/prisma/prisma/issues/2504)

您可以在 [GitHub（標記為 `topic:database-functionality`）](https://github.com/prisma/prisma/issues?q=is%3Aopen+label%3A%22topic%3A+database-functionality%22+label%3Ateam%2Fschema+sort%3Aupdated-desc+)上找到我們打算支援的功能清單。

### 不支援功能的自我檢視警告的因應措施

如果您使用的是關聯式資料庫並使用前一節中列出的上述功能之一：

1. 建立草稿遷移：
   ```terminal
   npx prisma migrate dev --create-only
   ```
2. 加入在警告中顯示的加入功能的 SQL。
3. 將草稿遷移套用到您的資料庫：
   ```terminal
   npx prisma migrate dev
   ```
