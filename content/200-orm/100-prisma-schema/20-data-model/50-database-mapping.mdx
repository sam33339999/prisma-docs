[Prisma schema](/orm/prisma-schema) 包含允許您定義某些資料庫物件名稱的機制。您可以：

- [將模型和欄位名稱映射到不同的集合/資料表和欄位/欄位名稱](#mapping-collectiontable-and-fieldcolumn-names)
- [定義約束和索引名稱](#constraint-and-index-names)

## 映射集合/資料表和欄位/欄位名稱

有時候，資料庫中用於描述實體的名稱可能不符合您在生成的 API 中偏好的名稱。在 Prisma schema 中映射名稱允許您影響 Client API 中的命名，而無需更改底層資料庫名稱。

例如，資料庫中命名資料表/集合的常見方法是使用複數形式和 [snake_case](https://en.wikipedia.org/wiki/Snake_case) 表示法。然而，我們建議使用不同的[命名慣例（單數形式，PascalCase）](/orm/reference/prisma-schema-reference#naming-conventions)。

`@map` 和 `@@map` 允許您通過將模型和欄位名稱與底層資料庫中的資料表和欄位名稱解耦，來[調整您的 Prisma Client API 的形式](/orm/prisma-client/setup-and-configuration/custom-model-and-field-names)。

### 映射集合/資料表名稱

例如，當您[內省](/orm/prisma-schema/introspection)一個包含名為 `comments` 的資料表的資料庫時，產生的 Prisma 模型將如下所示：

```prisma
model comments {
  // Fields
}
```

然而，您仍然可以選擇 `Comment` 作為模型的名稱（例如，遵循命名慣例），而無需在資料庫中重新命名底層的 `comments` 資料表，只需使用 [`@@map`](/orm/reference/prisma-schema-reference#map-1) 屬性：

```prisma highlight=4;normal
model Comment {
  // Fields

  //highlight-next-line
  @@map("comments")
}
```

透過這個修改過的模型定義，Prisma Client 會自動將 `Comment` 模型映射到底層資料庫中的 `comments` 資料表。

### 映射欄位/欄位名稱

您也可以 [`@map`](/orm/reference/prisma-schema-reference#map) 欄位/欄位名稱：

```prisma highlight=2-4;normal
model Comment {
  //highlight-start
  content String @map("comment_text")
  email   String @map("commenter_email")
  type    Enum   @map("comment_type")
  //highlight-end

  @@map("comments")
}
```

這樣，`comment_text` 欄位在 Prisma Client API 中無法透過 `prisma.comment.comment_text` 存取，但可以透過 `prisma.comment.content` 存取。

### 映射列舉名稱和值

您也可以 `@map` 列舉值，或 `@@map` 列舉：

```prisma highlight=3,5;normal
enum Type {
  Blog,
  //highlight-next-line
  Twitter @map("comment_twitter")

  //highlight-next-line
  @@map("comment_source_enum")
}
```

## 約束和索引名稱

您可以選擇性地使用 `map` 參數在 Prisma schema 中為屬性 [`@id`](/orm/reference/prisma-schema-reference#id)、[`@@id`](/orm/reference/prisma-schema-reference#id-1)、[`@unique`](/orm/reference/prisma-schema-reference#unique)、[`@@unique`](/orm/reference/prisma-schema-reference#unique-1)、[`@@index`](/orm/reference/prisma-schema-reference#index) 和 [`@relation`](/orm/reference/prisma-schema-reference#relation) 明確定義**底層約束和索引名稱**。（此功能在 Prisma ORM 版本 [2.29.0](https://github.com/prisma/prisma/releases/tag/2.29.0) 及更高版本中可用。）

當內省資料庫時，只有當名稱與 Prisma ORM 的[預設約束命名慣例](#prisma-orms-default-naming-conventions-for-indexes-and-constraints)_不同_時，`map` 參數才會在 schema 中_呈現_。

:::danger

如果您在 2.29.0 之前的版本中使用 Prisma Migrate，並希望在升級到較新版本後保持現有的約束和索引名稱，**請勿**立即執行 `prisma migrate` 或 `prisma db push`。這將**更改任何不遵循 Prisma ORM 慣例的底層約束名稱**。請遵循[允許您保持現有約束和索引名稱的升級路徑](/orm/more/upgrade-guides/upgrading-versions/upgrading-to-prisma-3/named-constraints#option-1-i-want-to-maintain-my-existing-constraint-and-index-names)。

:::

### 命名約束的使用情境

明確命名約束的一些使用情境包括：

- 公司政策
- 其他工具的慣例

### Prisma ORM 的預設索引和約束命名慣例

Prisma ORM 的命名慣例是為了與 PostgreSQL 保持一致，因為它是確定性的。這也有助於最大化不需要呈現名稱的次數，因為許多資料庫已經符合該慣例。

Prisma ORM 在生成預設索引和約束名稱時，始終使用實體的資料庫名稱。如果透過 `@@map` 或 `@map` 將模型重新映射到資料模型中的不同名稱，預設名稱生成仍將以資料庫中的_資料表_名稱作為輸入。欄位和_欄位_也是如此。

| 實體            | 慣例                        | 範例                        |
| ----------------- | --------------------------------- | ------------------------------ |
| 主鍵       | \{tablename}\_pkey                 | `User_pkey`                    |
| 唯一約束 | \{tablename}\_\{column_names}\_key  | `User_firstName_last_Name_key` |
| 非唯一索引  | \{tablename}\_\{column_names}\_idx  | `User_age_idx`                 |
| 外鍵       | \{tablename}\_\{column_names}\_fkey | `User_childName_fkey`          |

由於大多數資料庫對實體名稱有長度限制，如有必要，名稱將被修剪以不違反資料庫限制。我們將根據需要縮短 `_suffix` 之前的部分，以便完整名稱最多為允許的最大長度。

### 使用預設約束名稱

當沒有透過 `map` 參數提供明確名稱時，Prisma ORM 將遵循[預設命名慣例](#prisma-orms-default-naming-conventions-for-indexes-and-constraints)生成索引和約束名稱。

如果您內省資料庫，除非它們遵循 Prisma ORM 的命名慣例，否則索引和約束的名稱將被添加到您的 schema 中。如果它們遵循，名稱將不會呈現，以保持 schema 更具可讀性。當您遷移這樣的 schema 時，Prisma 將推斷預設名稱並將它們持久化到資料庫中。

#### 範例

以下 schema 定義了三個約束（`@id`、`@unique` 和 `@relation`）和一個索引（`@@index`）：

```prisma highlight=2,8,11,13;normal
model User {
  //highlight-next-line
  id    Int    @id @default(autoincrement())
  name  String @unique
  posts Post[]
}

model Post {
  //highlight-next-line
  id         Int    @id @default(autoincrement())
  title      String
  authorName String @default("Anonymous")
  //highlight-next-line
  author     User?  @relation(fields: [authorName], references: [name])

  //highlight-next-line
  @@index([title, authorName])
}
```

由於沒有透過 `map` 參數提供明確名稱，Prisma 將假設它們遵循我們的預設命名慣例。

下表列出了底層資料庫中每個約束和索引的名稱：
| 約束或索引 | 是否遵循慣例 | 底層約束或索引名稱 |
| ---------------------------------- | ------------------ | ------------------------------------ |
| `@id`（在 `User` > `id` 欄位上） | 是 | `User_pk` |
| `@@index`（在 `Post` 上） | 是 | `Post_title_authorName_idx` |
| `@id`（在 `Post` > `id` 欄位上） | 是 | `Post_pk` |
| `@relation`（在 `Post` > `author` 上） | 是 | `Post_authorName_fkey` |

### 使用自訂約束/索引名稱

您可以使用 `map` 參數在底層資料庫中定義**自訂約束和索引名稱**。

#### 範例

以下範例為一個 `@id` 和 `@@index` 添加了自訂名稱：

```prisma highlight=2,13;normal
model User {
  //highlight-next-line
  id    Int    @id(map: "Custom_Primary_Key_Constraint_Name") @default(autoincrement())
  name  String @unique
  posts Post[]
}

model Post {
  //highlight-next-line
  id         Int    @id @default(autoincrement())
  title      String
  authorName String @default("Anonymous")
  //highlight-next-line
  author     User?  @relation(fields: [authorName], references: [name])

  //highlight-next-line
  @@index([title, authorName], map: "My_Custom_Index_Name")
}
```

下表列出了底層資料庫中每個約束和索引的名稱：

| 約束或索引                | 是否遵循慣例 | 底層約束或索引名稱 |
| ---------------------------------- | ------------------ | ------------------------------------ |
| `@id`（在 `User` > `id` 欄位上）     | 否                 | `Custom_Primary_Key_Constraint_Name` |
| `@@index`（在 `Post` 上）              | 否                 | `My_Custom_Index_Name`               |
| `@id`（在 `Post` > `id` 欄位上）     | 是                | `Post_pk`                            |
| `@relation`（在 `Post` > `author` 上） | 是                | `Post_authorName_fkey`               |

### 相關：為 Prisma Client 命名索引和主鍵

除了 `map` 之外，`@@id` 和 `@@unique` 屬性還接受一個可選的 `name` 參數，允許您自訂 Prisma Client API。

在像這樣的模型上：

```prisma
model User {
  firstName String
  lastName  String

  @@id([firstName, lastName])
}
```

在該主鍵上選擇的預設 API 使用欄位的生成組合：

```ts
const user = await prisma.user.findUnique({
  where: {
    firstName_lastName: {
      firstName: 'Paul',
      lastName: 'Panther',
    },
  },
})
```

指定 `@@id([firstName, lastName], name: "fullName")` 將將 Prisma Client API 更改為：

```ts highlight=3;edit
const user = await prisma.user.findUnique({
  where: {
    //edit-next-line
    fullName: {
      firstName: 'Paul',
      lastName: 'Panther',
    },
  },
})
```
