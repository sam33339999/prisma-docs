<TopBlock>

並非 Prisma ORM 支援的資料庫的所有資料庫函式和功能都有 Prisma Schema Language 等效項。請參閱[資料庫功能矩陣](/orm/reference/database-features)以取得支援功能的完整清單。

</TopBlock>

## 原生資料庫函式

Prisma Schema Language 支援多個[函式](/orm/reference/prisma-schema-reference#attribute-functions)，您可以使用它們來設定欄位的預設值。以下範例使用 Prisma ORM 層級的 `uuid()` 函式來設定 `id` 欄位的值：

```prisma
model Post {
  id String @id @default(uuid())
}
```

然而，您也可以在關聯式資料庫上使用 [`dbgenerated(...)`](/orm/reference/prisma-schema-reference#dbgenerated) 來使用**原生資料庫函式**定義預設值（MongoDB 沒有資料庫層級函式的概念）。以下範例使用 PostgreSQL 的 `gen_random_uuid()` 函式來填充 `id` 欄位：

```prisma
model User {
  id String @id @default(dbgenerated("gen_random_uuid()")) @db.Uuid
}
```

### 何時使用資料庫層級函式

使用資料庫層級函式有兩個原因：

- 沒有等效的 Prisma ORM 函式（例如，PostgreSQL 中的 `gen_random_bytes`）。
- 您不能或不想依賴諸如 `uuid()` 和 `cuid()` 等函式，這些函式僅在 Prisma ORM 層級實作，不會在資料庫中呈現。

  考慮以下範例，它將 `id` 欄位設定為隨機產生的 `UUID`：

  ```prisma
  model Post {
    id String @id @default(uuid())
  }
  ```

  UUID _僅_在您使用 Prisma Client 建立 `Post` 時產生。如果您以任何其他方式建立貼文，例如以純 SQL 撰寫的批次匯入指令碼，則必須自己產生 UUID。

### 為原生資料庫函式啟用 PostgreSQL 擴充功能

在 PostgreSQL 中，某些原生資料庫函式是擴充功能的一部分。例如，在 PostgreSQL 版本 12.13 及更早版本中，`gen_random_uuid()` 函式是 [`pgcrypto`](https://www.postgresql.org/docs/10/pgcrypto.html) 擴充功能的一部分。

若要使用 PostgreSQL 擴充功能，您必須先將其安裝在資料庫伺服器的檔案系統上。

在 Prisma ORM 版本 4.5.0 及更高版本中，您可以透過在 Prisma schema 中使用 [`postgresqlExtensions` 預覽功能](/orm/prisma-schema/postgresql-extensions)來宣告它以啟用擴充功能：

```prisma file=schema.prisma highlight=3,9;add showLineNumbers
generator client {
  provider        = "prisma-client"
  output          = "./generated"
  //add-next-line
  previewFeatures = ["postgresqlExtensions"]
}

datasource db {
  provider   = "postgresql"
  //add-next-line
  extensions = [pgcrypto]
}
```
```

在較早版本的 Prisma ORM 中，您必須改為執行 SQL 指令來啟用擴充功能：

```sql
CREATE EXTENSION IF NOT EXISTS pgcrypto;
```

如果您的專案使用 [Prisma Migrate](/orm/prisma-migrate)，您必須[將擴充功能作為遷移的一部分安裝](/orm/prisma-migrate/workflows/native-database-functions)。請勿手動安裝擴充功能，因為影子資料庫也需要它。

如果擴充功能不可用，Prisma Migrate 會返回以下錯誤：

```
Migration `20210221102106_failed_migration` failed to apply cleanly to a temporary database.
Database error: Error querying the database: db error: ERROR: type "pgcrypto" does not exist
```

## 不支援的欄位類型

某些關聯式資料庫的資料庫類型（例如 `polygon` 或 `geometry`）沒有 Prisma Schema Language 等效項。使用 [`Unsupported`](/orm/reference/prisma-schema-reference#unsupported) 欄位類型在您的 Prisma schema 中表示該欄位：

```prisma highlight=3;normal
model Star {
  id       Int                    @id @default(autoincrement())
  //highlight-next-line
  position Unsupported("circle")? @default(dbgenerated("'<(10,4),11>'::circle"))
}
```

`prisma migrate dev` 和 `prisma db push` 指令都會在資料庫中建立類型為 `circle` 的 `position` 欄位。然而，該欄位將不會在產生的 Prisma Client 中可用。

## 不支援的資料庫功能

某些功能（如 SQL 視圖或部分索引）無法在 Prisma schema 中表示。如果您的專案使用 [Prisma Migrate](/orm/prisma-migrate)，您必須[將不支援的功能作為遷移的一部分包含在內](/orm/prisma-migrate/workflows/unsupported-database-features)。
