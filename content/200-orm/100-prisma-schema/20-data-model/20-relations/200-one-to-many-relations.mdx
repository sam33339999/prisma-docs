本頁介紹一對多關聯並說明如何在您的 Prisma schema 中使用它們。

<details>
<summary>本頁回答的問題</summary>

- 如何建模一對多關聯?
- 1-n 中哪一側持有外鍵?
- 可選與必需的 1-n 關聯如何運作?

</details>

## 概述

一對多 (1-n) 關聯是指關聯一側的一筆記錄可以連接到另一側的零筆或多筆記錄的關聯。在以下範例中,`User` 和 `Post` 模型之間有一個一對多關聯:

<TabbedContent code>
<TabItem value="Relational databases">

```prisma
model User {
  id    Int    @id @default(autoincrement())
  posts Post[]
}

model Post {
  id       Int  @id @default(autoincrement())
  author   User @relation(fields: [authorId], references: [id])
  authorId Int
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma
model User {
  id    String @id @default(auto()) @map("_id") @db.ObjectId
  posts Post[]
}

model Post {
  id       String @id @default(auto()) @map("_id") @db.ObjectId
  author   User   @relation(fields: [authorId], references: [id])
  authorId String @db.ObjectId
}
```

</TabItem>
</TabbedContent>

> **注意** `posts` 欄位不會在底層資料庫 schema 中「呈現」。在關聯的另一側,[標註的關聯欄位](/orm/prisma-schema/data-model/relations#relation-fields) `author` 及其關聯純量 `authorId` 代表在底層資料庫中儲存外鍵的關聯一側。

這個一對多關聯表達以下內容:

- 「一個使用者可以有零篇或多篇文章」
- 「一篇文章必須始終有一個作者」

在前面的範例中,`Post` 模型的 `author` 關聯欄位引用 `User` 模型的 `id` 欄位。您也可以引用不同的欄位。在這種情況下,您需要用 `@unique` 屬性標記該欄位,以保證每個 `Post` 只連接到單一的 `User`。在以下範例中,`author` 欄位引用 `User` 模型中的 `email` 欄位,該欄位用 `@unique` 屬性標記:

<TabbedContent code>
<TabItem value="Relational databases">

```prisma
model User {
  id    Int    @id @default(autoincrement())
  email String @unique // <-- add unique attribute
  posts Post[]
}

model Post {
  id          Int    @id @default(autoincrement())
  authorEmail String
  author      User   @relation(fields: [authorEmail], references: [email])
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma
model User {
  id    String @id @default(auto()) @map("_id") @db.ObjectId
  email String @unique // <-- add unique attribute
  posts Post[]
}

model Post {
  id          String @id @default(auto()) @map("_id") @db.ObjectId
  authorEmail String
  author      User   @relation(fields: [authorEmail], references: [email])
}
```

</TabItem>
</TabbedContent>

:::warning

在 MySQL 中,您可以只在引用側建立帶有索引的外鍵,而不需要唯一約束。在 Prisma ORM 4.0.0 及更高版本中,如果您內省此類型的關聯,將會觸發驗證錯誤。要修復此問題,您需要在引用的欄位上加入 `@unique` 約束。

:::

## 關聯式資料庫中的多欄位關聯

**僅在關聯式資料庫中**,您也可以使用[多欄位 ID](/orm/reference/prisma-schema-reference#id-1)/複合鍵來定義此關聯:

```prisma
model User {
  firstName String
  lastName  String
  post      Post[]

  @@id([firstName, lastName])
}

model Post {
  id              Int    @id @default(autoincrement())
  author          User   @relation(fields: [authorFirstName, authorLastName], references: [firstName, lastName])
  authorFirstName String // relation scalar field (used in the `@relation` attribute above)
  authorLastName  String // relation scalar field (used in the `@relation` attribute above)
}
```

## 資料庫中的 1-n 關聯

### 關聯式資料庫

以下範例示範如何在 SQL 中建立 1-n 關聯:

```sql
CREATE TABLE "User" (
    id SERIAL PRIMARY KEY
);
CREATE TABLE "Post" (
    id SERIAL PRIMARY KEY,
    "authorId" integer NOT NULL,
    FOREIGN KEY ("authorId") REFERENCES "User"(id)
);
```

由於 `authorId` 欄位(外鍵)上沒有 `UNIQUE` 約束,您可以建立**多筆指向相同 `User` 記錄的 `Post` 記錄**。這使得關聯成為一對多而不是一對一。

以下範例示範如何使用複合鍵(`firstName` 和 `lastName`)在 SQL 中建立 1-n 關聯:

```sql
CREATE TABLE "User" (
    firstName TEXT,
    lastName TEXT,
    PRIMARY KEY ("firstName","lastName")
);
CREATE TABLE "Post" (
    id SERIAL PRIMARY KEY,
    "authorFirstName" TEXT NOT NULL,
    "authorLastName" TEXT NOT NULL,
    FOREIGN KEY ("authorFirstName", "authorLastName") REFERENCES "User"("firstName", "lastName")
);
```

#### 比較一對一和一對多關聯

在關聯式資料庫中,1-1 和 1-n 關聯之間的主要區別在於,在 1-1 關聯中,外鍵必須定義 `UNIQUE` 約束。

### MongoDB

對於 MongoDB,Prisma ORM 目前使用[正規化資料模型設計](https://www.mongodb.com/docs/manual/data-modeling/),這意味著文件以類似於關聯式資料庫的方式透過 ID 相互引用。

以下 MongoDB 文件代表一個 `User`:

```json
{ "_id": { "$oid": "60d5922d00581b8f0062e3a8" }, "name": "Ella" }
```

以下每個 `Post` MongoDB 文件都有一個 `authorId` 欄位,引用相同的使用者:

```json
[
  {
    "_id": { "$oid": "60d5922e00581b8f0062e3a9" },
    "title": "How to make sushi",
    "authorId": { "$oid": "60d5922d00581b8f0062e3a8" }
  },
  {
    "_id": { "$oid": "60d5922e00581b8f0062e3aa" },
    "title": "How to re-install Windows",
    "authorId": { "$oid": "60d5922d00581b8f0062e3a8" }
  }
]
```

#### 比較一對一和一對多關聯

在 MongoDB 中,1-1 和 1-n 之間的唯一區別是資料庫中引用另一個文件的文件數量 - 沒有約束。

## 一對多關聯中的必需和可選關聯欄位

1-n 關聯總是有兩個關聯欄位:

- 一個[列表](/orm/prisma-schema/data-model/models#type-modifiers)關聯欄位,_未_用 `@relation` 標註
- [標註的關聯欄位](/orm/prisma-schema/data-model/relations#annotated-relation-fields)(包括其關聯純量)

1-n 關聯的標註關聯欄位和關聯純量可以_都_是可選的,或_都_是必需的。在關聯的另一側,列表**總是必需的**。

### 可選的一對多關聯

在以下範例中,您可以在不指派 `User` 的情況下建立 `Post`:

<TabbedContent code>
<TabItem value="Relational databases">

```prisma
model User {
  id    Int    @id @default(autoincrement())
  posts Post[]
}

model Post {
  id       Int   @id @default(autoincrement())
  author   User? @relation(fields: [authorId], references: [id])
  authorId Int?
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma
model User {
  id    String @id @default(auto()) @map("_id") @db.ObjectId
  posts Post[]
}

model Post {
  id       String  @id @default(auto()) @map("_id") @db.ObjectId
  author   User?   @relation(fields: [authorId], references: [id])
  authorId String? @db.ObjectId
}
```

</TabItem>
</TabbedContent>

### 必需的一對多關聯

在以下範例中,建立 `Post` 時必須指派 `User`:

  authorId Int
