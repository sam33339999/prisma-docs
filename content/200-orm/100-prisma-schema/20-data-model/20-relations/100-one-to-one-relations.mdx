## 概述

一對一 (1-1) 關聯是指在關聯的兩側最多只能連接**一筆**記錄的關聯。在下面的範例中,`User` 和 `Profile` 之間存在一對一關聯:

<TabbedContent code>
<TabItem value="Relational databases">

```prisma
model User {
  id      Int      @id @default(autoincrement())
  profile Profile?
}

model Profile {
  id     Int  @id @default(autoincrement())
  user   User @relation(fields: [userId], references: [id])
  userId Int  @unique // relation scalar field (used in the `@relation` attribute above)
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma
model User {
  id      String   @id @default(auto()) @map("_id") @db.ObjectId
  profile Profile?
}

model Profile {
  id     String @id @default(auto()) @map("_id") @db.ObjectId
  user   User   @relation(fields: [userId], references: [id])
  userId String @unique @db.ObjectId // relation scalar field (used in the `@relation` attribute above)
}
```

</TabItem>
</TabbedContent>

`userId` 關聯純量是底層資料庫中外鍵的直接表示。這個一對一關聯表達以下內容:

- 「一個使用者可以有零個或一個個人資料」(因為 `User` 上的 `profile` 欄位是[可選的](/orm/prisma-schema/data-model/models#type-modifiers))
- 「一個個人資料必須始終連接到一個使用者」

在前面的範例中,`Profile` 模型的 `user` 關聯欄位引用 `User` 模型的 `id` 欄位。您也可以引用不同的欄位。在這種情況下,您需要用 `@unique` 屬性標記該欄位,以保證每個 `Profile` 只連接到單一的 `User`。在以下範例中,`user` 欄位引用 `User` 模型中的 `email` 欄位,該欄位用 `@unique` 屬性標記:

<TabbedContent code>
<TabItem value="Relational databases">

```prisma
model User {
  id      Int      @id @default(autoincrement())
  email   String   @unique // <-- add unique attribute
  profile Profile?
}

model Profile {
  id        Int    @id @default(autoincrement())
  user      User   @relation(fields: [userEmail], references: [email])
  userEmail String @unique // relation scalar field (used in the `@relation` attribute above)
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma
model User {
  id      String   @id @default(auto()) @map("_id") @db.ObjectId
  email   String   @unique // <-- add unique attribute
  profile Profile?
}

model Profile {
  id        String @id @default(auto()) @map("_id") @db.ObjectId
  user      User   @relation(fields: [userEmail], references: [email])
  userEmail String @unique @db.ObjectId // relation scalar field (used in the `@relation` attribute above)
}
```

</TabItem>
</TabbedContent>

:::warning

在 MySQL 中,您可以只在引用側建立帶有索引的外鍵,而不需要唯一約束。在 Prisma ORM 4.0.0 及更高版本中,如果您內省此類型的關聯,將會觸發驗證錯誤。要修復此問題,您需要在引用的欄位上加入 `@unique` 約束。

:::

## 關聯式資料庫中的多欄位關聯

**僅在關聯式資料庫中**,您也可以使用[多欄位 ID](/orm/reference/prisma-schema-reference#id-1) 來定義 1-1 關聯:

```prisma
model User {
  firstName String
  lastName  String
  profile   Profile?

  @@id([firstName, lastName])
}

model Profile {
  id            Int    @id @default(autoincrement())
  user          User   @relation(fields: [userFirstName, userLastName], references: [firstName, lastName])
  userFirstName String // relation scalar field (used in the `@relation` attribute above)
  userLastName  String // relation scalar field (used in the `@relation` attribute above)

  @@unique([userFirstName, userLastName])
}
```

## 資料庫中的 1-1 關聯

### 關聯式資料庫

以下範例示範如何在 SQL 中建立 1-1 關聯:

```sql
CREATE TABLE "User" (
    id SERIAL PRIMARY KEY
);
CREATE TABLE "Profile" (
    id SERIAL PRIMARY KEY,
    "userId" INTEGER NOT NULL UNIQUE,
    FOREIGN KEY ("userId") REFERENCES "User"(id)
);
```

請注意,外鍵 `userId` 上有一個 `UNIQUE` 約束。如果缺少此 `UNIQUE` 約束,該關聯將被視為 [1-n 關聯](/orm/prisma-schema/data-model/relations/one-to-many-relations)。

以下範例示範如何使用複合鍵(`firstName` 和 `lastName`)在 SQL 中建立 1-1 關聯:

```sql
CREATE TABLE "User" (
    firstName TEXT,
    lastName TEXT,
    PRIMARY KEY ("firstName","lastName")
);
CREATE TABLE "Profile" (
    id SERIAL PRIMARY KEY,
    "userFirstName" TEXT NOT NULL,
    "userLastName" TEXT NOT NULL,
    UNIQUE ("userFirstName", "userLastName")
    FOREIGN KEY ("userFirstName", "userLastName") REFERENCES "User"("firstName", "lastName")
);
```

### MongoDB

對於 MongoDB,Prisma ORM 目前使用[正規化資料模型設計](https://www.mongodb.com/docs/manual/data-modeling/),這意味著文件以類似於關聯式資料庫的方式透過 ID 相互引用。

以下 MongoDB 文件代表一個 `User`:

```json
{ "_id": { "$oid": "60d58e130011041800d209e1" }, "name": "Bob" }
```

以下 MongoDB 文件代表一個 `Profile` - 注意 `userId` 欄位,它引用 `User` 文件的 `$oid`:

```json
{
  "_id": { "$oid": "60d58e140011041800d209e2" },
  "bio": "I'm Bob, and I like drawing.",
  "userId": { "$oid": "60d58e130011041800d209e1" }
}
```

## 必需和可選的 1-1 關聯欄位

在一對一關聯中,_沒有_關聯純量(代表資料庫中外鍵的欄位)的關聯一側_必須_是可選的:

```prisma highlight=3;normal
model User {
  id      Int      @id @default(autoincrement())
  //highlight-next-line
  profile Profile? // 沒有關聯純量 - 必須是可選的
}
```

此限制是在 2.12.0 中引入的。

但是,您可以選擇_具有_關聯純量的關聯一側應該是可選的還是必需的。

### 必需的 1-1 關聯

在以下範例中,`profile` 和 `profileId` 是必需的。這意味著您無法在不連接或建立 `Profile` 的情況下建立 `User`:

```prisma
model User {
  id        Int     @id @default(autoincrement())
  profile   Profile @relation(fields: [profileId], references: [id]) // references `id` of `Profile`
  profileId Int     @unique // relation scalar field (used in the `@relation` attribute above)
}

model Profile {
  id   Int   @id @default(autoincrement())
  user User?
}
```

### 可選的 1-1 關聯

在以下範例中,`profile` 和 `profileId` 是可選的。這意味著您可以在不連接或建立 `Profile` 的情況下建立使用者:

```prisma
model User {
  id        Int      @id @default(autoincrement())
  profile   Profile? @relation(fields: [profileId], references: [id]) // references `id` of `Profile`
  profileId Int?     @unique // relation scalar field (used in the `@relation` attribute above)
}

model Profile {
  id   Int   @id @default(autoincrement())
  user User?
}
```

## 選擇在 1-1 關聯中哪一側應該儲存外鍵

在 **1-1 關聯**中,您可以自己決定要用 `@relation` 屬性標註關聯的哪一側(因此持有外鍵)。

在以下範例中,`Profile` 模型上的關聯欄位用 `@relation` 屬性標註。`userId` 是底層資料庫中外鍵的直接表示:

<TabbedContent code>
<TabItem value="Relational databases">

```prisma
model User {
  id      Int      @id @default(autoincrement())
  profile Profile?
}

model Profile {
  id     Int  @id @default(autoincrement())
  user   User @relation(fields: [userId], references: [id])
  userId Int  @unique // relation scalar field (used in the `@relation` attribute above)
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma
model User {
  id      String   @id @default(auto()) @map("_id") @db.ObjectId
  profile Profile?
}

model Profile {
  id     String @id @default(auto()) @map("_id") @db.ObjectId
  user   User   @relation(fields: [userId], references: [id])
  userId String @unique @db.ObjectId
}
```

</TabItem>
</TabbedContent>

您也可以用 `@relation` 屬性標註關聯的另一側。以下範例標註 `User` 模型上的關聯欄位。`profileId` 是底層資料庫中外鍵的直接表示:

<TabbedContent code>
<TabItem value="Relational databases">

```prisma
model User {
  id        Int      @id @default(autoincrement())
  profile   Profile? @relation(fields: [profileId], references: [id])
  profileId Int?     @unique // relation scalar field (used in the `@relation` attribute above)
}

model Profile {
  id   Int   @id @default(autoincrement())
  user User?
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma
model User {
  id        String   @id @default(auto()) @map("_id") @db.ObjectId
  profile   Profile? @relation(fields: [profileId], references: [id])
  profileId String?  @unique @db.ObjectId // relation scalar field (used in the `@relation` attribute above)
}

model Profile {
  id   String @id @default(auto()) @map("_id") @db.ObjectId
  user User?
}
```

</TabItem>
