在 Prisma schema 中，記錄之間的關聯使用 [`@relation`](/orm/reference/prisma-schema-reference#relation) 屬性來定義。例如，在以下 schema 中，`User` 和 `Post` model 之間有一個一對多關聯：

```prisma file=schema.prisma highlight=4,5,10;normal showLineNumbers
model Post {
  id       Int    @id @default(autoincrement())
  title    String
  //highlight-start
  author   User   @relation(fields: [authorId], references: [id], onDelete: Cascade, onUpdate: Cascade)
  authorId Int
  //highlight-end
}

model User {
  id    Int    @id @default(autoincrement())
  //highlight-next-line
  posts Post[]
}
```

Prisma ORM 有兩種_關聯模式_，`foreignKeys` 和 `prisma`，用於指定如何強制執行記錄之間的關聯。

如果您使用 Prisma ORM 與關聯式資料庫，則預設情況下 Prisma ORM 使用 [`foreignKeys` 關聯模式](#handle-relations-in-your-relational-database-with-the-foreignkeys-relation-mode)，它在資料庫層級使用外鍵強制執行記錄之間的關聯。外鍵是一個資料表中的欄位或欄位組，它根據另一個資料表中的主鍵取值。外鍵允許您：

- 設定約束以防止您進行會破壞引用的更改
- 設定[參照動作](/orm/prisma-schema/data-model/relations/referential-actions)，定義如何處理對記錄的更改

這些約束和參照動作共同保證了資料的_參照完整性_。

對於上述範例 schema，如果您使用 PostgreSQL 連接器，Prisma Migrate 預設將生成以下 SQL：

```sql highlight=19-22;normal

-- CreateTable
CREATE TABLE "Post" (
    "id" SERIAL NOT NULL,
    "title" TEXT NOT NULL,
    "authorId" INTEGER NOT NULL,

    CONSTRAINT "Post_pkey" PRIMARY KEY ("id")
);

-- CreateTable
CREATE TABLE "User" (
    "id" SERIAL NOT NULL,

    CONSTRAINT "User_pkey" PRIMARY KEY ("id")
);

-- AddForeignKey
//highlight-start
ALTER TABLE "Post"
  ADD CONSTRAINT "Post_authorId_fkey"
  FOREIGN KEY ("authorId")
  REFERENCES "User"("id") ON DELETE CASCADE ON UPDATE CASCADE;
//highlight-end
```

在這種情況下，`Post` 資料表的 `authorId` 欄位上的外鍵約束引用 `User` 資料表的 `id` 欄位，並保證文章必須有一個存在的作者。如果您更新或刪除使用者，`ON DELETE` 和 `ON UPDATE` 參照動作指定 `CASCADE` 選項，這也會刪除或更新屬於該使用者的所有文章。

一些資料庫，例如 MongoDB 或 [PlanetScale](/orm/overview/databases/planetscale#differences-to-consider)，不支援外鍵。此外，在某些情況下，開發人員可能更願意不在通常支援外鍵的關聯式資料庫中使用外鍵。對於這些情況，Prisma ORM 提供了[`prisma` 關聯模式](#emulate-relations-in-prisma-orm-with-the-prisma-relation-mode)，它模擬關聯式資料庫中關聯的某些屬性。當您使用啟用 `prisma` 關聯模式的 Prisma Client 時，查詢的行為是相同或相似的，但參照動作和某些約束由 Prisma 引擎處理，而不是在資料庫中處理。

:::warning
  在 Prisma Client 中模擬參照完整性和參照動作會影響效能。在底層資料庫支援外鍵的情況下，通常是首選。
:::

## 如何在 Prisma schema 中設定關聯模式

要設定關聯模式，請在 `datasource` 區塊中新增 `relationMode` 欄位：

```prisma file=schema.prisma highlight=4,9;add showLineNumbers
datasource db {
  provider     = "mysql"
  //add-next-line
  relationMode = "prisma"
}
```

:::info

設定關聯模式的功能是在 Prisma ORM 3.1.1 版中作為 `referentialIntegrity` 預覽功能的一部分引入的，並在 Prisma ORM 4.8.0 及更高版本中正式可用。<br /><br />`relationMode` 欄位在 Prisma ORM 4.5.0 版中重新命名，以前稱為 `referentialIntegrity`。

:::

對於關聯式資料庫，可用的選項有：

- `foreignKeys`：這使用外鍵在資料庫中處理關聯。這是所有關聯式資料庫連接器的預設選項，如果 `datasource` 區塊中沒有明確設定 `relationMode`，則此選項為活動狀態。
- `prisma`：這在 Prisma Client 中模擬關聯。當您使用 MySQL 連接器與 PlanetScale 資料庫並且未在 PlanetScale 資料庫設定中啟用原生外鍵約束時，您也應該[啟用此選項](/orm/overview/databases/planetscale#option-1-emulate-relations-in-prisma-client)。

對於 MongoDB，唯一可用的選項是 `prisma` 關聯模式。如果 `datasource` 區塊中沒有明確設定 `relationMode`，則此模式也是活動的。

:::warning

如果您在關聯模式之間切換，下次使用 Prisma Migrate 或 `db push` 將更改應用到 schema 時，Prisma ORM 將向資料庫新增或移除外鍵。有關更多資訊，請參閱[在關聯模式之間切換](#switch-between-relation-modes)。

:::

## 使用 `foreignKeys` 關聯模式在關聯式資料庫中處理關聯

`foreignKeys` 關聯模式使用外鍵在關聯式資料庫中處理關聯。當您使用關聯式資料庫連接器（PostgreSQL、MySQL、SQLite、SQL Server、CockroachDB）時，這是預設選項。

當您使用 MongoDB 連接器時，`foreignKeys` 關聯模式不可用。一些關聯式資料庫，[例如 PlanetScale](/orm/overview/databases/planetscale#option-1-emulate-relations-in-prisma-client)，也禁止使用外鍵。在這些情況下，您應該改為[在 Prisma ORM 中使用 `prisma` 關聯模式模擬關聯](#emulate-relations-in-prisma-orm-with-the-prisma-relation-mode)。

### 參照完整性

`foreignKeys` 關聯模式使用外鍵約束和參照動作在資料庫層級維護參照完整性。

#### 外鍵約束

當您_建立_或_更新_與另一筆記錄有關聯的記錄時，相關記錄需要存在。外鍵約束在資料庫中強制執行此行為。如果記錄不存在，資料庫將返回錯誤訊息。

#### 參照動作

當您_更新_或_刪除_與另一筆記錄有關聯的記錄時，參照動作會在資料庫中觸發。為了在相關記錄中維護參照完整性，參照動作會防止會破壞參照完整性的更改、將更改級聯到相關記錄，或將引用已更新或刪除記錄的欄位值設為 `null` 或預設值。

有關更多資訊，請參閱[參照動作](/orm/prisma-schema/data-model/relations/referential-actions)頁面。

### 內省

當您使用啟用 `foreignKeys` 關聯模式的 `db pull` 命令內省關聯式資料庫時，會為存在外鍵的關聯向您的 Prisma schema 新增 `@relation` 屬性。

### Prisma Migrate 和 `db push`

當您使用啟用 `foreignKeys` 關聯模式的 Prisma Migrate 或 `db push` 將更改應用到 Prisma schema 時，將為 schema 中的所有 `@relation` 屬性在資料庫中建立外鍵。

## 在 Prisma ORM 中使用 `prisma` 關聯模式模擬關聯

`prisma` 關聯模式為每個 Prisma Client 查詢模擬一些外鍵約束和參照動作，以維護參照完整性，使用一些額外的資料庫查詢和邏輯。

`prisma` 關聯模式是 MongoDB 連接器的預設選項。如果您使用不支援外鍵的關聯式資料庫，也應該設定它。例如，[如果您使用 PlanetScale](/orm/overview/databases/planetscale#option-1-emulate-relations-in-prisma-client) 而沒有外鍵約束，您應該使用 `prisma` 關聯模式。

:::warning
  在 Prisma Client 中模擬參照完整性會影響效能，因為它使用額外的資料庫查詢來維護參照完整性。在底層資料庫可以使用外鍵處理參照完整性的情況下，通常是首選。
:::

關聯的模擬僅適用於 Prisma Client 查詢，不適用於原始查詢。

### 模擬了哪些外鍵約束？

當您_更新_記錄時，Prisma ORM 將模擬外鍵約束。這意味著當您更新與另一筆記錄有關聯的記錄時，相關記錄需要存在。如果記錄不存在，Prisma Client 將返回錯誤訊息。

但是，當您_建立_記錄時，Prisma ORM 不會模擬任何外鍵約束。您將能夠建立無效資料。

### 模擬了哪些參照動作？

當您_更新_或_刪除_具有相關記錄的記錄時，Prisma ORM 將模擬參照動作。

下表顯示了每個資料庫連接器可用的模擬參照動作：

| 資料庫      | Cascade | Restrict | NoAction | SetNull | SetDefault |
| :---------- | :------ | :------- | :------- | :------ | :--------- |
| PostgreSQL  | **✔️**  | **✔️**   | **❌**‡  | **✔️**  | **❌**†    |
| MySQL       | **✔️**  | **✔️**   | **✔️**   | **✔️**  | **❌**†    |
| SQLite      | **✔️**  | **✔️**   | **❌**‡  | **✔️**  | **❌**†    |
| SQL Server  | **✔️**  | **✔️**   | **✔️**   | **✔️**  | **❌**†    |
| CockroachDB | **✔️**  | **✔️**   | **✔️**   | **✔️**  | **❌**†    |
| MongoDB     | **✔️**  | **✔️**   | **✔️**   | **✔️**  | **❌**†    |

- † `prisma` 關聯模式不支援 `SetDefault` 參照動作。
- ‡ `prisma` 關聯模式不支援 PostgreSQL 和 SQLite 的 `NoAction` 參照動作。請改用 `Restrict` 動作。

### 錯誤訊息

`prisma` 關聯模式中模擬的約束和參照動作返回的錯誤訊息由 Prisma Client 生成，與 `foreignKeys` 關聯模式中的錯誤訊息略有不同：

```jsx
範例：
// foreignKeys:
... Foreign key constraint failed on the field: `ProfileOneToOne_userId_fkey (index)`
// prisma:
... The change you are trying to make would violate the required relation 'ProfileOneToOneToUserOneToOne' between the `ProfileOneToOne` and `UserOneToOne` models.
```

### 內省

當您使用啟用 `prisma` 關聯模式的 `db pull` 命令內省資料庫時，關聯不會自動新增到您的 schema。您需要使用 `@relation` 屬性手動新增任何關聯。這只需要做一次 - 下次內省資料庫時，Prisma ORM 將保留您新增的 `@relation` 屬性。

### Prisma Migrate 和 `db push`

當您使用啟用 `prisma` 關聯模式的 Prisma Migrate 或 `db push` 將更改應用到 Prisma schema 時，Prisma ORM 不會在資料庫中使用外鍵。

### 索引

在使用外鍵約束的關聯式資料庫中，資料庫通常也會隱式地為外鍵欄位建立索引。例如，[MySQL 將在所有外鍵欄位上建立索引](https://dev.mysql.com/doc/refman/8.0/en/constraint-foreign-key.html#:~:text=MySQL%20需要%20that%20foreign%20key%20columns%20be%20indexed%3B%20if%20you%20create%20a%20table%20with%20a%20foreign%20key%20constraint%20but%20no%20index%20on%20a%20given%20column%2C%20an%20index%20is%20created.)。這是為了允許外鍵檢查快速運行，而不需要資料表掃描。

`prisma` 關聯模式不使用外鍵，因此當您使用 Prisma Migrate 或 `db push` 將更改應用到資料庫時不會建立索引。您需要使用 [`@@index`](/orm/reference/prisma-schema-reference#index) 屬性（或 [`@unique`](/orm/reference/prisma-schema-reference#unique)、[`@@unique`](/orm/reference/prisma-schema-reference#unique-1) 或 [`@@id`](/orm/reference/prisma-schema-reference#id-1) 屬性，如果適用）手動在關聯純量欄位上新增索引。

#### 索引驗證

如果您不手動新增索引，查詢可能需要完整的資料表掃描。這可能很慢，並且在按存取的行計費的資料庫提供商上也很昂貴。為了幫助避免這種情況，當您的 schema 包含在 `@relation` 中使用但沒有定義索引的欄位時，Prisma ORM 會警告您。例如，考慮以下在 `User` 和 `Post` model 之間具有關聯的 schema：

```prisma file=schema.prisma showLineNumbers
datasource db {
  provider     = "mysql"
  relationMode = "prisma"
}

model User {
  id    Int    @id
  posts Post[]
}

model Post {
  id     Int  @id
  userId Int
  user   User @relation(fields: [userId], references: [id])
}
```

當您執行 `prisma format` 或 `prisma validate` 時，Prisma ORM 會顯示以下警告：

```terminal wrap
With `relationMode = "prisma"`, no foreign keys are used, so relation fields will not benefit from the index usually created by the relational database under the hood. This can lead to poor performance when querying these fields. We recommend adding an index manually.
```

要修復此問題，請向您的 `Post` model 新增索引：

```prisma file=schema.prisma highlight=6;add showLineNumbers
model Post {
  id     Int  @id
  userId Int
  user   User @relation(fields: [userId], references: [id])

  //add-next-line
  @@index([userId])
}
```

如果您使用 [Prisma VS Code 擴充功能](https://marketplace.visualstudio.com/items?itemName=Prisma.prisma)（或在[另一個編輯器中使用我們的語言伺服器](/orm/more/development-environment/editor-setup)），警告會附帶一個快速修復，可為您新增所需的索引：

## 在關聯模式之間切換

只有當您使用關聯式資料庫連接器（PostgreSQL、MySQL、SQLite、SQL Server、CockroachDB）時，才能在關聯模式之間切換。

### 從 `foreignKeys` 切換到 `prisma`

如果您使用關聯式資料庫並且不在 `datasource` 區塊中包含 `relationMode` 欄位，預設的關聯模式是 `foreignKeys`。要切換到 `prisma` 關聯模式，請新增值為 `prisma` 的 `relationMode` 欄位，或者如果它已經存在，請將 `relationMode` 欄位值更新為 `prisma`。

當您將關聯模式從 `foreignKeys` 切換到 `prisma` 時，首次使用 Prisma Migrate 或 `db push` 將更改應用到 schema 後，Prisma ORM 將在下一次遷移中移除所有先前建立的外鍵。

如果您保留相同的資料庫，您可以繼續正常工作。如果您切換到完全不支援外鍵的資料庫，您現有的遷移歷史記錄包含建立外鍵的 SQL DDL，如果您需要重新運行這些遷移，可能會觸發錯誤。在這種情況下，我們建議您刪除 `migrations` 目錄。（如果您使用不支援外鍵的 PlanetScale，我們通常建議您[使用 `db push` 而不是 Prisma Migrate](/orm/overview/databases/planetscale#differences-to-consider)。）

### 從 `prisma` 切換到 `foreignKeys`

要從 `prisma` 關聯模式切換到 `foreignKeys` 關聯模式，請將 `relationMode` 欄位值從 `prisma` 更新為 `foreignKeys`。要執行此操作，資料庫必須支援外鍵。首次在切換關聯模式後使用 Prisma Migrate 或 `db push` 將更改應用到 schema 時，Prisma ORM 將在下一次遷移中為所有關聯建立外鍵。
