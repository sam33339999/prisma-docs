<TopBlock>

關聯是 Prisma schema 中兩個模型之間的_連接_。例如,`User` 和 `Post` 之間存在一對多關聯,因為一個使用者可以擁有多篇部落格文章。

以下 Prisma schema 定義了 `User` 和 `Post` 模型之間的一對多關聯。參與定義關聯的欄位已被標示:

<TabbedContent code>
<TabItem value="Relational databases">

```prisma highlight=3,8,9;normal
model User {
  id    Int    @id @default(autoincrement())
  //highlight-next-line
  posts Post[]
}

model Post {
  id       Int  @id @default(autoincrement())
  //highlight-start
  author   User @relation(fields: [authorId], references: [id])
  authorId Int // relation scalar field  (used in the `@relation` attribute above)
  //highlight-end

  title String
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma highlight=3,8,9;normal
model User {
  id    String @id @default(auto()) @map("_id") @db.ObjectId
  //highlight-next-line
  posts Post[]
}

model Post {
  id       String @id @default(auto()) @map("_id") @db.ObjectId
  //highlight-start
  author   User   @relation(fields: [authorId], references: [id])
  authorId String @db.ObjectId // relation scalar field  (used in the `@relation` attribute above)
  //highlight-end

  title String
}
```

</TabItem>
</TabbedContent>

在 Prisma ORM 層級,`User` / `Post` 關聯由以下組成:

- 兩個[關聯欄位](#relation-fields):`author` 和 `posts`。關聯欄位在 Prisma ORM 層級定義模型之間的連接,並**不存在於資料庫中**。這些欄位用於生成 Prisma Client。
- 純量 `authorId` 欄位,由 `@relation` 屬性引用。此欄位**確實存在於資料庫中** - 它是連接 `Post` 和 `User` 的外鍵。

在 Prisma ORM 層級,兩個模型之間的連接**總是**由關聯的**每一側**的[關聯欄位](#relation-fields)表示。

## 資料庫中的關聯

### 關聯式資料庫

以下實體關聯圖定義了**關聯式資料庫**中 `User` 和 `Post` 資料表之間相同的一對多關聯:

![A one-to-many relationship between a user and posts table.](./one-to-many.png)

在 SQL 中,您使用_外鍵_在兩個資料表之間建立關聯。外鍵儲存在關聯的**一側**。我們的範例由以下組成:

- `Post` 資料表中名為 `authorId` 的外鍵欄位。
- `User` 資料表中名為 `id` 的主鍵欄位。`Post` 資料表中的 `authorId` 欄位引用 `User` 資料表中的 `id` 欄位。

在 Prisma schema 中,外鍵/主鍵關係由 `author` 欄位上的 `@relation` 屬性表示:

```prisma
author     User        @relation(fields: [authorId], references: [id])
```

> **注意**: Prisma schema 中的關聯代表資料庫中資料表之間存在的關係。如果資料庫中不存在該關係,則 Prisma schema 中也不存在。

### MongoDB

對於 MongoDB,Prisma ORM 目前使用[正規化資料模型設計](https://www.mongodb.com/docs/manual/data-modeling/),這意味著文件以類似於關聯式資料庫的方式透過 ID 相互引用。

以下文件代表一個 `User`(在 `User` 集合中):

```json
{ "_id": { "$oid": "60d5922d00581b8f0062e3a8" }, "name": "Ella" }
```

以下 `Post` 文件清單(在 `Post` 集合中)每個都有一個 `authorId` 欄位,引用相同的使用者:

```json
[
  {
    "_id": { "$oid": "60d5922e00581b8f0062e3a9" },
    "title": "How to make sushi",
    "authorId": { "$oid": "60d5922d00581b8f0062e3a8" }
  },
  {
    "_id": { "$oid": "60d5922e00581b8f0062e3aa" },
    "title": "How to re-install Windows",
    "authorId": { "$oid": "60d5922d00581b8f0062e3a8" }
  }
]
```

此資料結構代表一對多關聯,因為多個 `Post` 文件引用相同的 `User` 文件。

#### ID 和關聯純量欄位上的 `@db.ObjectId`

如果您的模型 ID 是 `ObjectId`(由 `String` 欄位表示),您必須將 `@db.ObjectId` 加到模型的 ID _和_關聯另一側的關聯純量欄位:

```prisma highlight=3,9;normal
model User {
  id    String @id @default(auto()) @map("_id") @db.ObjectId
  //highlight-next-line
  posts Post[]
}

model Post {
  id       String @id @default(auto()) @map("_id") @db.ObjectId
  author   User   @relation(fields: [authorId], references: [id])
  //highlight-next-line
  authorId String @db.ObjectId // relation scalar field  (used in the `@relation` attribute above)

  title String
}
```

## Prisma Client 中的關聯

Prisma Client 從 Prisma schema 生成。以下範例示範當您使用 Prisma Client 來取得、建立和更新記錄時,關聯如何呈現。

### 建立一筆記錄和巢狀記錄

以下查詢建立一筆 `User` 記錄和兩筆連接的 `Post` 記錄:

```ts
const userAndPosts = await prisma.user.create({
  data: {
    posts: {
      create: [
        { title: 'Prisma Day 2020' }, // Populates authorId with user's id
        { title: 'How to write a Prisma schema' }, // Populates authorId with user's id
      ],
    },
  },
})
```

在底層資料庫中,此查詢:

1. 建立一個具有自動生成 `id` 的 `User`(例如,`20`)
2. 建立兩筆新的 `Post` 記錄,並將兩筆記錄的 `authorId` 設為 `20`

### 擷取記錄並包含相關記錄

以下查詢透過 `id` 擷取 `User` 並包含任何相關的 `Post` 記錄:

```ts
const getAuthor = await prisma.user.findUnique({
  where: {
    id: "20",
  },
  include: {
    //highlight-next-line 
    posts: true, // All posts where authorId == 20
  },
});
```

在底層資料庫中,此查詢:

1. 擷取 `id` 為 `20` 的 `User` 記錄
2. 擷取所有 `authorId` 為 `20` 的 `Post` 記錄

### 將現有記錄關聯到另一筆現有記錄

以下查詢將現有的 `Post` 記錄與現有的 `User` 記錄關聯:

```ts
const updateAuthor = await prisma.user.update({
  where: {
    id: 20,
  },
  data: {
    posts: {
      connect: {
        id: 4,
      },
    },
  },
})
```

在底層資料庫中,此查詢使用[巢狀 `connect` 查詢](/orm/reference/prisma-client-reference#connect)將 `id` 為 4 的文章連結到 `id` 為 20 的使用者。該查詢透過以下步驟執行:

- 查詢首先尋找 `id` 為 `20` 的使用者。
- 然後查詢將 `authorID` 外鍵設為 `20`。這將 `id` 為 `4` 的文章連結到 `id` 為 `20` 的使用者。

在此查詢中,`authorID` 的當前值並不重要。無論其當前值為何,查詢都會將 `authorID` 更改為 `20`。

## 關聯類型

Prisma ORM 中有三種不同類型(或[基數](<https://en.wikipedia.org/wiki/Cardinality_(data_modeling)>))的關聯:

- [一對一](/orm/prisma-schema/data-model/relations/one-to-one-relations)(也稱為 1-1 關聯)
- [一對多](/orm/prisma-schema/data-model/relations/one-to-many-relations)(也稱為 1-n 關聯)
- [多對多](/orm/prisma-schema/data-model/relations/many-to-many-relations)(也稱為 m-n 關聯)

以下 Prisma schema 包含所有類型的關聯:

- 一對一:`User` ↔ `Profile`
- 一對多:`User` ↔ `Post`
- 多對多:`Post` ↔ `Category`

<TabbedContent code>
<TabItem value="Relational databases">

```prisma
model User {
  id      Int      @id @default(autoincrement())
  posts   Post[]
  profile Profile?
}

model Profile {
  id     Int  @id @default(autoincrement())
  user   User @relation(fields: [userId], references: [id])
  userId Int  @unique // relation scalar field (used in the `@relation` attribute above)
}

model Post {
  id         Int        @id @default(autoincrement())
  author     User       @relation(fields: [authorId], references: [id])
  authorId   Int // relation scalar field  (used in the `@relation` attribute above)
  categories Category[]
}

model Category {
  id    Int    @id @default(autoincrement())
  posts Post[]
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma
model User {
  id      String   @id @default(auto()) @map("_id") @db.ObjectId
  posts   Post[]
  profile Profile?
}

model Profile {
  id     String @id @default(auto()) @map("_id") @db.ObjectId
  user   User   @relation(fields: [userId], references: [id])
  userId String @unique @db.ObjectId // relation scalar field (used in the `@relation` attribute above)
}

model Post {
  id          String     @id @default(auto()) @map("_id") @db.ObjectId
  author      User       @relation(fields: [authorId], references: [id])
  authorId    String     @db.ObjectId // relation scalar field  (used in the `@relation` attribute above)
  categories  Category[] @relation(fields: [categoryIds], references: [id])
  categoryIds String[]   @db.ObjectId
}

model Category {
  id      String   @id @default(auto()) @map("_id") @db.ObjectId
  posts   Post[]   @relation(fields: [postIds], references: [id])
  postIds String[] @db.ObjectId
}
```

</TabItem>
</TabbedContent>

:::info

此 schema 與[範例資料模型](/orm/prisma-schema/data-model/models)相同,但移除了所有[純量欄位](/orm/prisma-schema/data-model/models#scalar-fields)(除了必需的[關聯純量欄位](/orm/prisma-schema/data-model/relations#relation-scalar-fields)),以便您可以專注於[關聯欄位](#relation-fields)。

:::

:::info

此範例使用[隱式多對多關聯](/orm/prisma-schema/data-model/relations/many-to-many-relations#implicit-many-to-many-relations)。這些關聯不需要 `@relation` 屬性,除非您需要[消除關聯歧義](#disambiguating-relations)。

:::

請注意,關聯式資料庫和 MongoDB 之間的語法略有不同 - 特別是對於[多對多關聯](/orm/prisma-schema/data-model/relations/many-to-many-relations)。

對於關聯式資料庫,以下實體關聯圖代表與範例 Prisma schema 對應的資料庫:

![The sample schema as an entity relationship diagram](./sample-schema.png)

對於 MongoDB,Prisma ORM 使用[正規化資料模型設計](https://www.mongodb.com/docs/manual/data-modeling/),這意味著文件以類似於關聯式資料庫的方式透過 ID 相互引用。更多詳情請參閱 [MongoDB 部分](#mongodb)。

### 隱式和顯式多對多關聯

關聯式資料庫中的多對多關聯可以用兩種方式建模:

- [顯式多對多關聯](/orm/prisma-schema/data-model/relations/many-to-many-relations#explicit-many-to-many-relations),其中關聯資料表在您的 Prisma schema 中表示為顯式模型
- [隱式多對多關聯](/orm/prisma-schema/data-model/relations/many-to-many-relations#implicit-many-to-many-relations),其中 Prisma ORM 管理關聯資料表,它不會出現在 Prisma schema 中。

隱式多對多關聯需要兩個模型都有單一的 `@id`。請注意以下事項:

- 您不能使用[多欄位 ID](/orm/reference/prisma-schema-reference#id-1)
- 您不能使用 `@unique` 來代替 `@id`

要使用這些功能中的任何一個,您必須改為設定顯式多對多關聯。

隱式多對多關聯仍然在底層資料庫中以關聯資料表的形式存在。但是,Prisma ORM 管理此關聯資料表。

如果您使用隱式多對多關聯而不是顯式關聯,它會使 [Prisma Client API](/orm/prisma-client) 更簡單(例如,在[巢狀寫入](/orm/prisma-client/queries/relation-queries#nested-writes)中減少一層巢狀)。

如果您不使用 Prisma Migrate,而是從[內省](/orm/prisma-schema/introspection)獲取資料模型,您仍然可以透過遵循 Prisma ORM 的[關聯資料表慣例](/orm/prisma-schema/data-model/relations/many-to-many-relations#conventions-for-relation-tables-in-implicit-m-n-relations)來使用隱式多對多關聯。

## 關聯欄位

關聯[欄位](/orm/prisma-schema/data-model/models#defining-fields)是 Prisma [模型](/orm/prisma-schema/data-model/models#defining-models)上_沒有_[純量類型](/orm/prisma-schema/data-model/models#scalar-fields)的欄位。相反,它們的類型是另一個模型。

每個關聯必須恰好有兩個關聯欄位,每個模型上各一個。在一對一和一對多關聯的情況下,需要額外的_關聯純量欄位_,該欄位由 `@relation` 屬性中的兩個關聯欄位之一連結。此關聯純量欄位是底層資料庫中_外鍵_的直接表示。

<TabbedContent code>

<TabItem value="Relational databases">

```prisma
model User {
  id    Int    @id @default(autoincrement())
  email String @unique
  role  Role   @default(USER)
  posts Post[] // relation field (defined only at the Prisma ORM level)
}

model Post {
  id       Int    @id @default(autoincrement())
  title    String
  author   User   @relation(fields: [authorId], references: [id]) // relation field (uses the relation scalar field `authorId` below)
  authorId Int // relation scalar field (used in the `@relation` attribute above)
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma
model User {
  id    String @id @default(auto()) @map("_id") @db.ObjectId
  email String @unique
  role  Role   @default(USER)
  posts Post[] // relation field (defined only at the Prisma ORM level)
}

model Post {
  id       String @id @default(auto()) @map("_id") @db.ObjectId
  title    String
  author   User   @relation(fields: [authorId], references: [id]) // relation field (uses the relation scalar field `authorId` below)
  authorId String @db.ObjectId // relation scalar field (used in the `@relation` attribute above)
}
```

</TabItem>
</TabbedContent>

`posts` 和 `author` 都是關聯欄位,因為它們的類型不是純量類型,而是其他模型。

還要注意,[標註的關聯欄位](#annotated-relation-fields) `author` 需要在 `@relation` 屬性內連結 `Post` 模型上的關聯純量欄位 `authorId`。關聯純量欄位代表底層資料庫中的外鍵。

兩個關聯欄位(即 `posts` 和 `author`)都純粹在 Prisma ORM 層級定義,它們不會在資料庫中呈現。

### 標註的關聯欄位

需要關聯的一側用 `@relation` 屬性_標註_的關聯稱為_標註的關聯欄位_。這包括:

- 一對一關聯
- 一對多關聯
- 僅適用於 MongoDB 的多對多關聯

用 `@relation` 屬性標註的關聯一側代表**在底層資料庫中儲存外鍵**的一側。代表外鍵的「實際」欄位在關聯的該側也是必需的,它被稱為_關聯純量欄位_,並在 `@relation` 屬性內被引用:

<TabbedContent code>
<TabItem value="Relational databases">

```prisma
author     User    @relation(fields: [authorId], references: [id])
authorId   Int
```

</TabItem>
<TabItem value="MongoDB">

```prisma
author     User    @relation(fields: [authorId], references: [id])
authorId   String  @db.ObjectId
```

</TabItem>
</TabbedContent>

當純量欄位在 `@relation` 屬性的 `fields` 中使用時,它_成為_關聯純量欄位。

### 關聯純量欄位

#### 關聯純量欄位命名慣例

因為關聯純量欄位總是_屬於_一個關聯欄位,所以常見的命名慣例如下:

- 關聯欄位:`author`
- 關聯純量欄位:`authorId`(關聯欄位名稱 + `Id`)

## `@relation` 屬性

[`@relation`](/orm/reference/prisma-schema-reference#relation) 屬性只能應用於[關聯欄位](#relation-fields),不能應用於[純量欄位](/orm/prisma-schema/data-model/models#scalar-fields)。

在以下情況下需要 `@relation` 屬性:

- 您定義一對一或一對多關聯,它在關聯的_一側_是必需的(以及對應的關聯純量欄位)
- 您需要消除關聯的歧義(例如,當您在相同模型之間有兩個關聯時)
- 您定義[自關聯](/orm/prisma-schema/data-model/relations/self-relations)
- 您為 MongoDB 定義[多對多關聯](/orm/prisma-schema/data-model/relations/many-to-many-relations#mongodb)
- 您需要控制關聯資料表在底層資料庫中的表示方式(例如,為關聯資料表使用特定名稱)

> **注意**: 關聯式資料庫中的[隱式多對多關聯](/orm/prisma-schema/data-model/relations/many-to-many-relations#implicit-many-to-many-relations)不需要 `@relation` 屬性。

## 消除關聯歧義

當您在相同的兩個模型之間定義兩個關聯時,您需要在 `@relation` 屬性中加入 `name` 引數來消除它們的歧義。作為需要這樣做的範例,請考慮以下模型:

<TabbedContent code>
<TabItem value="Relational databases">

```prisma highlight=6,7,13,15;normal no-copy
// NOTE: This schema is intentionally incorrect. See below for a working solution.

model User {
  id           Int     @id @default(autoincrement())
  name         String?
  //highlight-start
  writtenPosts Post[]
  pinnedPost   Post?
  //highlight-end
}

model Post {
  id         Int     @id @default(autoincrement())
  title      String?
  //highlight-next-line
  author     User    @relation(fields: [authorId], references: [id])
  authorId   Int
  //highlight-next-line
  pinnedBy   User?   @relation(fields: [pinnedById], references: [id])
  pinnedById Int?
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma highlight=6,7,13,15;normal no-copy
// NOTE: This schema is intentionally incorrect. See below for a working solution.

model User {
  id           String  @id @default(auto()) @map("_id") @db.ObjectId
  name         String?
  //highlight-start
  writtenPosts Post[]
  pinnedPost   Post?
  //highlight-end
}

model Post {
  id         String  @id @default(auto()) @map("_id") @db.ObjectId
  title      String?
  //highlight-next-line
  author     User    @relation(fields: [authorId], references: [id])
  authorId   String  @db.ObjectId
  //highlight-next-line
  pinnedBy   User?   @relation(fields: [pinnedById], references: [id])
  pinnedById String? @db.ObjectId
}
```

</TabItem>
</TabbedContent>

在這種情況下,關聯是模糊的,有四種不同的解釋方式:

- `User.writtenPosts` ↔ `Post.author` + `Post.authorId`
- `User.writtenPosts` ↔ `Post.pinnedBy` + `Post.pinnedById`
- `User.pinnedPost` ↔ `Post.author` + `Post.authorId`
- `User.pinnedPost` ↔ `Post.pinnedBy` + `Post.pinnedById`

要消除這些關聯的歧義,您需要用 `@relation` 屬性標註關聯欄位並提供 `name` 引數。您可以設定任何 `name`(除了空字串 `""`),但它在關聯的兩側必須相同:

<TabbedContent code>
<TabItem value="Relational databases">

```prisma highlight=4,5,11,13;normal
model User {
  id           Int     @id @default(autoincrement())
  name         String?
  //highlight-start
  writtenPosts Post[]  @relation("WrittenPosts")
  pinnedPost   Post?   @relation("PinnedPost")
  //highlight-end
}

model Post {
  id         Int     @id @default(autoincrement())
  title      String?
  //highlight-next-line
  author     User    @relation("WrittenPosts", fields: [authorId], references: [id])
  authorId   Int
  //highlight-next-line
  pinnedBy   User?   @relation("PinnedPost", fields: [pinnedById], references: [id])
  pinnedById Int?    @unique
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma highlight=4,5,11,13;normal
model User {
  id           String  @id @default(auto()) @map("_id") @db.ObjectId
  name         String?
  //highlight-start
  writtenPosts Post[]  @relation("WrittenPosts")
  pinnedPost   Post?   @relation("PinnedPost")
  //highlight-end
}

model Post {
  id         String  @id @default(auto()) @map("_id") @db.ObjectId
  title      String?
  //highlight-next-line
  author     User    @relation("WrittenPosts", fields: [authorId], references: [id])
  authorId   String  @db.ObjectId
  //highlight-next-line
  pinnedBy   User?   @relation("PinnedPost", fields: [pinnedById], references: [id])
  pinnedById String? @unique @db.ObjectId
```
