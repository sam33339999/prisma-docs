本指南說明如何在 Prisma 中定義和使用多對多 (m-n) 關係，包含關聯式資料庫和 MongoDB 的範例。

<TopBlock>

多對多 (m-n) 關聯是指關聯一側的零筆或多筆記錄可以連接到另一側的零筆或多筆記錄。

Prisma schema 語法和底層資料庫中的實作在[關聯式資料庫](#relational-databases)和 [MongoDB](#mongodb) 之間有所不同。

</TopBlock>

## 關聯式資料庫

在關聯式資料庫中，m-n 關聯通常透過[關聯表](/orm/prisma-schema/data-model/relations/many-to-many-relations#relation-tables)來建立模型。在 Prisma schema 中，m-n 關聯可以是[顯式](#explicit-many-to-many-relations)或[隱式](#implicit-many-to-many-relations)。如果您不需要在關聯表本身儲存任何額外的詮釋資料，我們建議使用[隱式](#implicit-many-to-many-relations) m-n 關聯。如果需要，您隨時可以遷移到[顯式](#explicit-many-to-many-relations) m-n 關聯。

### 顯式多對多關聯

在顯式 m-n 關聯中，**關聯表在 Prisma schema 中表示為一個 model**，並可用於查詢。顯式 m-n 關聯定義了三個 model：

- 兩個具有 m-n 關聯的 model，例如 `Category` 和 `Post`。
- 一個代表[關聯表](#relation-tables)的 model，例如底層資料庫中的 `CategoriesOnPosts`（有時也稱為 _JOIN_、_link_ 或 _pivot_ 表）。關聯表 model 的欄位都是帶註解的關聯欄位（`post` 和 `category`），並帶有對應的關聯純量欄位（`postId` 和 `categoryId`）。

關聯表 `CategoriesOnPosts` 連接相關的 `Post` 和 `Category` 記錄。在此範例中，代表關聯表的 model 還**定義了額外的欄位**來描述 `Post`/`Category` 關係 - 誰分配了類別（`assignedBy`），以及類別何時被分配（`assignedAt`）：

```prisma
model Post {
  id         Int                 @id @default(autoincrement())
  title      String
  categories CategoriesOnPosts[]
}

model Category {
  id    Int                 @id @default(autoincrement())
  name  String
  posts CategoriesOnPosts[]
}

model CategoriesOnPosts {
  post       Post     @relation(fields: [postId], references: [id])
  postId     Int // relation scalar field (used in the `@relation` attribute above)
  category   Category @relation(fields: [categoryId], references: [id])
  categoryId Int // relation scalar field (used in the `@relation` attribute above)
  assignedAt DateTime @default(now())
  assignedBy String

  @@id([postId, categoryId])
}
```

底層 SQL 如下所示：

```sql
CREATE TABLE "Post" (
    "id" SERIAL NOT NULL,
    "title" TEXT NOT NULL,

    CONSTRAINT "Post_pkey" PRIMARY KEY ("id")
);

CREATE TABLE "Category" (
    "id" SERIAL NOT NULL,
    "name" TEXT NOT NULL,

    CONSTRAINT "Category_pkey" PRIMARY KEY ("id")
);


-- Relation table + indexes --

CREATE TABLE "CategoriesOnPosts" (
    "postId" INTEGER NOT NULL,
    "categoryId" INTEGER NOT NULL,
    "assignedAt" TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    "assignedBy" TEXT NOT NULL,

    CONSTRAINT "CategoriesOnPosts_pkey" PRIMARY KEY ("postId","categoryId")
);

ALTER TABLE "CategoriesOnPosts" ADD CONSTRAINT "CategoriesOnPosts_postId_fkey" FOREIGN KEY ("postId") REFERENCES "Post"("id") ON DELETE RESTRICT ON UPDATE CASCADE;
ALTER TABLE "CategoriesOnPosts" ADD CONSTRAINT "CategoriesOnPosts_categoryId_fkey" FOREIGN KEY ("categoryId") REFERENCES "Category"("id") ON DELETE RESTRICT ON UPDATE CASCADE;
```

請注意，與 [1-n 關聯](/orm/prisma-schema/data-model/relations/one-to-many-relations)相同的規則適用（因為 `Post`↔ `CategoriesOnPosts` 和 `Category` ↔ `CategoriesOnPosts` 實際上都是 1-n 關聯），這意味著關聯的一側需要用 `@relation` 屬性來註解。

當您不需要在關聯上附加額外資訊時，可以將 m-n 關聯建模為[隱式 m-n 關聯](#implicit-many-to-many-relations)。如果您不使用 Prisma Migrate 而是從[內省](/orm/prisma-schema/introspection)獲取資料模型，您仍然可以透過遵循 Prisma ORM 的[關聯表慣例](#conventions-for-relation-tables-in-implicit-m-n-relations)來使用隱式 m-n 關聯。

#### 查詢顯式多對多

以下部分示範如何查詢顯式 m-n 關聯。您可以直接查詢關聯 model（`prisma.categoriesOnPosts(...)`），或使用巢狀查詢從 `Post` -> `CategoriesOnPosts` -> `Category` 或反向查詢。

以下查詢執行三件事：

1. 建立一個 `Post`
2. 在關聯表 `CategoriesOnPosts` 中建立一筆新記錄
3. 建立一個新的 `Category`，與新建立的 `Post` 記錄關聯

```ts
const createCategory = await prisma.post.create({
  data: {
    title: 'How to be Bob',
    categories: {
      create: [
        {
          assignedBy: 'Bob',
          assignedAt: new Date(),
          category: {
            create: {
              name: 'New category',
            },
          },
        },
      ],
    },
  },
})
```

以下查詢：

- 建立一個新的 `Post`
- 在關聯表 `CategoriesOnPosts` 中建立一筆新記錄
- 將類別分配連接到現有類別（ID 為 `9` 和 `22`）

```ts
const assignCategories = await prisma.post.create({
  data: {
    title: 'How to be Bob',
    categories: {
      create: [
        {
          assignedBy: 'Bob',
          assignedAt: new Date(),
          category: {
            connect: {
              id: 9,
            },
          },
        },
        {
          assignedBy: 'Bob',
          assignedAt: new Date(),
          category: {
            connect: {
              id: 22,
            },
          },
        },
      ],
    },
  },
})
```

有時您可能不知道 `Category` 記錄是否存在。如果 `Category` 記錄存在，您想將新的 `Post` 記錄連接到該類別。如果 `Category` 記錄不存在，您想先建立記錄，然後將其連接到新的 `Post` 記錄。以下查詢：

1. 建立一個新的 `Post`
2. 在關聯表 `CategoriesOnPosts` 中建立一筆新記錄
3. 將類別分配連接到現有類別（ID 為 `9`），如果不存在則先建立新類別

```ts
const assignCategories = await prisma.post.create({
  data: {
    title: 'How to be Bob',
    categories: {
      create: [
        {
          assignedBy: 'Bob',
          assignedAt: new Date(),
          category: {
            connectOrCreate: {
              where: {
                id: 9,
              },
              create: {
                name: 'New Category',
                id: 9,
              },
            },
          },
        },
      ],
    },
  },
})
```

以下查詢回傳所有至少有一個（`some`）類別分配（`categories`）引用名為 `"New category"` 的類別的 `Post` 記錄：

```ts
const getPosts = await prisma.post.findMany({
  where: {
    categories: {
      some: {
        category: {
          name: 'New Category',
        },
      },
    },
  },
})
```

以下查詢回傳所有至少有一個（`some`）相關 `Post` 記錄標題包含 `"Cool stuff"` 字詞_且_類別由 Bob 分配的類別。

```ts
const getAssignments = await prisma.category.findMany({
  where: {
    posts: {
      some: {
        assignedBy: 'Bob',
        post: {
          title: {
            contains: 'Cool stuff',
          },
        },
      },
    },
  },
})
```

以下查詢取得所有由 `"Bob"` 分配給 5 篇文章之一的類別分配（`CategoriesOnPosts`）記錄：

```ts
const getAssignments = await prisma.categoriesOnPosts.findMany({
  where: {
    assignedBy: 'Bob',
    post: {
      id: {
        in: [9, 4, 10, 12, 22],
      },
    },
  },
})
```

### 隱式多對多關聯

隱式 m-n 關聯在關聯的兩側都將關聯欄位定義為列表。儘管關聯表存在於底層資料庫中，**但它由 Prisma ORM 管理，不會顯示在 Prisma schema 中**。隱式關聯表遵循[特定慣例](#conventions-for-relation-tables-in-implicit-m-n-relations)。

隱式 m-n 關聯使 m-n 關聯的 [Prisma Client API](/orm/prisma-client) 更簡單一些（因為在[巢狀寫入](/orm/prisma-client/queries/relation-queries#nested-writes)中少了一層巢狀）。

在下面的範例中，`Post` 和 `Category` 之間有一個_隱式_ m-n 關聯：

<TabbedContent code>
<TabItem value="Relational databases">

```prisma
model Post {
  id         Int        @id @default(autoincrement())
  title      String
  categories Category[]
}

model Category {
  id    Int    @id @default(autoincrement())
  name  String
  posts Post[]
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma
model Post {
  id          String     @id @default(auto()) @map("_id") @db.ObjectId
  categoryIDs String[]   @db.ObjectId
  categories  Category[] @relation(fields: [categoryIDs], references: [id])
}

model Category {
  id      String   @id @default(auto()) @map("_id") @db.ObjectId
  name    String
  postIDs String[] @db.ObjectId
  posts   Post[]   @relation(fields: [postIDs], references: [id])
}
```

</TabItem>
</TabbedContent>

#### 查詢隱式多對多

以下部分示範如何查詢[隱式 m-n](#implicit-many-to-many-relations) 關聯。查詢所需的巢狀比[顯式 m-n 查詢](#querying-an-explicit-many-to-many)少。

以下查詢建立一個 `Post` 和多個 `Category` 記錄：

```ts
const createPostAndCategory = await prisma.post.create({
  data: {
    title: 'How to become a butterfly',
    categories: {
      create: [{ name: 'Magic' }, { name: 'Butterflies' }],
    },
  },
})
```

以下查詢建立一個 `Category` 和多個 `Post` 記錄：

```ts
const createCategoryAndPosts = await prisma.category.create({
  data: {
    name: 'Stories',
    posts: {
      create: [
        { title: 'That one time with the stuff' },
        { title: 'The story of planet Earth' },
      ],
    },
  },
})
```

以下查詢回傳所有 `Post` 記錄及該文章已分配類別的列表：

```ts
const getPostsAndCategories = await prisma.post.findMany({
  include: {
    categories: true,
  },
})
```

#### 定義隱式 m-n 關聯的規則

隱式 m-n 關聯：

- 使用特定的[關聯表慣例](#conventions-for-relation-tables-in-implicit-m-n-relations)
- **不**需要 `@relation` 屬性，除非您需要使用名稱來[消除關聯歧義](/orm/prisma-schema/data-model/relations#disambiguating-relations)，例如 `@relation("MyRelation")` 或 `@relation(name: "MyRelation")`。
- 如果您確實使用 `@relation` 屬性，則不能使用 `references`、`fields`、`onUpdate` 或 `onDelete` 參數。這是因為這些參數對於隱式 m-n 關聯具有固定值且無法更改。
- 要求兩個 model 都具有單一 `@id`。請注意：

  - 您不能使用[多欄位 ID](/orm/reference/prisma-schema-reference#id-1)
  - 您不能使用 `@unique` 來取代 `@id`

  :::info

  要使用這些功能，您必須使用[顯式 m-n](#explicit-many-to-many-relations)。

  :::

#### 隱式 m-n 關聯中關聯表的慣例

如果您從[內省](/orm/prisma-schema/introspection)獲取資料模型，您仍然可以透過遵循 Prisma ORM 的[關聯表慣例](#conventions-for-relation-tables-in-implicit-m-n-relations)來使用隱式 m-n 關聯。以下範例假設您想建立一個關聯表，以便為兩個名為 `Post` 和 `Category` 的 model 建立隱式 m-n 關聯。

##### 關聯表

如果您希望內省將關聯表識別為隱式 m-n 關聯，名稱必須遵循以下確切結構：

- 它必須以底線 `_` 開頭
- 然後是按字母順序排列的第一個 model 名稱（在本例中為 `Category`）
- 然後是關係（在本例中為 `To`）
- 然後是按字母順序排列的第二個 model 名稱（在本例中為 `Post`）

在此範例中，正確的表名是 `_CategoryToPost`。

當您在 Prisma schema 檔案中自己建立隱式 m-n 關聯時，您可以[配置關聯](#configuring-the-name-of-the-relation-table-in-implicit-many-to-many-relations)以使用不同的名稱。這將更改資料庫中關聯表的名稱。例如，對於名為 `"MyRelation"` 的關聯，相應的表將被稱為 `_MyRelation`。

###### 多 schema

如果您的隱式多對多關係跨越多個資料庫 schema（使用 [`multiSchema` 功能](/orm/prisma-schema/data-model/multi-schema)），關聯表（具有上面直接定義的名稱，在範例中為 `_CategoryToPost`）必須存在於與按字母順序排列的第一個 model（在本例中為 `Category`）相同的資料庫 schema 中。

##### 欄位

隱式 m-n 關聯的關聯表必須恰好有兩個欄位：

- 一個指向 `Category` 的外鍵欄位，稱為 `A`
- 一個指向 `Post` 的外鍵欄位，稱為 `B`

欄位必須稱為 `A` 和 `B`，其中 `A` 指向按字母順序排列的第一個 model，`B` 指向按字母順序排列的最後一個 model。

##### 索引

還必須有：

- 在兩個外鍵欄位上定義的唯一索引：

  ```sql
  CREATE UNIQUE INDEX "_CategoryToPost_AB_unique" ON "_CategoryToPost"("A" int4_ops,"B" int4_ops);
  ```

- 在 B 上定義的非唯一索引：

  ```sql
  CREATE INDEX "_CategoryToPost_B_index" ON "_CategoryToPost"("B" int4_ops);
  ```

##### 範例

這是一個範例 SQL 語句，它將建立包括索引在內的三個表（使用 PostgreSQL 方言），這些表會被 Prisma 內省識別為隱式 m-n 關聯：

```sql
CREATE TABLE "_CategoryToPost" (
    "A" integer NOT NULL REFERENCES "Category"(id) ,
    "B" integer NOT NULL REFERENCES "Post"(id)
);
CREATE UNIQUE INDEX "_CategoryToPost_AB_unique" ON "_CategoryToPost"("A" int4_ops,"B" int4_ops);
CREATE INDEX "_CategoryToPost_B_index" ON "_CategoryToPost"("B" int4_ops);

CREATE TABLE "Category" (
    id integer SERIAL PRIMARY KEY
);

CREATE TABLE "Post" (
    id integer SERIAL PRIMARY KEY
);
```

您可以使用不同的關係名稱在兩個表之間定義多個多對多關聯。此範例顯示了在這種情況下 Prisma 內省的工作原理：

```sql
CREATE TABLE IF NOT EXISTS "User" (
    "id" SERIAL PRIMARY KEY
);
CREATE TABLE IF NOT EXISTS "Video" (
    "id" SERIAL PRIMARY KEY
);
CREATE TABLE IF NOT EXISTS "_UserLikedVideos" (
    "A" SERIAL NOT NULL,
    "B" SERIAL NOT NULL,
    CONSTRAINT "_UserLikedVideos_A_fkey" FOREIGN KEY ("A") REFERENCES "User" ("id") ON DELETE CASCADE ON UPDATE CASCADE,
    CONSTRAINT "_UserLikedVideos_B_fkey" FOREIGN KEY ("B") REFERENCES "Video" ("id") ON DELETE CASCADE ON UPDATE CASCADE
);
CREATE TABLE IF NOT EXISTS "_UserDislikedVideos" (
    "A" SERIAL NOT NULL,
    "B" SERIAL NOT NULL,
    CONSTRAINT "_UserDislikedVideos_A_fkey" FOREIGN KEY ("A") REFERENCES "User" ("id") ON DELETE CASCADE ON UPDATE CASCADE,
    CONSTRAINT "_UserDislikedVideos_B_fkey" FOREIGN KEY ("B") REFERENCES "Video" ("id") ON DELETE CASCADE ON UPDATE CASCADE
);
CREATE UNIQUE INDEX "_UserLikedVideos_AB_unique" ON "_UserLikedVideos"("A", "B");
CREATE INDEX "_UserLikedVideos_B_index" ON "_UserLikedVideos"("B");
CREATE UNIQUE INDEX "_UserDislikedVideos_AB_unique" ON "_UserDislikedVideos"("A", "B");
CREATE INDEX "_UserDislikedVideos_B_index" ON "_UserDislikedVideos"("B");
```

如果您在此資料庫上執行 `prisma db pull`，Prisma CLI 將透過內省生成以下 schema：

```prisma
model User {
  id                       Int     @id @default(autoincrement())
  Video_UserDislikedVideos Video[] @relation("UserDislikedVideos")
  Video_UserLikedVideos    Video[] @relation("UserLikedVideos")
}

model Video {
  id                      Int    @id @default(autoincrement())
  User_UserDislikedVideos User[] @relation("UserDislikedVideos")
  User_UserLikedVideos    User[] @relation("UserLikedVideos")
}
```

#### 配置隱式多對多關聯中關聯表的名稱

使用 Prisma Migrate 時，您可以使用 `@relation` 屬性配置由 Prisma ORM 管理的關聯表名稱。例如，如果您希望關聯表被稱為 `_MyRelationTable` 而不是預設名稱 `_CategoryToPost`，您可以按如下方式指定：

```prisma
model Post {
  id         Int        @id @default(autoincrement())
  categories Category[] @relation("MyRelationTable")
}

model Category {
  id    Int    @id @default(autoincrement())
  posts Post[] @relation("MyRelationTable")
}
```

### 關聯表

關聯表（有時也稱為 _JOIN_、_link_ 或 _pivot_ 表）連接兩個或多個其他表，從而在它們之間建立_關聯_。在 SQL 中建立關聯表是表示不同實體之間關係的常見資料建模實踐。本質上，這意味著「一個 m-n 關聯在資料庫中被建模為兩個 1-n 關聯」。

我們建議使用[隱式](#implicit-many-to-many-relations) m-n 關聯，Prisma ORM 會自動在底層資料庫中生成關聯表。當您需要在關聯中儲存額外資料（例如關聯建立日期）時，應使用[顯式](#explicit-many-to-many-relations) m-n 關聯。

## MongoDB

在 MongoDB 中，m-n 關聯由以下表示：

- 雙方的關聯欄位，每個都有一個 `@relation` 屬性，並帶有必需的 `fields` 和 `references` 參數
- 每側的引用 ID 的純量列表，類型與另一側的 ID 欄位匹配

以下範例示範了文章和類別之間的 m-n 關聯：

```prisma
model Post {
  id          String     @id @default(auto()) @map("_id") @db.ObjectId
  categoryIDs String[]   @db.ObjectId
  categories  Category[] @relation(fields: [categoryIDs], references: [id])
}

model Category {
  id      String   @id @default(auto()) @map("_id") @db.ObjectId
  name    String
  postIDs String[] @db.ObjectId
  posts   Post[]   @relation(fields: [postIDs], references: [id])
}
```

Prisma ORM 使用以下規則驗證 MongoDB 中的 m-n 關聯：

- 關聯雙方的欄位必須具有列表類型（在上面的範例中，`categories` 的類型為 `Category[]`，`posts` 的類型為 `Post[]`）
- `@relation` 屬性必須在雙方定義 `fields` 和 `references` 參數
- `fields` 參數必須只定義一個純量欄位，並且必須是列表類型
- `references` 參數必須只定義一個純量欄位。此純量欄位必須存在於被引用的 model 上，並且必須與 `fields` 參數中的純量欄位類型相同，但為單數（非列表）
- `references` 指向的純量欄位必須具有 `@id` 屬性
- `@relation` 中不允許使用[參照動作](/orm/prisma-schema/data-model/relations/referential-actions)

[在關聯式資料庫中使用](/orm/prisma-schema/data-model/relations/many-to-many-relations#implicit-many-to-many-relations)的隱式 m-n 關聯在 MongoDB 上不受支援。

### 查詢 MongoDB 多對多關聯

本節示範如何使用上述範例 schema 查詢 MongoDB 中的 m-n 關聯。

以下查詢尋找具有特定匹配類別 ID 的文章：

```ts
const newId1 = new ObjectId()
const newId2 = new ObjectId()

const posts = await prisma.post.findMany({
  where: {
    categoryIDs: {
      hasSome: [newId1.toHexString(), newId2.toHexString()],
    },
  },
})
```

以下查詢尋找類別名稱包含字串 `'Servers'` 的文章：

```ts
const posts = await prisma.post.findMany({
  where: {
    categories: {
      some: {
        name: {
          contains: 'Servers',
        },
      },
    },
  },
})
```
