參照動作決定了當您的應用程式刪除或更新相關記錄時會發生什麼事。

從版本 2.26.0 開始,您可以在 Prisma schema 的關聯欄位上定義參照動作。這允許您在 Prisma ORM 層級定義參照動作,如串聯刪除和串聯更新。

:::info

**版本差異**

- 如果您使用版本 3.0.1 或更新版本,您可以按照此頁面所述使用參照動作。
- 如果您使用 2.26.0 到 3.0.0 之間的版本,您可以按照此頁面所述使用參照動作,但您必須[啟用預覽功能旗標](/orm/reference/preview-features/client-preview-features#enabling-a-prisma-client-preview-feature) `referentialActions`。
- 如果您使用版本 2.25.0 或更早版本,您可以在資料庫中手動配置串聯刪除。

:::

在以下範例中,在 `Post` 模型的 `author` 欄位上添加 `onDelete: Cascade` 意味著刪除 `User` 記錄也會刪除所有相關的 `Post` 記錄。

```prisma file=schema.prisma highlight=4;normal showLineNumbers
model Post {
  id       Int    @id @default(autoincrement())
  title    String
  author   User   @relation(fields: [authorId], references: [id], onDelete: Cascade)
  authorId Int
}

model User {
  id    Int    @id @default(autoincrement())
  posts Post[]
}
```

如果您沒有指定參照動作,Prisma ORM [使用預設值](#referential-action-defaults)。

## 什麼是參照動作?

參照動作是定義當您執行 [`update`](/orm/prisma-client/queries/crud#update) 或 [`delete`](/orm/prisma-client/queries/crud#delete) 查詢時,資料庫如何處理被參照記錄的策略。

<details>

<summary>資料庫層級的參照動作</summary>

參照動作是外鍵約束的功能,存在的目的是為了保持資料庫中的參照完整性。

當您在 Prisma schema 中定義資料模型之間的關聯時,您使用[關聯欄位](/orm/prisma-schema/data-model/relations#relation-fields),**這些欄位不存在於資料庫中**,以及[純量欄位](/orm/prisma-schema/data-model/models#scalar-fields),**這些欄位存在於資料庫中**。這些外鍵在資料庫層級連接模型。

參照完整性指出這些外鍵必須參照相關資料庫表中的現有主鍵值。在您的 Prisma schema 中,這通常由相關模型上的 `id` 欄位表示。

預設情況下,資料庫會拒絕任何違反參照完整性的操作,例如刪除被參照的記錄。

</details>

### 如何使用參照動作

參照動作在 [`@relation`](/orm/reference/prisma-schema-reference#relation) 屬性中定義,並對應到底層資料庫中**外鍵約束**的動作。如果您沒有指定參照動作,[Prisma ORM 會退回到預設值](#referential-action-defaults)。

以下模型定義了 `User` 和 `Post` 之間的一對多關聯,以及 `Post` 和 `Tag` 之間的多對多關聯,並明確定義了參照動作:

```prisma file=schema.prisma highlight=10,16-17;normal showLineNumbers
model User {
  id    Int    @id @default(autoincrement())
  posts Post[]
}

model Post {
  id     Int          @id @default(autoincrement())
  title  String
  tags   TagOnPosts[]
  User   User?        @relation(fields: [userId], references: [id], onDelete: SetNull, onUpdate: Cascade)
  userId Int?
}

model TagOnPosts {
  id     Int   @id @default(autoincrement())
  post   Post? @relation(fields: [postId], references: [id], onUpdate: Cascade, onDelete: Cascade)
  tag    Tag?  @relation(fields: [tagId], references: [id], onUpdate: Cascade, onDelete: Cascade)
  postId Int?
  tagId  Int?
}

model Tag {
  id    Int          @id @default(autoincrement())
  name  String       @unique
  posts TagOnPosts[]
}
```

這個模型明確定義了以下參照動作:

- 如果您刪除 `Tag`,相應的標籤分配也會在 `TagOnPosts` 中被刪除,使用 `Cascade` 參照動作
- 如果您刪除 `User`,作者會從所有文章中被移除,通過將欄位值設為 `Null`,這是因為 `SetNull` 參照動作。為了允許這樣做,`User` 和 `userId` 必須是 `Post` 中的可選欄位。

Prisma ORM 支援以下參照動作:

- [`Cascade`](#cascade)
- [`Restrict`](#restrict)
- [`NoAction`](#noaction)
- [`SetNull`](#setnull)
- [`SetDefault`](#setdefault)

### 參照動作預設值

如果您沒有指定參照動作,Prisma ORM 使用以下預設值:

| 子句       | 可選關聯           | 必填關聯            |
| :--------- | :----------------- | :------------------ |
| `onDelete` | `SetNull`          | `Restrict`          |
| `onUpdate` | `Cascade`          | `Cascade`           |

例如,在以下 schema 中,所有 `Post` 記錄必須通過 `author` 關聯連接到 `User`:

```prisma highlight=4;normal
model Post {
  id       Int    @id @default(autoincrement())
  title    String
  //highlight-next-line
  author   User   @relation(fields: [authorId], references: [id])
  authorId Int
}

model User {
  id    Int    @id @default(autoincrement())
  posts Post[]
}
```

schema 沒有在必填的 `author` 關聯欄位上明確定義參照動作,這意味著會套用預設的參照動作:`onDelete` 為 `Restrict`,`onUpdate` 為 `Cascade`。

## 注意事項

以下注意事項適用:

- [隱式多對多關聯](/orm/prisma-schema/data-model/relations/many-to-many-relations#implicit-many-to-many-relations)**不**支援參照動作。要使用參照動作,您必須定義明確的多對多關聯,並在[連接表](/orm/prisma-schema/data-model/relations/troubleshooting-relations#how-to-use-a-relation-table-with-a-many-to-many-relationship)上定義您的參照動作。
- 某些參照動作和必填/可選關聯的組合不相容。例如,在必填關聯上使用 `SetNull` 會在刪除被參照記錄時導致資料庫錯誤,因為會違反非空約束。更多資訊請參見[這個 GitHub issue](https://github.com/prisma/prisma/issues/7909)。

## 參照動作的類型

以下表格顯示每個資料庫支援哪些參照動作。

| Database      | Cascade | Restrict | NoAction | SetNull | SetDefault |
| :------------ | :------ | :------- | :------- | :------ | :--------- |
| PostgreSQL    | ✔️      | ✔️         | ✔️        | ✔️⌘      | ✔️          |
| MySQL/MariaDB | ✔️      | ✔️         | ✔️        | ✔️       | ❌ (✔️†)    |
| SQLite        | ✔️      | ✔️         | ✔️        | ✔️       | ✔️          |
| SQL Server    | ✔️      | ❌‡       | ✔️        | ✔️       | ✔️          |
| CockroachDB   | ✔️      | ✔️         | ✔️        | ✔️       | ✔️          |
| MongoDB††     | ✔️      | ✔️         | ✔️        | ✔️       | ❌         |

- † 參見 [MySQL 的特殊情況](#mysqlmariadb)。
- ⌘ 參見 [PostgreSQL 的特殊情況](#postgresql)。
- ‡ 參見 [SQL Server 的特殊情況](#sql-server)。
- †† MongoDB 的參照動作在 Prisma ORM 版本 3.7.0 及更新版本中可用。

### 參照動作的特殊情況

參照動作是 ANSI SQL 標準的一部分。但是,有一些特殊情況,某些關聯式資料庫會偏離標準。

#### MySQL/MariaDB

MySQL/MariaDB 及底層的 InnoDB 儲存引擎不支援 `SetDefault`。確切的行為取決於資料庫版本:

- 在 MySQL 版本 8 及更新版本,以及 MariaDB 版本 10.5 及更新版本中,`SetDefault` 實際上作為 `NoAction` 的別名。您可以使用 `SET DEFAULT` 參照動作定義表格,但在執行時會觸發外鍵約束錯誤。
- 在 MySQL 版本 5.6 及更新版本,以及 MariaDB 10.5 之前的版本中,嘗試使用 `SET DEFAULT` 參照動作建立表格定義會失敗並出現語法錯誤。

因此,當您將 `mysql` 設為資料庫提供者時,Prisma ORM 會警告使用者將 Prisma schema 中的 `SetDefault` 參照動作替換為其他動作。

#### PostgreSQL

PostgreSQL 是 Prisma ORM 支援的唯一允許您定義參照非空欄位的 `SetNull` 參照動作的資料庫。但是,這會在執行時觸發動作時引發外鍵約束錯誤。

因此,當您在(預設的) `foreignKeys` 關聯模式中將 `postgres` 設為資料庫提供者時,Prisma ORM 會警告使用者將包含在具有 `SetNull` 參照動作的 `@relation` 屬性中的任何欄位標記為可選。對於所有其他資料庫提供者,Prisma ORM 會以驗證錯誤拒絕 schema。

#### SQL Server

[`Restrict`](#restrict) 不適用於 SQL Server 資料庫,但您可以改用 [`NoAction`](#noaction)。

### `Cascade`

- `onDelete: Cascade` 刪除被參照的記錄將觸發參照記錄的刪除。
- `onUpdate: Cascade` 如果更新依賴記錄的被參照純量欄位,會更新關聯純量欄位。

#### 範例用法

```prisma file=schema.prisma highlight=4;add showLineNumbers
model Post {
  id       Int    @id @default(autoincrement())
  title    String
  //add-next-line
  author   User   @relation(fields: [authorId], references: [id], onDelete: Cascade, onUpdate: Cascade)
  authorId Int
}

model User {
  id    Int    @id @default(autoincrement())
  posts Post[]
}
```

##### 使用 `Cascade` 的結果

如果刪除 `User` 記錄,他們的文章也會被刪除。如果更新使用者的 `id`,則相應的 `authorId` 也會被更新。

### `Restrict`

- `onDelete: Restrict` 如果存在任何參照記錄,則防止刪除。
- `onUpdate: Restrict` 防止更改被參照記錄的識別碼。

#### 範例用法

```prisma file=schema.prisma highlight=4;add showLineNumbers
model Post {
  id       Int    @id @default(autoincrement())
  title    String
  //add-next-line
  author   User   @relation(fields: [authorId], references: [id], onDelete: Restrict, onUpdate: Restrict)
  authorId Int
}

model User {
  id    Int    @id @default(autoincrement())
  posts Post[]
}
```

##### 使用 `Restrict` 的結果

有文章的 `User` **無法**被刪除。`User` 的 `id` **無法**被更改。

:::warning

`Restrict` 動作在 [Microsoft SQL Server](/orm/overview/databases/sql-server) 上**不**可用,會觸發 schema 驗證錯誤。相反,您可以使用 [`NoAction`](#noaction),它會產生相同的結果並與 SQL Server 相容。

:::

### `NoAction`

`NoAction` 動作類似於 `Restrict`,兩者之間的差異取決於所使用的資料庫:

- **PostgreSQL**: `NoAction` 允許將檢查(表上是否存在被參照的列)延遲到事務的稍後時間。更多資訊請參見 [PostgreSQL 文件](https://www.postgresql.org/docs/current/ddl-constraints.html#DDL-CONSTRAINTS-FK)。
- **MySQL**: `NoAction` 的行為與 `Restrict` 完全相同。更多資訊請參見 [MySQL 文件](https://dev.mysql.com/doc/refman/8.0/en/create-table-foreign-keys.html#foreign-key-referential-actions)。
- **SQLite**: 當相關的主鍵被修改或刪除時,不會採取任何動作。更多資訊請參見 [SQLite 文件](https://www.sqlite.org/foreignkeys.html#fk_actions)。
- **SQL Server**: 當被參照的記錄被刪除或修改時,會引發錯誤。更多資訊請參見 [SQL Server 文件](https://learn.microsoft.com/en-us/sql/relational-databases/tables/graph-edge-constraints?view=sql-server-ver15#on-delete-referential-actions-on-edge-constraints)。
- **MongoDB**(從版本 3.6.0 開始預覽): 當記錄被修改或刪除時,不會對任何相關記錄執行任何操作。

:::warning

如果您[在 Prisma Client 中管理關聯](/orm/prisma-schema/data-model/relations/relation-mode#emulate-relations-in-prisma-orm-with-the-prisma-relation-mode)而不是在資料庫中使用外鍵,您應該注意目前 Prisma ORM 僅實作參照動作。外鍵也會建立約束,使得無法以違反這些約束的方式操作資料:資料庫會回應錯誤而不是執行查詢。如果您在 Prisma Client 中模擬參照完整性,這些約束將不會被建立,因此如果您將參照動作設為 `NoAction`,將沒有檢查來防止您破壞參照完整性。

:::

#### 範例用法

```prisma file=schema.prisma highlight=4;add showLineNumbers
model Post {
  id       Int    @id @default(autoincrement())
  title    String
  //add-next-line
  author   User   @relation(fields: [authorId], references: [id], onDelete: NoAction, onUpdate: NoAction)
  authorId Int
}

model User {
  id    Int    @id @default(autoincrement())
  posts Post[]
}
```

##### 使用 `NoAction` 的結果

有文章的 `User` **無法**被刪除。`User` 的 `id` **無法**被更改。

### `SetNull`

- `onDelete: SetNull` 參照物件的純量欄位將被設為 `NULL`。

- `onUpdate: SetNull` 當更新被參照物件的識別碼時,參照物件的純量欄位將被設為 `NULL`。

`SetNull` 僅在可選關聯上有效。在必填關聯上,會拋出執行時錯誤,因為純量欄位不能為 null。

```prisma file=schema.prisma highlight=4;add showLineNumbers
model Post {
  id       Int    @id @default(autoincrement())
  title    String
  //add-next-line
  author   User?  @relation(fields: [authorId], references: [id], onDelete: SetNull, onUpdate: SetNull)
  authorId Int?
}

model User {
  id    Int    @id @default(autoincrement())
  posts Post[]
}
```

##### 使用 `SetNull` 的結果

當刪除 `User` 時,其所有撰寫的文章的 `authorId` 將被設為 `NULL`。

當更改 `User` 的 `id` 時,其所有撰寫的文章的 `authorId` 將被設為 `NULL`。

### `SetDefault`

- `onDelete: SetDefault` 參照物件的純量欄位將被設為該欄位的預設值。

- `onUpdate: SetDefault` 參照物件的純量欄位將被設為該欄位的預設值。

這些需要使用 [`@default`](/orm/reference/prisma-schema-reference#default) 為關聯純量欄位設定預設值。如果沒有為任何純量欄位提供預設值,將會拋出執行時錯誤。

```prisma file=schema.prisma highlight=4,5;add showLineNumbers
model Post {
  id             Int     @id @default(autoincrement())
  title          String
  //add-start
  authorUsername String? @default("anonymous")
  author         User?   @relation(fields: [authorUsername], references: [username], onDelete: SetDefault, onUpdate: SetDefault)
  //add-end
}

model User {
  username String @id
  posts    Post[]
}
```

##### 使用 `SetDefault` 的結果

當刪除 `User` 時,其現有文章的 `authorUsername` 欄位值將被設為 'anonymous'。

當 `User` 的 `username` 更改時,其現有文章的 `authorUsername` 欄位值將被設為 'anonymous'。

### 資料庫特定要求

如果您的資料模型中有[自我關聯](/orm/prisma-schema/data-model/relations/referential-actions/special-rules-for-referential-actions#self-relation-sql-server-and-mongodb)或[循環關聯](/orm/prisma-schema/data-model/relations/referential-actions/special-rules-for-referential-actions#cyclic-relation-between-three-tables-sql-server-and-mongodb),MongoDB 和 SQL Server 對參照動作有特定要求。如果您有具有[多個串聯路徑](/orm/prisma-schema/data-model/relations/referential-actions/special-rules-for-referential-actions#multiple-cascade-paths-between-two-models-sql-server-only)的關聯,SQL Server 也有特定要求。

## 從版本 2.25.0 及更早版本升級的路徑

升級時您可以採取幾種路徑,這將根據期望的結果產生不同的結果。

如果您目前使用遷移工作流程,您可以執行內省來檢查預設值如何在您的 schema 中反映。如果需要,您可以手動更新您的資料庫。

您也可以決定跳過檢查預設值,並執行遷移以使用[新的預設值](#referential-action-defaults)更新您的資料庫。

以下假設您已升級到 2.26.0 或更新版本並啟用了預覽功能旗標,或升級到 3.0.0 或更新版本:

### 使用內省

如果您[內省](/orm/prisma-schema/introspection)您的資料庫,在資料庫層級配置的參照動作將反映在您的 Prisma Schema 中。如果您一直使用 Prisma Migrate 或 `prisma db push` 來管理資料庫 schema,這些可能是 2.25.0 及更早版本的[預設值](#referential-action-defaults)。

當您執行內省時,Prisma ORM 會將資料庫中的所有外鍵與 schema 進行比較,如果 SQL 語句 `ON DELETE` 和 `ON UPDATE` **不**符合預設值,它們將在 schema 檔案中明確設定。

內省後,您可以檢視 schema 中的非預設子句。最重要的要檢視的子句是 `onDelete`,在 2.25.0 及更早版本中預設為 `Cascade`。

:::warning

如果您使用 [`delete()`](/orm/prisma-client/queries/crud#delete-a-single-record) 或 [`deleteMany()`](/orm/prisma-client/queries/crud#delete-all-records) 方法,**現在將執行[串聯刪除](#how-to-use-cascading-deletes)**,因為 `referentialActions` 預覽功能**移除了 Prisma Client 中先前防止執行時串聯刪除的安全網**。請務必檢查您的程式碼並進行相應的調整。

:::

確保您對 schema 中每個 `onDelete: Cascade` 的情況都滿意。如果不滿意,可以:

- 修改您的 Prisma schema 並使用 `db push` 或 `dev migrate` 來更改資料庫

_或_

- 如果您使用僅內省工作流程,則手動更新底層資料庫

以下範例會導致串聯刪除,如果 `User` 被刪除,他們的所有 `Post` 也會被刪除。

#### 部落格 schema 範例

```prisma showLineNumbers
model Post {
  id       Int    @id @default(autoincrement())
  title    String
  //add-next-line
  author   User   @relation(fields: [authorId], references: [id], onDelete: Cascade)
  authorId Int
}

model User {
  id    Int    @id @default(autoincrement())
  posts Post[]
}
```

### Using Migration

When running a [Migration](/orm/prisma-migrate) (or the [`prisma db push`](/orm/prisma-migrate/workflows/prototyping-your-schema) command) the [new defaults](#referential-action-defaults) will be applied to your database.

:::info

Unlike when you run an Introspect for the first time, the new referential actions clause and property, will **not** automatically be added to your prisma schema by the Prisma VSCode extension.
You will have to manually add them if you wish 使用 anything other than the new defaults.

:::

Explicitly defining referential actions in your Prisma schema is optional. If you do not explicitly define a referential action for a relation, Prisma ORM uses the [new defaults](#referential-action-defaults).

請注意 referential actions can be added on a case by case basis. This means that 您可以 add them to one single relation and leave the rest set to the defaults by not manually specifying anything.

### Checking for errors

**Before** upgrading to 2.26.0 and enabling the referential actions **preview feature**, Prisma ORM prevented the deletion of records while using `delete()` or `deleteMany()` to preserve referential integrity. A custom runtime error would be thrown by Prisma Client with the error code `P2014`.

**After** upgrading and enabling the referential actions **preview feature**, Prisma ORM no longer performs runtime checks. 您可以 instead specify a custom referential action to preserve the referential integrity between relations.

When you use [`NoAction`](#noaction) or [`Restrict`](#restrict) to prevent the deletion of records, the error messages will be different post 2.26.0 compared to pre 2.26.0. This is because they are now triggered by the database and **not** Prisma Client. The new error code that can be expected is `P2003`.

To make sure you catch these new errors 您可以 adjust your code accordingly.

#### Example of catching errors

以下範例 uses the below blog schema with a one-to-many relationship between `Post` and `User` and sets a [`Restrict`](#restrict) referential actions on the `author` field.

This means that if a user has a post, that user (and their posts) **cannot** be deleted.

```prisma file=schema.prisma showLineNumbers
model Post {
  id       Int    @id @default(autoincrement())
  title    String
  author   User   @relation(fields: [authorId], references: [id], onDelete: Restrict)
  authorId String
}

model User {
  id    Int    @id @default(autoincrement())
  posts Post[]
}
```

Prior to upgrading and enabling the referential actions **preview feature**, the error code you would receive when trying 刪除 a user which has posts would be `P2014` and it's message:

> "The change you are trying to make would violate the required relation '\{relation_name}' between the \{model_a_name\} and \{model_b_name\} models."

```ts
import { PrismaClient } from '../prisma/generated/client'

const prisma = new PrismaClient()

async function main() {
  try {
    await prisma.user.delete({
      where: {
        id: 'some-long-id',
      },
    })
  } catch (error) {
    if (error instanceof Prisma.PrismaClientKnownRequestError) {
      if (error.code === 'P2014') {
        console.log(error.message)
      }
    }
  }
}

main()
```
