## 如果關聯欄位順序改變，隱式多對多自身關聯會返回錯誤資料

### 問題

在以下隱式多對多自身關聯中，關聯欄位 `a_eats` (1) 和 `b_eatenBy` (2) 的字母順序：

```prisma highlight=4,5;normal
model Animal {
  id        Int      @id @default(autoincrement())
  name      String
  //highlight-start
  a_eats    Animal[] @relation(name: "FoodChain")
  b_eatenBy Animal[] @relation(name: "FoodChain")
  //highlight-end
}
```

SQL 中產生的關聯表如下所示，其中 `A` 代表獵物（`a_eats`），`B` 代表掠食者（`b_eatenBy`）：

| A            | B          |
| :----------- | :--------- |
| 8 (Plankton) | 7 (Salmon) |
| 7 (Salmon)   | 9 (Bear)   |

以下查詢返回鮭魚的獵物和掠食者：

<cmd>

```ts
const getAnimals = await prisma.animal.findMany({
  where: {
    name: 'Salmon',
  },
  include: {
    b_eats: true,
    a_eatenBy: true,
  },
})
```

</cmd>
<cmdResult>

```js no-copy

  "name": "Salmon",
  "b_eats": [
    {
      "id": 8,

    {
      "id": 9,
      "name": "Bear"
    }
  ]

```

</cmdResult>

現在更改關聯欄位的順序：

```prisma highlight=4,5;normal
model Animal {
  id        Int      @id @default(autoincrement())
  name      String
  //highlight-start
  b_eats    Animal[] @relation(name: "FoodChain")
  a_eatenBy Animal[] @relation(name: "FoodChain")
  //highlight-end
}
```

遷移您的更改並重新生成 Prisma Client。當您使用更新的欄位名稱執行相同的查詢時，Prisma Client 會返回錯誤的資料（鮭魚現在吃熊並被浮游生物吃掉）：

<CodeWithResult expanded="{true}" outputResultText="query">

```ts
  },

    a_eatenBy: true,
  },
})
```

</cmd>

```js no-copy

  "id": 1,
  "name": "Salmon",
  "b_eats": [
    {
      "id": 3,
      "name": "Bear"
    }
  ],

    {
      "id": 2,
      "name": "Plankton"
    }
  ]

```

</cmdResult>

雖然 Prisma schema 中關聯欄位的字母順序改變了，但資料庫中的 `A` 和 `B` 欄位**沒有改變**（它們沒有被重新命名，資料也沒有移動）。因此，`A` 現在代表掠食者（`a_eatenBy`），`B` 代表獵物（`b_eats`）：

| A            | B          |
| :----------- | :--------- |
| 8 (Plankton) | 7 (Salmon) |
| 7 (Salmon)   | 9 (Bear)   |

### 解決方案

如果您在隱式多對多自身關聯中重新命名關聯欄位，請確保維持欄位的字母順序 - 例如，透過使用 `a_` 和 `b_` 前綴。

## 如何在多對多關係中使用關聯表

有幾種方法可以定義 m-n 關係，隱式或顯式。隱式意味著讓 Prisma ORM 在底層處理關聯表（JOIN 表），您只需在每個 model 上為非純量類型定義陣列/列表，請參閱[隱式多對多關聯](/orm/prisma-schema/data-model/relations/many-to-many-relations#implicit-many-to-many-relations)。

當建立[顯式 m-n 關係](/orm/prisma-schema/data-model/relations/many-to-many-relations#explicit-many-to-many-relations)時，您可能會遇到麻煩，也就是自己建立和處理關聯表。**可能會被忽視的是，Prisma ORM 要求關聯的雙方都必須存在**。

以下範例建立了一個關聯表來充當 `Post` 和 `Category` 表之間的 JOIN。但這不會正常運作，因為關聯表（`PostCategories`）必須與其他兩個 model 分別形成 1 對多關係。

`Post` 到 `PostCategories` 和 `Category` 到 `PostCategories` model 缺少反向關聯欄位。


```prisma
// 此範例 schema 顯示如何不定義顯式 m-n 關聯

model Post {
  id             Int              @id @default(autoincrement())
  title          String
  categories     Category[] // 這應該引用 PostCategories
}

model PostCategories {
  post       Post     @relation(fields: [postId], references: [id])
  postId     Int
  category   Category @relation(fields: [categoryId], references: [id])
  categoryId Int
  @@id([postId, categoryId])
}

model Category {
  id             Int              @id @default(autoincrement())
  name           String
  posts          Post[] // 這應該引用 PostCategories
}
```


要修復此問題，`Post` model 需要定義一個與關聯表 `PostCategories` 的多關聯欄位。`Category` model 也是如此。

這是因為關聯 model 與它所連接的其他兩個 model 形成 1 對多關係。

```prisma highlight=5,21;add|4,20;delete
model Post {
  id             Int              @id @default(autoincrement())
  title          String
  //delete-next-line
  categories     Category[]
  //add-next-line
  postCategories PostCategories[]
}

model PostCategories {
  post       Post     @relation(fields: [postId], references: [id])
  postId     Int
  category   Category @relation(fields: [categoryId], references: [id])
  categoryId Int

  @@id([postId, categoryId])
}

model Category {
  id             Int              @id @default(autoincrement())
  name           String
  //delete-next-line
  posts          Post[]
  //add-next-line
  postCategories PostCategories[]
}
```

## 在多對多關係中使用 `@relation` 屬性

在撰寫隱式多對多關係時，在 model 的關聯欄位上新增 `@relation("Post")` 註解似乎是合理的。

```prisma
model Post {
  id         Int        @id @default(autoincrement())
  title      String
  categories Category[] @relation("Category")
  Category   Category?  @relation("Post", fields: [categoryId], references: [id])
  categoryId Int?
}

model Category {
  id     Int    @id @default(autoincrement())
  name   String
  posts  Post[] @relation("Post")
  Post   Post?  @relation("Category", fields: [postId], references: [id])
  postId Int?
}
```

但這會告訴 Prisma ORM 期望**兩個**獨立的一對多關係。有關使用 `@relation` 屬性的更多資訊，請參閱[消除關聯歧義](/orm/prisma-schema/data-model/relations#disambiguating-relations)。

以下範例是定義隱式多對多關係的正確方式。

```prisma highlight=4,11;delete|5,12;add
model Post {
  id         Int        @id @default(autoincrement())
  title      String
  //delete-next-line
  categories Category[] @relation("Category")
  //add-next-line
  categories Category[]
}

model Category {
  id    Int    @id @default(autoincrement())
  name  String
  //delete-next-line
  posts Post[] @relation("Post")
  //add-next-line
  posts Post[]
}
```

`@relation` 註解也可以用於[命名底層關聯表](/orm/prisma-schema/data-model/relations/many-to-many-relations#configuring-the-name-of-the-relation-table-in-implicit-many-to-many-relations)，該表在隱式多對多關係上建立。

```prisma
model Post {
  id         Int        @id @default(autoincrement())
  title      String
  categories Category[] @relation("CategoryPostRelation")
}

model Category {
  id    Int    @id @default(autoincrement())
  name  String
  posts Post[] @relation("CategoryPostRelation")
}
```

## 在強制主鍵的資料庫中使用 m-n 關聯

### 問題

某些雲端提供商在所有表中強制要求主鍵存在。但是，Prisma ORM 為多對多關聯使用隱式語法（透過 `@relation` 表示）建立的任何關聯表（JOIN 表）都沒有主鍵。

### 解決方案

您需要使用[顯式關聯語法](/orm/prisma-schema/data-model/relations/many-to-many-relations#explicit-many-to-many-relations)，手動建立連接 model，並驗證此連接 model 具有主鍵。
