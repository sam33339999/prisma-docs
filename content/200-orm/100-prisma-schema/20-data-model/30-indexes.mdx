<TopBlock>

Prisma ORM 允許配置資料庫索引、唯一約束和主鍵約束。這在版本 `4.0.0` 及更高版本中為正式版本。您可以在版本 `3.5.0` 及更高版本中透過 `extendedIndexes` 預覽功能啟用此功能。

版本 `3.6.0` 還透過新的 `@@fulltext` 屬性引入了對 MySQL 和 MongoDB 中全文索引的自省和遷移支援,可透過 `fullTextIndex` 預覽功能使用。

:::warning

如果您從 4.0.0 之前的版本升級,這些索引配置和全文索引的變更可能是**破壞性變更**,如果您的資料庫已經使用這些功能。請參閱[從早期版本升級](#upgrading-from-previous-versions)以獲取有關如何升級的更多資訊。

:::

</TopBlock>

## 索引配置

您可以使用以下屬性參數配置索引、唯一約束和主鍵約束:

- [`length` 參數](#configuring-the-length-of-indexes-with-length-mysql)允許您為 `String` 和 `Bytes` 類型的索引值子部分指定最大長度

  - 在 `@id`、`@@id`、`@unique`、`@@unique` 和 `@@index` 屬性上可用
  - 僅限 MySQL

- [`sort` 參數](#configuring-the-index-sort-order-with-sort)允許您指定約束或索引的條目在資料庫中儲存的順序

  - 在所有資料庫的 `@unique`、`@@unique` 和 `@@index` 屬性上可用,以及在 SQL Server 的 `@id` 和 `@@id` 屬性上可用

- [`type` 參數](#configuring-the-access-type-of-indexes-with-type-postgresql)允許您支援 PostgreSQL 預設 `BTree` 存取方法以外的索引存取方法

  - 在 `@@index` 屬性上可用
  - 僅限 PostgreSQL
  - 支援的索引存取方法: `Hash`、`Gist`、`Gin`、`SpGist` 和 `Brin`

- [`clustered` 參數](#configuring-if-indexes-are-clustered-or-non-clustered-with-clustered-sql-server)允許您配置約束或索引是叢集還是非叢集
  - 在 `@id`、`@@id`、`@unique`、`@@unique` 和 `@@index` 屬性上可用
  - 僅限 SQL Server

請參閱連結的章節以了解每個功能首次引入的版本詳細資訊。

### 使用 `length` 配置索引長度 (MySQL)

`length` 參數特定於 MySQL,允許您在 `String` 和 `Byte` 類型的欄位上定義索引和約束。對於這些類型,MySQL 要求您為要索引的值子部分指定最大長度,以防完整值超過 MySQL 對索引大小的限制。請參閱 [MySQL 文件](https://dev.mysql.com/doc/refman/8.0/en/innodb-limits.html)以獲取更多詳細資訊。

`length` 參數在 `@id`、`@@id`、`@unique`、`@@unique` 和 `@@index` 屬性上可用。它在版本 4.0.0 及更高版本中為正式版本,並在版本 3.5.0 及更高版本中作為 `extendedIndexes` 預覽功能的一部分可用。

例如,以下資料模型宣告了一個最大長度為 3000 個字元的 `id` 欄位:

```prisma file=schema.prisma showLineNumbers
model Id {
  id String @id @db.VarChar(3000)
}
```

這在 MySQL 中無效,因為它超過了 MySQL 的索引儲存限制,因此 Prisma ORM 拒絕此資料模型。生成的 SQL 將被資料庫拒絕。

```sql
CREATE TABLE `Id` (
  `id` VARCHAR(3000) PRIMARY KEY
)
```

`length` 參數允許您指定只有 `id` 值的一個子部分代表主鍵。在下面的範例中,使用前 100 個字元:

```prisma file=schema.prisma showLineNumbers
model Id {
  id String @id(length: 100) @db.VarChar(3000)
}
```

如果在資料模型中指定,Prisma Migrate 能夠建立帶有 `length` 參數的約束和索引。這意味著您可以在 Prisma schema 類型 `Byte` 和 `String` 的值上建立索引和約束。如果您不指定參數,索引將被視為覆蓋完整值,如之前一樣。

自省將獲取資料庫中存在的這些限制。這允許 Prisma ORM 支援先前被抑制的索引和約束,並改善對使用此功能的 MySQL 資料庫的支援。

`length` 參數也可以用於複合主鍵,使用 `@@id` 屬性,如下面的範例所示:

```prisma file=schema.prisma showLineNumbers
model CompoundId {
  id_1 String @db.VarChar(3000)
  id_2 String @db.VarChar(3000)

  @@id([id_1(length: 100), id_2(length: 10)])
}
```

類似的語法可用於 `@@unique` 和 `@@index` 屬性。

### 使用 `sort` 配置索引排序順序

`sort` 參數允許您指定索引或約束的條目在資料庫中儲存的順序。這可能會影響資料庫是否能夠為特定查詢使用索引。行為和支援因資料庫而異:

- 在 MySQL/MariaDB 中,您可以直接在唯一約束和索引中指定排序順序(`ASC`/`DESC`)
- 在 PostgreSQL 中,排序順序只能在索引上指定,不能在唯一約束上指定
- 在 SQL Server 中,所有約束和索引(包括 `@id` 和 `@@id`)都支援排序順序

`sort` 參數在版本 4.0.0 及更高版本中為正式版本,並在版本 3.5.0 及更高版本中作為 `extendedIndexes` 預覽功能的一部分可用。

例如,在 MySQL/MariaDB 中,使用降序唯一約束的以下表格:

```sql
CREATE TABLE `Unique` (
  `unique` INT,
  CONSTRAINT `Unique_unique_key` UNIQUE (`unique` DESC)
)
```

將被自省為

```prisma file=schema.prisma showLineNumbers
model Unique {
  unique Int @unique(sort: Desc)
}
```

請注意,在 PostgreSQL 中,雖然您不能直接在唯一約束上指定排序順序,但您可以建立一個具有排序順序的唯一索引來強制唯一性:

```sql
-- PostgreSQL approach
CREATE UNIQUE INDEX "unique_index_desc" ON "Unique" ("unique" DESC);
```

`sort` 參數也可以用於複合索引:

```prisma file=schema.prisma showLineNumbers
model CompoundUnique {
  unique_1 Int
  unique_2 Int

  @@unique([unique_1(sort: Desc), unique_2])
}
```

### 範例: 同時使用 `sort` 和 `length`

以下範例示範了如何使用 `sort` 和 `length` 參數來配置 `Post` 模型的索引和約束:

```prisma file=schema.prisma showLineNumbers
model Post {
  title      String   @db.VarChar(300)
  abstract   String   @db.VarChar(3000)
  slug       String   @unique(sort: Desc, length: 42) @db.VarChar(3000)
  author     String
  created_at DateTime

  @@id([title(length: 100, sort: Desc), abstract(length: 10)])
  @@index([author, created_at(sort: Desc)])
}
```

### 使用 `type` 配置索引的存取類型 (PostgreSQL)

`type` 參數可用於在 PostgreSQL 中使用 `@@index` 屬性配置索引類型。可用的索引存取方法有 `Hash`、`Gist`、`Gin`、`SpGist` 和 `Brin`,以及預設的 `BTree` 索引存取方法。`type` 參數在版本 4.0.0 及更高版本中為正式版本。`Hash` 索引存取方法在版本 3.6.0 及更高版本中作為 `extendedIndexes` 預覽功能的一部分可用,而 `Gist`、`Gin`、`SpGist` 和 `Brin` 索引存取方法在版本 3.14.0 及更高版本中處於預覽狀態。

#### Hash

`Hash` 類型將以更快的搜尋和插入格式儲存索引資料,並且使用更少的磁碟空間。但是,只有 `=` 和 `<>` 比較可以使用索引,因此其他比較運算子如 `<` 和 `>` 在使用 `Hash` 時會比使用預設的 `BTree` 類型慢得多。

例如,以下模型為 `value` 欄位新增了一個 `type` 為 `Hash` 的索引:

```prisma file=schema.prisma showLineNumbers
model Example {
  id    Int @id
  value Int

  @@index([value], type: Hash)
}
```

這轉換為以下 SQL 命令:

```sql
CREATE TABLE "Example" (
  id INT PRIMARY KEY,
  value INT NOT NULL
);

CREATE INDEX "Example_value_idx" ON "Example" USING HASH (value);
```

#### 廣義倒排索引 (GIN)

GIN 索引儲存複合值,例如陣列或 `JsonB` 資料。這對於加速查詢一個物件是否為另一個物件的一部分很有用。它通常用於全文搜尋。

索引欄位可以定義運算子類別,該類別定義索引處理的運算子。

:::warning

Prisma ORM 尚不支援使用函式(例如 `to_tsvector`)來確定索引值的索引。以這種方式定義的索引在使用 `prisma db pull` 時將不可見。

:::

例如,以下模型為 `value` 欄位新增了一個 `Gin` 索引,並將 `JsonbPathOps` 作為允許使用索引的運算子類別:

```prisma file=schema.prisma showLineNumbers
model Example {
  id    Int  @id
  value Json
  //    ^ field type matching the operator class
  //                  ^ operator class      ^ index type

  @@index([value(ops: JsonbPathOps)], type: Gin)
}
```

這轉換為以下 SQL 命令:

```sql
CREATE TABLE "Example" (
  id INT PRIMARY KEY,
  value JSONB NOT NULL
);

CREATE INDEX "Example_value_idx" ON "Example" USING GIN (value jsonb_path_ops);
```

作為 `JsonbPathOps` 的一部分,`@>` 運算子由索引處理,加速查詢如 `value @> '{"foo": 2}'`。

##### GIN 支援的運算子類別

Prisma ORM 通常支援 PostgreSQL 版本 10 及更高版本提供的運算子類別。如果運算子類別需要欄位類型為 Prisma ORM 尚不支援的類型,使用帶有字串輸入的 `raw` 函式允許您使用這些運算子類別而無需驗證。

預設運算子類別(標記為 ✅)可以從索引定義中省略。

| 運算子類別     | 允許的欄位類型(原生類型) | 預設 | 其他                          |
| -------------- | --------------------------------- | ------- | ----------------------------- |
| `ArrayOps`     | 任何陣列                          | ✅      | 也可在 CockroachDB 中使用     |
| `JsonbOps`     | `Json` (`@db.JsonB`)              | ✅      | 也可在 CockroachDB 中使用     |
| `JsonbPathOps` | `Json` (`@db.JsonB`)              |         |                               |
| `raw("other")` |                                   |         |                               |

請在[官方 PostgreSQL 文件](https://www.postgresql.org/docs/14/gin-builtin-opclasses.html)中閱讀更多關於內建運算子類別的資訊。

##### CockroachDB

GIN 和 BTree 是 CockroachDB 支援的唯一索引類型。標記為與 CockroachDB 配合使用的運算子類別是該資料庫上唯一允許且受 Prisma ORM 支援的運算子類別。運算子類別無法在 Prisma Schema Language 中定義:`ops` 參數在 CockroachDB 上不是必需的或不允許的。

#### 廣義搜尋樹 (GiST)

GiST 索引類型用於為使用者定義的類型實作索引方案。預設情況下,GiST 索引沒有太多直接用途,但例如 B-Tree 索引類型是使用 GiST 索引建構的。

例如,以下模型為 `value` 欄位新增了一個 `Gist` 索引,並將 `InetOps` 作為將使用索引的運算子:

```prisma file=schema.prisma showLineNumbers
model Example {
  id    Int    @id
  value String @db.Inet
  //           ^ native type matching the operator class
  //                                   ^ index type
  //                  ^ operator class

  @@index([value(ops: InetOps)], type: Gist)
}
```

這轉換為以下 SQL 命令:

```sql
CREATE TABLE "Example" (
  id INT PRIMARY KEY,
  value INET NOT NULL
);

CREATE INDEX "Example_value_idx" ON "Example" USING GIST (value inet_ops);
```

比較 IP 位址的查詢,例如 `value > '10.0.0.2'`,將使用索引。

##### GiST 支援的運算子類別

Prisma ORM 通常支援 PostgreSQL 版本 10 及更高版本提供的運算子類別。如果運算子類別需要欄位類型為 Prisma ORM 尚不支援的類型,使用帶有字串輸入的 `raw` 函式允許您使用這些運算子類別而無需驗證。

| 運算子類別     | 允許的欄位類型(允許的原生類型) |
| -------------- | ----------------------------------------- |
| `InetOps`      | `String` (`@db.Inet`)                     |
| `raw("other")` |                                           |

請在[官方 PostgreSQL 文件](https://www.postgresql.org/docs/14/gist-builtin-opclasses.html)中閱讀更多關於內建運算子類別的資訊。

#### 空間分割 GiST (SP-GiST)

SP-GiST 索引對於許多不同的非平衡資料結構是一個不錯的選擇。如果查詢與分割規則匹配,它可以非常快。

與 GiST 一樣,SP-GiST 作為使用者定義類型的構建塊非常重要,允許直接使用資料庫實作自訂搜尋運算子。

例如,以下模型為 `value` 欄位新增了一個 `SpGist` 索引,並將 `TextOps` 作為使用索引的運算子:

```prisma file=schema.prisma showLineNumbers
model Example {
  id    Int    @id
  value String
  //    ^ field type matching the operator class

  @@index([value], type: SpGist)
  //                     ^ index type
  //       ^ using the default ops: TextOps
}
```

這轉換為以下 SQL 命令:

```sql
CREATE TABLE "Example" (
  id INT PRIMARY KEY,
  value TEXT NOT NULL
);

CREATE INDEX "Example_value_idx" ON "Example" USING SPGIST (value);
```

查詢如 `value LIKE 'something%'` 將被索引加速。

##### SP-GiST 支援的運算子類別

Prisma ORM 通常支援 PostgreSQL 版本 10 及更高版本提供的運算子類別。如果運算子類別需要欄位類型為 Prisma ORM 尚不支援的類型,使用帶有字串輸入的 `raw` 函式允許您使用這些運算子類別而無需驗證。

預設運算子類別(標記為 ✅)可以從索引定義中省略。

| 運算子類別     | 允許的欄位類型(原生類型)    | 預設 | 支援的 PostgreSQL 版本 |
| -------------- | ------------------------------------ | ------- | ----------------------------- |
| `InetOps`      | `String` (`@db.Inet`)                | ✅      | 10+                           |
| `TextOps`      | `String` (`@db.Text`, `@db.VarChar`) | ✅      |                               |
| `raw("other")` |                                      |         |                               |

請在[官方 PostgreSQL 文件](https://www.postgresql.org/docs/14/spgist-builtin-opclasses.html)中閱讀更多關於內建運算子類別的資訊。

#### 區塊範圍索引 (BRIN)

BRIN 索引類型對於您有大量資料在插入後不會變更的情況很有用,例如日期和時間值。如果您的資料非常適合索引,它可以在最小的空間中儲存大型資料集。

例如,以下模型為 `value` 欄位新增了一個 `Brin` 索引,並將 `Int4BloomOps` 作為將使用索引的運算子:

```prisma file=schema.prisma showLineNumbers
model Example {
  id    Int @id
  value Int
  //    ^ field type matching the operator class
  //                  ^ operator class      ^ index type

  @@index([value(ops: Int4BloomOps)], type: Brin)
}
```

這轉換為以下 SQL 命令:

```sql
CREATE TABLE "Example" (
  id INT PRIMARY KEY,
  value INT4 NOT NULL
);

CREATE INDEX "Example_value_idx" ON "Example" USING BRIN (value int4_bloom_ops);
```

查詢如 `value = 2` 現在將使用索引,該索引使用的空間是 `BTree` 或 `Hash` 索引使用的空間的一小部分。

| `raw("other")`              |                                      |         |                               |

請在[官方 PostgreSQL 文件](https://www.postgresql.org/docs/14/brin-builtin-opclasses.html)中閱讀更多關於內建運算子類別的資訊。

### 使用 `clustered` 配置索引是否為叢集或非叢集 (SQL Server)

`clustered` 參數可用於在 SQL Server 中配置(非)叢集索引。它可以在 `@id`、`@@id`、`@unique`、`@@unique` 和 `@@index` 屬性上使用。它在版本 4.0.0 及更高版本中為正式版本,並在版本 3.13.0 及更高版本中作為 `extendedIndexes` 預覽功能的一部分可用。

例如,以下模型將 `@id` 配置為非叢集(而不是叢集預設值):

```prisma file=schema.prisma showLineNumbers
model Example {
  id    Int @id(clustered: false)
  value Int
}
```

這轉換為以下 SQL 命令:

```sql
CREATE TABLE [Example] (
  id INT NOT NULL,
  value INT,
  CONSTRAINT [Example_pkey] PRIMARY KEY NONCLUSTERED (id)
)
```

每個屬性的 `clustered` 預設值如下:

| 屬性       | 值      |
| ---------- | ------- |
| `@id`      | `true`  |
| `@@id`     | `true`  |
| `@unique`  | `false` |
| `@@unique` | `false` |
| `@@index`  | `false` |

一個表格最多可以有一個叢集索引。

### 從早期版本升級

:::warning

這些索引配置變更可能是**破壞性變更**,當為現有資料庫的某些現有 Prisma schema 啟用功能時。在啟用使用它們所需的預覽功能後,執行 `prisma db pull` 以自省現有資料庫以更新您的 Prisma schema,然後再次使用 Prisma Migrate。

:::

在以下情況下可能會發生破壞性變更:

- **現有的排序約束和索引**: 如果沒有明確指定順序,早期版本的 Prisma ORM 將假設所需的排序順序為_升序_。這意味著,如果您有使用降序排序順序的現有約束或索引,並且在沒有首先在資料模型中指定這一點的情況下遷移資料庫,這將是一個破壞性變更。
- **現有的長度約束和索引**: 在早期版本的 Prisma ORM 中,在 MySQL 中長度受限的索引和約束無法在 Prisma schema 中表示。因此,`prisma db pull` 沒有獲取這些,您也無法手動指定它們。當您執行 `prisma db push` 或 `prisma migrate dev` 時,如果它們已經存在於資料庫中,它們會被忽略。由於您現在能夠指定這些,如果它們在資料模型中缺少但在資料庫中存在,遷移命令現在將刪除它們。
- **現有的非 `BTree` 索引 (PostgreSQL)**: 早期版本的 Prisma ORM 僅支援預設的 `BTree` 索引類型。其他支援的索引(`Hash`、`Gist`、`Gin`、`SpGist` 和 `Brin`)需要在遷移資料庫之前新增。
- **現有的(非)叢集索引 (SQL Server)**: 早期版本的 Prisma ORM 不支援將索引配置為叢集或非叢集。對於不使用預設值的索引,這些需要在遷移資料庫之前新增。

在上述每種情況下,都可以透過在資料模型中適當地指定這些屬性來防止對資料庫的不需要的變更。**最簡單的方法是使用 `prisma db pull` 來檢索任何現有的約束或配置。**或者,您也可以手動新增這些參數。這應該在升級後第一次使用 `prisma db push` 或 `prisma migrate dev` 之前完成。

## 全文索引 (MySQL 和 MongoDB)

`fullTextIndex` 預覽功能在版本 3.6.0 及更高版本中提供對 MySQL 和 MongoDB 中全文索引的自省和遷移支援。這可以使用 `@@fulltext` 屬性配置。資料庫中的現有全文索引在使用 `db pull` 自省後會新增到您的 Prisma schema 中,並且在 Prisma schema 中新增的新全文索引在使用 Prisma Migrate 時會在資料庫中建立。這也可以防止在某些以前無法工作的資料庫 schema 中出現驗證錯誤。

:::warning

目前我們不會在 Prisma Client 中為 MongoDB 啟用全文搜尋命令;進度可以在 [MongoDB](https://github.com/prisma/prisma/issues/9413) 問題中追蹤。

:::

### 啟用 `fullTextIndex` 預覽功能

要啟用 `fullTextIndex` 預覽功能,請將 `fullTextIndex` 功能標誌新增到 `schema.prisma` 檔案的 `generator` 區塊中:

```prisma file=schema.prisma showLineNumbers
generator client {
  provider        = "prisma-client"
  output          = "./generated"
  previewFeatures = ["fullTextIndex"]
}
```

### 範例

以下範例示範了為 `Post` 模型的 `title` 和 `content` 欄位新增 `@@fulltext` 索引:

```prisma file=schema.prisma showLineNumbers
model Post {
  id      Int    @id
  title   String @db.VarChar(255)
  content String @db.Text

  @@fulltext([title, content])
}
```

在 MongoDB 上,您可以使用 `@@fulltext` 索引屬性(透過 `fullTextIndex` 預覽功能)與 `sort` 參數一起以升序或降序將欄位新增到您的全文索引中。以下範例為 `Post` 模型的 `title` 和 `content` 欄位新增了一個 `@@fulltext` 索引,並以降序排序 `title` 欄位:

```prisma file=schema.prisma showLineNumbers
generator js {
  provider        = "prisma-client-js"
  previewFeatures = ["fullTextIndex"]
}

datasource db {
  provider = "mongodb"
  url      = env("DATABASE_URL")
}

model Post {
  id      String @id @map("_id") @db.ObjectId
  title   String
  content String

  @@fulltext([title(sort: Desc), content])
}
```

### 從早期版本升級

:::warning

這可能是**破壞性變更**,當為現有資料庫的某些現有 Prisma schema 啟用功能時。在啟用使用它們所需的預覽功能後,執行 `prisma db pull` 以自省現有資料庫以更新您的 Prisma schema,然後再次使用 Prisma Migrate。

:::

早期版本的 Prisma ORM 使用 `@@index` 屬性而不是 `@@fulltext` 屬性轉換全文索引。在啟用 `fullTextIndex` 預覽功能後,執行 `prisma db pull` 以在再次使用 Prisma Migrate 遷移之前將這些索引轉換為 `@@fulltext`。如果您不這樣做,現有的索引將被刪除,並在它們的位置建立普通索引。
