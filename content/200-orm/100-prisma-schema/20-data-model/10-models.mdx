[Prisma schema](/orm/prisma-schema) 的資料模型定義部分定義了您的應用程式模型(也稱為 **Prisma 模型**)。模型:

- 代表您應用程式領域的**實體**
- 對應到資料庫中的**表格**(關聯式資料庫如 PostgreSQL)或**集合**(MongoDB)
- 形成生成的 [Prisma Client API](/orm/prisma-client) 中可用**查詢**的基礎
- 當與 TypeScript 一起使用時,Prisma Client 為您的模型及其任何[變體](/orm/prisma-client/type-safety/operating-against-partial-structures-of-model-types)提供生成的**型別定義**,使資料庫存取完全型別安全。

以下 schema 描述了一個部落格平台 - 資料模型定義已被標記:

您的資料模型反映_您的_應用程式領域。例如:

- 在**電商**應用程式中,您可能有 `Customer`、`Order`、`Item` 和 `Invoice` 等模型。
- 在**社群媒體**應用程式中,您可能有 `User`、`Post`、`Photo` 和 `Message` 等模型。

## 自省和遷移

有兩種方式可以定義資料模型:

- **手動撰寫資料模型並使用 Prisma Migrate**: 您可以手動撰寫資料模型,並使用 [Prisma Migrate](/orm/prisma-migrate) 將其對應到您的資料庫。在這種情況下,資料模型是應用程式模型的單一真實來源。
- **透過自省生成資料模型**: 當您擁有現有資料庫或偏好使用 SQL 遷移資料庫 schema 時,您可以透過[自省](/orm/prisma-schema/introspection)資料庫來生成資料模型。在這種情況下,資料庫 schema 是應用程式模型的單一真實來源。

## 定義模型

模型代表您應用程式領域的實體。模型由 [`model`](/orm/reference/prisma-schema-reference#model) 區塊表示,並定義多個[欄位](/orm/reference/prisma-schema-reference#model-fields)。在上面的範例資料模型中,`User`、`Profile`、`Post` 和 `Category` 都是模型。

部落格平台可以擴展以下模型:

```prisma
model Comment {
  // Fields
}

model Tag {
  // Fields
}
```

### 將模型名稱對應到表格或集合

Prisma 模型的[命名慣例(單數形式、PascalCase)](/orm/reference/prisma-schema-reference#naming-conventions)並不總是與資料庫中的表格名稱相符。資料庫中表格/集合的常見命名方式是使用複數形式和 [snake_case](https://en.wikipedia.org/wiki/Snake_case) 標記法 - 例如: `comments`。當您自省一個名為 `comments` 的表格的資料庫時,產生的 Prisma 模型將如下所示:

```prisma
model comments {
  // Fields
}
```

然而,您仍然可以遵守命名慣例,而無需在資料庫中重新命名底層的 `comments` 表格,方法是使用 [`@@map`](/orm/reference/prisma-schema-reference#map-1) 屬性:

```prisma
model Comment {
  // Fields

  @@map("comments")
}
```

使用此模型定義,Prisma ORM 會自動將 `Comment` 模型對應到底層資料庫中的 `comments` 表格。

> **注意**: 您也可以 [`@map`](/orm/reference/prisma-schema-reference#map) 欄位名稱或列舉值,以及 `@@map` 列舉名稱。

`@map` 和 `@@map` 允許您[調整 Prisma Client API 的形狀](/orm/prisma-client/setup-and-configuration/custom-model-and-field-names#using-map-and-map-to-rename-fields-and-models-in-the-prisma-client-api),將模型和欄位名稱與底層資料庫中的表格和欄位名稱解耦。

## 定義欄位

模型的屬性稱為_欄位_,其由以下組成:

- 一個**[欄位名稱](/orm/reference/prisma-schema-reference#model-fields)**
- 一個**[欄位類型](/orm/reference/prisma-schema-reference#model-fields)**
- 可選的**[類型修飾符](#type-modifiers)**
- 可選的**[屬性](#defining-attributes)**,包括[原生資料庫類型屬性](#native-types-mapping)

欄位的類型決定其_結構_,並符合以下兩個類別之一:

- [純量類型](#scalar-fields)(包括[列舉](#defining-enums)),對應到資料庫中的欄位(關聯式資料庫)或文件欄位(MongoDB) - 例如 [`String`](/orm/reference/prisma-schema-reference#string) 或 [`Int`](/orm/reference/prisma-schema-reference#int)
- 模型類型(該欄位稱為[關聯欄位](/orm/prisma-schema/data-model/relations#relation-fields)) - 例如 `Post` 或 `Comment[]`。

下表描述了範例 schema 中 `User` 模型的欄位:

| :-------- | :-------- | :---------------------------- | :------------ | :------------------------------------ |
| `id`      | `Int`     | 純量                          | -             | `@id` 和 `@default(autoincrement())` |
| `email`   | `String`  | 純量                          | -             | `@unique`                             |
| `name`    | `String`  | 純量                          | `?`           | -                                     |
| `role`    | `Role`    | 純量 (`enum`)                 | -             | `@default(USER)`                      |
| `posts`   | `Post`    | 關聯 (Prisma 層級欄位)        | `[]`          | -                                     |
| `profile` | `Profile` | 關聯 (Prisma 層級欄位)        | `?`           | -                                     |

</details>

### 關聯欄位

關聯欄位的類型是另一個模型 - 例如,一篇文章(`Post`)可以有多個評論(`Comment[]`):

### 原生類型對應

版本 [2.17.0](https://github.com/prisma/prisma/releases/tag/2.17.0) 及更高版本支援**原生資料庫類型屬性**(類型屬性),用於描述底層資料庫類型:

```prisma highlight=3;normal
model Post {
  id      Int    @id
  //highlight-next-line
  title   String @db.VarChar(200)
  content String
}
```

類型屬性:

- 特定於底層提供者 - 例如,PostgreSQL 對 `Boolean` 使用 `@db.Boolean`,而 MySQL 使用 `@db.TinyInt(1)`
- 使用 PascalCase 撰寫(例如 `VarChar` 或 `Text`)
- 以 `@db` 為前綴,其中 `db` 是您 schema 中 `datasource` 區塊的名稱

此外,在[自省](/orm/prisma-schema/introspection)期間,類型屬性_僅_在底層原生類型**不是預設類型**時才會新增到 schema 中。例如,如果您使用 PostgreSQL 提供者,底層原生類型為 `text` 的 `String` 欄位將不會有類型屬性。

請參閱[每個純量類型和提供者的原生資料庫類型屬性完整列表](/orm/reference/prisma-schema-reference#model-field-scalar-types)。

#### 好處和工作流程

- 控制 [Prisma Migrate](/orm/prisma-migrate) 在資料庫中建立的**確切原生類型** - 例如,`String` 可以是 `@db.VarChar(200)` 或 `@db.Char(50)`
- 當您自省時可以看到**豐富的 schema**

### 類型修飾符

欄位的類型可以透過附加以下兩種修飾符之一來修改:

- [`[]`](/orm/reference/prisma-schema-reference#-modifier) 使欄位成為列表
- [`?`](/orm/reference/prisma-schema-reference#-modifier-1) 使欄位可選

> **注意**: 您**不能**組合類型修飾符 - 不支援可選列表。

#### 列表

以下範例包含一個純量列表和一個相關模型的列表:

```prisma highlight=4,5;normal
  //highlight-end

```

</TabItem>

#### 可選和必填欄位

<TabbedContent code>

當**未**使用 `?` 類型修飾符標註欄位時,該欄位將在模型的每個記錄上都是_必填的_。這在兩個層級上有影響:

- **資料庫**
  - **關聯式資料庫**: 必填欄位在底層資料庫中透過 `NOT NULL` 約束表示。
  - **MongoDB**: 必填欄位不是 MongoDB 資料庫層級的概念。
- **Prisma Client**: Prisma Client 生成的 [TypeScript 類型](#type-definitions)表示應用程式程式碼中的模型,也會將這些欄位定義為必填,以確保它們在執行時總是攜帶值。

> **注意**: 可選欄位的預設值是 `null`。

### 不支援的類型

當您自省關聯式資料庫時,不支援的資料類型會新增為 [`Unsupported`](/orm/reference/prisma-schema-reference#unsupported):

```prisma
location    Unsupported("POLYGON")?
```

`Unsupported` 類型允許您在 Prisma schema 中為 Prisma ORM 尚不支援的資料庫類型定義欄位。例如,MySQL 的 `POLYGON` 類型目前不受 Prisma ORM 支援,但現在可以使用 `Unsupported("POLYGON")` 類型新增到 Prisma schema 中。

`Unsupported` 類型的欄位不會出現在生成的 Prisma Client API 中,但您仍然可以使用 Prisma ORM 的[原始資料庫存取功能](/orm/prisma-client/using-raw-sql/raw-queries)來查詢這些欄位。

> **注意**: 如果模型有**必填的 `Unsupported` 欄位**,生成的 client 將不會包含該模型的 `create` 或 `update` 方法。

> **注意**: MongoDB 連接器不支援也不需要 `Unsupported` 類型,因為它支援所有純量類型。

## 定義屬性

屬性修改欄位或模型區塊的行為。以下範例包含三個欄位屬性([`@id`](/orm/reference/prisma-schema-reference#id)、[`@default`](/orm/reference/prisma-schema-reference#default) 和 [`@unique`](/orm/reference/prisma-schema-reference#unique))和一個區塊屬性([`@@unique`](/orm/reference/prisma-schema-reference#unique-1)):

<TabbedContent code>
<TabItem value="Relational databases">

```prisma
model User {
  id        Int     @id @default(autoincrement())
  firstName String
  lastName  String
  email     String  @unique
  isAdmin   Boolean @default(false)

  @@unique([firstName, lastName])
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma
model User {
  id        String  @id @default(auto()) @map("_id") @db.ObjectId
  firstName String
  lastName  String
  email     String  @unique
  isAdmin   Boolean @default(false)

  @@unique([firstName, lastName])
}
```

</TabItem>
</TabbedContent>

某些屬性接受[參數](/orm/reference/prisma-schema-reference#attribute-argument-types) - 例如,`@default` 接受 `true` 或 `false`:

```prisma
isAdmin   Boolean @default(false) // short form of @default(value: false)
```

請參閱[欄位和區塊屬性的完整列表](/orm/reference/prisma-schema-reference#attributes)

### 定義 ID 欄位

ID 唯一標識模型的單個記錄。一個模型只能有_一個_ ID:

- 在**關聯式資料庫**中,ID 可以是單一欄位或基於多個欄位。如果模型沒有 `@id` 或 `@@id`,您必須定義一個必填的 `@unique` 欄位或 `@@unique` 區塊來代替。
- 在 **MongoDB** 中,ID 必須是定義 `@id` 屬性和 `@map("_id")` 屬性的單一欄位。

#### 在關聯式資料庫中定義 ID

在關聯式資料庫中,ID 可以使用 [`@id`](/orm/reference/prisma-schema-reference#id) 屬性由單一欄位定義,或使用 [`@@id`](/orm/reference/prisma-schema-reference#id-1) 屬性由多個欄位定義。

##### 單一欄位 ID

在以下範例中,`User` ID 由 `id` 整數欄位表示:

```prisma highlight=2;normal
model User {
  //highlight-next-line
  id      Int      @id @default(autoincrement())
  email   String   @unique
  name    String?
  role    Role     @default(USER)
  posts   Post[]
  profile Profile?
}
```

##### 複合 ID

在以下範例中,`User` ID 由 `firstName` 和 `lastName` 欄位的組合表示:

```prisma highlight=7;normal
model User {
  firstName String
  lastName  String
  email     String  @unique
  isAdmin   Boolean @default(false)

  //highlight-next-line
  @@id([firstName, lastName])
}
```

預設情況下,此欄位在 Prisma Client 查詢中的名稱將是 `firstName_lastName`。

您也可以使用 [`@@id`](/orm/reference/prisma-schema-reference#id-1) 屬性的 `name` 欄位為複合 ID 提供您自己的名稱:

```prisma highlight=7;normal
model User {
  firstName String
  lastName  String
  email     String  @unique
  isAdmin   Boolean @default(false)

  //highlight-next-line
  @@id(name: "fullName", fields: [firstName, lastName])
}
```

`firstName_lastName` 欄位現在將被命名為 `fullName`。

:::info

請參閱[使用複合 ID](/orm/prisma-client/special-fields-and-types/working-with-composite-ids-and-constraints) 的文件,了解如何在 Prisma Client 中與複合 ID 互動。

:::

##### `@unique` 欄位作為唯一識別碼

在以下範例中,使用者由 `@unique` 欄位唯一標識。因為 `email` 欄位作為模型的唯一識別碼(這是必需的),它必須是必填的:

```prisma highlight=2;normal
model User {
  //highlight-next-line
  email   String   @unique
  name    String?
  role    Role     @default(USER)
  posts   Post[]
  profile Profile?
}
```

:::info

**關聯式資料庫中的約束名稱** <br />
您可以選擇在底層資料庫中定義[自訂主鍵約束名稱](/orm/prisma-schema/data-model/database-mapping#constraint-and-index-names)。

:::

#### 在 MongoDB 中定義 ID

MongoDB 連接器對於定義 ID 欄位有[特定規則](/orm/reference/prisma-schema-reference#mongodb),與關聯式資料庫不同。ID 必須使用 [`@id`](/orm/reference/prisma-schema-reference#id) 屬性由單一欄位定義,並且必須包含 `@map("_id")`。

在以下範例中,`User` ID 由接受自動生成的 `ObjectId` 的 `id` 字串欄位表示:

```prisma highlight=2;normal
model User {
  //highlight-next-line
  id      String   @id @default(auto()) @map("_id") @db.ObjectId
  email   String   @unique
  name    String?
  role    Role     @default(USER)
  posts   Post[]
  profile Profile?
}
```

在以下範例中,`User` ID 由接受 `ObjectId` 以外的其他內容的 `id` 字串欄位表示 - 例如,唯一的使用者名稱:

```prisma highlight=2;normal
model User {
  //highlight-next-line
  id      String   @id @map("_id")
  email   String   @unique
  name    String?
  role    Role     @default(USER)
  posts   Post[]
  profile Profile?
}
```

:::warning

**MongoDB 不支援 `@@id`**<br />
MongoDB 不支援複合 ID,這意味著您無法使用 `@@id` 區塊識別模型。

:::

### 定義預設值

您可以使用 [`@default`](/orm/reference/prisma-schema-reference#default) 屬性為模型的純量欄位定義預設值:

<TabbedContent code>
<TabItem value="Relational databases">

```prisma highlight=3,5;normal
model Post {
  id         Int        @id @default(autoincrement())
  //highlight-next-line
  createdAt  DateTime   @default(now())
  title      String
  //highlight-next-line
  published  Boolean    @default(false)
  //highlight-next-line
  data       Json       @default("{ \"hello\": \"world\" }")
  author     User       @relation(fields: [authorId], references: [id])
  authorId   Int
  categories Category[] @relation(references: [id])
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma highlight=3,5;normal
model Post {
  id         String     @id @default(auto()) @map("_id") @db.ObjectId
  createdAt  DateTime   @default(now())
  title      String
  published  Boolean    @default(false)
  author     User       @relation(fields: [authorId], references: [id])
  authorId   String     @db.ObjectId
  categories Category[] @relation(references: [id])
}
```

</TabItem>
</TabbedContent>

`@default` 屬性可以:

- 在底層資料庫中表示 `DEFAULT` 值(僅限關聯式資料庫)_或_
- 使用 Prisma ORM 層級的函式。例如,`cuid()` 和 `uuid()` 由 Prisma Client 的[查詢引擎](/orm/more/under-the-hood/engines)為所有連接器提供。

預設值可以是:

- 對應到欄位類型的靜態值,例如 `5`(`Int`)、`Hello`(`String`)或 `false`(`Boolean`)
- 靜態值的[列表](/orm/reference/prisma-schema-reference#-modifier),例如 `[5, 6, 8]`(`Int[]`)或 `["Hello", "Goodbye"]`(`String`[])。這些在 Prisma ORM 版本 `4.0.0` 及更高版本中可用,當使用支援的資料庫(PostgreSQL、CockroachDB 和 MongoDB)時
- [函式](#using-functions),例如 [`now()`](/orm/reference/prisma-schema-reference#now) 或 [`uuid()`](/orm/reference/prisma-schema-reference#uuid)
- JSON 資料。請注意,JSON 需要在 `@default` 屬性內用雙引號括起來,例如: `@default("[]")`。如果您想提供一個 JSON 物件,您需要用雙引號括起來,然後使用反斜線轉義任何內部的雙引號,例如: `@default("{ \"hello\": \"world\" }")`。

:::info

請參閱[屬性函式參考文件](/orm/reference/prisma-schema-reference#attribute-functions)以獲取有關連接器支援函式的資訊。

:::

### 定義唯一欄位

您可以在模型中新增唯一屬性,以便能夠唯一識別該模型的單個記錄。唯一屬性可以使用 [`@unique`](/orm/reference/prisma-schema-reference#unique) 屬性在單一欄位上定義,或使用 [`@@unique`](/orm/reference/prisma-schema-reference#unique-1) 屬性在多個欄位上定義(也稱為複合或組合唯一約束)。

在以下範例中,`email` 欄位的值必須是唯一的:

<TabbedContent code>
<TabItem value="Relational databases">

```prisma
model User {
  id    Int     @id @default(autoincrement())
  email String  @unique
  name  String?
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma
model User {
  id    String  @id @default(auto()) @map("_id") @db.ObjectId
  email String  @unique
  name  String?
}
```

</TabItem>
</TabbedContent>

在以下範例中,`authorId` 和 `title` 的組合必須是唯一的:

<TabbedContent code>
<TabItem value="Relational databases">

```prisma highlight=10;normal
model Post {
  id         Int        @id @default(autoincrement())
  createdAt  DateTime   @default(now())
  title      String
  published  Boolean    @default(false)
  author     User       @relation(fields: [authorId], references: [id])
  authorId   Int
  categories Category[] @relation(references: [id])

  //highlight-next-line
  @@unique([authorId, title])
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma highlight=10;normal
model Post {
  id         String     @id @default(auto()) @map("_id") @db.ObjectId
  createdAt  DateTime   @default(now())
  title      String
  published  Boolean    @default(false)
  author     User       @relation(fields: [authorId], references: [id])
  authorId   String     @db.ObjectId
  categories Category[] @relation(references: [id])

  //highlight-next-line
  @@unique([authorId, title])
}
```

</TabItem>
</TabbedContent>

:::info

**關聯式資料庫中的約束名稱** <br />
您可以選擇在底層資料庫中定義[自訂唯一約束名稱](/orm/prisma-schema/data-model/database-mapping#constraint-and-index-names)。

:::

預設情況下,此欄位在 Prisma Client 查詢中的名稱將是 `authorId_title`。

您也可以使用 [`@@unique`](/orm/prisma-schema/data-model/database-mapping#constraint-and-index-names) 屬性的 `name` 欄位為複合唯一約束提供您自己的名稱:

```prisma highlight=10;normal
model Post {
  id         String     @id @default(auto()) @map("_id") @db.ObjectId
  createdAt  DateTime   @default(now())
  title      String
  published  Boolean    @default(false)
  author     User       @relation(fields: [authorId], references: [id])
  authorId   String     @db.ObjectId
  categories Category[] @relation(references: [id])

  //highlight-next-line
  @@unique(name: "authorTitle", [authorId, title])
}
```

`authorId_title` 欄位現在將被命名為 `authorTitle`。

:::info

請參閱[使用複合唯一識別碼](/orm/prisma-client/special-fields-and-types/working-with-composite-ids-and-constraints)的文件,了解如何在 Prisma Client 中與複合唯一約束互動。

:::

#### 複合類型唯一約束

當在版本 `3.12.0` 及更高版本中使用 MongoDB 提供者時,您可以使用語法 `@@unique([compositeType.field])` 在[複合類型](#defining-composite-types)的欄位上定義唯一約束。與其他欄位一樣,複合類型欄位可以作為多欄位唯一約束的一部分使用。

以下範例基於 `User` 模型的 `email` 欄位和 `Address` 複合類型的 `number` 欄位(在 `User.address` 中使用)定義了一個多欄位唯一約束:

```prisma file=schema.prisma showLineNumbers
type Address {
  street String
  number Int
}

model User {
  id      Int     @id
  email   String
  address Address

  @@unique([email, address.number])
}
```

如果有多個巢狀複合類型,此標記法可以連結:

```prisma file=schema.prisma showLineNumbers
type City {
  name String
}

type Address {
  number Int
  city   City
}

model User {
  id      Int       @id
  address Address[]

  @@unique([address.city.name])
}
```

### 定義索引

您可以透過模型上的 [`@@index`](/orm/reference/prisma-schema-reference#index) 在模型的一個或多個欄位上定義索引。以下範例基於 `title` 和 `content` 欄位定義了一個多欄位索引:

```prisma
model Post {
  id      Int     @id @default(autoincrement())
  title   String
  content String?

  @@index([title, content])
}
```

:::info

**關聯式資料庫中的索引名稱** <br />
您可以選擇在底層資料庫中定義[自訂索引名稱](/orm/prisma-schema/data-model/database-mapping#constraint-and-index-names)。

:::

#### 定義複合類型索引

當在版本 `3.12.0` 及更高版本中使用 MongoDB 提供者時,您可以使用語法 `@@index([compositeType.field])` 在[複合類型](#defining-composite-types)的欄位上定義索引。與其他欄位一樣,複合類型欄位可以作為多欄位索引的一部分使用。

以下範例基於 `User` 模型的 `email` 欄位和 `Address` 複合類型的 `number` 欄位定義了一個多欄位索引:

```prisma file=schema.prisma showLineNumbers
type Address {
  street String
  number Int
}

model User {
  id      Int     @id
  email   String
  address Address

  @@index([email, address.number])
}
```

如果有多個巢狀複合類型,此標記法可以連結:

```prisma file=schema.prisma showLineNumbers
type City {
  name String
}

type Address {
  number Int
  city   City
}

model User {
  id      Int       @id
  address Address[]

  @@index([address.city.name])
}
```

## 定義列舉

如果您的資料庫連接器[支援列舉](/orm/reference/database-features#misc),您可以在資料模型中定義列舉,無論是原生支援還是在 Prisma ORM 層級支援。

列舉在 Prisma schema 資料模型中被視為[純量](#scalar-fields)類型。因此,它們[預設](/orm/prisma-client/queries/select-fields#return-the-default-fields)作為回傳值包含在 [Prisma Client 查詢](/orm/prisma-client/queries/crud)中。

```prisma highlight=5,8-11;normal
  USER
  ADMIN

//highlight-end
```

</TabItem>

```prisma highlight=5,8-11;normal
model User {

  name  String?
```

## 定義複合類型

:::info

複合類型在版本 `3.10.0` 中作為 `mongodb` 預覽功能新增,並從版本 `3.12.0` 開始進入正式版本。

:::

:::warning

複合類型目前僅在 MongoDB 上可用。

:::

複合類型(在 MongoDB 中稱為[嵌入式文件](https://www.mongodb.com/docs/manual/data-modeling/#embedded-data))透過允許您定義新的物件類型來提供在其他記錄內嵌入記錄的支援。複合類型的結構和類型化方式與[模型](#defining-models)類似。

要定義複合類型,請使用 `type` 區塊。例如,以下 schema:

```prisma file=schema.prisma showLineNumbers
model Product {
  id     String  @id @default(auto()) @map("_id") @db.ObjectId
  name   String
  photos Photo[]
}

type Photo {
  height Int
  width  Int
  url    String
}
```

在這種情況下,`Product` 模型有一個儲存在 `photos` 中的 `Photo` 複合類型列表。

### 使用複合類型時的注意事項

複合類型僅支援有限的[屬性](/orm/reference/prisma-schema-reference#attributes)集。支援以下屬性:

- `@default`
- `@map`
- [原生類型](/orm/reference/prisma-schema-reference#model-field-scalar-types),例如 `@db.ObjectId`

複合類型內不支援以下屬性:

- `@unique`
- `@id`
- `@relation`
- `@ignore`
- `@updatedAt`

然而,仍然可以透過在使用複合類型的模型層級上使用 `@@unique` 屬性來定義唯一約束。有關更多詳細資訊,請參閱[複合類型唯一約束](#composite-type-unique-constraints)。

可以透過在使用複合類型的模型層級上使用 `@@index` 屬性來定義索引。有關更多詳細資訊,請參閱[複合類型索引](#defining-composite-type-indexes)。

## 使用函式

Prisma schema 支援多個[函式](/orm/reference/prisma-schema-reference#attribute-functions)。這些可以用來指定模型欄位上的[預設值](/orm/reference/prisma-schema-reference#default)。

例如,`createdAt` 的預設值是 [`now()`](/orm/reference/prisma-schema-reference#now):

<TabbedContent code>
<TabItem value="Relational databases">

```prisma
model Post {
  id        Int      @id @default(autoincrement())
  createdAt DateTime @default(now())
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma
model Post {
  id        String   @default(auto()) @map("_id") @db.ObjectId
  createdAt DateTime @default(now())
}
```

</TabItem>
</TabbedContent>

[`cuid()`](/orm/reference/prisma-schema-reference#cuid) 和 [`uuid()`](/orm/reference/prisma-schema-reference#uuid) 由 Prisma ORM 實作,因此在底層資料庫 schema 中不「可見」。當使用[自省](/orm/prisma-schema/introspection)時,您仍然可以透過[手動變更 Prisma schema](/orm/prisma-client/setup-and-configuration/custom-model-and-field-names) 和[生成 Prisma Client](/orm/prisma-client/setup-and-configuration/generating-prisma-client) 來使用它們,在這種情況下,值將由 Prisma Client 的[查詢引擎](/orm/more/under-the-hood/engines)生成

[`autoincrement()`](/orm/reference/prisma-schema-reference#autoincrement)、[`now()`](/orm/reference/prisma-schema-reference#now) 和 [`dbgenerated(...)`](/orm/reference/prisma-schema-reference#dbgenerated) 的支援在不同資料庫之間有所不同。

**關聯式資料庫連接器**在資料庫層級實作 `autoincrement()`、`dbgenerated(...)` 和 `now()`。**MongoDB 連接器**不支援 `autoincrement()` 或 `dbgenerated(...)`,並且 `now()` 在 Prisma ORM 層級實作。[`auto()`](/orm/reference/prisma-schema-reference#auto) 函式用於生成 `ObjectId`。

## Prisma Client 中的模型

### 查詢 (CRUD)

資料模型定義中的每個模型都會在生成的 [Prisma Client API](/orm/prisma-client) 中產生多個 CRUD 查詢:

- [`findMany()`](/orm/reference/prisma-client-reference#findmany)
- [`findFirst()`](/orm/reference/prisma-client-reference#findfirst)
- [`findFirstOrThrow()`](/orm/reference/prisma-client-reference#findfirstorthrow)
- [`findUnique()`](/orm/reference/prisma-client-reference#findunique)
- [`findUniqueOrThrow()`](/orm/reference/prisma-client-reference#finduniqueorthrow)
- [`create()`](/orm/reference/prisma-client-reference#create)
- [`update()`](/orm/reference/prisma-client-reference#update)
- [`upsert()`](/orm/reference/prisma-client-reference#upsert)
- [`delete()`](/orm/reference/prisma-client-reference#delete)
- [`createMany()`](/orm/reference/prisma-client-reference#createmany)
- [`createManyAndReturn()`](/orm/reference/prisma-client-reference#createmanyandreturn)
- [`updateMany()`](/orm/reference/prisma-client-reference#updatemany)
- [`updateManyAndReturn()`](/orm/reference/prisma-client-reference#updatemanyandreturn)
- [`deleteMany()`](/orm/reference/prisma-client-reference#deletemany)

這些操作可透過 Prisma Client 實例上生成的屬性存取。預設情況下,屬性的名稱是模型名稱的小寫形式,例如 `User` 模型的 `user` 或 `Post` 模型的 `post`。

以下是一個範例,說明如何使用 Prisma Client API 中的 `user` 屬性:

```js
const newUser = await prisma.user.create({
  data: {
    name: 'Alice',
  },
})
const allUsers = await prisma.user.findMany()
```

### 型別定義

Prisma Client 還會生成反映您模型結構的**型別定義**。這些是生成的 [`@prisma/client`](/orm/prisma-client/setup-and-configuration/generating-prisma-client#the-prismaclient-npm-package) node 模組的一部分。

當使用 TypeScript 時,這些型別定義確保您的所有資料庫查詢都是完全型別安全的,並在編譯時驗證(即使使用 [`select`](/orm/reference/prisma-client-reference#select) 或 [`include`](/orm/reference/prisma-client-reference#include) 的部分查詢也是如此)。

即使使用純 JavaScript,型別定義仍然包含在 `@prisma/client` node 模組中,在您的編輯器中啟用 [IntelliSense](https://code.visualstudio.com/docs/editor/intellisense)/自動完成等功能。

> **注意**: 實際的型別儲存在 `.prisma/client` 資料夾中。`@prisma/client/index.d.ts` 匯出此資料夾的內容。

例如,上面 `User` 模型的型別定義如下:

```ts
export type User = {
  id: number
  email: string
  name: string | null
  role: string
}
```

請注意,關聯欄位 `posts` 和 `profile` 預設不包含在型別定義中。但是,如果您需要 `User` 型別的變體,您仍然可以使用一些 [Prisma Client 生成的輔助型別](/orm/prisma-client/setup-and-configuration/generating-prisma-client)來定義它們(在這種情況下,這些輔助型別將被稱為 `UserGetIncludePayload` 和 `UserGetSelectPayload`)。

## 限制

### 記錄必須可唯一識別

Prisma ORM 目前僅支援至少有一個唯一欄位或欄位組合的模型。實際上,這意味著每個 Prisma 模型必須至少有以下屬性之一:

- 單一或多欄位主鍵約束的 `@id` 或 `@@id`(每個模型最多一個)
- 單一或多欄位唯一約束的 `@unique` 或 `@@unique`
