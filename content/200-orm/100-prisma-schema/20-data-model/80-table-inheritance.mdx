## 概述

資料表繼承是一種軟體設計模式，允許對實體之間的階層關係進行建模。在資料庫層級使用資料表繼承還可以在您的 JavaScript/TypeScript 應用程式中使用聯合類型，或在多個模型之間共享一組通用屬性。

本頁面介紹資料表繼承的兩種方法，並說明如何在 Prisma ORM 中使用它們。

資料表繼承的常見使用案例可能是當應用程式需要顯示某種_內容活動_的_動態_時。在這種情況下，內容活動可以是_影片_或_文章_。例如，讓我們假設：

- 內容活動始終具有 `id` 和 `url`
- 除了 `id` 和 `url` 之外，影片還具有 `duration`（建模為 `Int`）
- 除了 `id` 和 `url` 之外，文章還具有 `body`（建模為 `String`）

### 使用案例

#### 聯合類型

聯合類型是 TypeScript 中的一個便利功能，允許開發人員更靈活地使用其資料模型中的類型。

在 TypeScript 中，聯合類型如下所示：

```ts no-copy
type Activity = Video | Article
```

雖然[目前無法在 Prisma schema 中建模聯合類型](https://github.com/prisma/prisma/issues/2505)，但您可以透過使用資料表繼承和一些額外的類型定義，在 Prisma ORM 中使用它們。

#### 在多個模型之間共享屬性

如果您有一個使用案例，其中多個模型應該共享特定的屬性集，您也可以使用資料表繼承來建模。

例如，如果上面的 `Video` 和 `Article` 模型都應該具有共享的 `title` 屬性，您也可以透過資料表繼承來實現此目的。

### 範例

在簡單的 Prisma schema 中，這將如下所示。請注意，我們還加入了一個 `User` 模型來說明這如何與關聯一起工作：

```prisma file=schema.prisma showLineNumbers
model Video {
  id       Int    @id
  url      String @unique
  duration Int

  user   User @relation(fields: [userId], references: [id])
  userId Int
}

model Article {
  id   Int    @id
  url  String @unique
  body String

  user   User @relation(fields: [userId], references: [id])
  userId Int
}

model User {
  id       Int       @id
  name     String
  videos   Video[]
  articles Article[]
}
```

讓我們探討如何使用資料表繼承來建模這個情況。

### 單表繼承與多表繼承

以下是資料表繼承的兩種主要方法的快速比較：

- **單表繼承（STI）**：使用_單一_資料表在一個位置儲存_所有_不同實體的資料。在我們的範例中，將有一個單一的 `Activity` 資料表，包含 `id`、`url` 以及 `duration` 和 `body` 欄位。它還使用一個 `type` 欄位來指示_活動_是_影片_還是_文章_。
- **多表繼承（MTI）**：使用_多個_資料表分別儲存不同實體的資料，並透過外鍵將它們連結。在我們的範例中，將有一個包含 `id`、`url` 欄位的 `Activity` 資料表，一個包含 `duration` 和指向 `Activity` 外鍵的 `Video` 資料表，以及一個包含 `body` 和外鍵的 `Article` 資料表。還有一個 `type` 欄位作為判別器，指示_活動_是_影片_還是_文章_。請注意，多表繼承有時也稱為_委派類型_。

您可以在[下方](#tradeoffs-between-sti-and-mti)了解這兩種方法的權衡。

## 單表繼承（STI）

### 資料模型

使用 STI，上述情境可以建模如下：

```prisma
model Activity {
  id       Int          @id // shared
  url      String       @unique // shared
  duration Int? // video-only
  body     String? // article-only
  type     ActivityType // discriminator

  owner   User @relation(fields: [ownerId], references: [id])
  ownerId Int
}

enum ActivityType {
  Video
  Article
}

model User {
  id         Int        @id @default(autoincrement())
  name       String?
  activities Activity[]
}
```

需要注意以下幾點：

- 模型特定的屬性 `duration` 和 `body` 必須標記為可選（即使用 `?`）。這是因為 `Activity` 資料表中代表_影片_的記錄不能有 `body` 的值。相反地，代表_文章_的 `Activity` 記錄永遠不能設定 `duration`。
- `type` 判別器欄位指示每個記錄代表_影片_還是_文章_項目。

### Prisma Client API

由於 Prisma ORM 為資料模型產生類型和 API 的方式，您只能使用 `Activity` 類型及其所屬的 CRUD 查詢（`create`、`update`、`delete`...）。

#### 查詢影片和文章

您現在可以透過在 `type` 欄位上進行篩選來僅查詢_影片_或_文章_。例如：

```ts
// Query all videos
const videos = await prisma.activity.findMany({
  where: { type: 'Video' },
})

// Query all articles
const articles = await prisma.activity.findMany({
  where: { type: 'Article' },
})
```

#### 定義專用類型

當這樣查詢影片和文章時，TypeScript 仍然只會識別 `Activity` 類型。這可能會很煩人，因為即使 `videos` 中的物件也會有（可選的）`body`，而 `articles` 中的物件會有（可選的）`duration` 欄位。

如果您希望對這些物件擁有類型安全性，您需要為它們定義專用類型。例如，您可以透過使用產生的 `Activity` 類型和 TypeScript 的 `Omit` 實用類型來從中移除屬性：

```ts
import { Activity } from '../prisma/generated/client'

type Video = Omit<Activity, 'body' | 'type'>
type Article = Omit<Activity, 'duration' | 'type'>
```

此外，建立將 `Activity` 類型的物件轉換為 `Video` 和 `Article` 類型的對應函式會很有幫助：

```ts
function activityToVideo(activity: Activity): Video {
  return {
    url: activity.url,
    duration: activity.duration ? activity.duration : -1,
    ownerId: activity.ownerId,
  } as Video
}

function activityToArticle(activity: Activity): Article {
  return {
    url: activity.url,
    body: activity.body ? activity.body : '',
    ownerId: activity.ownerId,
  } as Article
}
```

現在您可以在查詢後將 `Activity` 轉換為更特定的類型（即 `Article` 或 `Video`）：

```ts
const videoActivities = await prisma.activity.findMany({
  where: { type: 'Video' },
})
const videos: Video[] = videoActivities.map(activityToVideo)
```

您可以使用 [Prisma Client 擴充功能](/orm/prisma-client/client-extensions)為資料庫中的資料表結構建立更方便的 API。

## 多表繼承（MTI）

### 資料模型

使用 MTI，上述情境可以建模如下：

```prisma
model Activity {
  id   Int          @id @default(autoincrement())
  url  String // shared
  type ActivityType // discriminator

  video   Video? // model-specific 1-1 relation
  article Article? // model-specific 1-1 relation

  owner   User @relation(fields: [ownerId], references: [id])
  ownerId Int
}

model Video {
  id         Int      @id @default(autoincrement())
  duration   Int // video-only
  activityId Int      @unique
  activity   Activity @relation(fields: [activityId], references: [id])
}

model Article {
  id         Int      @id @default(autoincrement())
  body       String // article-only 
  activityId Int      @unique
  activity   Activity @relation(fields: [activityId], references: [id])
}

enum ActivityType {
  Video
  Article
}

model User {
  id         Int        @id @default(autoincrement())
  name       String?
  activities Activity[]
}
```

需要注意以下幾點：

- `Activity` 和 `Video` 以及 `Activity` 和 `Article` 之間需要 1-1 關聯。此關聯用於在需要時擷取有關記錄的特定資訊。
- 使用此方法，模型特定的屬性 `duration` 和 `body` 可以設為_必填_。
- `type` 判別器欄位指示每個記錄代表_影片_還是_文章_項目。

### Prisma Client API

這次，您可以透過 `PrismaClient` 實例上的 `video` 和 `article` 屬性直接查詢影片和文章。

#### 查詢影片和文章

如果您想要存取共享屬性，您需要使用 `include` 來擷取與 `Activity` 的關聯。

```ts
// Query all videos
const videos = await prisma.video.findMany({
  include: { activity: true },
})

// Query all articles
const articles = await prisma.article.findMany({
  include: { activity: true },
})
```

根據您的需求，您也可以透過在 `type` 判別器欄位上進行篩選來以另一種方式查詢：

```ts
// Query all videos
const videoActivities = await prisma.activity.findMany({
  where: { type: 'Video' }
  include: { video: true }
})
```

#### 定義專用類型

雖然與 STI 相比，在類型方面更方便一些，但產生的類型可能仍然無法滿足您的所有需求。

以下是如何透過結合 Prisma ORM 產生的 `Video` 和 `Article` 類型與 `Activity` 類型來定義 `Video` 和 `Article` 類型。這些組合建立了一個具有所需屬性的新類型。請注意，我們還省略了 `type` 判別器欄位，因為在特定類型上不再需要它：

```ts
import {
  Video as VideoDB,
  Article as ArticleDB,
  Activity,
} from '../prisma/generated/client'

type Video = Omit<VideoDB & Activity, 'type'>
type Article = Omit<ArticleDB & Activity, 'type'>
```

一旦定義了這些類型，您就可以定義對應函式，將從上述查詢收到的類型轉換為所需的 `Video` 和 `Article` 類型。以下是 `Video` 類型的範例：

```ts
import { Prisma, Video as VideoDB, Activity } from '../prisma/generated/client'

type Video = Omit<VideoDB & Activity, 'type'>

// Create `VideoWithActivity` typings for the objects returned above
const videoWithActivity = Prisma.validator<Prisma.VideoDefaultArgs>()({
  include: { activity: true },
})
type VideoWithActivity = Prisma.VideoGetPayload<typeof videoWithActivity>

// Map to `Video` type
function toVideo(a: VideoWithActivity): Video {
  return {
    id: a.id,
    url: a.activity.url,
    ownerId: a.activity.ownerId,
    duration: a.duration,
    activityId: a.activity.id,
  }
}
```

現在您可以獲取上述查詢返回的物件，並使用 `toVideo` 對其進行轉換：

```ts
const videoWithActivities = await prisma.video.findMany({
  include: { activity: true },
})
const videos: Video[] = videoWithActivities.map(toVideo)
```

## STI 和 MTI 之間的權衡

- **資料模型**：使用 MTI 可能會讓資料模型感覺更乾淨。使用 STI，您最終可能會得到非常寬的行以及許多包含 `NULL` 值的欄位。
- **效能**：MTI 可能會帶來效能成本，因為您需要連接父表和子表才能存取與模型相關的_所有_屬性。
- **類型**：使用 Prisma ORM，MTI 已經為您提供了特定模型的適當類型（即上述範例中的 `Article` 和 `Video`），而使用 STI 則需要從頭建立這些類型。
- **ID / 主鍵**：使用 MTI，記錄有兩個 ID（一個在父表上，另一個在子表上），它們可能不匹配。您需要在應用程式的業務邏輯中考慮這一點。

## 第三方解決方案

雖然 Prisma ORM 目前本身不支援聯合類型或多型，但您可以查看 [Zenstack](https://github.com/zenstackhq/zenstack)，它為 Prisma schema 加入了額外的功能層。閱讀他們關於 [Prisma ORM 中的多型](https://zenstack.dev/blog/polymorphism)的部落格文章以了解更多資訊。
