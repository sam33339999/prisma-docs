資料庫視圖允許您命名和儲存查詢。在關聯式資料庫中,視圖是[儲存的 SQL 查詢](https://www.postgresql.org/docs/current/sql-createview.html),可能包含多個表格中的欄位,或計算值如聚合。在 MongoDB 中,視圖是可查詢的物件,其內容由其他集合上的[聚合管道](https://www.mongodb.com/docs/manual/core/aggregation-pipeline)定義。

`views` 預覽功能允許您使用 `view` 關鍵字在 Prisma schema 中表示視圖。要在 Prisma ORM 中使用視圖,請遵循以下步驟:

1. [啟用 `views` 預覽功能](#enable-the-views-preview-feature)
1. [在底層資料庫中建立視圖](#create-a-view-in-the-underlying-database),直接建立或作為 [Prisma Migrate 遷移檔案的手動新增](#use-views-with-prisma-migrate-and-db-push),或使用現有視圖
1. [在 Prisma schema 中表示視圖](#add-views-to-your-prisma-schema)
1. [在 Prisma Client 中查詢視圖](#query-views-in-prisma-client)


:::warning

視圖支援目前是[預覽](/orm/more/releases#preview)功能。您可以使用 `view` 關鍵字將視圖新增到 Prisma schema 中,或使用 `db pull` 自省資料庫 schema 中的視圖。除非使用 `--create-only` 標誌將變更手動新增到遷移檔案中,否則您還無法使用 Prisma Migrate 和 `db push` 將 schema 中的視圖應用到資料庫。<br /><br />有關此功能的進度更新,請關注[我們的 GitHub 問題](https://github.com/prisma/prisma/issues/17335)。

:::

## 啟用 `views` 預覽功能

視圖支援目前處於早期預覽階段。要啟用 `views` 預覽功能,請將 `views` 功能標誌新增到 Prisma Schema 中 `generator` 區塊的 `previewFeatures` 欄位中:

```prisma file=schema.prisma highlight=3;add showLineNumbers
generator client {
  provider        = "prisma-client"
  output          = "./generated"
  //add-next-line
  previewFeatures = ["views"]
}
```

請在我們專門的預覽功能[回饋問題](https://github.com/prisma/prisma/issues/17335)中留下關於 `views` 的回饋。

## 在底層資料庫中建立視圖

目前,您無法使用 Prisma Migrate 或 `db push` 將在 Prisma schema 中定義的視圖應用到資料庫。相反,您必須首先在底層資料庫中建立視圖,手動建立或[作為遷移的一部分](#use-views-with-prisma-migrate-and-db-push)。

例如,以下 Prisma schema 包含一個 `User` 模型和一個相關的 `Profile` 模型:

<TabbedContent code>
<TabItem value="Relational databases">

```prisma
model User {
  id      Int      @id @default(autoincrement())
  email   String   @unique
  name    String?
  profile Profile?
}

model Profile {
  id     Int    @id @default(autoincrement())
  bio    String
  user   User   @relation(fields: [userId], references: [id])
  userId Int    @unique
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma
model User {
  id      String   @id @default(auto()) @map("_id") @db.ObjectId
  email   String   @unique
  name    String?
  profile Profile?
}

model Profile {
  id     String @id @default(auto()) @map("_id") @db.ObjectId
  bio    String
  User   User   @relation(fields: [userId], references: [id])
  userId String @unique @db.ObjectId
}
```

</TabItem>
</TabbedContent>

接下來,在底層資料庫中使用一個 `UserInfo` 視圖,該視圖結合了 `User` 模型的 `email` 和 `name` 欄位以及 `Profile` 模型的 `bio` 欄位。

對於關聯式資料庫,建立此視圖的 SQL 語句是:

```sql
CREATE VIEW "UserInfo" AS
    SELECT u.id, email, name, bio
    FROM "User" u
    LEFT JOIN "Profile" p ON u.id = p."userId";
```

對於 MongoDB,您可以使用以下命令[建立視圖](https://www.mongodb.com/docs/manual/core/views/join-collections-with-view/):

```ts
db.createView('UserInfo', 'User', [
  {
    $lookup: {
      from: 'Profile',
      localField: '_id',
      foreignField: 'userId',
      as: 'ProfileData',
    },
  },
  {
    $project: {
      _id: 1,
      email: 1,
      name: 1,
      bio: '$ProfileData.bio',
    },
  },
  { $unwind: '$bio' },
])
```

## 使用 Prisma Migrate 和 `db push` 的視圖

如果您使用 Prisma Migrate 或 `db push` 將變更應用到 Prisma schema,Prisma ORM 不會建立或執行任何與視圖相關的 SQL。

要在遷移中包含視圖,執行 `migrate dev --create-only`,然後手動將視圖的 SQL 新增到您的遷移檔案中。或者,您可以在資料庫中手動建立視圖。

## 將視圖新增到 Prisma schema

要將視圖新增到 Prisma schema,請使用 `view` 關鍵字。

您可以在 Prisma schema 中表示上述範例中的 `UserInfo` 視圖,如下所示:

<TabbedContent code>
<TabItem value="Relational databases">

```prisma
view UserInfo {
  id    Int
  email String
  name  String
  bio   String
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma
view UserInfo {
  id    String @map("_id") @db.ObjectId
  email String
  name  String
  bio   String
}
```

</TabItem>
</TabbedContent>

### 手動撰寫

`view` 區塊由兩個主要部分組成:

- `view` 區塊定義
- 視圖的欄位定義

這兩個部分允許您定義生成的 Prisma Client 中視圖的名稱以及視圖查詢結果中存在的欄位。

#### 定義 `view` 區塊

要定義上述範例中的 `UserInfo` 視圖,首先使用 `view` 關鍵字在 schema 中定義一個名為 `UserInfo` 的 `view` 區塊:

```prisma
view UserInfo {
  // Fields
}
```

#### 定義欄位

視圖的屬性稱為_欄位_,其由以下組成:

- 欄位名稱
- 欄位類型

`UserInfo` 範例視圖的欄位可以定義如下:

<TabbedContent code>
<TabItem value="Relational databases">

```prisma highlight=2-5;normal
view UserInfo {
  //highlight-start
  id    Int
  email String
  name  String
  bio   String
  //highlight-end
}
```

</TabItem>
<TabItem value="MongoDB">

```prisma highlight=2-5;normal
view UserInfo {
  //highlight-start
  id    String @map("_id") @db.ObjectId
  email String
  name  String
  bio   String
  //highlight-end
}
```

</TabItem>
</TabbedContent>

`view` 區塊的每個_欄位_代表底層資料庫中視圖查詢結果的一個欄位。

### 使用自省

:::warning
目前只能使用 PostgreSQL、MySQL、SQL Server 和 CockroachDB 資料庫自省視圖。如果您使用其他資料庫提供者,則必須手動新增視圖。
:::


如果您在資料庫中定義了現有的一個或多個視圖,[自省](/orm/prisma-schema/introspection)將自動在 Prisma schema 中生成代表這些視圖的 `view` 區塊。

假設範例 `UserInfo` 視圖存在於您的底層資料庫中,執行以下命令將在 Prisma schema 中生成代表該視圖的 `view` 區塊:

```terminal copy
npx prisma db pull
```

產生的 `view` 區塊將定義如下:

```prisma
view UserInfo {
  id    Int?
  email String?
  name  String?
  bio   String?
}
```

:::warning
請注意,目前 `db pull` 只會在使用 PostgreSQL、MySQL、SQL Server 或 CockroachDB 時自省 schema 中的視圖。此工作流程的支援將擴展到其他資料庫提供者。
:::

#### `views` 目錄

自省包含一個或多個現有視圖的資料庫還會在您的 `prisma` 目錄中建立一個新的 `views` 目錄(從 Prisma 版本 4.12.0 開始)。此目錄將包含一個以資料庫 schema 命名的子目錄,該子目錄包含為該 schema 中自省的每個視圖建立的 `.sql` 檔案。每個檔案將以單個視圖命名,並將包含相關視圖定義的查詢。

例如,在使用上述模型自省具有預設 `public` schema 的資料庫後,您會發現建立了一個 `prisma/views/public/UserInfo.sql` 檔案,其內容如下:

```sql
SELECT
  u.id,
  u.email,
  u.name,
  p.bio
FROM
  (
    "User" u
    LEFT JOIN "Profile" p ON ((u.id = p."userId"))
  );
```

## 在 Prisma Client 中查詢視圖

:::note

請確保在更新 Prisma schema 後執行 `prisma generate`,以便 `view` 定義成為 Prisma Client API 的一部分。

:::

您可以在 Prisma Client 中以與查詢模型相同的方式查詢視圖。例如,以下查詢在上面定義的 `UserInfo` 視圖中查找所有 `name` 為 `'Alice'` 的使用者。

```ts
const userinfo = await prisma.userInfo.findMany({
  where: {
    name: 'Alice',
  },
})
```

:::note

寫入查詢(create/update/delete)不支援在 `views` 上。

:::


## 特殊類型的視圖

本節描述如何在資料庫中使用 Prisma ORM 與可更新視圖和物化視圖。

### 可更新視圖

某些資料庫支援_可更新視圖_(例如 [PostgreSQL](https://www.postgresql.org/docs/current/sql-createview.html#SQL-CREATEVIEW-UPDATABLE-VIEWS)、[MySQL](https://dev.mysql.com/doc/refman/8.0/en/view-updatability.html) 和 [SQL Server](https://learn.microsoft.com/en-us/sql/t-sql/statements/create-view-transact-sql?view=sql-server-ver16#updatable-views))。如果底層資料庫支援此類操作,可更新視圖允許建立、更新或刪除條目。

Prisma ORM 不允許在視圖上進行任何變更(create、update、delete),無論資料庫的能力如何。此變更提供護欄,確保視圖在 Prisma Client 中被一致地視為唯讀實體。因此,在 Prisma Client API 中不會為 `view` 區塊生成執行寫入的方法,如 `create`、`update`、`delete` 或 `upsert`。

如果您需要修改視圖表示的資料,您必須直接在底層表格上執行寫入操作或使用原始 SQL 查詢。

### 物化視圖

某些資料庫支援物化視圖,例如 [PostgreSQL](https://www.postgresql.org/docs/current/rules-materializedviews.html)、[CockroachDB](https://www.cockroachlabs.com/docs/stable/views.html#materialized-views)、[MongoDB](https://www.mongodb.com/docs/manual/core/materialized-views/) 和 [SQL Server](https://learn.microsoft.com/en-us/sql/relational-databases/views/create-indexed-views?view=sql-server-ver16)(在其中稱為「索引視圖」)。

物化視圖將視圖查詢的結果保存以便更快地存取,並且只在需要時更新它。

目前,Prisma ORM 不支援物化視圖。但是,當您[手動建立視圖](#create-a-view-in-the-underlying-database)時,您也可以使用底層資料庫中的相應命令建立物化視圖。然後,您可以使用 Prisma Client 的 [TypedSQL 功能](/orm/prisma-client/using-raw-sql)來執行命令並手動刷新視圖。

未來 Prisma Client 可能會支援將單個視圖標記為物化,並新增 Prisma Client 方法來刷新物化視圖。請在我們的 [`views` 回饋問題](https://github.com/prisma/prisma/issues/17335)上評論您的使用案例。

## 限制

Prisma ORM 將所有 `view` 區塊視為_唯讀_資料庫查詢的表示,而不是真正的表格。因此,為了確保 Prisma Client 與底層資料庫的行為保持一致,適用一些限制。

### 沒有識別碼

視圖是虛擬表格,沒有內在的主鍵。因此,您無法在 `view` 區塊上定義 `@id`、`@@id` 屬性。

### 沒有索引

因為視圖是虛擬表格,所以它們不能有索引。因此,`@index` 和 `@@index` 無法在 `view` 區塊上定義。

### 不安全的 `@unique` 屬性

雖然 Prisma ORM 允許您在視圖上放置 `@unique` 和 `@@unique` 屬性,但底層資料庫和 Prisma 不會強制執行這些約束。因此,多行可能會共享同一個應該是唯一欄位的值。

資料庫和 Prisma ORM 都不會強制執行該屬性表達的唯一約束。

在這種情況下,`@unique` 屬性的目的只是為了在 Prisma Client 中啟用跨視圖的關係以及 `findUnique` 查詢和基於游標的分頁。

### 停用寫入查詢

所有寫入操作(`create`、`update`、`delete`、`upsert`)都被停用,並且不會在 Prisma Client 中生成。
