## 概述


Prisma ORM 中的_外部管理的資料表_（或簡稱_外部資料表_）是可以**透過 Prisma Client 查詢**但**被 Prisma Migrate 忽略**的資料表。

有時，您可能不希望 Prisma ORM 管理特定資料表——例如由另一個團隊或服務處理的資料表。

這方面的一些具體使用情境包括：
- 像 Clerk 或 Auth0 這樣的認證服務，它們管理包含使用者和會話資料的特定資料表
- 像 Supabase Storage 這樣的儲存服務，它們有用於儲存有關 bucket 和物件的中繼資料的資料表
- 基於微服務的組織，其中特定團隊擁有資料庫中的特定資料表

基於自訂組織約束或偏好，可能有許多其他情境，您可能不希望 Prisma ORM 管理特定資料表。

:::warning
外部管理的資料表目前處於[預覽](/orm/more/releases#preview)階段。
:::

:::note
外部管理的資料表經常與[多重 schema](/orm/prisma-schema/data-model/multi-schema) 資料庫設定結合使用。然而，這並不是硬性要求。您可以在資料庫中只有一個 schema，並在其中宣告外部管理的資料表。
:::

:::warning
Prisma ORM 不會驗證資料庫中資料表的結構與 Prisma 模型的結構是否實際匹配。
一方面，這要求開發人員在更新 Prisma schema 時要仔細（最安全的方法是使用 `prisma db pull`）。
另一方面，這種靈活性使您能夠僅表示資料庫中底層資料表的一部分（例如，不公開_所有_欄位）。
:::

## 工作流程

如果您想使用外部資料表，以下是主要工作流程：
1. 在您的 [Prisma Config 檔案](/orm/reference/prisma-config-reference)中宣告外部資料表的名稱
1. 更新您的 Prisma schema（例如透過 `npx prisma db pull`）
1. 使用 `npx prisma generate` 重新生成 Prisma Client
1. 您現在可以使用 Prisma Client 查詢外部資料表，但它將被 Prisma Migrate 忽略
1. 當資料表被更改時（由擁有它的人）：
    1. 使用 `npx prisma db pull` 重新內省您的資料庫，或手動更新 prisma 檔案中的模型
    1. 使用 `npx prisma generate` 重新生成 Prisma Client

## Prisma Config 語法

您可以透過 `tables.external` 屬性在您的 [Prisma Config](/orm/reference/prisma-config-reference) 檔案中指定外部管理的資料表：

```ts file=prisma.config.ts
import 'dotenv/config'
import { defineConfig, env } from 'prisma/config'

export default defineConfig({
  schema: 'prisma/schema.prisma',
  migrations: {
    path: 'prisma/migrations',
  },
  datasource: {
    url: env('DATABASE_URL'),
  },
  // required when using unstable features
  experimental: {
    // add-next-line
    externalTables: true
  },
  // declare the `users` table and `role` enum as external
  // add-start
  tables: {
    external: [
      "public.users",
    ]
  },
  enums: {
    external: [
      "public.role",
    ]
  },
  // add-end
})
```

- 與資料表類似，您也可以有外部管理的_列舉_。
- 在 PostgreSQL 和 SQL Server 上，您必須指定包含 schema 名稱的完全限定資料表/列舉名稱。例如：`public.products` 或 `auth.users`。
- 在 MySQL 和 SQLite 上，您只需指定資料表名稱。

## 關聯

Prisma 可以從它管理的資料表建立和更新到外部管理資料表的關聯。

然而，為此，Prisma 需要在遷移建立期間知道這些外部管理資料表的結構。
您可以提供一個 SQL 腳本，Prisma 將在所有遷移之前在其[影子資料庫](/orm/prisma-migrate/understanding-prisma-migrate/shadow-database)上執行該腳本，以在遷移建立期間模擬外部資料表和列舉。

建立的佔位符資料表不需要具有實際資料表的完整結構，但主鍵需要存在。

如果外部資料表未被任何受管理的資料表引用——也就是說，沒有受管理的資料表包含對外部資料表的外鍵約束——您不需要在 `migrations.initShadowDb` 中為其提供任何 SQL。


```ts file=prisma.config.ts
import 'dotenv/config'
import { defineConfig, env } from 'prisma/config'

export default defineConfig({
  schema: 'prisma/schema.prisma',
  datasource: {
    url: env('DATABASE_URL'),
  },
  // required when using unstable features
  experimental: {
    // add-next-line
    externalTables: true
  },
  // add-start
  // declare a `users` table
  tables: {
    external: [
      "public.users",
    ]
  },
  migrations: {
    path: 'prisma/migrations',
    // setup the users table for the shadow database
    initShadowDb: `
      CREATE TABLE public.users (id SERIAL PRIMARY KEY);
    `
  },
  // add-end
})
```

從外部資料表到受管理資料表的關聯，其中外部資料表包含對受管理資料表的外鍵約束，**不**由 Prisma 管理，因為這將修改外部資料表。

## 範例

假設您有以下 Prisma schema，其中僅包含 `posts` 資料表：

```prisma
generator client {
  provider = "prisma-client"
  output   = "./generated"
  // ...
}

datasource db {
  provider = "postgresql"
  // ...
}

model posts {
  id          Int       @id @default(autoincrement())
  created_at  DateTime  @default(now())
  title       String
  content     String?
}
```

您已經透過先前的遷移建立了該 `posts` 資料表。
您現在在資料庫中還有一個 `users` 資料表和 `role` 列舉，您希望將其視為外部管理。

因此，您的 PostgreSQL 資料庫中預設 `public` schema 中的資料表如下所示：

```sql
-- Enum used by users table
CREATE TYPE role AS ENUM ('customer', 'support', 'admin');

-- Users table
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) NOT NULL UNIQUE,
  email VARCHAR(100) NOT NULL UNIQUE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  role role
);

-- Posts table
CREATE TABLE posts (
  id SERIAL PRIMARY KEY,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  title VARCHAR(200) NOT NULL,
  content TEXT
);
```

### 1. 在 Prisma Config 中宣告外部管理的資料表

透過 `tables.external` 屬性啟用外部管理資料表的使用：

```ts file=prisma.config.ts
import 'dotenv/config'
import { defineConfig, env } from 'prisma/config'

export default defineConfig({
  schema: 'prisma/schema.prisma',
  migrations: {
    path: 'prisma/migrations',
  },
  datasource: {
    url: env('DATABASE_URL'),
  },
  experimental: {
    // add-next-line
    externalTables: true
  },
  // declare the `users` table and `role` enum as external
  // add-start
  tables: {
    external: [
      "public.users",
    ]
  },
  enums: {
    external: [
      "public.role",
    ]
  },
  // add-end
})
```

### 2. 更新 Prisma schema

接下來，您需要更新 Prisma schema。您可以透過以下任一方式執行此操作：
- 手動建立模型
- 或使用[內省](/orm/prisma-schema/introspection)：

```terminal
npx prisma db pull
```

`users` 資料表現在在您的 Prisma schema 中：

```prisma
model posts {
  id         Int       @id @default(autoincrement())
  created_at DateTime? @default(now()) @db.Timestamp(6)
  title      String    @db.VarChar(200)
  content    String?
}

// highlight-start
model users {
  id         Int       @id @default(autoincrement())
  username   String    @unique @db.VarChar(50)
  email      String    @unique @db.VarChar(100)
  created_at DateTime? @default(now()) @db.Timestamp(6)
  role       role
}

enum role {
  customer
  support
  admin
}
// highlight-end
```

### 3. 重新生成 Prisma Client

為了能夠查詢 `users` 資料表，您需要重新生成 Prisma Client：

```terminal
npx prisma generate
```

### 4. 使用 Prisma Client 查詢 `users` 資料表

您現在可以使用 Prisma Client 查詢外部 `users` 資料表：

```ts
await prisma.users.findMany()
```

### 5. 添加關聯

假設您現在想從 `posts` 到 `users` 添加一個作者關聯。

首先更新您的 Prisma schema。

```prisma
model posts {
  id         Int       @id @default(autoincrement())
  created_at DateTime? @default(now()) @db.Timestamp(6)
  title      String    @db.VarChar(200)
  content    String?
  // add-start
  author     users @relation(fields: [author_id], references: [id])
  author_id  Int
  // add-end
}

model users {
  id         Int       @id @default(autoincrement())
  username   String    @unique @db.VarChar(50)
  email      String    @unique @db.VarChar(100)
  created_at DateTime? @default(now()) @db.Timestamp(6)
  role       role
  // add-start
  posts      posts[]
  // add-end
}

enum role {
  customer
  support
  admin
}
```

然後添加 `migrations.initShadowDb` 腳本，以便 Prisma 在遷移期間知道 `users` 資料表。

```ts file=prisma.config.ts
import 'dotenv/config'
import { defineConfig, env } from 'prisma/config'

export default defineConfig({
  schema: 'prisma/schema.prisma',
  datasource: {
    url: env('DATABASE_URL'),
  },
  experimental: {
    externalTables: true
  },
  tables: {
    external: [
      "public.users",
    ]
  },
  // add-start
  migrations: {
    path: 'prisma/migrations',
    // setup the users table for the shadow database
    initShadowDb: `
      CREATE TABLE public.users (id SERIAL PRIMARY KEY);
    `
  },
  // add-end
})
```

現在您可以執行 `prisma migrate dev` 命令。
