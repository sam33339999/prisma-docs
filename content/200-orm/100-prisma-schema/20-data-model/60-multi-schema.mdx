## 概述

PostgreSQL、CockroachDB 和 SQL Server 允許您將資料庫資料表組織成命名群組。這些群組稱為 _schema_，並充當_命名空間_，用於邏輯上分組資料表（例如，避免名稱衝突或具有更清晰的領域分離），並允許您在它們之間定義外鍵約束。為避免歧義，本頁面將這些命名空間稱為_資料庫 schema_。

本頁面說明如何：
- 在您的 Prisma schema 中包含多個資料庫 schema
- 使用 Prisma Migrate 將您的 schema 變更應用到資料庫
- 內省具有多個資料庫 schema 的現有資料庫
- 使用 Prisma Client 跨多個資料庫 schema 進行查詢

:::note

多重 schema 功能僅支援 PostgreSQL、CockroachDB 和 SQL Server。它不適用於 SQLite 和 MySQL，因為這些資料庫沒有相同的 _schema 作為命名空間_ 的概念。

:::


## 如何在您的 Prisma schema 中包含多個資料庫 schema

要在您的 Prisma schema 檔案中使用多個資料庫 schema，請在 `datasource` 區塊的 `schemas` 欄位中將資料庫 schema 的名稱添加到陣列中。以下範例添加了 `"base"` 和 `"shop"` schema：

```prisma file=schema.prisma
generator client {
  provider        = "prisma-client"
  output          = "./generated"
}

datasource db {
  provider = "postgresql"
  //add-next-line
  schemas  = ["base", "shop"]
}
```

您不需要更改連接字串。連接字串的 `schema` 值是 Prisma Client 連接到並用於原始查詢的預設資料庫 schema。所有其他 Prisma Client 查詢都使用您正在查詢的模型或列舉的 schema。

要指定模型或列舉屬於特定的資料庫 schema，請添加 `@@schema` 屬性，並將資料庫 schema 的名稱作為參數。在以下範例中，`User` 模型是 `"base"` schema 的一部分，而 `Order` 模型和 `Size` 列舉是 `"shop"` schema 的一部分：

```prisma file=schema.prisma
model User {
  id     Int     @id
  orders Order[]

  //add-next-line
  @@schema("base")
}

model Order {
  id      Int  @id
  user    User @relation(fields: [userId], references: [id])
  userId  Int

  //add-next-line
  @@schema("shop")
}

enum Size {
  Small
  Medium
  Large

  //add-next-line
  @@schema("shop")
}
```

### 不同資料庫 schema 中具有相同名稱的資料表

如果您在不同的資料庫 schema 中有相同名稱的資料表，您需要將資料表名稱映射到 Prisma schema 中的唯一模型名稱。這可以避免在 Prisma Client 中查詢模型時的名稱衝突。

例如，考慮 `base` 資料庫 schema 中的 `Config` 資料表與 `users` 資料庫 schema 中的 `Config` 資料表具有相同名稱的情況。為了避免名稱衝突，請在您的 Prisma schema 中為模型提供唯一名稱（`BaseConfig` 和 `UserConfig`），並使用 `@@map` 屬性將每個模型映射到相應的資料表名稱：

```prisma file=schema.prisma
model BaseConfig {
  id Int @id

  @@map("Config")
  @@schema("base")
}

model UserConfig {
  id Int @id

  @@map("Config")
  @@schema("users")
}
```

## 如何使用 Prisma Migrate 應用您的 schema 變更

您可以使用 Prisma Migrate（或 `prisma db push`）將變更應用到具有多個資料庫 schema 的 Prisma schema。

作為範例，將 `Profile` 模型添加到上面的 `base` schema：

```prisma file=schema.prisma
model User {
  id      Int      @id
  orders  Order[]
  //add-next-line
  profile Profile?

  @@schema("base")
}

//add-start
model Profile {
  id     Int    @id @default(autoincrement())
  bio    String
  user   User   @relation(fields: [userId], references: [id])
  userId Int    @unique

  @@schema("base")
}
//add-end

model Order {
  id      Int  @id
  user    User @relation(fields: [userId], references: [id])
  userId  Int

  @@schema("shop")
}

enum Size {
  Small
  Medium
  Large

  @@schema("shop")
}
```

然後，您可以將此 schema 變更應用到您的資料庫。例如，您可以使用 `migrate dev` 建立並應用您的 schema 變更作為遷移：

```terminal
npx prisma migrate dev --name add_profile
```

請注意，如果您將模型或列舉從一個 schema 移動到另一個 schema，Prisma ORM 會從來源 schema 中刪除模型或列舉，並在目標 schema 中建立一個新的。

## 如何內省具有多個資料庫 schema 的現有資料庫

您可以使用與內省具有單個資料庫 schema 的資料庫相同的方式內省具有多個資料庫 schema 的現有資料庫，使用 `prisma db pull`：

```terminal
npx prisma db pull
```

這會更新您的 Prisma schema 以符合資料庫的當前狀態。

如果您在不同的資料庫 schema 中有相同名稱的資料表，Prisma ORM 會顯示驗證錯誤，指出衝突。要解決此問題，請[使用 `@map` 屬性重新命名內省的模型](#tables-with-the-same-name-in-different-database-schemas)。

## 如何使用 Prisma Client 跨多個資料庫 schema 進行查詢

您可以在多個資料庫 schema 中查詢模型，而無需更改 Prisma Client 查詢語法。例如，以下查詢使用上述 Prisma schema 查找給定使用者的所有訂單：

```ts
const orders = await prisma.order.findMany({
  where: {
    user: {
      id: 42,
    },
  },
})
```

### 外部管理的資料表

有時，您可能不希望 Prisma ORM 管理特定資料表，例如由另一個團隊或服務處理的資料表（例如，Auth0 或 Clerk 資料表）。在這種情況下，您可以使用 [Prisma Config 檔案](/orm/reference/prisma-config-reference#tablesexternal-and-enumsexternal)中的 `tables.external` 配置選項將這些標記為**外部管理的資料表**。深入了解[外部管理的資料表](/orm/prisma-schema/data-model/externally-managed-tables)。
